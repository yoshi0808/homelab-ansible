# Slack通知は本文だけで判断でき、本文をコピーできる形で送る

決定日: 2026-09-27(本文で判断できること)、2026-11-27(コピーできる形) / 決定者: Yoshinobu / 記録: Coordinator

## 決めたこと

**Yoshinobuはスマホの Slack で通知を読み、その本文だけで「何が起きたか・対応が要るか」を判断する。** 通知を設計・変更するときは、この読み方で足りるかを見る。

- **reportのパスを載せても代わりにならない。** スマホからは開けない。パスは「このreportを見て」と頼むときの目印(ファイル名1行)にしかならない。
- **金曜のdry-run通知は予告にすぎない。** 土曜は状況が変わる(2026-09-26は金曜3件→土曜7件)。土曜の完了通知は「金曜の通知を参照」で済ませず、実際に適用したpackageごとのパッチ内容を自分で持つ(Policy SB-070)。「予告外」の印までは要らない。
- **本文はメッセージの最上位の `text` に入れる。** attachment(色帯つきの旧形式)の中に置いた本文は、スマホの「テキストをコピー」で拾われない。`text` の1行目はタイトルにする(スマホのpush通知のプレビューに出るため)。attachmentには色帯とタイトルだけを残す。2026-11-27に #info への試しの1通で、本文全体をコピーでき、色帯も目印として残ることをYoshinobuが確かめた。

## 退けた案

- 色をやめて絵文字だけで区別する — 一覧で色を見て判断できなくなる。
- Block Kitへ作り直す — コピーの挙動が読めない。
- attachmentのタイトルを外して色帯だけにする(タイトルの重複を避ける案) — titleもtextも無いattachmentは色帯が表示されない(2026-11-27、試し送信で確認)。

## 経緯

2026-09-27、案件2b(`docs/ai/reviews/proxmox_patch_notifications_2b/`)の計画でCoordinatorは①reportパスを通知に載せる ②changelogは金曜の通知を参照させる、と提案し、2つとも退けられた(「Slackからどうやって見るんだろう」「金曜日はあくまで予告」)。2026-11-26の月次振り返りでこの判断を記録へ移す際、「丁寧に載せてくれても、色分けした通知はテキストでコピーできない」と追加の指摘があり、送信形式を変えた。
