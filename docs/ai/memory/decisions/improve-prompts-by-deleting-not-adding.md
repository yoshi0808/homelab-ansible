# 規範の品質向上をAI側で自律的に回す。ただし自律化するのは「削る」側だけとする

決定日: 2026-08-19 / 決定者: Yoshinobu / 起案: Coordinator

## 決定

規範文書の品質向上を、Yoshinobuが主導する棚卸しからAI側の自律的な運用へ移す。**ただし自律化の対象は削除に限る。**

- **削るのは測れる。** ある規範文を書いた後にも同じ形の誤りが記録され続けているなら、その文は効いていない。これは証拠であり、判断ではない。
- **足すのは測れない。** 新しい制約を課すかどうかは将来についての判断であり、Yoshinobuが決める。

Yoshinobuが残すのは**この環境固有の事実と、Yoshinobu自身の考え方**である。関与するのはそこまでとし、削除案の採否以外を判断しない。

### 判定基準を逆にしない

- **発火していない文は「不要」ではない。** 効いているから出てこない可能性がある。
- **書いた後にも再発している文が「効いていない」。** 削除の根拠にしてよいのはこちらだけである。

### 冗長さは、効かなさとは別の問題として扱う

経緯・根拠・履歴が規範文書に残って膨らむのは効果の問題ではなく**希釈**である。判定は機械的にできる — その一文が「何をせよ」を言っているか、「なぜ」を言っているか。後者は規範文書から出す。規約自体は2026-08-01に決まっており(`docs/ai/roles/` 5本へ適用済み)、**その後に足された分が掃かれていないだけである。**

## なぜこうしたか

**規範文は、誤りが起きるその瞬間に読まれていなければ発火しない。** 常時読み込みの文書へ文を足すと一文あたりの想起確率が下がるため、**足すほど既に効いていた文まで薄まる。** 「協議しながら追記を重ねても効果が出ない」のは、この方法を続けたときに出るはずの結果であって、努力の不足ではない。

Yoshinobuは短い周期で棚卸しと削除を繰り返してこの希釈を抑えてきたが、**本望ではない**と表明した(2026-08-19)。現状は能力の不在と別体によるレビューで運用できているが、AI側が自律的にレビューと改善を回して質を上げられるはずだ、という判断である。

対策として取れるのは①能力を消す ②別体に検査させる ③設計要件として積む、の3つだけである(`docs/ai/memory/lessons/permission-boundaries-must-be-designed-not-prompted.md`)。**推測で断定する類には①が使えない**(断定する能力は消せない)。したがって「文言をどう直すか」という問いには最初から答えが無く、②か③へ回すか、書くのをやめるかしかない。

## 実施内容

月次のKnowledge振り返り(次回 2026-08-26)で、再発記録の各行を次の4列で仕分ける。

| 列 | 値 | その行動 |
|---|---|---|
| 手段 | ①能力で消せる | 消す。対応する規範文は削除する |
| 手段 | ②別体でしか捕まえられない | 検査へ回す。規範文の役目は「いつ回すか」だけに縮める |
| 手段 | ③どちらでもない | **もう書かない。** 残存リスクとして名前を付けて受け入れる |
| 再発 | その規範文を書いた**後**にも再発している | その文は効いていない。削除候補 |
| 再発 | 書く**前**だけ | 効いている。残す |
| 種別 | 経緯・根拠 | 規範文ではない。規範文書から出す |

**Yoshinobuへ出すのは削除案の採否だけ**とし、どう書き直すかを考えてもらわない。③に落ちた行について、Coordinatorから文案を出さない(出せばまた一文増える)。

いまの再発記録の節は「3回を超えたらSkill化の候補として人へ出す」と書いているが、**Skill化はもう一文足すことと同じ**である。3回を超えたときの結論は「この類に文章は効かない。②か③へ回す」の側になる可能性が高い。8/26の仕分けで確かめる。

## 引き受けたリスク

**Coordinatorは縛られる側なので、自分の制約の要否を単独で判定できない。** 「冗長そうだ」で削れば、自分を縛っている文から先に消える。したがって削除は「測定 → 別体の確認 → 実行」の形にしかできず、この工程は短縮しない。

**固定点がまだ無い。** 自律的な圧縮は、止めるものが無ければ最後に制約そのものを食べる。**AIが書き換えてよい文書と、Yoshinobuしか触らない文書を明示的に分ける**必要があるが、2026-08-19時点で分離されていない。分離してあれば、暴走は「触ってはいけない側に手が伸びた」という観測可能な形で現れる。**未着手である。**

**削除の効果は、削除しても測れない。** ある文を消して悪化しないことは、悪化が起きるまで分からない。gitで戻せることだけが担保である。

## 見直し条件

- 削除した規範文に対応する誤りが、削除後に再発した場合(その文は効いていた)。
- 再発記録が計測手段として使えないと判明した場合。**過検出は2026-08-19時点で10件中1件残っており、合否を判定する手段が無い**(`docs/ai/status.md`)。この計測が信用できないなら、削除の根拠も無くなる。
- AIが書き換えてよい文書の分離を入れないまま、削除の規模が大きくなった場合。
