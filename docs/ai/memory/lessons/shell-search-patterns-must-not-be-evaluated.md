# Lesson: 検索パターンをshell評価させない

`rg`や`grep`がread-onlyでも、その前にshellがコマンド文字列を解釈する。検索パターンを
ダブルクォートへ入れ、文字列中にバッククォートを含めると、検索開始前にコマンド置換が実行される。
「検索のつもり」は安全性の根拠にならない。

## 守ること

- shellメタ文字を含む検索パターンは単引用符で囲み、展開させない。
- 実行可能なコマンド断片を検索語へ含める必要がなければ、識別語へ分割して検索する。
- read-only検査でも、shellへ渡す文字列にバッククォート、`$()`、リダイレクト、globが無いか
  実行前に確認する。
- 誤って起動した場合は、意図した検索を続ける前に、起動されたコマンドと変更の有無を確認する。

## 根拠

| 日付 | 事象 | 結果 |
|---|---|---|
| 2026-09-08 | 規範の残存検索でバッククォート付きのGitコマンドをダブルクォート内へ置き、shellが実行した | SSH設定検査で接続前に失敗。HEADとorigin/mainに変化なし |
| 2026-09-09 | Implementer経路の旧語検索で3つのバッククォート識別子をダブルクォート内へ置き、shellが各文字列をコマンドとして実行した | 2コマンドはnot found、Claude Codeは入力不足で終了。直後の`git status`で想定外変更なし |

この同型再発により、2026-09-08 Incidentの個別対処を再利用可能なLessonへ昇格した。
