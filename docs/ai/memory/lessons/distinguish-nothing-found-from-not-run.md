# 「何も見つからなかった」と「動かなかった」を区別できる形にする

## 教訓

検査や観測の仕組みを書くとき、**結果が空であること**には2つの意味がある。

1. 正常に動いて、該当が無かった
2. **そもそも動いていない、または対象へ到達していない**

この2つが同じ出力(空、無言、成功終了)に落ちる設計は、**壊れていることが原理的に観測できない**。しかも壊れている間ほど「問題なし」に見えるため、放置期間が長引く。

したがって、**動いたこと自体を、見つけたかどうかとは独立に観測可能にする**。手段は2つある。

- **判定不能を明示的に失敗させる(fail-closed)**。「該当なし」と「判定できなかった」を同じ経路に落とさない。読めない入力は「安全」ではなく「未判定」である
- **動いたことの痕跡を、結果と無関係に残す**(ハートビート)。サイズが増えない単一ファイルの上書きで足りる

## 根拠(2026-07-27、独立した2箇所で同日に発生)

いずれも本番影響が出る前に独立レビューで検出した。詳細は各Incidentを参照。

**1件目: commit前の秘密ファイル検査**([[../incidents/2026-07-27_precommit-quotepath-bypass]])。`git diff --cached --name-only` は既定で非ASCIIパスを8進エスケープし引用符で包む。名前で突き合わせる検査(`grep` / `case` / `[[ -f ]]`)はすべて一致せず、**無音でスキップ**していた。`秘密dir/id_rsa` のような名前なら、公開リポジトリへ秘密鍵をcommitできた。

ここでの構造的な問題は、`grep` の0件も、`case` の不一致も、`[[ -f ]]` の偽も、**「該当しない」と「判定できない」を同じ経路に落とす**ことだった。修正は根本原因(`core.quotepath=false`)に加えて、**それでも読めない名前が残ったら止める**ガードを入れている。

**2件目: 障害証拠の自動捕捉**([[../incidents/2026-07-27_incident-capture-spool-root-ownership]])。spoolディレクトリがroot所有で作られ、捕捉プロセスが永久に書き込めない状態になりうるバグがあった。単独なら気づける。しかし**無音化の判断が3つ重なっていた**。

- 捕捉の失敗は自身の`rescue`が吸収する(観測が被観測を壊さないための、意図的な設計)
- 捕捉停止の検出は「失敗ジョブがある周期」でしか発火しない(既存クエリの制約)
- 正常時に成果物を残さない(ファイル増殖を避ける意図)

**3つとも単独では正当な理由を持つ。** 合成された結果だけが「捕捉が一度も動いていないのに誰も気づかない」だった。修正はハートビートの追加、つまり**動いたことを結果と独立に残す**ことである。

## 適用

- ゲートや検査を書くとき、**入力が読めない・到達できない場合に何が起きるか**を明示的に決める。既定は fail-closed とする
- 周期実行される観測プロセスには、**結果が空でも書かれる痕跡**を持たせる
- **無音化の判断を1つ入れるたびに「これが他の無音と重なったら何が見えなくなるか」を問う。** 個別レビューでは各判断の正当性しか問われないため、合成を見る立場(Coordinator、または全体を見る独立レビュー)がこの問いを持つ
- 検証では、守ろうとしている対象ではなく**仕組みを迂回しうる入力**を作って試す([[verify-the-outside-of-a-claimed-boundary]])。1件目はASCII名しか試していなかったため、何年でも正常に見え続けたはずである
