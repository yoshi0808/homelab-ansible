# Incident: 検索パターンのバッククォートがgit pushを起動した

日付: 2026-09-08
状態: 解決済み(接続前に失敗し、local・remoteとも変更なし)
対象: Coordinatorのローカル検査コマンド
種別: 未遂
原因分類: #運用考慮ミス

## 症状

規範変更後の残存表現を`rg`で検索する際、shellへ渡すコマンド全体を二重引用符で
囲み、その検索パターン内へバッククォート付きの`git push`を含めた。shellがこれを
コマンド置換として評価し、承認されていない`git push`を1回起動した。

pushはSSH設定ファイルのowner/permission検査で接続前に失敗した。直後に
`git rev-parse HEAD`と`git rev-parse origin/main`を比較し、どちらも
`f10b21b9b9643c95761b642d494146d69d2896fe`であることを確認した。

## 原因

検索パターンをshellへ渡す際の引用規則を誤った。バッククォートを含む文字列を
二重引用符内へ置けばコマンド置換されることを考慮せず、読み取り専用検索のつもりで
コマンド文字列を組み立てた。

## 修正内容

- バッククォートを含む検索パターンは単引用符で囲み、shell展開させない。
- 検査コマンドへ実行可能なGit断片を含めず、必要なら語を分割した検索にする。
- 失敗したpushを成功させるための再実行や経路変更は行わない。

## 確認方法

- `HEAD`とローカルの`origin/main`追跡refが同一で、commitが増えていないことを確認した。
- SSHエラーはremote repositoryへ接続する前の設定検査で発生しており、push結果は無い。
- 修正後の残存表現検索は単引用符を使って再実行する。
