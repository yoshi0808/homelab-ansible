## 変更

- `playbooks/semaphore_upgrade.yml` の案内と `check-mode-native` 理由を、Semaphore UI Dry Run / CLI `--check` の意味へ更新した。
- `roles/semaphore_upgrade/tasks/main.yml` に旧 `dry_run` のfail-closed移行guardと、通常/check共通の単一host guardを追加した。モードは `rollback` と `ansible_check_mode` の2軸で選択する。
- `upgrade_diagnose.yml` / `rollback_diagnose.yml` を追加し、version、binary、running job、service owner、consumer reading path、SQLite baseline、rollback candidateを状態変更なしで観測する。check modeでは共通shape(`host`、`mode`、`current`、`target`/`rollback_candidate`、`action`、`running_jobs`、`reading_path_check`)を表示する。
- 通常変更処理を `not ansible_check_mode` の動的includeへ限定し、included taskへ `destructive` tagを適用した。check modeではbackup directory/work directory、package取得・install、transaction/marker/result書込み、detached起動、通知経路へ到達しない。
- `semaphore_upgrade_dry_run` と有効なdry-run gateを削除し、rollback candidate selectorの時刻生成を通常実行側へ移した。
- Semaphore upgrade apply/rollback templateから `dry_run` Survey Variableを削除し、applyの `--limit quory` とrollbackの `rollback` / `rollback_to` は維持した。READMEの説明を更新した。schedule catalogは変更していない。
- native check-mode fixtureと既存境界fixtureの検査を更新した。
