# Closeout: Semaphore upgrade native check mode

作成: 2026-09-07 / Coordinator
状態: 実装・レビュー・安全な検証・commit / push完了、quory reconcile待ち

## 結論

`semaphore_upgrade`の独自`dry_run`を廃止し、Semaphore UI Dry Run / Ansible
`--check`を唯一のdry-run経路とする差分は、2名の独立Reviewerからblocking 0の
Approveを得た。localhost/decoyの受入マトリクスとansy自身のnative checkでも、
upgrade/rollback双方のread-only診断とP0-4の副作用ゼロが成立した。

実ホストの通常upgrade/rollbackは本案件の検証として実行していない。実装はcommit
`374f12e`としてpush済みだが、quoryの実templateは未更新である。

## 採用した証拠

- Reviewer 2名の最終Verdict: Approve(blocking 0)。
- localhost fixture: upgrade/rollback × reading path available/unavailableの4組を
  3周直列実行し12/12 rc=0。診断出力は予定動作、running jobs、reading path、
  rollback candidateを表示した。
- decoy: 旧`dry_run=true`/`false`、2host、`--tags destructive`併用がすべて
  診断・変更より前にrc非ゼロとなった。
- ansy: 安全wrapper経由のupgrade/rollback `--check`が各rc=0、`changed=0`。
  backup/work root、DB、result/marker、service MainPIDの前後差分は0件だった。
- syntax、ansible-lint、tester-gate lint(60 playbooks)、doc consistency、Python
  13 tests、capture-origin、rollback-candidate fixtureが成功した。

## 証拠から除外したもの

fixture先頭のcheck-only assertを動的に確認するため、TesterとReviewerが各1回、
fixtureを`--check`なしで直接起動した。どちらも先頭assertで`ok=0`、`changed=0`、
rc=2となり実害はなかったが、TS-023に例外はないため受入証拠から除外した。
check-only不変条件の根拠は、`test_detach_boundary.py`の静的検査と安全wrapperの
引数欠落拒否に限定する。手続きとCoordinator依頼の不備はIncidentへ記録した。

## Findingsの扱い

- 解消: fixtureのcheck-only guard、実パス隔離、reading path available側の未検証、
  backup generation不増加、guardの`always` tag、rollback診断shape、READMEの
  単一host必須表現。
- 現状維持: rollback候補0件のcheckは、実行可能なrollback計画が成立しないため、
  明示的fail message付きrc非ゼロをfail-closedとして採用する。
- scope外: upgrade/rollback診断の重複refactorは、通常経路の挙動変更リスクを避ける。
- non-blocking: fixtureの固定`/tmp` rootは並行実行非対応。今回の衝突結果は破棄し、
  単独直列12回で再取得した。今後もこのfixtureを並行実行しない。
- non-blocking: unavailable fixtureではquery command不在・token存在の片側欠落を作る。
  roleのAND判定を検証でき、ansyの実状態とも一致するため受入に影響しない。
- 記録訂正: `006_review.md`所見#9の「ansyはquery/token両方不在」は、007/008の
  実測と食い違う。正しくはquery command不在・token存在であり、本closeoutでは
  実測2件が一致する後者を採用する。
- scope外の既存事項: rollback側のrunning-job assert非対称と、`systemctl show
  semaphore.service`のリテラル指定。本差分が持ち込んだ退行ではない。
- 未確認として維持: `sqlite3 <db> SELECT`は既存の通常preflightにも存在したが、
  check modeでWAL/SHM補助ファイルを生成しうるかは未確認。ansy検証ではDB本体の
  size/mtimeまでしか比較していないため、quory初回Dry Runの前後観測へ引き継ぐ。
