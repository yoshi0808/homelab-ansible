## 指摘

### 1. 案件の残存リスクと運用制約が `docs/ai/status.md` へ出ていない(**クローズを妨げる**)

closeout §残存リスク は4件を挙げるが、`docs/ai/status.md` に現れているのは §Next(着手候補)
—システム・運用 の `dry_run` 名前衝突の行(以下「該当行」)だけで、そこに書かれているのは
「残る配備境界はcommit/push、quoryのtemplate catalog reconcile、実templateからSurveyが
消えたことの観測」までである。次の2つが正本へ出ていない。

- **reading path「有り」側は、fixtureのstubでしか成立していない。** 実 `homelab-semaphore-query`
  と実ACLに対する初回実行が、そのまま**本番quoryのDry Run**になる。005 Suggestion #1 →
  006 Major #1 として2名のReviewerが独立に挙げ、007・008の双方が「解消していない残存リスク」
  として明記した、本案件で最も重い未検証事項である。
- **closeout §残存リスク 4 の運用制約** —「その観測前に `UN-SAFE: Semaphore upgrade (apply)`
  または rollback template を実運用へ使わない」。これは案件が閉じたあとも効く**現在の制約**で
  あり、案件フォルダにしか無い状態では、次のセッションが該当行だけを読んで template を
  起動しうる。

`docs/ai/status.md` は現在地と観測待ちの正本であり、案件フォルダは閉じたあと通常は読まれない。
該当行は残り2 playbook を抱えるため**消さず**、上記2点を Now(観測待ち)側へ足すか該当行へ
追記する必要がある。**Coordinatorが同一セッションで反映すれば足り、再監査は要らない。**

### 2. `2026-09-06_003_plan_review.md` に作成日・担当が無い(クローズを妨げない)

本案件は「計画査読は別CLI」「差分レビューは計画査読とは別体」という**独立性**を判断の柱に
しており(002 §5、005・006の見出し)、005 は `reviewer_tests` 等の identity を、007 / 008 は
`Tester` / `tester_matrix` を名乗っている。003だけが日付・担当・使用CLIのいずれも持たない。
「別CLIだった」という事実は 002 §5-1 の予定と 005 の自称からの推定でしか辿れず、3か月後に
「誰がいつ査読したか」を確定できない。1行のヘッダで解消する。

### 3. 003 Suggestion #1 と現行 requirement が矛盾し、requirement 側に改訂記録が無い(クローズを妨げない)

003 Suggestion #1 は「check mode での複数host診断を禁じる記述が requirement 中に見当たらない」
と述べ、適用範囲の確定をCoordinatorへ求めている。しかし現行 requirement は P0-7 で
「通常実行・`--check`のどちらも、1回の実行対象はちょうど1host」、AC6 で「通常実行または
`--check`」と**明示している**。002 §6 は反映先を計画§1.1-3 とだけ記し、requirement を直した
とは書いていない。requirement にも改訂履歴の節が無い(§7 オープンクエスチョンは「なし」)。

読み手には「査読者が読み落とした」のか「requirement が査読後に黙って書き足された」のかを
判別する手段が無い。案件フォルダは全体が未commitで `git log` も助けにならない。requirement
へ改訂を1行残すか、003 が現行 requirement に対して stale であることを注記すれば閉じる。

### 4. ansy の consumer reading path の実態について、006 と 007 / 008 が逆のことを述べている(クローズを妨げない)

- `2026-09-06_006_review.md` 所見 #9: unavailable変種の状態は「ansyの実態(**両方不在**)とは
  ずれている」。
- `2026-09-06_007_test_ansy.md` 事前確認: ansy では `homelab-semaphore-query` バイナリが不在、
  token ファイルは root:root 0600 で**存在する**(実測)。
- `2026-09-06_008_test_matrix.md` F1: 「binaryは不在・tokenは存在」という形は 007 が記録した
  実ansyの状態と**一致する**(実測)。

closeout は 008 側(「ansyの実状態とも一致する」)を採ったが、006 の記述はそのまま残っている。
実測2件が一致している以上どちらが正しいかは記録内で決着するが、006 だけを読んだ次の読み手は
ansy の環境について誤った事実を得る。006 へ1行の訂正注記、または closeout に「006 所見 #9 の
ansy 記述は実測と食い違う」と明記すれば閉じる。

### 5. 005 の未確認事項1件が closeout / status へ引き継がれていない(クローズを妨げない)

005「未確認事項」は、check mode の診断が `check_mode: false` で本番DBに対し `sqlite3` を
実行するため、**WALモードで `-wal` / `-shm` が生成されうる**(production DBのjournal mode
未確認)ことを挙げている。005 自身が「本差分固有の新規リスクではない」と評価しているが、
closeout の残存リスクにも status の該当行にも現れない。007 / 008 の前後比較は
`semaphore.db` の mtime / size と marker 不在までで、`-wal` / `-shm` の有無は見ていないため、
**未確認のまま消えている**。「既存挙動として不問にする」なら、その判断を1行残すのが
closeout の「証拠から除外したもの」と同じ扱いで一貫する。

### 6. closeout に AC と根拠の対応が無い(クローズを妨げない)

AC1〜AC10 の充足判定は 007 / 008 の AC 表にあり、そこまで辿れば欠落は無い。ただし closeout
本文は「採用した証拠」を検証手段の側から並べているため、**AC6 の通常実行側が未実施である
こと**(008 が「`--check`側のみ実測PASS」と明記)は closeout だけを読むと残存リスク1の
「通常upgrade/rollback未実施」に埋もれる。closeout に AC×根拠の1行表を置くか、残存リスク1へ
AC番号を添えると、次に読む者が Tester 記録まで降りずに未充足範囲を把握できる。
