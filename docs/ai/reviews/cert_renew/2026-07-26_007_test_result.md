## 事前確認

`git diff`で両ファイルを確認し、claudeの説明(slurp/copy削除→absent回収タスク、
ルートCA配布は維持、ヘッダ更新)と完全に一致することを確認した。

## 実行時の注記(tester側の手違いと是正)

`playbooks/ca_trust_deploy.yml`の対象6ホスト(quory, ansy, monnie, authy, pve1, pve2)へ
初回適用した際、`ANSIBLE_REMOTE_TEMP`をtester側で誤って`"$USER"`(ダブルクォート、
ローカルbashで`yoshi`へ即時展開)として渡してしまい、[[reference_tester_ansible_temp_isolation]]
が警告する固定パス衝突が発生した。ansy(コントローラ兼ターゲット)への接続で使われる
リモートユーザーが`yoshi`と異なるため、既存の`/tmp/ansible-remote-yoshi`(yoshi所有・
0700)へ書き込めず`ansy`だけ`UNREACHABLE`になった(quory/authy/monnie/pve1/pve2は
問題なく`changed`)。

是正: `ANSIBLE_REMOTE_TEMP='/tmp/ansible-remote-$USER'`(シングルクォートでリモート側
shell展開に委ねる、正しい形)で`--limit ansy`のみ再実行し、成功した。この間、ansyの
トラストストアだけ他5ホストより数分遅れて更新された状態が一時的に生じたが、中間CA
除去前の状態(旧来どおり中間・ルート両方配布済み)のままだっただけで、実害・セキュリティ
上のリスクはない。以降の確認タスク(post-apply検証)は全ホストが揃った状態で実施した。

## 3. カナリア: monnie→cloudkey(適用後)

`ansible.builtin.fetch`でmonnieの適用後`/etc/ssl/certs/ca-certificates.crt`を再取得し
(122証明書、適用前の123から1件減少)、デコードして`Home-RADIUS-CA`(ルート)のみが
残り`Home-TLS-CA`(中間)が消えていることを確認した。このバンドルを`-CAfile`に指定して
cloudkey:443を検証した。

```
$ openssl s_client -connect cloudkey.internal:443 -CAfile <monnie適用後のca-certificates.crt>
Verify return code: 0 (ok)
```

2026-07-18に発生していた`unable to get issuer certificate`の経路は、中間CA配布廃止後も
問題なく解消されたままである。

## 失敗・ブロッカー

なし。tester側の`ANSIBLE_REMOTE_TEMP`指定ミス(上記「実行時の注記」)は環境変数の
渡し方の誤りであり、claudeの実装(diff)そのものには起因しない。

## 総合判定

**中間CA配布廃止の適用は全6ホストで成功、6/6エンドポイントがデフォルトのシステム
CAバンドルだけで引き続き検証成功、カナリアも解消状態を維持。ブロッカーなし。
ロールバックは不要と判断する。**
