## 要件・実装の独立確認

### gate位置・実行host・check mode

- 旧HEADではHA復帰waitがL230-L255、healthcheckがL261以降だった。新版では同じHA waitがL255-L280、helper gateがL282-L355、healthcheckがL361以降であり、要求された順序である。
- gateに`delegate_to`はなく、playbookの`hosts: "{{ target_node }}"`上でhelper copy /実行 /削除とHTTP HEADを行う。
- gateはL111-L114の`when: not ansible_check_mode` / `tags: [destructive]` block内にある。check modeではgateとhealthcheckを実行せず、初期値`NOT_RUN` / 0 / 0とalways reportの`PLAN_ONLY`を維持する。

### HTTP到達判定

- `recovery-probe.py` L107-L118はHEAD成功または`HTTPError`をreachable、その他exceptionをunreachableとする。
- helper L80は`urllib.request.Request(..., method="HEAD")`。通常responseとL86の`HTTPError`を`REACHABLE`、`URLError` / timeout / socket / transport `OSError`を`UNCONFIRMED`としてdeadlineまでretryする。
- `NoRedirectHandler`はredirect requestを生成しないため、3xx responseは`HTTPError`として到達成功になり、redirect先へcredentialやrequestを送らない。
- roleはURLをstring、HTTP(S) DNS-name形、userinfoなし、IPv4 literalなし、timing値をinteger/正数かつoverall >= requestとして実行前にassertする。helperも`urlsplit` / `ipaddress`、finite/positive/budget関係を再検証し、IPv4/IPv6 literalを拒否する。

### deadline、attempts、JSON / rc

- helperは`deadline = monotonic start + overall`を一度だけ定め、各request timeoutを`min(request_timeout, remaining)`、各sleepを`min(poll_interval, remaining)`へcapする。
- fast-fail既定値は時刻0,15,...,285で20回HEAD後に300秒、5秒timeoutは時刻0,20,...,280で15回HEAD後に300秒となる。short overrideのoverall 7 / request 5 / poll 15もrequest / sleep capにより1 attempt / 7秒で停止し、failure速度に依存する不足・overshootはない。
- attemptsは`opener.open()`直前だけincrementする。network exhaustionはrc=0で`UNCONFIRMED` JSON、HTTP responseはrc=0で`REACHABLE` JSON、configuration / code / JSON生成のunexpected exceptionはmessageやURLを含めずerror typeだけをstderrへ出してrc=2とする。
- Ansibleはcommand rc非0をouter rescueへ流す。rc=0 stdoutだけを`from_json`し、status allowlist、attempts integer >=1、elapsed number >=0 / budget上限をassertした後にreport factsへ入れる。不正JSON/型/statusもouter rescueとなる。

### failure、healthcheck、manual recovery

- network exhaustionはgeneric command failureにせず、rc=0 / `UNCONFIRMED`をL347-L355の専用failへ流す。messageは「HA復帰済み」「Sophos経由の外部到達性未確認」「healthcheckへ進まない」を明記し、人間が必要時にmanual playbookを直接実行する案内だけを返す。
- 専用failによりL361のhealthcheckへ進まず、outer rescueが`_restore_failed`と専用messageを捕捉する。helper unexpected rc、不正JSON、assert failureもouter rescueへ流れる。alwaysのJSON保存後、既存のre-raiseを維持する。
- role内のrecovery action名はfail messageの手動案内1件だけであり、include/import/command/subprocessによる自動呼出しは0。Policy AR-008の経路分離、AR-083の人間責任manual layer、AR-094の人間escalation境界と一致する。

### 既存挙動・report

- HEAD差分はdefaults 13行追加、tasks 103行追加、削除0、新規固定helper 129行。既存のmigration、maintenance、HA relocate/wait、healthcheck判定、outer rescue、always report保存、re-raise式を変更していない。
- reportにはhelperのstatus /実attempts / monotonic elapsed secondsを追加する。check mode初期値は`NOT_RUN` / 0 / 0。
- report保存の`ignore_errors`、failure時再raise、check-modeの`PLAN_ONLY`は旧HEADどおりである。

### temporary helper lifecycle

- helperはtarget nodeの内部生成pathへ`copy`し、destination modeを0700へ固定する。URL/timingはshell文字列へ連結せず、`ansible.builtin.command.argv`の独立要素として渡す。
- copy / command / parse / validate / factの全体をblockで囲み、`always`で同一pathを`state: absent`にする。copy失敗、command rc非0、不正JSON、assert failure、正常、network exhaustionのすべてでcleanupを試行する。
- helperは標準libraryだけをimportし、shell/subprocess、dynamic import、eval/exec、file read、environment credential参照を行わない。unexpected errorは型名だけをstderrへ出し、URLやexception messageを露出しない。

## What Looks Good

- HA status確認とhealthcheckの間、target node上、destructive/non-check block内というgate位置が正確である。
- HEAD + redirect非追従 + HTTPError成功により、response受信とDNS/TLS/transport/timeout failureを分離している。
- monotonic deadlineとremaining capでfailure速度に依存しない300秒budgetと実attemptsを得ている。
- network exhaustionはrc0 JSON→専用fail、unexpected helper failureはouter rescueへ分け、healthcheckへ進まずalways / report / re-raiseへ接続する。
- empty proxy/custom opener、fixed argv、0700 temporary copy / always cleanupによりcredentialとinjection境界を明確にしている。
- Sophos recoveryは人間向けmanual案内だけで、自律actionを新しい第4経路として起動していない。
- elapsed/status、check-mode初期値、PLAN_ONLY、既存restore lifecycleを壊さず追加している。
