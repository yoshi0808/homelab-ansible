## 指摘

### 1. AC-2は文言どおりには満たされていないが、その事実が「未解決事項」として明示されていない(受入条件の充足)

`003_implement.md` §4 自身が「**ACの文言(『確認プロンプトが表示される』)そのものは満たしていない**。観測されたのは prompt ではなく block」と書いている。実際に起きたのは autoMode 分類器のエラー起因のブロックであり、requirement AC-2 が求める「確認プロンプトが表示される(パターン一致の迂回が成立しない)」ではない。

この事実自体は隠されておらず、§4 に正直に記載されている。しかし:

- `003_implement.md` §3 の検証結果表では AC-2 の行に PASS/FAIL の判定が付いていない(「本ファイル§4に追記」とあるのみ)。
- §5「未解決事項」には、AC-2が文言どおりに満たされていないことも、それをこのまま受け入れるかどうかの判断も載っていない(載っているのは「Coordinator/subagentの区別」と「承認疲れ」の2件のみ)。
- 観測されたブロックの原因は「分類器のtransient error」と記録されているが、再現性(次回も同じ経路で同じくblockするのか、それとも稀に素通りしうるのか)は検証されていない。

「絶対パス形の迂回を塞ぐ」はP0要件であり、旧`deny`のパターン一致迂回という実害が既にあったことが要件の動機である。AC-2が実際には「promptではなくblock」という異なる挙動で決着した以上、それを受け入れて良いかはYoshinobuまたはCoordinatorの明示的な判断が要る一件であり、record上は判断されないまま次点(未解決事項)にも上がっていない。

**クローズを妨げるか: 妨げない(条件付き)。** 技術的な正否(blockで足りるか)はAuditorの判定範囲外。求めるのは記録上の整合だけであり、`003_implement.md` §3のAC-2行に結果(PASS/FAILではなく「文言不一致、blockで代替」等の実情)を明記するか、§5未解決事項へ1行足すことで足りる。再監査は前提にしない。

### 2. `docs/ai/core-migration-map.md`(C17-01)は既にレビュー指摘を反映済みで、`002_review.md`のSuggestion本文は反映前の状態を指したまま(記録どうしの整合、指摘ではあるが軽微)

`002_review.md` Suggestion 1は「次にこの表へ触れる機会に言い換えるとよい」という将来形で書かれているが、`003_implement.md` §1は「独立レビューの指摘で追加した」とし、実際に現物のC17-01行は既に「2026-08-03に禁止からYoshinobuの都度承認へ変更」を含む更新後の文言になっている(commit `079ea09`で確認)。

内容自体に矛盾はない(reviewが先、implementが追随という時系列どおり)。ただし`002_review.md`だけを読むと「まだ直っていない」ように読め、`003_implement.md`まで読まないと解消済みだと分からない。両ファイルは同じ案件フォルダにあり、Suggestion側に「§1で解消」のような追記は無い。

**クローズを妨げるか: 妨げない。** レビュー文書は生成時点のスナップショットとして正当であり、追随したことは実装記録側に書かれている。将来この案件を読む者が誤読するリスクは小さい。
