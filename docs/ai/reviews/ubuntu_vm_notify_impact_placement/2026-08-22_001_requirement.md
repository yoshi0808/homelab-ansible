# requirement: 主力serviceへの影響を通知の先頭へ出す(UV-084の充足)

起案: Coordinator / 2026-08-22 / 依頼者: Yoshinobu

## 1. 問題定義

**Policy UV-084 は「通知でその影響を明示し、他候補に埋没させない」と定めているが、実装は明示までしか満たしていない。**

`roles/ubuntu_vm_full_upgrade/tasks/main.yml` の `slack_message` は、product_impact のブロックを**本文の最後尾**へ置いている。その手前には版の一覧(2026-08-22の #800 では monnie で27件)が入るため、Slackが長文を畳み、**既定表示では影響行が見えない。**

2026-08-22 の #800 で実際に見落としが起きた。monnie の `unpoller` が **3.3.4+git → 4.0.0+git** というメジャー更新だったが、Yoshinobu は通知から気づけなかった。要因は3つある。

1. 影響行が27件の一覧の**後ろ**にあり、「少なく表示する」の内側に入った。
2. 影響行は**パッケージ名だけで版を持たない**(`... : alloy, grafana, loki, unpoller`)ため、開いてもメジャー更新だと分からない。
3. **非aptの `apt外:` 行だけが一覧より前**にあり、apt側の重要コンポーネントとの間に非対称がある。Yoshinobu の認識は「aptか否かに関わらず重要コンポーネントの変更は欄外に出る」であり、UV-084 の文面もそれを支持する。

## 2. ゴール

- 主力serviceへの影響を、**Slackが畳む前の位置(本文の先頭)**へ出す。
- 影響行に**版の変化**を載せ、メジャー更新かどうかを開かずに判断できるようにする。
- `authy` の FreeRADIUS でも同じ形で出す(定義は既に存在し、置き場所だけの問題である)。

## 3. 非ゴール

- **判定ロジックを変えない。** important パターン、Status 昇格、non-apt レジストリのいずれにも触らない。
- **「該当なし」を消さない。** `classify.yml` が全製品を常に出しているのは、該当なしと未実施を区別するための意図的な設計である。先頭へ移しても該当なしの行は残す。
- **一覧側の各行に重要の印を付けない**(2026-08-22にYoshinobuが①のみと決定)。書式変更が全ホストの通知へ波及するため。
- **`apt外:` 行を動かさない。** 現在の位置(一覧より前)で既に見えている。

## 4. ユーザーストーリー

Yoshinobu として、monthly dry-run の通知を**開かずに**見たとき、主力serviceに関わる更新があるか、それがメジャー更新かを知りたい。手動applyの判断はそこから始まるためである。

## 5. 要件

| # | 要件 | 優先度 |
|---|---|---|
| R1 | product_impact のブロックを `slack_message` の**先頭**(status_reason より前)へ移す | P0 |
| R2 | 影響行のパッケージに版を併記する。install候補は `name old → new`、remove候補は削除と分かる表記にする | P0 |
| R3 | 該当なしの製品は現行どおり「該当なし」と出す | P0 |
| R4 | `authy` / `ansy` / `quory` / `monnie` の全4ホストで同じ形になる | P0 |
| R5 | 版の出所は `inst_detail`(name / old / new)とする。一覧と同じ値を使い、二重に持たない | P0 |
| R6 | Policy本文は改訂しない。UV-084 は既に本件を要求しており、実装が追いついていないだけである | P0 |

## 6. 受入条件

**AC1** — Given #800 の monnie の実レポート、When 変更後のテンプレートを描画、Then 本文の**1行目**が `Prometheus/Grafana/Loki/unpoller監視基盤:` で始まり、`unpoller 3.3.4+git → 4.0.0+git` を含む。

**AC2** — Given #800 の authy の実レポート、When 同上、Then 先頭に `FreeRADIUS/WPA3認証基盤:` の行が出る(該当パッケージが無ければ「該当なし」)。

**AC3** — Given 影響パッケージが1件も無いホスト、When 同上、Then 先頭の行は消えず「該当なし」と出る(**空欄にしない**)。

**AC4** — Given 変更後のrole、When `ansible-playbook --syntax-check` を通す、Then rc=0。

**AC5**(Yoshinobu実施) — Given quory の Semaphore から `SEMI-SAFE: Ubuntu vm full upgrade (dry-run)` を手動起動、When 通知が `#patches` へ届く、Then **「少なく表示する」を開く前に**影響行と版が読める。**終了コードは0**であること。
