# requirement: 掃き出し 第3家族 — `| default(x, true)`

日付: 2026-09-05
依頼: Coordinator → codex側 Implementer
性質: **実装ではない。読んで一覧にする(事実収集)。直さない。**
先行: `2026-09-05_001_requirement.md`(第2家族 `| length`)と同じ契約。**差分だけを本書に書く。**

## 探すもの(この家族に固有の点)

`docs/ai/core.md`「作るものが満たすこと」の次に反している箇所を挙げる。

> **判定できないときは止める。** …**空の成功、無言の完走、既定値へのフォールバックで先へ進めない。** 壊れているときほど「問題なし」に見える設計を作らない。

**第2引数 `true` を付けた `default` は、未定義のときだけでなく falsy な値のときも既定へ差し替える。** したがってこの家族で問うのは次の1点である。

- **その位置に `false` / `0` / `""` / `[]` / `{}` が、正当な意味を持つ値として来ることがあるか。** 来るなら、それが既定値に化けて判定が変わる。
- 来ないなら(未定義かどうかだけが問題で、falsy な正当値が存在しないなら)、`, true` は無害である。

**「`, true` が付いていること」自体は指摘ではない。** 正当な falsy 値が存在する経路を示せたときだけ findings に入れる。

## 走査の起点と範囲

```
git grep -nE '\| *default\([^)]*, *true *\)' -- playbooks roles scripts
```

現在90ヒット。**このヒット行だけが対象である。** `| default(x)`(第2引数なし、869ヒット)は**対象外**。

範囲の絞り方、判定している箇所に限る条件、1件あたり4行の上限、到達経路を示せないものを findings に入れない足切り、深追いせず「未確定」へ回す扱いは、**すべて第2家族と同じ**。

## 進め方

成果物へ逐次追記し、途中で止まっても走査済み範囲と findings が残る形を保つ。**枠に余裕があるあいだは1ターンで可能な限り進めてよい。** 区切って止めるのは枠が近いと判断したときだけでよい。止めるときは書き切ってから終える。全件終わらなくてよい。

## 受入条件

第2家族の AC1〜AC4 と同じ。加えて次を満たす。

- **AC5**: 各 findings について、**その位置に来る正当な falsy 値が何か**を明示すること(「`false` が『引数なし』を意味して API から来る」など)。これを示せないものは findings に入れない。
