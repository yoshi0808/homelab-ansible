### 2. `reconcile_finalize.yml`のtmp削除 — **成功経路限定、失敗経路と衝突なし**

`roles/semaphore_templates/tasks/reconcile_finalize.yml`で、run report用
block(94-131行)・latest-success用block(140-176行)のいずれも、「Atomically
publish...」taskの**直後**(同一`block:`内)に`state: absent`/`failed_when:
false`の削除taskが追加されている(121-126行、166-173行)。この位置のため:

- publish自体が失敗した場合はそのtaskで例外が飛び、新設の削除task手前で
  `rescue:`へ移るため、新設の削除taskは実行されない(rescueが独自に持つ
  「Remove an unpublished .../temporary file」が代わりに動く、既存のまま
  変更無し)。
- 新設の削除taskはpublish成功時のみ到達し、対象pathは常に`.{{run_id}}.json.tmp`
  /`.latest-success.{{run_id}}.json.tmp`という**tmpファイルのみ**であり、
  publish先の本体ファイル(`runs/{{run_id}}.json`/`latest-success.json`)を
  指していない。publish済み成果物を巻き添えにする経路は無い。
- `failed_when: false`により、削除自体が失敗しても(例: 権限)最終rcへ影響しない。

`scripts/tests/semaphore_schedules/test_phase2_helpers.py`の
`FinalizerReportingContractsTests.
test_successful_atomic_publishes_remove_their_temporary_files`(229-247行)が
`reconcile_finalize.yml`をYAMLとして読み込み、削除taskがpublish taskより後ろに
あること、`state: absent`、`failed_when: False`であることを両blockで機械的に
確認している。

### 3. `semaphore_reconcile_stale`の`actual`整形 — **None/Undefinedとも安全**

`roles/semaphore_templates/filter_plugins/semaphore_templates.py`に新設された
`semaphore_reconcile_marker_actual(freshness)`(473-480行)は、
`isinstance(freshness, dict)`を最初に確認するため、`freshness`が辞書でない
任意の値(`None`、Jinja `Undefined`インスタンス含む)でも`isinstance`は例外を
投げず`False`を返し、「鮮度を判定できません」へ倒れる。自分でPythonから直接
呼び出し確認した:

```
semaphore_reconcile_marker_actual(None)                 -> '鮮度を判定できません'
semaphore_reconcile_marker_actual(jinja2.Undefined())    -> '鮮度を判定できません'
```

`freshness`が正しい辞書でも`age_seconds`が`None`(marker欠落/非正規ファイル/
JSON不正など、`semaphore_reconcile_marker_freshness`が例外系で返す形)の場合は
`error`文字列へフォールバックし(`test_finding_actual_reports_elapsed_seconds_or_
the_failure_reason`で`{'error': None, 'age_seconds': None}` →
「経過時間を判定できません」を確認済み)、値が測れる場合(int/float、bool除外)は
秒数を出す。呼び出し元`roles/deployment_drift_check/tasks/semaphore_probe.yml`の
`actual`フィールドは常に`deployment_drift_check_reconcile_freshness`
(直前task で無条件に`set_fact`される辞書)を経由するため、本番実行時に
`freshness`自体がUndefinedになる経路は無いが、関数自体がその場合も安全に
振る舞うことを確認した。
