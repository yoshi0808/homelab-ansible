## AC10の充足

> **AC10** Given 金曜(`Asia/Tokyo`)、実物で `active: false` が1件以上、Then **一覧が通知される**。Given 金曜で停止0件、Then 通知しない。**Given 金曜以外、停止が1件以上あっても、一覧は通知しない。**

| ケース | 結果 | 根拠 |
|---|---|---|
| 金曜・停止0件 → 通知しない | **PASS(本番実データ)** | 下記 |
| 金曜・停止あり → 一覧が通知される | **未観測。条件が発生しなかった** | 下記 |
| 金曜以外・停止あり → 通知しない | PASS(既済) | `_022`(木曜・停止25件で実機PASS) |

### 「金曜・停止0件」

- ジョブ出力で `TASK [semaphore_templates : ansible.builtin.include_tasks]` が **`skipping`**。`reconcile_finalize.yml` の通知blockは `when: _semaphore_reconcile_notify_required` で、この変数は**7項のOR**である。**skipしたことは、`semaphore_schedules_friday_paused | length > 0` を含む全項がfalseだったことを意味する。**
- 同時刻の本番schedule実物を独立に確認: **25本すべて `active: true`**、`active` の型もすべてbool(filterの `ValueError` 経路にも入らない)。**通知が出なかったことと、実物の状態が一致している。**
- 曜日判定は起動時刻そのものが金曜04:00 JSTであることで成立する。`semaphore_schedules_friday_paused` は金曜以外なら無条件に `[]` を返すが、**本ジョブは金曜に走っているため、空だったのは「停止が0件だから」である。**

### 「金曜・停止あり」

**この週は停止中のscheduleが1本も無かったため、条件そのものが発生しなかった。** 実装の欠陥ではない。

**申し送りとする。期限は置かない。** 埋まるのは、**schedule を停止した状態で金曜を迎えた週**である(計画停止やメンテナンスで実際に止めたときに自然に発生する)。確かめるために本番のscheduleを止めることはしない — 観測のために本番の状態を変えることになる。

なお、この未観測が残っていても次の2つは既に押さえてある。

- **曜日判定そのもの** — production moduleを直接importした7パターンの確認(`_022`)
- **停止ありのときに一覧を組み立てる側** — 木曜・停止25件で「金曜以外は出さない」を実機確認(`_022`)。組み立ての入力が揃う経路は通っている

残るのは「金曜 × 停止あり」という組み合わせが本番で一度も成立していないことだけである。
