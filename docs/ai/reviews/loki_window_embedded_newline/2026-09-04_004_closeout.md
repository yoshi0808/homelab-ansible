## Coordinatorが自分で確かめたこと

- **差分の現物**(`git diff`)。requirement §3 の非ゴール(`cmd_count`、`cmd_errors` の挙動、各定数値、切り詰め通知の文言・書式・数値、認可境界、repoへのテスト追加)のいずれにも触れていない。
- **`str.splitlines()` の分割対象**。NEL(`\x85`)/ LS(U+2028)/ PS(U+2029)/ VT / FF / FS / GS / RS / CR / LF / CRLF のすべてが行境界として分割され、`" ".join(...)` 後にLFもCRも残らないことを直接実行して確認した。**改行相当文字が本文の先頭・末尾にある場合も同じ**であることを個別に確認している(Reviewerのfixtureは本文中間への埋め込みのみで、この2条件を回していない — requirement AC1 が列挙する条件のうち Reviewer 側で欠けていたのはここである。Implementer 側のfixtureは先頭LF / 末尾LFを含む)。
- **Reviewerの検証スクリプトの現物**。Auditorが `003_review.md` の件数の内部矛盾を指摘したため、`scratchpad/verify.py` を読み、再実行した。`NEWLINE_CHARS` は11要素(NEL / LS / PS を含む)+ 混在1種 = 12バリアントで、`AC1: 72 combos / 0 failures`、`AC2: 22 combos / 0 failures`、`AC3: 7 combos / 0 failures`、`AC4 (errors): 72 combos / 0 failures`、`AC4 (count) match: True` を再現した。**記録が現物より少ない件数を書いており、かつ実際には回していたものを「確認していない」と書いていた。** Reviewerへ差し戻して `003_review.md` を現物と一致させた(Verdictは据え置き)。

  **Coordinator自身の誤り**: この差し戻しの前、Reviewerの「確認していないこと」欄をそのまま事実として引き継ぎ、「未検証の4種を実測で閉じた」とYoshinobuへ報告していた。**その未検証は存在しなかった。** `docs/ai/roles/coordinator.md`「先行成果物・先行subagentの主張を、現物で確かめずに引き継がない」に反している。
- **測定が循環していないこと。** 正規化と `splitlines()` による測定は同じ関数に依るが、`stdout.count("\n")` は独立した指標であり、実際の消費者(SSH経由で行単位に読むcodex)が数えるのはこちらである。
