## 検証方法(自分で実行したもの)

- `git show HEAD:...` と作業ツリー版をそれぞれ別モジュールとしてロードし、`loki_get` をスタブに差し替える自前スクリプトを `/tmp/claude-1000/.../scratchpad/verify.py` に作成して実行(本番Lokiへは問い合わせていない)。
- `NEWLINE_CHARS` は11要素: LF(`\n`) / CRLF(`\r\n`) / 単独CR(`\r`) / VT(`\x0b`) / FF(`\x0c`) / FS(`\x1c`) / GS(`\x1d`) / RS(`\x1e`) / NEL(`\x85`) / LS(U+2028) / PS(U+2029)。これに加え、この11要素すべてを連結した「混在」1種を別バリアントとして使う箇所がある(合計12バリアント)。本文は `f"a{nl}b{nl}c"` の形でnlを本文中間の2箇所に埋め込む — 本文の先頭・末尾そのものに改行相当文字を置く変化は個別のバリアントとして作っていない。
- **AC1**: 12バリアント(individual 11 + 混在1) × entry件数 {0,1,299,300,301,500} の6通り = **72組合せ**で `len(stdout.splitlines())` と `stdout.count("\n")` の両方を測定 — **物理行数の単位で**測った。全72組合せで両指標とも300以下。
- **AC2**: individual 11バリアント(混在は含まない) × entry超過側の件数 {301, 500} の2通り = **22組合せ**で、stdout末尾行に `earliest 299 of >300 lines` を含む切り詰め通知があることを確認。
- **AC3**: 改行を含まない本文(`"plain text"`)で entry件数 {0,1,3,299,300,301,500} の7組合せ、HEAD版とstdout完全一致を確認。
- **AC4**: `cmd_errors`(AC1と同じ12バリアント×6件数=72組合せ)と `cmd_count`(level有り/無し/空文字列の3系列を1回)でHEAD版とstdout完全一致を確認。
- **AC5**: 改行相当文字を複数種混ぜた本文(`'x\ny\r\nz\rw'`)で、正規化後の本文がスペース結合の期待値と一致し、時刻表記・`[host]`・時刻昇順が保たれることを個別に確認。
- **AC6**: `python3 -m py_compile` と `git diff --check` をこの場で再実行し、両方rc=0。
- **AC7**: `git status --short --untracked-files=all` を実行。`docs/ai/memory/lessons/verification-referent-and-path-mismatch.md` の変更は実装記録の申告どおりImplementerが触れていないもの(前セッションのSessionEnd hook由来、本レビューの対象外として扱う指示のとおり)。実装者が変更したファイルは helper 本体と本案件フォルダの成果物のみで、requirement §6 AC7(是正後の「変更の主体」基準)を満たす。
