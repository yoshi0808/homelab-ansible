# Code Review: Prometheus LTS track / Ubuntu VM patch Policy 改訂

Reviewer: Codex / 2026-08-23

## Summary

track の抽出は数値 tag の厳密一致で、検知と apply は同じ `effective_target_version` を使う。UV-090 の5値表は現行の apply gate・通知先・重大度と一致し、UV-094 も5値のいずれも否定していない。

一方、Policy の新しい「週次・機械適用」原則は既存の Prometheus 手動適用境界と正面から矛盾する。また、installed version が設定 track と異なる場合に週次経路が系統跨ぎを候補・適用でき、異常時の週次 Slack 通知には系統外の版も残る。安全境界と正本の双方に blocking finding があるため Request Changes とする。

## Policy / Status Cross-check

- UV marker は `<!-- UV-nnn -->` 形式で機械的に集計し、UV-085〜094を含め重複ゼロ。UV-083 は既存履歴どおり統合・退役済みであり、新設番号との衝突は無い。
- UV-090 は実装と一致する。`BLOCKED` は apply不可 / `#alerts` / critical、`MAJOR_UPGRADE_DETECTED` は不可 / `#patches` / warning、`REVIEW_REQUIRED` は可 / `#patches` / warning、`UPGRADE_READY` は可 / `#patches` / ok、`NO_UPDATES` は可 / `#patches` / info。apply gate は前2値だけを拒否し、通知式も5値を同じ対応へ写す。
- UV-094 は5値を消さない。`BLOCKED` は apply・通知先・重大度、`MAJOR_UPGRADE_DETECTED` は apply、`REVIEW_REQUIRED` は重大度、`UPGRADE_READY` と `NO_UPDATES` も重大度が隣接状態と異なる。
- UV-032〜034 の改訂範囲では、non-apt の確定 update は reason に残り Status を変えず、取得失敗も従来どおり fail-quiet。UV-033 の降格禁止も維持される。
- UV-042以降の reboot lifecycle は今回の track / Status 改訂から独立しており、実行条件・復帰確認・通知境界の変更は無い。

## What Looks Good

- track は `tag_name` を `^<escaped major.minor>[.]<numeric patch>$` で選び、release body・LTS表記などの自由文に依存しない。prerelease suffix も混入しない。
- `prometheus_update_check_track` の既定 `3.13` は role defaults の1箇所だけで、Semaphore schedule に複製されていない。空文字では repository-wide latest の従来動作へ戻る。
- trackが見つかる通常経路では、比較基準と `effective_target_version` が同じ track latest を参照し、download URL もその値を消費する。
- `prometheus_target_version` と track の major.minor 不一致を assert する追加制約は妥当である。明示 pin だけが週次境界を迂回する経路を閉じ、R2/AC7を強める。ただし Finding 2 の installed 側 gate も必要である。
- 月次 classify は apt ladderをそのまま最終 Status とし、non-apt は reason だけへ追記するため、R5/改訂UV-032に一致する。
- security観点では track/target の形式を assert し、URIやcommandに shell 展開を追加していない。download・checksum・lock・rollback の既存境界を再利用し、新しい秘密値や権限昇格も無い。
