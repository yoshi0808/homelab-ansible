## Direct Fix Verification

### R4 / AC3 / UV-088

- R4は禁じる対象を「上流から取得した系統外の版」とし、mismatch診断時のcurrent installed versionだけを例外にする。UV-088の「いま入っている版」例外と同じである。
- AC3も同じ対象を描画条件へ落とし、`track_installed_mismatch`だけinstalled versionを許可する。実装はmismatch本文にcurrentとconfigured trackだけを出し、overall latest / track latestを出さない。
- `track_not_found`へ到達するcurrentはconfigured trackとmajor.minorが一致するため、そこで表示するcurrentは系統外版ではない。`collection_failed`はmismatchより後順位なので、configured track外currentをその分岐へ流さない。

### AC3 testability

AC3はfixture描画で判定可能である。少なくとも次の値を相互に異なるsentinelにすれば、許可・禁止を機械判定できる。

- installed mismatch: 許可されるsentinel
- configured track: 版候補ではなく系統label
- in-track latest: normal `update_available`で許可される候補
- overall latest / その他のupstream out-of-track version: 全通知本文で禁止するsentinel

「それ以外の版」は前文と合わせれば「installed例外以外の系統外版」と読める。Testerが誤読しないよう、このsentinel行列をtest planへ明記するのは有用だが、AC3自体を判定不能にはしていない。

### UV-085 / UV-086 boundary

- requirement §8とPolicy UV-085は、aptの担い手をUbuntu Pro対象 / 対象外monthlyへ分け、aptが両レーンに跨ることを本文で明記する。
- apt以外はweeklyで機械が検知し、適用は人が `dry_run=false` を明示する。UV-035〜038と一致する。
- monthly non-aptは版を提示するがStatusを上げず、UV-032 / R5 / AC6と一致する。
- Finding 1を除けば、requirement全文とPolicy全文に、前回と同型の適用主体・通知例外の不一致は見当たらない。
