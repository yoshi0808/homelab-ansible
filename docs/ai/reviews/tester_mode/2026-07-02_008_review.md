## 指摘

### suggestion: lint が「実ゲート」ではなく `tester_mode` 文字列の存在だけを見ている

- 対象: `scripts/check-tester-gate.sh:21`
- 関連: `scripts/check-tester-gate.sh:24`, `scripts/git-pre-commit-check.sh:56`

`scripts/check-tester-gate.sh` は、playbook 内に `tester_mode` という文字列が1回でも出れば「ゲートあり」と判定します。これは今回の既存ファイルには大きな問題を起こしていませんが、将来の新規 playbook で以下のような抜け道を許します。

- `vars:` に `skip_notifications: "{{ tester_mode | default(false) | bool }}"` だけを書く
- コメントや説明文に `tester_mode` と書く
- 危険操作より後ろに `tester_gate` を置く

この場合でも lint は OK になりますが、「変更系 playbook は危険操作の前に `tester_gate` を置く」という不変条件までは機械的に保証できません。

現時点では pre-commit の最低限ガードとして許容できます。ただし、「新規 playbook のゲート付け忘れを検知する」という目的を強く満たすなら、少なくとも以下のいずれかに寄せるとよいです。

- `tester_mode` 文字列ではなく `name: tester_gate` / `tester-gate:` マーカーを判定する
- `role-guarded` は許可対象 role 名も併記させる
- 変更系 playbook 用の明示マーカー（例: `# tester-gate: guarded-by-role`）を導入し、単なる `tester_mode` vars では通さない

1. `meta: end_play` / `end_host` の include_role 経由利用
   `roles/tester_gate/tasks/main.yml:34` から `end_host`、`roles/tester_gate/tasks/main.yml:38` から `end_play` を呼ぶ構成は syntax-check 上も問題ありません。`roles/sophos_trim/tasks/main.yml` からの role 内 include_role も syntax-check で通っています。

2. ゲート位置・停止方式の互換性
   diff 上、既存の `end_play` / `end_host` の使い分けは維持されています。停止のみの後続 play も `tester_gate_plan` なしで停止する構造になっています。

3. `tester_gate_plan` の変数スコープ
   `ubuntu_nightly` の `reboot_required`、recovery 系の `target`、proxmox 系の `target_node` などは、従来と同じ task vars / play vars の評価範囲で参照されています。今回見た範囲では遅延評価による破綻は見当たりません。

4. lint 判定の妥当性
   上記 suggestion の通り、現状は最低限の存在確認です。今回の変更を通す用途としては許容できますが、強い不変条件チェックとしては弱いです。

5. safe-readonly / role-guarded 分類
   `recovery_escalate.yml` / `recovery_notify_trigger.yml` は `roles/common_slack/tasks/notify.yml` 側で `tester_mode` により送信が抑止されるため、role-guarded 分類は妥当です。healthcheck 系、snapshot check、time sync check、`test_ca_env`、`proxmox_patch_dryrun` の safe-readonly 分類も、core.md に追加された許容範囲（read-only 収集、冪等な収集スクリプト配置、ローカルレポート出力、apt update 等）と整合しています。

6. core.md との整合
   §15 / §18 の「tester は常に `-e tester_mode=true`」「変更系は `tester_gate`、read-only はマーカー」という説明と実装は整合しています。
