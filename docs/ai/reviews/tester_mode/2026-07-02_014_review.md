## 指摘

### suggestion: `tester_gate_end: continue` は dry-run 差し替え専用として運用を厳格に保つ

- 対象: `roles/tester_gate/tasks/main.yml:11`
- 関連: `roles/sophos_trim/tasks/main.yml:10`, `roles/sophos_trim/tasks/main.yml:18`

`tester_gate_end: continue` は、従来の「plan 表示して停止」から外れ、後続タスクの安全性を呼び出し側の dry-run 差し替えに委ねる設計です。今回の `sophos_trim` では `tester_mode` 時に `fstrim -n -v` へ差し替えており、不変条件との整合は取れています。

一方で、この値を他 role に安易に使うと「tester_mode なのに変更系タスクへ進む」抜け道になります。現状のコメントと assert は妥当ですが、今後のレビューでは `continue` 使用箇所ごとに「後続の全変更操作が dry-run または read-only に差し替わっているか」を必ず確認対象にしてください。

## レビュー観点への回答

1. `tester_gate_end: continue` の設計妥当性
   L3 dry-run リハーサル用としては妥当です。`assert` で typo を落とす点もよいです。安全性は呼び出し側の差し替えに移るため、使用箇所は限定運用が前提です。

2. `sophos_trim` の fstrim オプション差し替え
   `sophos_trim_fstrim_opts` を `tester_mode` で `-n -v`、通常時で `-v` に分ける実装は明確です。expect responses 内の Jinja 展開も構文上問題ありません。`-n` 非サポート時に RC マーカーが 0 にならず FAILED へ進む挙動も、テスト失敗として妥当です。

3. recovery 3 role の gate 位置
   `recovery_vm_reboot` は pvesh タグ再検証後、shutdown 前で停止しています。`recovery_ha_failover` は HA 登録確認・移行先選定後、relocate 前で停止しています。`recovery_service_restart` はタグ・running・サービス一覧解決後、restart 前で停止しています。いずれも read-only / 変更系の境界として妥当です。

4. `meta: end_play` と block `always` の関係
   tester_mode でレポート・通知がスキップされる挙動は、今回の P1 目的では許容できます。plan 表示自体がテスト証跡になり、Slack 送信も tester_mode では不要です。

5. playbook 側 gate 撤去による SSH + pvesh get 実行
   対象解決・タグ検証・HA 登録確認はいずれも `pvesh get` ベースの read-only 収集であり、SAFE(read-only) の範囲内として整理できます。
