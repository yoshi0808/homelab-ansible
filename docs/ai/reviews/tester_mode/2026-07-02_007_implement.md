# tester_mode 不変条件化・共通ゲート実装 — 2026-07-02

## 背景と目的

前回実装（2026-07-01_002_implement.md）で全 playbook に tester_mode ゲートを入れたが、
以下の構造的な課題が残っていた。

1. ゲート実装（debug + end_play/end_host の block）が 29 箇所コピペされており drift リスクがある
2. tester の検証手順が選択式（--syntax-check → --check → --check --diff → tester_mode）で、
   検証方法の選択ミスが安全性に直結する
3. 「全 playbook がゲートを持つ or SAFE である」ことが規約でしか担保されていない
   （新規 playbook のゲート付け忘れを検知できない）

これを解消するため、tester_mode を**不変条件（invariant）**として再定義し、
共通 role + lint で機械的に担保する。

## 設計方針（Yoshinobu 合意済み 2026-07-02）

1. **不変条件**: どの playbook も `-e tester_mode=true` 付きで実行した場合、対象ホストの
   実変更・外部副作用（Slack 通知含む）を起こさない。
   - 変更系 playbook はゲートでこの条件を満たす
   - read-only playbook はゲートなしで自明に満たす（tester_mode=true でも通常どおり全体が実行される）
   - 許容される操作: コントローラへのレポート出力 / read-only 収集のための冪等な収集スクリプト配置 /
     apt update 等のキャッシュ更新
2. **tester は常に `-e tester_mode=true` を付ける**。--syntax-check / --check --diff は
   置き換えではなく、情報を増やすために重ねて使う追加手段（安全性が検証方法の選択に依存しない）
3. ゲート実装は共通 role `tester_gate` に集約する（コピペ drift 防止）
4. lint（pre-commit）で「全 playbook がゲート or マーカーを持つ」を機械チェックする
5. `group_vars/all.yml` に `tester_mode: false` のデフォルトを置く（`-e` は変数優先順位で上書き）

18 playbook + 1 role の計 29 ゲート:

- `recovery_vm_reboot` / `recovery_service_restart` / `recovery_ha_failover` /
  `recovery_io_setup` / `recovery_exec_setup`
- `proxmox_patch_apply_node`(2) / `proxmox_patch_weekly_full` / `proxmox_evacuate_node`(2) /
  `proxmox_restore_vm_placement`(2) / `proxmox_backup_restore_verify`
- `cert_renew`(5) / `cert_renew_quory`(3) / `ca_trust_deploy` / `cloudkey_cert_deploy`
- `ubuntu_nightly`(2) / `systemd_timers` / `time_sync_ntp_reference` / `unifi_backup_fetch`
- `roles/sophos_trim/tasks/main.yml`(1)

置き換えパターン:

```yaml
- name: "[tester_mode] Plan-only: show intended X and stop"
  ansible.builtin.include_role:
    name: tester_gate
  when: tester_mode | default(false) | bool
  vars:
    tester_gate_end: host        # end_host の場合のみ。省略時 end_play
    tester_gate_plan:
      - "操作 : ..."
```

- 元の plan 表示 1 行目「[tester_mode] plan-only — 実変更は行いません」は role 側が付与
- 停止のみの後続 play ゲートは `tester_gate_plan` を渡さない（表示なしで停止）
- ゲート位置・停止方式（end_play/end_host）は従来と同一
