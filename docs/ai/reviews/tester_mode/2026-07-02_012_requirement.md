## テスト深度の定義

| 深度 | 実装 | 検証できること |
|---|---|---|
| L1(浅い) | gate が先頭で固定文言 + 停止 | 構文・インベントリ・gate 動作のみ |
| L2(中間) | read-only 収集を実行し、実データで plan を計算して停止 | 判定ロジック・対象解決が本物のデータで動く |
| L3(深い) | tester_mode 時にコマンド自身の dry-run を実行 | 接続・対話・出力パースまで本番同等 |

## 深掘りの共通パターン

1. **L2 パターン**: gate を「read-only 収集の後」へ移動する(role 内 Phase 境界)か、gate の
   直前に read-only タスクを追加し、収集結果を `tester_gate_plan` に渡す。
   注意: gate が role 内へ移る playbook は lint 対応として `# tester-gate: gated-in-role` マーカーに切り替える。
2. **L3 パターン**: tester_mode 時にコマンド自身の dry-run(`fstrim -n` 等)へ差し替えて
   実行し、停止ではなく「dry-run で完走」させる。不変条件(実変更ゼロ)は dry-run の性質で担保。
3. **check-passthrough パターン(新規オプション)**: 純モジュール構成の playbook に限り、
   `tester_gate_check_passthrough: true` を宣言すると、`--check` 実行時(ansible_check_mode)
   は gate が停止せず `--check --diff` の全シミュレーションを許す。
   - 適用条件: command / shell / uri / expect / `check_mode: false` を含まないこと
   - 条件は lint で機械チェックする(宣言 playbook とその role を走査)
   - 通常の tester_mode 単独実行では従来どおり停止(挙動追加のみ、既定動作は不変)
