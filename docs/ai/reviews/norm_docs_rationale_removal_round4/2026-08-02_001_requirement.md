# requirement: `skills/` から日付つきの経緯注記を落とす

日付: 2026-08-02 (JST)
起点: Yoshinobu「引き続き、経緯除去は進めます」(2026-08-02)。経緯除去シリーズの最終ラウンド。
先行案件: `norm_docs_rationale_removal`(単独) / `_round2`(分類・索引) / `_round3`(Policy)

## 1. Skillは前3案件と規則が違う

**`skills/` では参照を落とさない。** 2026-08-01に確立した方針は次のとおりで、Skillを明示的に例外としている。

> 規範文書へ `docs/ai/reviews/` や `docs/ai/memory/lessons/` への参照を置かない。**ただしSkill内で手順の脚注として引くのは可**(その作業時にしか読まれないため)。

理由は読まれる頻度である。Role文書やPolicyは全Roleが起動のたびに読むが、**Skillはその作業をするときにしか読まれない**。脚注のコストが毎回かからない。

## 2. 3つのクラスと扱い

`skills/*/SKILL.md` に現れる日付は3種類あり、**落とすのはCだけ**である。

| クラス | 実体 | 扱い | 理由 |
|---|---|---|---|
| **A. upstream revision追跡** | `取り込み時点のrevision: commit <sha>(<日付>)`、`**revision追跡**` の段落、外部URLに添えた取り込み日 | **残す** | **経緯ではなく生きた機構である。** 上流(`anthropics/knowledge-work-plugins` 等)が更新されたかを判定する基準点であり、日付とshaは固定revisionの識別子そのもの。落とすと更新確認の手順が成立しない |
| **B. 手順の脚注としての根拠** | `根拠: docs/ai/reviews/<target>/...`、`根拠: <日付>、<案件>で踏んだ` | **残す** | §1のとおりSkillでは許可されている |
| **C. 日付つきの見出し・経緯注記** | `## <見出し>(2026-07-23、自作)`、`(2026-07-29、Tech Lead廃止に伴い統合)`、`(2026-07-26に移設)` | **落とす** | いま従うべき手順を述べておらず、読み手が前提となるベースラインを特定できない |

**AとBをCと誤判定して落とすことが本案件の主要リスクである。**

### BとCの境界(2026-08-02、Coordinator判断)

実装から、**`根拠:` の明示タグは無いが、具体的な事故・実測の日付を伴って直前の規則を裏づけている文**が5箇所あり、BともCとも取れると報告があった(`ansible-implementation-style` L46・L50、`document-norm-review` L20・L63、`test-strategy` L35-36)。

**5箇所とも残す。** 判定はタグの有無ではなく**機能**で行う。

| 機能 | クラス |
|---|---|
| 直前・直後の**規則を裏づけている**(なぜその手順なのかを述べる) | **B。残す** |
| **文書自身の来歴**を述べている(いつ作られたか、どこから移されたか、誰の判断で統合されたか) | **C。落とす** |

`根拠:` というタグは B の目印ではあるが、**要件ではない**。タグの有無で判定すると、同じ働きをする文が書き方の違いだけで生き死にする。

判断に迷ったものを落とさなかったのはR2の指示どおりであり、正しい振る舞いである。

### 対象ファイル数

requirement §1 は11本と書いていたが、`skills/*/SKILL.md` は**実在12本**である(実装が指摘)。数え漏れであり、対象は「`skills/*/SKILL.md` の全件」とする。

## 3. ゴール

`skills/*/SKILL.md` からクラスCを除去する。**AとBは1件も減らさない。**

## 4. 非ゴール

- **手順そのものを変えない。** 落とすのは日付つきの注記であって、Skillが定める作業の型ではない。
- **参照(クラスB)を落とさない。** 前3案件とここが違う。
- `docs/ai/` 配下・playbook・roleへ広げない。経緯除去シリーズはこのラウンドで完了する。
- `docs/ai/reviews/` や `docs/ai/memory/` の既存記録を書き換えない。

## 5. 要件

| ID | 要件 |
|---|---|
| R1 | `skills/*/SKILL.md` からクラスCを除去する。見出しに含まれる場合は見出しを内容だけにする |
| R2 | **クラスAとBを1件も落とさない。** 判定に迷ったら落とさず報告する |
| R3 | 落とした結果、手順の主語・条件・順序が曖昧になっていないことを確認する |
| R4 | 他の文書から、削除した記述・見出しを指す参照が壊れていないことを確認する |

## 6. 受入条件

| AC | Given / When / Then |
|---|---|
| AC1 | **Given** 改訂後の `skills/*/SKILL.md` **When** 全文を読む **Then** クラスCが0件 |
| AC2 | **Given** 改訂前後 **When** `grep -c "取り込み時点のrevision\|revision追跡"` と `grep -c "根拠"` を比較する **Then** **件数が減っていない**(クラスA・Bの保全) |
| AC3 | **Given** 改訂前後 **When** 逐行で突合する **Then** 落ちているのはクラスCだけで、**手順・判定基準・出力の型が1つも変わっていない** |
| AC4 | **Given** リポジトリ全体 **When** `scripts/check-doc-consistency.py` と `scripts/git-pre-commit-check.sh` を実行する **Then** OK。宙ぶらりんの参照が無い |
