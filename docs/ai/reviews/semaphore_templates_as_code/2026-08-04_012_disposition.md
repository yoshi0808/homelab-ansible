## 初回実行で見つかった欠陥 — レポートに「走った証拠」が無い

**`findings: []` を突合が走った証拠と読めなかった。** レポートは `findings` と `checked_counts` しか持たず、`checked_counts` に Semaphore の欄が無かったため、**「通って0件」と「そもそも走っていない」がレポートから区別できない。** 今回はジョブログまで見て判別したが、レポートだけを見る運用では、突合が黙って消えても毎朝「異常なし」に見える。

**このリポジトリが繰り返し踏んでいる「沈黙は正常と抑止の両方を意味する」形そのものである**(`docs/ai/status.md` の複数のWatch行が同じ注意を書いている)。**requirement の AC8 が「finding がレポートに含まれること」しか要求しておらず、陽性の証拠を要求していなかった** — Reviewer も Coordinator も、findingの側だけを見て充足と判定した。

**是正**: 突合が比較した実物の件数を `checked_counts.<probe host>.semaphore_templates` へ入れた。成功時は観測件数、失敗時は 0 とし、**成功側と失敗側の両方で必ず欄を立てる** — 欄が無いことが「走っていない」を意味するようにするため。成功して0件は「Semaphore上にテンプレートが1つも無い」を意味するが、その場合はカタログ43件分の new finding が同時に立つので取り違えは起きない。

**AC を1つ足すなら「正常時に、検査が実行された陽性の証拠が残ること」である。** 異常が出ることの確認に寄ると、この欠陥クラスは毎回すり抜ける。
