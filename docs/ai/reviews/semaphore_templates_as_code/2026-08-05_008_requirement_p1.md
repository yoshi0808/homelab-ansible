# requirement(P1残件: R9 / R10)

2026-08-05 / Coordinator。`2026-08-04_001_requirement.md` §5 P1 の R9 / R10 を実施範囲とする追補である。**P0部分は本番適用まで完了しており(`2026-08-04_007_deploy_result.md`)、本書はその上に足す差分だけを定義する。**

## 1. 問題定義

**(a) 定義とSemaphore実物がずれても、誰も気づかない。**

`roles/semaphore_templates/defaults/main.yml` が正本になったが、実物(Semaphore上のテンプレート)がそれと一致しているかを見る仕組みは、reconcileを人が流したときにしか動かない。UIでの手編集、`description` の同定マーカーの消失、テンプレートの手動削除は、次に誰かが reconcile を流すまで検出されない。**マーカーが失われた場合は、次回適用が同じテンプレートを新規作成し、元のものが orphan として残る**(`2026-08-04_006_review_final.md` の非ブロッキング指摘。現在 `docs/ai/status.md` Next に立っている)。

**(b) ドリフト通知の「直し方」が、Yoshinobuの操作面と一致していない。**

`roles/deployment_drift_check/tasks/report.yml:97` が出す `直し方: ansible-playbook <playbook> -l <host>` は、**受け取った人が打つことを前提にしている**。2026-08-04 に「コマンドを流すのは自分の仕事ではない」と表明されており、押すべきものはSemaphoreのボタンである。定義がrepoへ来たので、`playbook` からテンプレート名を**導出ではなく参照で**引けるようになった。

## 2. ゴール

- 日次のドリフト検査が、配備物に加えて**Semaphoreテンプレートのずれ**も見る。
- ドリフト通知が、**押すボタンの名前**で直し方を言う。

## 3. 非ゴール

- **テンプレートの削除**(R5のまま。orphanは報告するだけ)。
- **schedule / inventory / environment の管理**(P0の §3 Won't のまま。`docs/ai/status.md` Next の Operator役の項目が扱う)。
- **`class` と `tester-gate` の一致検査**(R8のまま)。
- **root CA の作り直しと、ansy / quory のAPI接続設定の見直し**(独立案件。`docs/ai/status.md` Next)。本案件はその案件が完了するまでの回避を**引き継いで使う**だけで、恒久化しない。
- **「playbookはあるがSemaphoreのボタンが無い」をcommit時に警告する検査**(別件として `docs/ai/status.md` Next に立てたまま)。本案件の差分へ後から足すと、その部分だけ検証をやり直すことになる。

## 4. ユーザーストーリー

- 運用者として、テンプレートが誰かの手編集でずれたら、**次に誰かがreconcileを流すのを待たずに**朝の通知で知りたい。
- 運用者として、ドリフト通知を受け取ったら、**Semaphoreを開いてその名前のボタンを押すだけ**で直したい。コマンドを組み立てたくない。

## 5. 要件

### P0(本案件で必須)

**R10-a. 「直し方」をテンプレート名で言う**

`roles/deployment_drift_check` が、finding の `playbook` から `roles/semaphore_templates/defaults/main.yml` のカタログを引き、`semaphore_templates_render_name` フィルタでレンダリングした名前を通知本文へ出す。

- **参照はrepo内で完結させる。Semaphore APIを使わない。** R10はAPI・token・到達性のいずれにも依存してはならない(依存させると、通知を出す経路そのものが増えた依存で落ちうる)。
- **一致が0件のときは、現行の `ansible-playbook <playbook> -l <run_host>` 行へフォールバックする。** 消さない。実在する例が1件ある — ドリフト検査カタログが持つ9本のplaybookのうち `playbooks/knowledge_review_timer.yml` だけは **ansy のtimer**であり、quoryのSemaphoreカタログに定義が無い(2026-08-05にCoordinatorが両カタログの `playbook:` フィールドを突合して確認。残る8本は定義がある)。
- **一致が複数件のときは、候補をすべて並べる。** カタログは43エントリ/37 playbookで、5本のplaybookが複数variantを持つ(`prometheus_update_check` / `recovery_ha_failover` / `recovery_service_restart` / `recovery_vm_reboot` / `ubuntu_vm_full_upgrade`)。**このいずれも現在はドリフト検査カタログに現れないため、この分岐は現時点で実データでは起きない** — それでも、どれを押すかを機械が勝手に選ばない。
- `-l` は落ちる。ボタンには引数が無く、押すと play の `hosts:` 全体へ流れる。**復元という目的には上位集合で足りる**ため許容し、判断をコード側のコメントへ残す(通知本文へは書かない)。

**R9-a. 定義とSemaphore実物の突合を、日次ドリフト検査へ組み込む**

`playbooks/deployment_drift_check.yml` が、既存の配備物検査に加えて Semaphore テンプレートの突合を行い、**同じ1本の通知**へ finding を統合する。

- 通す経路は `token` → `resolve` → `read` → `reconcile` までとし、**`apply.yml` へ到達する経路を作らない。**
- `reconcile` の返す `new` / `changed` / `orphans` を finding へ変換する。`unchanged` は finding にしない。
- **`orphans` は期待値との差分だけを finding にする。** 現在1件(ブートストラップtemplate)が正常な状態であり、これを毎朝通知しない。期待値は変数で持つ。
- **同じマーカー消失の兆候は `new` と `orphans` の両方に現れる。** この2つを別々のfindingとして出すことで、`docs/ai/status.md` Next の「同定マーカーが消されると重複が作られる」が閉じる見込みである(閉じるかどうかの判断は本案件のクローズ時にCoordinatorが行う)。

**R9-b. 突合が失敗しても、日次検査を赤くしない**

token が読めない、`become` できない、APIが応答しない、`resolve` が名前を解決できない、TLS検証に失敗する — **いずれの場合も、playbookは終了コード0で完走し、その事実を finding として通知する。**

根拠: 日次検査の `rc=0` は既存の設計判断である(`playbooks/deployment_drift_check.yml` ヘッダ「差分があっても **0**」。pve1の平日停止運用で毎朝赤くしないため)。**新しく足す依存のためにこの性質を壊さない。**

**R9-c. API接続は、独立案件が終わったときに戻せる形で持つ**

接続先と証明書検証の扱いは変数で持ち、**選んだ理由をコード側に残す**。恒久の既定として書かない。

現時点の回避は、P0のブートストラップtemplateと同じ形を踏襲する — 接続先を**ループバックへ寄せた上で**検証を切る。**検証を切るだけの形にしない**ことが要点である(内部DNSはsophos-fw自身であり、名前で引く形のまま検証を切ると、DNSを取られたときにAPI tokenを奪える)。恒久対応は `docs/ai/status.md` Next の独立案件が持つ。

### P1(できれば)

**R11-a.** 突合のfindingにも「直し方」を出す。テンプレートがずれているときの直し方は `ansible-playbook` ではなく **Semaphoreのブートストラップtemplate(`SEMI-SAFE: Semaphore templates`相当)を押すこと**である。R10-aの機構をそのまま使えるなら使い、使えないなら固定文言でよい。

### Won't

- reconcileの結果を使ってテンプレートを自動修復すること。**日次ジョブに書き込みを持たせない。**
