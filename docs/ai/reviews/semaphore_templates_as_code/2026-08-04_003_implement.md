## 6. オープンクエスチョンへの回答(このImplementerの判断)

### 6.1 OQ1(APIバージョン・エンドポイント) — 未確認のまま実装

requirement §8の指示どおり、**確認する手段が無いため確認していない**。設計で対応した点:

- `read.yml`のGETを`apply.yml`の書き込みより必ず先に実行する(task順そのものが安全機構)。
- GET応答が「テンプレートのJSON配列」として読めなければ`assert`で即停止し、推測で書き込みへ進まない。
- POSTの応答に`id`が無ければ`assert`で即停止し、state fileを更新しない(重複作成の芽を摘む)。
- エンドポイント(`GET/POST/PUT /api/project/{id}/templates[/{id}]`)、認証方式(`Authorization: Bearer <token>`)、`arguments`/`survey_vars`のボディ上のJSON表現(文字列二重エンコードでなくネイティブ配列を採用)は、いずれも**Semaphoreの一般的なREST API規約を仮定した未検証の値**であり、`ansible.builtin.uri`の`status_code`チェックに落ちれば安全側(task失敗・停止)に転ぶ設計にしてある。
- ベースURLは`http://127.0.0.1:3000/api`(Semaphoreの既定ポート3000を想定)を既定値としたが、**quoryの実ポートは確認していない**。`/etc/semaphore/config.json`のbind portと一致するかはYoshinobuの初回実行で判明する。

### 6.2 OQ3(ブートストラップ) — 除外する

`playbooks/semaphore_templates_setup.yml`自身を起動するSemaphoreテンプレートは、**カタログに含めない**。

理由: 含めると「自分を実行するボタンの定義を、自分の実行結果が書き換える」自己参照になる。誤った定義(壊れたJSON、間違ったエンドポイント等)を一度適用してしまうと、それを直す手段が壊れたボタンそのものに依存する——最悪、UIから手で直すしかなくなり、それは今回解消しようとしているドリフトの温床そのものに逆戻りする。このテンプレートの新規作成と以後の編集はUIでの手作業のままとする(OQ2のtoken発行と同じ、一度きりの人手)。

### 6.3 OQ4(project_id / inventory_id / repository_id) — 固定値

**【superseded — §11.5参照】** 当初は`defaults/main.yml`に固定値(いずれも既定1)として持たせた。この前提はrequirement追補のR12により崩れた(ansyでproject_id=2、quoryでproject_id=1と実測され、「全て1」という仮定が誤りだったことが確定した)。現在は名前解決に置き換えている(§11.5)。以下は当初の判断であり、現在の実装とは一致しない — 経緯として残す。
