## 3. 契約に書かれていない実バグ(このセッションで発見)

**`roles/semaphore_templates/tasks/apply.yml` は現状のまま quory へ流しても、テンプレートの作成・更新が一切成立しない。**

- POST/PUTの両方で `survey_vars` を `| to_json`(JSON文字列化)して送信している(19-27行目・71-89行目)。
- しかし実測したSemaphore APIは、`survey_vars` を**書き込み時はネイティブなJSON配列**として要求する(`arguments` は文字列だが `survey_vars` は配列という非対称な仕様。GET応答ではどちらも見えない/文字列に見えるため、この非対称性は書き込みを試すまで分からない)。
- 文字列化した `survey_vars`(例: `"[]"`)を送ると **HTTP 400** が返り、`ansible.builtin.uri` の `status_code` チェックにより即座にtask失敗・playbook停止する(**fail-closed自体は機能している**。中途半端な作成や重複は発生しない。実測、rc=2、対象APIには何も作成されなかったことをGETで確認済み)。
- `survey_vars: "{{ item.target.survey_vars | to_json }}"` → `survey_vars: "{{ item.target.survey_vars }}"` に変更する(POST/PUT両方、2箇所)だけで、AC1/AC3/AC4/R11/R13の書き込み経路はすべて正しく動作することを実測で確認済み(§1・§2参照)。**`arguments` 側は文字列化のままで正しい**(混同して両方を配列化すると、今度は `arguments` 側で失敗する設計になっている点に注意)。

この修正はTester自身では行っていない(`/tmp` の複製に対してのみ適用し、リポジトリの `apply.yml` は無改変のまま)。Coordinator経由でImplementerへ差し戻すべき事項として報告する。

## 4. 契約外だが重要な観測: `validate_certs: true`(既定)がこの環境で失敗する

`semaphore_templates_api_validate_certs` の既定値は `true` だが、このTesterセッション(ansy、Python 3.14)から `ansible.builtin.uri` で素の設定のまま `https://ansy.internal:3000` へGETすると、

```
SSL: CERTIFICATE_VERIFY_FAILED: certificate verify failed:
CA cert does not include key usage extension
```

で失敗する(`curl` は同じ証明書チェーンを問題なく検証する — Python の `ssl` モジュールの方が厳格)。原因を追ったところ、信頼ストア中のルートCA証明書 `Home-RADIUS-CA`(自己署名、`CA:TRUE`)に **KeyUsage拡張そのものが付与されていない**ことを確認した(中間CA `Home-TLS-CA` は `Certificate Sign, CRL Sign` を正しく持つ)。これはPKI証明書自体の既存事実であり、今回のroleが作り込んだ不具合ではない。

- Testerの機能検証はすべて `-e semaphore_templates_api_validate_certs=false` を明示して行った(§0参照)。
- **これは今回のACの対象外だが、Yoshinobuが初回に既定値のまま `playbooks/semaphore_templates_setup.yml` を実行すると、`read.yml` の最初のGETで同じ理由で失敗しうる**(role自身は「推測せず停止する」設計どおりに安全側で止まるが、原因不明のまま止まって見える可能性がある)。quoryが同じルートCA・同程度に新しいPython/OpenSSLかどうかは**未確認**であり、確認できていない。
