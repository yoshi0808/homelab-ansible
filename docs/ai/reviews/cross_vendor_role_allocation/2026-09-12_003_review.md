## Code Review: Implementer / Reviewerのベンダー分離実験(規範差分)

### Summary

ADR-013新設とADR-011/012のsupersede関係、Role表・agent-messaging・`new-session.sh`の一貫性、旧配分のlive残存掃引、identity分離(計画ReviewerとImplementer別identity、差分Reviewer/Testerの別fresh Codex context)はいずれも整合し、`check-doc-consistency.py`もrc=0を維持する。ただし、ADR-013と`coordinator.md`が明記する「Implementer=high / 計画Reviewer・Auditor=medium」というeffort差別化は、agmsgのClaude Code起動経路(`spawn.sh` / `type.conf`)にeffort受け渡し機構が無く、`new-session.sh`も全Claude roleへ単一の`--model sonnet`しか渡していないため、実行経路上は実現されない。Major 1件。

### Critical Issues

なし。

### What Looks Good

- **ADR supersede関係**: ADR-011のStatusは「部分的にADR-013でsupersede、ベンダー中立とCoordinator effort原則は維持」、ADR-012のStatusは「実験的にADR-013でsupersede」と明記され、ADR-013本文も「ADR-011のRoleを二群へ固定する割当決定と、ADR-012の現在値表を実験期間中supersedeする」「ベンダー中立、Coordinatorを最低effortへ置かない、Role間のcontext独立という原則は維持する」と対応関係が一致している。ADR-010/011/012の決定本文(Context/Options/Decision/Consequences)は本diffで書き換えられておらず(Statusのみ変更)、非ゴール「過去のADRと案件記録は当時の判断として書き換えない」に適合する。
- **現行Role表・agent-messaging・launcherの一貫性**: `coordinator.md`のRole表(計画Reviewer=Claude Code/agmsg、Implementer=Claude Code/agmsg、差分Reviewer・Tester=Codex native subagent/fresh、Auditor=Claude Code/agmsg案件クローズ時)と、`agent-messaging.md`のactive識別子表(`coordinator`/`implementer`/`reviewer`/`auditor`)、`new-session.sh`の`CLAUDE_ROLES=(implementer reviewer auditor)`が3点とも一致することを確認した。
- **AC3/AC4(identity分離)**: `new-session.sh`は`implementer`・`reviewer`(計画査読用)・`auditor`を別々のagmsg identityとしてfresh起動し(`--fresh`は`agent-messaging.md`§10の記述どおり)、差分ReviewerとTesterは「別のfresh context」の native subagentとして案件ごとに起動する設計になっている。3 identityがtmux常駐、差分Reviewer/Testerは非常駐という設計もagent-messaging.md §10・new-session.shコメントで一致している。
- **旧配分のlive残存**: `grep -rn 'Reviewer / Tester / Auditor'`等で全docs/ai・CLAUDE.md・AGENTS.md・skills・.claudeを検索し、ヒットしたのは①role名を列挙するだけでCLI割当を主張しない箇所(core.md、memory-classification.md、status.mdのNext候補行)、②非ゴールで保護されるADR-010〜012本体・incident記録のみで、CLI割当を旧配分のまま主張する現行記述は見つからなかった。`ImplementerはCodex native`という旧断定も現行文書に残存しない。
- **model/effort検査との整合**: `python3 scripts/check-doc-consistency.py`を独立再実行し、check1/2/3すべてrc=0。check2が参照する「Claude Code subagent経路」表(`.claude/agents/*.md`のfrontmatterと対になるもの、Agent tool経由でCoordinator自身がClaude Codeで動く場合専用)はこの実験の対象外であり本diffで変更されておらず、`.claude/agents/`自体も無変更(`git status`で確認)。整合は崩れていない。
- **非ゴール遵守**: agmsg本体・sandbox/承認設定・過去案件記録の書き換えを行わず、「文書だけの軽微変更、緊急対応、実験自体の規範変更はこの制約の対象外」と明記することで「機械的に委任する規則にしない」という非ゴールとも整合する。
- **`bash -n new-session.sh`**、`git diff --check`をいずれも独立再実行し、rc=0を確認した。
