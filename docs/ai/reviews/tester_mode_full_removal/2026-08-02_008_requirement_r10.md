# requirement: R10 — 移行assertの撤去とTS-003の削除

日付: 2026-08-02 (JST)
位置づけ: `2026-08-02_001_requirement.md` の P1(R10)。001〜007 は監査を経てクローズ済みで、本ファイルはその続きである。

## 1. 問題定義

`tester_mode` の識別子は撤廃されたが、**渡されたら停止するassertが29本のplaybookに残っている**。このassertは移行のためのガード(task名 `[migration]`)であり、移行が完了した今は役目を終えている。残したままだと、リポジトリに死んだ識別子が29箇所残り、Policyもそれを説明し続けることになる。

## 2. 前提条件の充足(2026-08-02に確認済み)

001のリスク1は「assertを先に外すとdrill経由で本番VMが実リブートされる」だった。**この前提は解消した。**

| 確認対象 | 結果 | 手段 |
|---|---|---|
| リポジトリ内に `tester_mode` を渡す箇所 | 無し(assertのfail_msg内の文字列のみ) | `grep -rnE "tester_mode[[:space:]]*[:=][[:space:]]*(true\|True\|yes)\|-e[[:space:]]+tester_mode"` |
| ansy の `/usr/local/sbin/recovery-probe.py` | `tester_mode` 0件、`drill` 0件、mtime 2026-08-02 10:20 | ローカルの `stat` / `grep` |
| quory の同ファイル | 同上 | `ssh quory`(状態を変えない確認) |

**残存リスク: Semaphoreのテンプレートはrepo外でAIから確認できない。** ただしassertは2026-07-08から存在し、渡すテンプレートがあれば当該ジョブはその日から毎回rc=2で赤くなっていたはずである。定期ジョブは緑で回っているため、**定期ジョブ側には無い**と判断する。残るのは2026-07-08以降一度も実行されていない手動テンプレートのみで、そこに該当があればassert撤去後は停止せず本適用になる。

## 3. ゴール

`tester_mode` という識別子を、**現行の指示・コードの双方から完全に消す**。撤去後、この識別子が残るのは `docs/ai/reviews/` と `docs/ai/memory/` の過去記録、および各Policyの「変更履歴」節だけになる。

## 4. 非ゴール

- `docs/ai/reviews/`、`docs/ai/memory/`、`docs/ai/adr/`、Policyの「変更履歴」節を書き換えない(001と同じ)。
- `# tester-gate:` マーカーそのものには触れない。**名前が似ているだけの別物であり、こちらは現役の主機構である。**
- assertを外す以外の理由でplaybookのロジックを変えない。
