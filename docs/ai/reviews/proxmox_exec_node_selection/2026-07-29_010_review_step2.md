## Code Review: proxmox_exec_node_selection Step 2 (U4 + U5)

### Summary

U4はADR-001のinline preflightを共通role呼び出しへ機械的に置換したのみで、Play 2以降・`# tester-gate:`は無変更。決め打ちで用意した4条件decoy(両系可/pve1のみ/pve2のみ/両系不能)を独自に実行し、選定結果とfailメッセージが置換前と同値であることを確認した。U5は操作ごとのフォールバックを廃し「発火のたびに1回だけ選定」という設計に沿っており、`pvesh_vm_start`のリトライ経路・stdout/stderr文字列解析への依存は無い。ただし独自のdecoy検証で、`pick_pve_host`が「ansibleのhostパターンが1台もマッチしない」場合に`rc=0`となり誤って「到達可能」と判定してしまう経路を再現した(実装者の自己検証はstub `ansible`を使っていたためこの経路を再現していない)。あわせて、`pick_pve_host`を含む`subprocess.run`の例外(timeout超過等)を捕捉するtry/exceptがfire_ladder〜main()のどこにも無く、デーモン全体がクラッシュする経路が現に存在する(既存の`pvesh_vm_status`/`pvesh_vm_start`から続く既存構造をU5がそのまま踏襲・拡張したもの。systemdの`Restart=on-failure`/`RestartSec=30`により自動再起動はされる)。
