## 対象パス

## 変更内容

Play 1(旧 L29-72、pve1/pve2 の到達性を probe して `unifi_backup_fetch_target` へ1台登録する inline preflight)を、共通role `roles/proxmox_exec_node` の呼び出しへ置き換えた。

```yaml
- name: Select unifi_backup_fetch execution host (pve1 preferred, pve2 fallback)
  hosts: proxmox
  gather_facts: false
  become: false
  roles:
    - role: proxmox_exec_node
      vars:
        pen_prefer: pve1
        pen_target_group: unifi_backup_fetch_target
        pen_caller: unifi_backup_fetch
```

`pen_candidate_group` は指定していない(既定値 `proxmox` を使用)。`hosts: proxmox` と一致するため、role T1 の呼び出し規約assert(`ansible_play_hosts_all` と `groups[pen_candidate_group]` の一致)を満たす。この形は U1(`recovery_vm_reboot.yml` 等)で既に使われているパターンと同一にした。

冒頭のコメントブロック(旧L6-11)のうち選定方式を説明していた箇所を、「実行ノードは共通role `roles/proxmox_exec_node` で選定する」という記述に改めた。ADR-001への参照(`docs/ai/adr/001-unifi_backup_fetch-pve1-shutdown-target.md`)は保持した。Play 1直前のコメントブロック(旧L29-33)も同様に共通roleへの参照へ改めた。

`# tester-gate: risk-accepted` のマーカーとその説明(旧L19-27)は変更していない。Play 2以降(fetch処理・レポート・Slack通知)は無変更。

## 契約の充足状況

- **`# tester-gate: risk-accepted` マーカー・安全分類の説明**: 変更していない。選定Playは `ping`/`set_fact`/`add_host` のみで副作用を持たないため、分類はそのまま成立する(plan §2 U1と同じ理由づけがそのまま当てはまる)。
