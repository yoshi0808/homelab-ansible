# requirement: 依頼文とCoordinator作法の申し送り5件を宛先ごとに落とす

案件: `subagent_briefing_handover`
作成: 2026-08-02 / Coordinator
状態: 進行中

## 1. 問題定義

`docs/ai/reviews/incident_auto_capture_step2/progress.md` の後続への申し送りのうち5件(A-4 / A-5 / A-6 / A-7 / A-12)が、`docs/ai/status.md` の Next に「`skills/subagent-briefing/` の改訂(5件を1本化)」として1行で積まれたまま消化されていない。

**この枠組み自体が誤っている。** 5件は同じ「Coordinatorの依頼文・作法の欠陥が実装・検証を歪めた」クラスだが、**直すべき場所は1つではない**。依頼文の型に入るものと、Coordinatorの作法に入るものが混在しており、1ファイルへまとめると片方が本来の場所から外れる。

## 2. ゴール

5件を宛先ごとに落とし、`docs/ai/status.md` の当該Next行を消す。

## 3. 非ゴール

- 機械的検査の新設(旧A-10)は行わない。索引の正本だった `role-map.md` / `playbook-map.md` は2026-07-29に廃止済みで、残る `playbooks/README.md` は**既存の別Next行**(`skills/requirements-analysis/` へ索引更新を成果物として含める)が扱う。
- `docs/ai/core.md` は変更しない。5件はいずれも全Role共通の不変原則ではない。
- コード・playbook・Policyは変更しない。

## 6. 受入条件(Given/When/Then)

**AC1 — A-5が依頼文の型に入っている**
Given 改訂後の `skills/subagent-briefing/SKILL.md`
When 所要時間の読めない単位の依頼文を書こうとする
Then バックグラウンド実行の可否と完了検知を依頼文で扱うべきことが読み取れ、**具体的なコマンド・監視手段は指定されていない**(同SKILLの「書かないもの」の方針と一貫している)

**AC2 — A-7 ①〜③が境界の粒度として入っている**
Given 同SKILL「実行identityと権限境界」
When 触れてよいパスを絞る依頼文を書こうとする
Then 値が本来置かれるべき場所を境界から外した場合に何をすべきかが読み取れる

**AC3 — A-4 / A-6 / A-12 がCoordinatorの作法に入っている**
Given 改訂後の `docs/ai/roles/coordinator.md`
When commit前の確認、検証項目の置き場所、走行中subagentの扱いを判断する
Then 3件それぞれに対応する指示が存在する

**AC4 — 規範文書に経緯が混入していない**
Given 改訂後の2ファイル
When 追加された本文を読む
Then `progress.md`・A番号・日付・案件名・事故の経緯・lessonsへの参照が**1つも含まれていない**

**AC5 — 現在地が更新されている**
Given 改訂後の `docs/ai/status.md`
When Next(工程・体制)を読む
Then 当該行が存在せず、A-7 ④ を扱う既存行(`skills/requirements-analysis/` への索引更新)は残っている

**AC6 — 対象外が変更されていない**
Given 作業ツリー
When `git status` を確認する
Then 差分は `skills/subagent-briefing/SKILL.md`、`docs/ai/roles/coordinator.md`、`docs/ai/status.md`、本案件フォルダのみ
