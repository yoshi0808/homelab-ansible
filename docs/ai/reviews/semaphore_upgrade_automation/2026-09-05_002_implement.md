## Tester実走差し戻し対応(2026-09-05、006追記3 / D4・AC17)

- `tasks/upgrade.yml` の適用条件は従来から実バイナリのversionとsha256由来editionを
  targetと比較しており、dpkg台帳だけでalready-currentとは判断しない。一方、適用
  taskの`apt` moduleは同一versionが台帳にあるとno-opになり得たため、pin済みlocal

  形へ変更した。`NEEDRESTART_MODE=l`とnoninteractive指定は維持する。

  binary hashとの一致をMainPID不変と同じassertで要求する。これによりdpkg台帳が
  target版でも実体がrollback版なら再installされ、再展開がno-op/不完全なら不可逆点
  より前で明示的に停止する。
- localhost fixtureのfake `apt-get`へ、`install --yes --reinstall
  --allow-downgrades --no-remove`とpin済みlocal package pathが渡ること、台帳上は同版
  というfixtureでもtarget binaryへ置換されること、置換後sha256一致を確認した。
  production lint、syntax check、`git diff --check`もrc=0。実ホストへのAnsible実行は
  行っていない。

## Audit / 007 Suggestions対応(2026-09-05、008)

- 007 S1は説明追加として採用した。`--check`は`dry_run`と独立した全面停止gateで、
  preflight自体がDB・バイナリ退避、package取得、transaction書込みを伴いread-only

- 007 S3は採用した。rollback実行時に読み取り経路が存在する場合、元transactionの
  `query_user` / baselineを盲目的に再利用せず、現在のservice ownerとtoken ACLから
  非owner consumer identityを再選定し、そのidentityで現在のJSON key baselineを
  取得してrollback configへ上書きする。元transactionがskipで空文字を保存していても
  `pwd.getpwnam("")`へ進まない。
- S2 / S3は実ホストで踏めない失敗経路であり、実機未検証である。`/tmp` localhost
  fixtureでsystemd-run失敗時のwebhook削除とrc非ゼロ、およびskip由来の空query_userが
  現在ACL由来のconsumerへ置換されることを確認した。syntax check、ansible-lint
  production、`git diff --check`もrc=0。実ホストへのAnsible実行は行っていない。
