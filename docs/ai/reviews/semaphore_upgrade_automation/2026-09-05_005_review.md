### What Looks Good

**差し戻し5点の確認(観測事実→現状)**

1. **通知の無条件POST** → 解消。`prepare_detached.yml`がAnsible側で
   `semaphore_upgrade_notifications_suppressed`(`skip_notifications` / `ansible_check_mode` /
   controller環境の`CLAUDECODE`検出の三項)を計算し、transaction.json経由で
   `skip_notifications`としてスクリプトへ渡す。`notify()`はこの入力を`suppressed`として
   評価し(`semaphore-upgrade-detached.py:255`)、抑止時はPOSTを行わずwebhookファイルを
   削除するだけ。`CLAUDECODE`ベースの第3条件は`roles/common_slack/tasks/notify.yml`の
   既存trigger3・`docs/ai/policies/ansible_test_safety_policy.md` TS-031と同じ確立済み
   パターンであり、逸脱ではない。
2. **dry-runがMainPIDを読まずtrueを報告** → 解消。`upgrade.yml`は`dry_run`分岐の手前で
   `MainPID`をpreflight前後の2回読み(`semaphore_upgrade_preflight_pid_before/after`)、
   一致をassertしてから(`Assert preflight and backup did not restart Semaphore`)dry-run
   report debugへ`main_pid_before`/`main_pid_after`/`main_pid_unchanged`を明示的に載せる
   (AC1の「MainPIDが変わっていないこと」要求と対応)。
3. **`main()`のargv検査・設定読込がtry外** → 解消。`sys.argv`の長さ検査と
   `json.loads`によるconfig読込は`try:`ブロック内(188-194行目)にあり、失敗しても
   `except Exception`で捕捉され、`finally`で結果ファイル書き込みと通知(抑止判断含む)
   が必ず実行される。
4. **消費側identity検査が「rootでない」のみ** → 解消。二重に検査している。
   Ansible側(`upgrade.yml` "Discover non-owner consumer identity from token ACL" /
   "Require the selected query identity to differ from the service owner")が
   `yoshi`(service owner)と`root`の両方を除外してACLからidentityを選び、選んだ
   identityがservice ownerと異なることをassertする。Python側`consumer_query_ok()`も
   `pwd.getpwnam(user).pw_uid == 0 or user == service_owner`で再検査しており、
   service_owner文字列はAnsibleが`systemctl show --property=User`で実測した値を
   transaction.json経由で渡している。
5. **`dry_run`の既定値埋め** → 解消。`tasks/main.yml`の先頭taskが`dry_run is defined`
   をassertし(省略時rc非ゼロ、明確なfail_msg)、`roles/prometheus_update_check/tasks/main.yml`
   と同型。`defaults/main.yml`の`semaphore_upgrade_dry_run: "{{ dry_run | bool }}"`は
   このassertの後でしか評価されないため、既定値埋めにはならない。

**前回Approve領域の回帰確認**

- 秘密情報: webhookは`systemd-run --setenv`を使わず、root所有0600ファイル
  (`semaphore_upgrade_webhook_file`)経由で渡され、スクリプトが使用後に`unlink`する。
  `systemd-run`のargvにはスクリプトパスと設定ファイルパスのみで秘密値を含まない
  (AC10相当)。`include_vars`/webhook書き込みtaskとも`no_log: true`。
- `systemd-run`切り離し: PID1配下のtransient unit経由は維持、`--collect`でunit
  自動片付け、`Refuse to overlap`で多重起動を防止。
- ロールバックの世代選択: `find`→`transaction.json`のみを`mtime`降順で走査し、
  `rollback_to`一致でフィルタ、`[0]`が最新一致という構造は維持。ロールバック自身の
  metadata(`rollback.json`)はfind patternの対象外で自己選択しない。
- health checkの窓: `is-active`と`http_ok`の両方をAND評価し、`stability_seconds`の
  連続成立を要求する構造は維持(`ConditionPathExists`/`Restart=always`対策、P0-5/P0-6)。
- tester-gate分類: `check-mode-native`で維持。`prometheus_update_check.yml`と同じ
  「playbook固有のdry_runゲートを持つがcheck-mode-native」という既存の分類慣行と
  一致しており、逸脱ではない。
- scheduleカタログ: `semaphore_schedules_catalog`に`semaphore_upgrade.yml`関連の
  エントリは無い(grep確認済み)。P2-2/§3の非ゴールと一致。

### Verdict

近い。差し戻し対象の5点はすべて解消されており、Critical Issuesは無い。
