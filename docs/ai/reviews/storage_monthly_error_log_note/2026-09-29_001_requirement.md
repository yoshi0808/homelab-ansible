# requirement: NVMeのerror-log増加だけでは「要確認」にしない

作成: 2026-09-29 / Coordinator
起点: 2026-09-15の月次点検(Semaphore #1111)のNotionレポートが「確認が必要です(要確認)」「[要確認] pve2: <serial>: NVMe error-logの累積数が増加しました」と出た。2026-09-20の調査(`docs/ai/reviews/pve2_nvme_error_log/2026-09-20_001_investigation.md`)で実害を示す観測は無いと結論したが、レポートを読むだけではそれが分からない。範囲はYoshinobu合意済み(2026-09-29)。

## 1. 問題定義

`roles/proxmox_storage_monthly/module_utils/storage_monthly.py` は、NVMe smart-logの `num_err_log_entries` が前月より増えると `WARNING`(要確認)を出す。この値は**コントローラがコマンドを拒否した記録の累計**で、媒体の異常を数える値ではない(媒体の異常は `media_errors`)。pve2では「Invalid Field in Command」の記録が月に数件ずつ増え、そのたびにレポートの総合判定が「要確認」になる。

9/20の判断は「毎月WARNINGが出ても、その都度調査記録と同じ読み方をすればよい」だったが、Notionの本文だけでは読む人がその判断にたどり着けない。

## 2. ゴール

- error-logの増加だけでは、総合判定を「要確認」にしない。レポートには参考として、増えた件数と「媒体エラー0・重大警告なし」であることが1行で出る
- 媒体の異常(`media_errors` / `critical_warning` / spare)は、従来どおり「異常」(`CRITICAL`)で出る

## 3. 非ゴール

- 収集処理(`storage_collect.py`)は変えない。`nvme error-log` の中身の収集は足さない(9/20に退けた案)
- カウンタの減少(リセットの疑い)の扱いは変えない(`WARNING` のまま)
- Policy(`proxmox_operations_policy.md` SB-096〜SB-099)は変えない。error-log増加の扱いはPolicyに規定が無い
- ZFSの判定、到達不能・収集失敗の扱い、Slack短報の送信条件は変えない

## 4. 要件

| # | 要件 |
|---|---|
| R1 | NVMeの `num_err_log_entries` が前月より増え、かつ既存のNVMe健康CRITICAL条件(`media_errors == 0`、`critical_warning == 0`、`avail_spare >= spare_thresh`)を満たすときは、`WARNING` の issue を出さない。代わりに、総合判定(health)に影響しない**参考の行**をreportに持たせ、Notionの本文とSlack短報の該当箇所に出す。文言の例: 「参考: pve2: <serial>: NVMeが拒否したコマンドの記録が+2件(媒体エラー0・重大警告なし。実害を示す値ではありません)」 |
| R2 | `num_err_log_entries` が増え、かつ `media_errors > 0` または `critical_warning != 0` のときは、従来どおりの判定(既存の `CRITICAL` を含む)を変えない |
| R3 | カウンタの減少(`counter reset suspected`)、デバイスの交換・追加、初回(比較基準なし)の扱いは変えない |
| R4 | 参考の行はJSON正本(report)にも残す。形式は既存のreportのschemaを壊さない形とし、過去のreportを読む処理(replay、比較)が新旧どちらのreportでも動くこと |
| R5 | `docs/ai/context/operations/proxmox-storage-monthly.md` の「増加は要確認」の記述を、R1〜R2の実態に合わせる |

## 5. 受入条件

**実ホストには触れない。** 既存の `tests/test_storage_monthly.py` の流儀で、JSON入力を固定したテストで確かめる。

| AC | Given / When / Then |
|---|---|
| AC1 | **Given** 前月 `num_err_log_entries=239`、今回 `241`、`media_errors=0`、`critical_warning=0`、ほかは正常 **Then** 総合判定は `OK`(問題なし)、issuesに `WARNING` が無く、参考の行に「+2件」と「媒体エラー0・重大警告なし」がある。Notion本文とSlack短報の文面にも参考の行が出る |
| AC2 | **Given** AC1と同じで `media_errors=1` **Then** 従来どおり `CRITICAL` |
| AC3 | **Given** AC1と同じで `critical_warning=4` **Then** 従来どおり `CRITICAL` |
| AC4 | **Given** 今回の値が前月より減った **Then** 従来どおり `WARNING`(reset疑い) |
| AC5 | **Given** error-logが増えていない **Then** 参考の行は出ない |
| AC6 | **Given** 参考の行を持たない旧形式のreport(既存のfixture)を比較基準・replay対象にする **Then** 従来どおり動く |
| AC7 | **Given** 既存の `tests/test_storage_monthly.py` の全テストと `scripts/check-doc-consistency.py` **Then** 通ること。stageした状態で `scripts/git-pre-commit-check.sh` が通ること |
