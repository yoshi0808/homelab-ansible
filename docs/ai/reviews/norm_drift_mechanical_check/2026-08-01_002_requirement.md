# requirement — 転記ドリフトの機械検査(Step 2)

日付: 2026-08-01
状態: 確定(Yoshinobu承認済み)
前提: `2026-08-01_001_survey.md`(何を作り、何を作らないかの判定)

## 1. 目的

正本が別にある値を転記している箇所のうち、**両側が同一語彙の構造化された値であるもの**について、commit時に不一致を検出する。

**この検査は現在存在するドリフトを直さない**(調査時点で3件とも0件)。目的は再発防止のみである。根拠は、検査対象#1が2026-07-31に12本ドリフトし、案件クローズでもAuditorでも検出されなかったこと。

## 2. 検査する3件

### 検査#1 playbook安全区分

- 正本: `playbooks/*.yml` 冒頭の `# tester-gate: <値>`
- 転記先: `playbooks/README.md` の表。1列目がplaybookへのMarkdownリンク、4列目が `tester-gate` 列
- 一致条件: (a) 全playbookが表に1行以上ある (b) 表の行が指すplaybookが実在する (c) 4列目の値がヘッダの値と一致する

### 検査#2 subagentのmodel / effort

- 正本: `.claude/agents/<role>.md` のfrontmatter `model:` / `effort:`
- 転記先: `docs/ai/role-routing-index.md`「モデル・effort配分」表
- 対応規則: 表のRole名を小文字化したものが `.claude/agents/<name>.md` に対応する
- 一致条件: (a) 両側の集合が一致する (b) `model` と `effort` の値が一致する

### 検査#3 規範層のMarkdown内部リンク

- 一致条件: リンク先ファイルが実在する
- **対象は「全Markdownから除外を引いたもの」ではなく、明示した集合とする**(2026-08-01改訂。下記「対象の決め方」)

#### 対象の決め方

当初この節は「対象: リポジトリ内の `*.md`、除外: `docs/ai/reviews/`」と書いていた。**これは誤りだった** — 除外リストは新しい種類のファイルが増えるたびに伸び、書き漏らすと直しようのない指摘が出る。実際に `scripts/tests/fixtures/` を追跡対象へ戻した時点で、**この差分自身のcommitで検査が落ちる**状態になった(うち1件は fixture が意図的に壊しているリンクで、原理的に直せない)。

したがって**対象を明示列挙する**。規範(どう振る舞うかを定める文書)とリポジトリの索引だけを見る。

- `CLAUDE.md`、`AGENTS.md`
- `docs/ai/*.md`(直下)
- `docs/ai/policies/`、`docs/ai/context/`、`docs/ai/roles/`、`docs/ai/memory/`、`docs/ai/adr/`、`docs/ai/prompts/` の各配下
- `skills/` 配下
- `.claude/agents/` 配下
- `playbooks/README.md`
- `roles/` 配下の `*.md`

> `docs/ai/prompts/` と `.claude/agents/` は2026-08-01に**追加した**。当初の列挙から漏れていたものを独立レビューが検出した。根拠は `skills/document-norm-review/SKILL.md` が規範文書のクラスとして「Policy / Context / Role文書 / SKILL.md / **prompt** / CLAUDE.md」を挙げていること。**どちらも現時点で内部リンクを1本も含まないため、追加しても検査結果は変わらない**(実測)。将来リンクが書かれたときに対象へ入ることが目的である。

**対象外**(規範ではないもの): `docs/ai/reviews/`(案件当時の記録。その後ファイルが移動・削除されても記録の側は正しい)、`scripts/tests/`(検査自身のテストデータであり、意図的に壊したリンクを含む)、`reports/`。

**列挙漏れによる過少検査が、この形の残存リスクである。** 対象集合が意図通りかは実装記録に列挙して残し、レビューが確認する。

## 3. 制約

- **偽陽性ゼロで運用できること。** これは性能目標ではなく成立条件である。1件でも「直しようがない指摘」が残る状態では、この検査は作る価値がない(根拠: `docs/ai/status.md`「載せていないもの」— 効かない検査は「掃引済み」という誤った安心を生む)
- **解析結果が空のときにPASSを返さないこと。** 表やfrontmatterの解析が壊れた場合の自然な出方は「比較対象が0件 → 不一致0件 → PASS」であり、これは本検査が防ごうとしている誤った安心そのものである
- 依存はPython3標準ライブラリのみ。pre-commitは毎commitで走るため、外部パッケージ導入・`ansible` 起動・ネットワークアクセスを行わない
- 判定は決定的であること(入力が同じなら常に同じ終了コード)
- `scripts/git-pre-commit-check.sh` から呼ばれ、不一致があればcommitを止める

## 4. 観測されている事実(調査時点)

因果の説明ではなく、確認された現象のみを記す。

- 検査#1: playbook 48本、README表の該当行48行。未記載・実在しない行・区分不一致はいずれも0件
- 検査#2: `.claude/agents/` に auditor / implementer / reviewer / tester の4件。表の4行と値まで一致
- 検査#3: リポジトリ内の全Markdownから抽出した**内部リンク103本**(ファイル数ではなくリンクの本数。`docs/ai/reviews/` を含む)のうち、リンク先が存在しないものは13件。うち11件は `docs/ai/reviews/` 配下
- **残る2件は規範層にあり、リンク先が `...` という文字列である**(`docs/ai/memory/lessons/verification-referent-and-path-mismatch.md`、`skills/document-norm-review/SKILL.md`)。いずれも本文中の記法上のプレースホルダであってリンクではない。**この2件を不一致として報告する実装は制約「偽陽性ゼロ」を満たさない**

## 6. 実行identityと権限境界

**到達してはいけない状態**として示す。

- **実ホストに接続した状態で報告が返らないこと。** 本作業は ansy のリポジトリ作業ツリーと `/tmp` 配下で完結する
- **`scripts/` と `scripts/tests/fixtures/` および本案件フォルダ `docs/ai/reviews/norm_drift_mechanical_check/` 以外のファイルが変更された状態で報告が返らないこと。** ただし AC5 のため `scripts/git-pre-commit-check.sh` の変更は範囲内
- **`playbooks/README.md`・`.claude/agents/*.md`・`docs/ai/role-routing-index.md`・Policy・Context が変更された状態で報告が返らないこと。** これらは検査対象であって修正対象ではない。不一致を見つけた場合は直さず報告する
- **`git add` / `git commit` / `git push` が実行された状態で報告が返らないこと**
- 権限が昇格した状態に到達しないこと

harnessの安全機構にブロックされた場合、別の形で同じ結果へ到達せず、ブロックされた事実を報告に含めて返すこと。
