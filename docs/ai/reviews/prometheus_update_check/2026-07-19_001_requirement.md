# 要求仕様: prometheus_update_check(手動インストール Prometheus の更新チェック・通知)

作成日: 2026-07-19
起票: claude(要件定義)
種別: 追加系(新規 role + playbook)。**ホスト無変更のチェック+Slack通知のみ**

## 目的

monnie の Prometheus は apt 外の**手動バイナリインストール**(GitHub Releases から
`/opt/prometheus/prometheus`)で、apt の更新フローに乗らない。新しい版が出ても気づけない
ため、**週次でインストール済み版と GitHub 最新版を突き合わせ、上位版があれば Slack 通知**する。
**自動更新はしない(人間ゲート)** — Prometheus は稼働中の監視サービス本体で、バイナリ差し替え+
restart は codex CLI の自動更新とは危険度が異なるため。通知を受けて適用は Yoshinobu が判断。

## 背景 / 根拠

- monnie の監視スタック管理方式: [[project_monnie_monitoring_stack]](prometheus=apt外・手動 →
  別 playbook で更新チェックする将来タスク、として記録済み)。
- 雛形: `roles/codex_update_check` + `playbooks/codex_update_check.yml`
  (バージョンは command で収集のみ・判定は Ansible 側・古い→新しいで Slack。core.md §7)。
  本件は codex と違い**自動更新フェーズを持たない**(チェック+通知で終わり)。
- 通知は old→new 版必須([[feedback_upgrade_report_needs_versions]])。
- 実インストール手順(Yoshinobu 提供): バイナリ `/opt/prometheus/prometheus`、config
  `/opt/prometheus/prometheus.yml`、systemd `prometheus.service`、`--web.enable-lifecycle`、
  storage `/var/lib/prometheus`、retention 60d。現在 v3.4.0(過去に手動で1回更新済み)。

## 対象

- 新規 role: `prometheus_update_check`
- 新規 playbook: `playbooks/prometheus_update_check.yml`
- 実行対象ホスト: **monnie**(monitoring_servers)。GitHub API への egress が必要。
- スケジュール: Semaphore UI に登録(codex_update_check と同様、systemd timer は使わない。
  監視サービスに触れない読み取りチェックのため。core.md §12)。playbook 側は登録しない。

## 実施内容

### Phase 1: インストール済みバージョン取得(collect only)

- `ansible.builtin.command: /opt/prometheus/prometheus --version`(`changed_when: false`,
  `failed_when: false`)。
- 出力例 `prometheus, version 3.4.0 (branch: ...)` から `3.4.0` を Ansible 側で regex 抽出。
- バイナリパスは defaults 変数化(`prometheus_update_check_binary: /opt/prometheus/prometheus`)。

### Phase 2: GitHub 最新リリース取得(collect only)

- `ansible.builtin.uri` で `https://api.github.com/repos/prometheus/prometheus/releases/latest`
  を GET、`return_content: true`、`failed_when: false`、適切な timeout。
- `tag_name`(例 `v3.4.0`)から先頭 `v` を除いて `3.4.0` を得る。
- repo/URL は defaults 変数化(`prometheus_update_check_repo: prometheus/prometheus`)。
- GitHub API のプレリリース混入を避けるため `/releases/latest`(= latest stable)を使う。

### Phase 3: 判定(Ansible 側。shell で判定しない)

- `_collected` = 両フェーズ rc 成功 かつ current/latest とも非空・`^\d+\.\d+\.\d+` にマッチ。
- `_update_available` = `_collected` かつ **`latest is version(current, '>')`**
  (単純 `!=` でなく semver 比較で「上位版のみ」。ダウングレード/等価は通知しない)。
- ステータス: `update_available` / `up_to_date` / `collection_failed`。

### Phase 4: Slack 通知(通知のみ・ホスト無変更)

- `roles/common_slack/tasks/notify.yml` を include。
- 通知するのは **update_available または collection_failed のときだけ**(up_to_date は静音)。
- channel/status: `update_available`→`info`/`info`、`collection_failed`→`alerts`/`error`。
- 本文に **current → latest** を必ず記載(例 `monnie: 3.4.0 → 3.5.1`)+ リリース URL。
  **自動更新はしない**旨と、手動更新手順の参照(install 手順)を1行添える。
- `collection_failed` は `--version` 取得失敗 or GitHub API 失敗の切り分けが分かる本文に。

## 制約

- **ホストを一切変更しない**(バイナリ更新・restart・config 変更なし)。純粋な read + 通知。
- **`--check` での Slack 誤送信ガード**: notify を `when: not ansible_check_mode` 等でガード
  ([[feedback_check_mode_slack_notify]]。command/uri は `check_mode: false` で --check 中も
  収集を実走させ、通知だけ抑止)。tester-gate 分類は **check-mode-native**
  (収集は --check でも実走・通知は抑止、ホスト変更が無いので destructive gate 不要)。
  ※ codex_update_check は自動更新があるため risk-accepted だが、本件は更新しないので
  check-mode-native が適切。
- shell でバージョン判定・比較をしない(collect は command/uri、判定は set_fact)。core.md §7。
- 秘密情報・IP をリポに書かない。GitHub は認証なし公開 API(rate limit 内、失敗は
  collection_failed で握る)。時刻は JST。

## 初回実装スコープ

- role `prometheus_update_check`(defaults + tasks)
- playbook `prometheus_update_check.yml`(monnie 対象、localhost 実行前提のアサート等は
  codex に倣う。ただし本件は monnie 上で version 取得するため hosts: monnie)
- Phase 1〜4、check-mode-native ガード、Slack old→new 通知

## 初回除外スコープ

- **自動更新**(バイナリ DL・差し替え・restart・promtool config 検証)。将来別タスク。
- promtool / grafana / loki など他コンポーネントの更新チェック(prometheus 単体に限定)。
- Semaphore スケジュール登録(UI 側作業。playbook には含めない)。

## shell / Ansible 責務分離

- shell/command: `prometheus --version` の**取得のみ**。
- uri: GitHub API の**取得のみ**。
- Ansible tasks: パース・semver 判定・ステータス確定・Slack 本文組み立て・通知ガード。

## テスト観点(tester 向け)

- monnie で `--version` から current(例 3.4.0)を正しく抽出。
- GitHub API から latest を取得し `v` 除去。
- current==latest のとき **up_to_date で無通知**(Slack 静音)。
- latest>current を擬似(defaults の repo/binary を差し替え or fact 上書き)して
  **update_available で current→latest を含む Slack** が出る。
- `--version` 失敗 / API 失敗で **collection_failed→alerts** 通知、ホスト無変更。
- `--check` 実行で収集は走り Slack は飛ばない(誤送信ガード)。
- ホストに一切変更が無いこと(prometheus.service 無風・binary mtime 不変)。
