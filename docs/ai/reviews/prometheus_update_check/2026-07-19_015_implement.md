## 実装概要

`prometheus_update_check`の主モード選択を、Ansible native `--check`から必須extra-var `dry_run`へ移行した。`ansible_check_mode`は破壊的blockの独立した二次ゲートとして維持した。

| 起動 | destructive処理 | statusの扱い |
|---|---|---|
| `-e dry_run=true` | upgradeしない | `update_available` / `up_to_date` / `collection_failed` |
| `-e dry_run=false` | 更新対象があればupgrade | `upgraded` / `upgrade_failed` / `up_to_date` / `collection_failed` |
| `-e rollback=true -e dry_run=true` | restoreしない | `rollback_available` / `rollback_failed` |
| `-e rollback=true -e dry_run=false` | 選択backupをrestore | `rolled_back` / `rollback_failed` / `lock_release_failed` |
| `--check -e dry_run=false` | native check-mode二次ゲートでskip | apply-modeの引数・判定経路を無変更で検証 |

## fail-closed入力

playbookのlocalhost preflightとrole先頭の両方で`dry_run is defined`をassertする。未指定時はcurrent/latest収集やdestructive blockへ進まず停止するため、既存Semaphoreタスクが未更新でも自動upgradeにはならない。

定義後は`true`/`false`のboolean表現だけを許可する。role defaultではCLI extra-varを`prometheus_update_check_dry_run: "{{ dry_run }}"`へ受け、role内部のゲートに使用する。

## 二段destructiveゲート

upgrade blockは次の全条件でのみ実行する。

- rollback modeではない
- `dry_run=false`
- `not ansible_check_mode`
- `upgrade_wanted=true`

manual rollback blockは次の全条件でのみ実行する。

- rollback mode
- `dry_run=false`
- `not ansible_check_mode`
- 有効な選択backupあり

rollback discoveryは両dry-run layerでも実行する。`dry_run=true`かつ選択backupありの場合は、既存discoveryの`rollback_pending`を`tasks/main.yml`側で`rollback_available`へ再分類する。backup不在やcurrent version収集失敗の`rollback_failed`は上書きしない。

通知blockは既存どおり`check_mode: false`で実行し、`skip_notifications=true`も維持した。status名、channel分類、通知本文は変更していない。

## Playbook header / Semaphore

playbook headerへ次の起動例を追加した。

- 週次確認: `-e dry_run=true`
- 実適用: `-e dry_run=false`、任意で`-e prometheus_target_version=X.Y.Z`
- 手動rollback: `-e rollback=true -e dry_run=false`、任意で`-e rollback_to=X.Y.Z`
- rollback事前確認: `-e rollback=true -e dry_run=true`
- apply経路の無変更検証: `--check -e dry_run=false`

デプロイ時は、既存の金曜Semaphoreタスクへ`-e dry_run=true`を必ず追加する。未追加の場合はrequired-variable assertでjobが失敗するが、upgradeは実行されない。対象は従来どおり`monnie`固定で、node selectorは追加していない。

tester-gateは`check-mode-native`を維持し、header理由をdry_run主ゲート＋native check-mode二次ゲートへ更新した。
