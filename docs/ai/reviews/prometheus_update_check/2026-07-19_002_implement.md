## 実装概要

monnieへ手動導入されたPrometheusについて、インストール済み版とGitHub latest stable releaseを比較し、上位版または収集失敗だけをSlack通知するread-only role/playbookを追加した。

処理は次の4 phaseで構成する。

1. defaultsで指定したPrometheus binaryへ `--version` を実行し、stdoutだけを収集する。
2. defaultsで組み立てたGitHub Releases APIの `/releases/latest` を `uri` で収集する。
3. Ansible側でcurrent/latestを抽出・検証し、`version` testで上位版だけを判定する。
4. `update_available` または `collection_failed` の場合だけ既存common Slack taskをincludeする。

バイナリdownload/置換、設定変更、service restart、自動更新処理は含めていない。

## 設定

新規defaultsは次を管理する。

- Prometheus binary path
- GitHub repository
- latest release API URL
- human-facing release URL
- API timeout
- 手動更新手順の参照名

GitHub APIは公開・認証なしのlatest stable endpointを使う。

## 収集と判定

- currentは `prometheus, version X.Y.Z` からAnsible `regex_findall`で抽出する。
- latestはJSON `tag_name`の先頭 `v` だけを除去する。
- command rc、HTTP status、両versionの数値3 component形式が全て正常な場合だけ `collected=true` とする。
- `latest is version(current, '>')` の場合だけ `update_available=true` とする。
- 同版またはlatestが下位の場合は `up_to_date` とし、単純な不一致判定は使わない。
- 収集・抽出失敗は `collection_failed` とし、通知本文でbinary commandとGitHub API/tag parseのどちらが失敗したかを分けて表示する。

## 通知とcheck mode

- `update_available`: channel/statusは `info` / `info`。
- `collection_failed`: channel/statusは `alerts` / `error`。
- `up_to_date`: 無通知。
- 本文に `current → latest`、release URL、自動更新しない旨、手動更新手順の参照を含める。
- command/uriは `check_mode: false` で `--check` 中もread-only収集を実走する。
- Slack includeは `not ansible_check_mode` で抑止し、`--check` 中の誤送信を防ぐ。

playbookは `tester-gate: check-mode-native` とし、localhost playで実行元がquoryであることを確認した後、monnieでroleを実行する。
