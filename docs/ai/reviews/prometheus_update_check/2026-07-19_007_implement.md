## 実装概要

既存のPrometheus version check roleを、同一playbookで次の3モードを排他的に扱う構成へ拡張した。

| 起動方法 | 動作 |
|---|---|
| 通常 + `--check` | current/latestを収集し、更新ありまたは収集失敗をSlack通知。binary変更・restartなし |
| 通常（`--check`なし） | targetへupgradeし、失敗時は取得済みbackupから自動rollbackして通知 |
| `-e rollback=true` | 最新または`rollback_to`指定世代へ手動rollbackし、結果を通知 |

`prometheus_target_version=X.Y.Z`指定時はtargetを固定し、currentと異なれば明示的なdowngradeも許可する。未指定時はGitHub latestがcurrentより上位の場合だけupgrade対象とする。

## Upgrade

- 現行`prometheus`/`promtool`のregular file・non-symlinkと、install/backup directoryのcanonical境界を検証する。
- `backups/<current>-<JST timestamp>/`へowner/group/modeを保持して2バイナリを退避し、保持世代数を超えた旧世代をpruneする。
- GitHub releaseの`sha256sums.txt`から対象archive名に完全一致するSHA-256を抽出し、`get_url checksum`でarchiveを検証する。
- tempへ展開し、新しい`promtool`で既存`prometheus.yml`を事前検証する。失敗時はswap前に中断する。
- 2バイナリだけを配置してserviceをrestartし、active・target version一致・`/-/healthy` HTTP 200を確認する。
- swap開始後の失敗ではbackupを復元し、restart後にactive・旧version一致を確認する。tempは`always`で削除する。

config、storage、systemd unit、retentionは変更しない。

## Manual rollback

- backup root配下の`X.Y.Z-YYYYMMDDTHHMMSS`世代を列挙し、2バイナリがregular file・non-symlinkの世代だけを候補にする。
- `rollback_to`指定時は一致する最新版、未指定時はmtime最新の世代を選択する。候補なし・unsafe rootは`rollback_failed`でfail-closedとする。
- restore直前にもinstall directory、backup root、選択世代のcanonical境界とnon-symlinkを再検証する。
- 現行2バイナリを新しい世代へ退避してrollback自体を可逆にしてから、選択世代をrestoreする。
- restart後にactive・選択版とのversion一致・HTTP 200を確認する。restore後の失敗では退避した現行2バイナリの復旧を試みる。
- `--check -e rollback=true`ではrestoreせず、対象があれば`rollback_available`として現版、戻し先版、backup pathを通知する。対象がなければ`rollback_failed`としてalerts通知後に失敗終了する。

## Status / notification

| status | channel | 意味 |
|---|---|---|
| `up_to_date` | 無通知 | 通常モードで適用不要 |
| `update_available` | info | `--check`で更新対象あり・未適用 |
| `upgraded` | info | upgradeとhealth確認成功 |
| `upgrade_failed` | alerts/error | upgrade失敗。失敗step、自動rollback状態、復旧後versionを含む |
| `rollback_available` | info | rollback dry-runで対象backupあり |
| `rolled_back` | info | 手動rollbackとhealth確認成功 |
| `rollback_failed` | alerts/error | backup不在または手動rollback失敗 |
| `collection_failed` | alerts/error | current/latest収集失敗。既存diagnosticを最大200文字で維持 |

通知blockには意図的に`check_mode: false`を指定し、`--check`でもSlackを成果物として送る。`skip_notifications=true`と`tester_mode=true`は共通Slack role側で従来どおり送信を抑止する。
