# 要求仕様: prometheus_update_check のモードゲートを dry_run extra-var 方式へ(house 流儀統一)

作成日: 2026-07-19
起票: claude(要件定義)
種別: 変更系(既存 role のモードゲート変数のみ差し替え。安全機構は不変)

## 目的

`prometheus_update_check`(commit `0d8f2e4`)のモード選択を、ansible native `--check` 主ゲートから
**`dry_run` extra-var 主ゲート**へ変更し、`playbooks/ubuntu_vm_full_upgrade.yml` と同じ二段ゲート
idiom に統一する。Semaphore は survey 変数(= extra-var)で操作するのが自然で、`--check` は CLI Args
固定になり survey ドロップダウン化できないため、house の他 apply 系と操作感を揃える。

**副次効果(重要・ハザード解消)**: `dry_run` を**必須**にすることで、既存の金曜スケジュール
タスクが `dry_run` 未指定のまま `0d8f2e4` で走っても、**自動 upgrade でなく fail-closed(assert
失敗)**になる。現状は「`--check` 無し=実 upgrade」なので、金曜タスクを放置すると次回実行で
monnie を自動 upgrade してしまう。本変更でこの事故経路を構造的に塞ぐ。

## 背景 / 根拠

- 雛形 idiom: `playbooks/ubuntu_vm_full_upgrade.yml` + `roles/ubuntu_vm_full_upgrade/tasks/main.yml`。
  - `dry_run`(extra-var)が**主モード選択**(`-e dry_run=true` 月次判定 / `-e dry_run=false -e node=..`
    実適用)。`dry_run is defined` を assert(未指定は fail-closed)。
  - `--check`(ansible native)は**二次検証レイヤー**として併用: destructive include を
    `not ansible_check_mode` でゲートし、`--check -e dry_run=false` で「適用引数処理を壊さず検証」。
    (「--check が dry_run=true を丸ごと強制しない」理由もヘッダに明記されている idiom。)
- Semaphore: survey 変数は `-e key=value`(extra-var)。`--check` は CLI Args(静的)。→ 実行時
  ドロップダウンで check/apply を切り替えるには extra-var(`dry_run`)が必要。
- prometheus は対象が常に monnie 単一なので **node セレクタ不要**(ubuntu の node choice/manual は不要)。
- CLI 引数規約: `rollback` / `rollback_to`([[feedback_rollback_arg_convention]])。

## 対象

- `roles/prometheus_update_check/tasks/main.yml`(モードゲートと assert)
- `roles/prometheus_update_check/defaults/main.yml`(必要なら dry_run の受け口)
- `playbooks/prometheus_update_check.yml`(ヘッダ docs / assert)
- **既存の upgrade.yml / manual_rollback.yml / discover_backups.yml / notify.yml のロジックは変更しない**
  (安全機構=lock・世代所有権・全AND復旧・checksum・promtool・health・retention は不変)。

## 実施内容

### 1. dry_run を必須の主ゲートにする

- **`dry_run` を必須**にする: `dry_run is defined` を早期 assert(未定義は fail-closed で停止、
  auto-upgrade を防ぐ)。値は bool。
- モード行列(destructive の発火条件):
  - **upgrade**: `when: (not (dry_run|bool)) and (not prometheus_update_check_rollback)
    and (not ansible_check_mode) and prometheus_update_check_upgrade_wanted` + `tags:[destructive]`
  - **manual rollback restore**: `when: prometheus_update_check_rollback and (not (dry_run|bool))
    and (not ansible_check_mode) and selected_backup有` + `tags:[destructive]`
- `--check` は**二次検証**として残す(上の `not ansible_check_mode` を維持)。よって
  `--check -e dry_run=false` は適用経路を無変更で検証できる(destructive は skip)。

### 2. モード別の挙動(status/通知は既存踏襲・意味論のみ再マップ)

- `-e dry_run=true`: 確認のみ。status = `update_available`(上位版あり)/ `up_to_date`(無通知)/
  `collection_failed`。**upgrade しない**。
- `-e dry_run=false`: 実 upgrade。status = `upgraded` / `upgrade_failed`(自動 rollback 済)/
  `up_to_date` / `collection_failed`。`-e prometheus_target_version=X.Y.Z` でピン可。
- `-e rollback=true -e dry_run=true`(or `--check`): rollback dry-run。`rollback_available` /
  `rollback_failed`。restore しない。
- `-e rollback=true -e dry_run=false`: 実 rollback。`rolled_back` / `rollback_failed` /
  `lock_release_failed`。`-e rollback_to=X.Y.Z` で版指定。
- 通知は既存どおり `check_mode: false` で送出(`--check` 併用でも POST)、`skip_notifications=true`
  で抑止。status→channel 分類・本文は既存 notify.yml を維持。

### 3. ヘッダ docs / Semaphore 手順

playbook ヘッダに使用例と Semaphore テンプレ手順を明記(ubuntu_vm_full_upgrade 同様):
- 週次確認(スケジュール): `-e dry_run=true`
- 実適用: `-e dry_run=false [-e prometheus_target_version=X.Y.Z]`
- 手動 rollback: `-e rollback=true -e dry_run=false [-e rollback_to=X.Y.Z]`
- rollback 事前確認: `-e rollback=true -e dry_run=true`
- 適用経路の無変更検証: `--check -e dry_run=false`
- **デプロイ時の必須手当て**: 既存の金曜 Semaphore タスクに `-e dry_run=true` を付与する
  (未付与だと dry_run 必須 assert で job が失敗する=auto-upgrade はしないが赤くなる)。

## 制約

- **安全機構(006〜013 で固めた lock/所有権 cleanup/全AND 復旧/checksum/promtool/health/
  retention/世代検証)を一切壊さない**。本変更はゲート変数の差し替えに限定。
- tester-gate 分類は引き続き `check-mode-native`(destructive は `not ansible_check_mode` かつ
  `not dry_run`、read-only collect と通知は実走)。
- shell で判定しない。秘密/IP を書かない。時刻 JST。
- 対象は monnie のみ(node セレクタ追加しない)。

## テスト観点(tester 向け)

- `dry_run` 未指定 → fail-closed(assert)。**auto-upgrade しない**ことを確認(ハザード解消の要)。
- `-e dry_run=true` → 確認のみ・upgrade/rollback destructive skip・update_available 通知
  (monnie 無風)。
- `-e dry_run=false` → 実 upgrade 経路に入る(実適用は GO 下で。テストは `--check -e dry_run=false`
  で destructive skip の検証まで=無変更)。
- `-e rollback=true -e dry_run=true` → rollback_available/rollback_failed の表示のみ・restore しない。
- `--check -e dry_run=false` → 適用経路を評価しつつ destructive skip(無変更)。
- 既存の擬似失敗 a〜g(checksum/promtool/health→自動rollback/backup不在/lock競合/所有権/lock解放)
  が非回帰。
