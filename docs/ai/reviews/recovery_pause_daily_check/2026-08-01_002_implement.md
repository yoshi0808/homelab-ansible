## 2. 設計上の判断

- **AR番号はAR-103**。当初AR-083を予定したが、同番号は既存(manual layerの規定)であり衝突していた。Policy内の最大値がAR-102であることを確認して採番し直した。
- **pause flagのパスを直書きしない**(P0-2)。probe自身が読む `/etc/homelab-recovery/recovery-probe.json` の `monitoring_pause_flag` から取り、そこへ `stat` を掛けてmtimeを得る。同じ値は既に wrapper 3本・probe config・probe本体に存在しており、playbookへ書くと4箇所目の複製になる。片方だけ変わったとき「pauseされているのにmtimeが読めない」形でずれる。
- **有効hostを直書きしない**(P0-3)。`recovery_probe_service_enabled`(role defaultsは `false`、`host_vars/quory.yml` が `true`)を条件に使う。probeの配備先が変わってもplaybook側の修正が要らない。
- **probeの状態は `ansible.builtin.systemd_service` の `status.ActiveState` で見る。** 当初 `command: systemctl is-active` で書いたが `ansible-lint` の `command-instead-of-module` に触れたため置換した。unitが存在しない場合は `failed_when: false` と `| default('unknown')` により `unknown` となり、**down側へ倒れる**(握り潰したうえで正常扱いにしない)。
- **時刻はJST(`+09:00`)表記に揃え、`%z` で実オフセットを出す。** リテラルの `+09:00` を書くと、実行ホストのTZが変わったときUTCの値にJSTのラベルを付ける詐称になる。`%z` は `+0900` 形式で返るため、コロン区切りへ整える置換だけを掛けている。
- **通知はplay内の1箇所のみ**で、`rmc_paused` または `rmc_probe_down` のときだけ発火する。正常時に通知経路へ入らないことが、この仕組みの信号設計そのものである。

## 4. 実装中に作って撤回した欠陥(記録として残す)

Suggestion 1への最初の対応は、正規表現へ単語境界 `\b` を足すものだった。これは**壊れていた** — Jinjaの文字列リテラルが `\b` をバックスペース文字(0x08)として解釈するため、`'ACTIVE' is match('^(ACTIVE|PAUSED)\b')` が `false` になる。**正常時に毎朝assertで停止する(毎日赤くなる)回帰**であり、YAMLのクォート形式(plain / double-quoted)を変えても解決しない。多層エスケープの典型で、decoyに5パターン(`ACTIVE` / `PAUSED (all targets)` / `ACTIVE_but_stale` / `unexpected` / 空文字列)を流して検出し、正規表現そのものを捨てて文字列分割へ置き換えた。

この欠陥は**レビューでもテストでも先に発見されていない**(両者は変更前の版を検証していた)。実装者自身が変更のたびに実行して確かめる以外に捕まえる経路が無かった、という意味で記録に残す。
