# incident-capture: スナップショット手順の無いホストを収集エラーにしない — requirement

日付: 2026-10-03 (JST)
状態: 着手前(方針はYoshinobu了承、2026-10-03。案a)。計画査読 `_002` のMajor 3件(M1→R6b、M2→AC4、M3→R1/R6/AC7b)とS1(R6)を反映済み

## 1. 問題定義

**2026-10-03、`homelab-incident-capture.service` が1日に5回 `status=2` で失敗した。** 7件のバンドルすべてが同じ理由 — `no named investigate operations available for a spool-correlated host` — を持つ。

通知元(OPRES `req-20261003T163124+0900-941d459370e9135f`。Operatorがquory上の各 `summary.json` を読んだ結果):

| spool(JST) | `play_host` | 通知 | `slack_status` |
|---|---|---|---|
| 06:28:22 | localhost | quory worktree sync(`[worktree_sync] git fetch failed`) | error |
| 06:29:43 / 06:59:08 / 10:32:14 | localhost | recovery probe | warning |
| 10:27:31 / 10:29:44 | quory | ubuntu full-upgrade apply | warning / info |
| 16:01:24 | ansy | ubuntu full-upgrade apply | warning |

**7件とも `play_host` がスナップショット手順の登録先(`incident_capture_failure_snapshot_ops` = authy / monnie / pve1 / pve2)に無い。** localhostはquory上のtimer/probeが自分から出した通知である。同日のmonnie / authyのapply後の周期は成功している。

収集器はこの場合 `collect_host_snapshot`(`roles/incident_capture/files/incident-capture-collector.py:434-459`)が返すエラーをバンドルの `collection_errors` へ積み(`:990-993`)、周期は `exit 2` になる。**バンドル自体と基礎スナップショット(pve1/pve2のクラスタ状態)は取れており、収集は失敗していない。**

**これはADR-003 (d) の意図した挙動である。** d-2は「操作が無い事実が `collection_errors[]` に残り、カタログ拡張の根拠になる」というループを狙っていた(`docs/ai/adr/003-incident-capture-collector-runtime.md` (d))。2か月の運用でこのループは答えを出した — 該当するのは quory(localhost含む)と ansy であり、両者のスナップショットをカタログへ足すことは採らない(§3)。**答えが出たあとも毎回 `Failed to start` を出し続けると、その行は読まれなくなる。** 9/21の案件(`docs/ai/reviews/incident_capture_exit_semantics/`)が直した「成功ジョブの通知」と同じ形である。

## 2. ゴール

**スナップショット手順の登録が無いホストを、収集エラーとして数えない。** 「手順が無かった」事実はバンドルに残す。それ以外の挙動は変えない。

## 3. 非ゴール(今回やらない)

- **quory / ansy / localhost のスナップショット手順をカタログへ足すこと**(案b)。localhost→quoryの読み替えが別に要り、quoryからansyへの到達経路は無い。recovery probeの通知は対象が別ホストであり、quoryの状態を撮っても判断材料にならない
- **相関の仕組み**(失敗ジョブとしか相関しない、ADR-003 (c))と **notable判定**を変えること
- **`no correlated Semaphore job` の扱い。** `error` / `critical` は従来どおり収集エラーに残す(06:28の1件はこれで、今回の変更後も `exit 2` になる。正しい動作である)
- **06:28 の `git fetch` 失敗そのもの。** 別件として `docs/ai/status.md` のNextで扱う
- 終了コードの定数、unit template、`incident_capture_policy.md`(IC-024)の変更。**「手順が無い」を収集エラーと呼ばなくなるため、IC-024の文面は触らない**

## 4. ユーザーストーリー

運用者として、syslogの `Failed to start homelab-incident-capture.service` を見たときに、**人の対応が要るものだと信じたい。** 月1のapplyと週1のProxmoxパッチのたびに出るなら、その行は読まれなくなる。
