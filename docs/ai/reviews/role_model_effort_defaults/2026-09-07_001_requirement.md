# Role別model / effort既定値の固定

## 1. 問題定義

現在のRole配分は、作る側をCodex、検める側をClaude Codeへ分けている。一方、model / effortの現在値は複数箇所に分散し、実効値も一致していない。

- `docs/ai/adr/011-vendor-neutral-role-allocation.md` はImplementerを`gpt-5.6-sol` / lowとしている。
- `~/.agmsg/config/spawn_options.yaml` はCodex spawn全体をlowにする。
- 直近のImplementer保存セッションは`gpt-5.6-luna` / mediumだった。
- `docs/ai/roles/coordinator.md`の表はClaude Code subagent経路だけを示し、現在使うagmsg経路の値を一覧できない。

このままでは、CoordinatorのCLI既定や直前のセッション状態により、同じRoleが意図しないmodel / effortで起動する。

## 2. ゴール

- 現在のRole割り当てについて、Roleごとの既定model / effortを一意に決める。
- 実際のagmsg起動経路と文書上の値を一致させる。
- 高いeffortへ引き上げる条件と、低いeffortを許す例外を明示する。

## 3. 非ゴール

- Coordinator自身のmodelを固定しない。
- ADR-011の「作る側 / 検める側を別CLIへ分ける」決定を変更しない。
- agmsg upstreamへRole別effort機能を追加しない。
- Testerの通常既定をlowにしない。
- `.claude/agents/*.md`のClaude Code subagent用frontmatterを変更しない。

## 4. ユーザーストーリー

- Yoshinobuとして、どのRoleがどのmodel / effortで起動するかを事前に把握したい。
- Coordinatorとして、CLIの現在設定を推測せず、Roleの既定値を見てsubagentを起動したい。
- Reviewerとして、過去のADRと現在の運用値が競合せず、どちらが有効か判断できる状態を確認したい。

## 5. 要件

| ID | 優先度 | 要件 |
|---|---|---|
| R1 | P0 | 現在の既定を、Implementer=`gpt-5.6-luna` / medium、Reviewer=`sonnet` / medium、Tester=`sonnet` / medium、Auditor=`sonnet` / mediumとする |
| R2 | P0 | Implementerは、複数role、複雑なcheck mode、rollback、shell / Pythonを含む場合にhighへ引き上げられる |
| R3 | P0 | Testerのlowは、実ホストへ到達せず、期待値と手順が完全に固定されたローカル検査で明示指定した場合だけ許す |
| R4 | P0 | agmsgの実効設定でCodex spawnの既定effortをmedium、Claude Code spawnの既定effortをmediumにする |
| R5 | P0 | agmsg起動時のmodelは省略せず、Role表の値を`spawn.sh --model`へ渡す運用にする |
| R6 | P0 | ADR-011の旧現在値を履歴として残しつつ、ADR-012がその値だけをsupersedeしたことを明示する |
| R7 | P1 | Claude Code subagent経路のfrontmatterと既存整合性検査は維持する |

## 6. 成功指標・受入条件

### AC1: Role別既定値

Given `docs/ai/roles/coordinator.md`を読む、When 現在のagmsg配分表を確認する、Then R1の4Roleとmodel / effortが一意に読み取れ、Coordinatorのmodelは固定されていない。

### AC2: 引き上げ・引き下げ条件

Given 通常案件と複雑な実装案件とローカル限定テスト、When effortを選ぶ、Then Implementer highとTester lowを選べる条件がR2 / R3どおり区別される。

### AC3: 実効設定

Given `~/.agmsg/config/spawn_options.yaml`、When Codex / Claude Codeのspawn optionを確認する、Then両方の既定effortがmediumである。

### AC4: 旧決定との関係

Given ADR-011とADR-012を読む、When現在値を判断する、ThenADR-011のCLI分離決定は有効なままで、model / effort現在値だけがADR-012により置き換えられたと分かる。

### AC5: 文書整合性

Given変更をstageした状態、When `scripts/check-doc-consistency.py`とpre-commit検査を実行する、Then終了コード0となり、Reviewerが規範の消失・競合・適用範囲の変化についてblocking findingなしと判定する。

## 7. オープンクエスチョン

なし。Role別effortをagmsg自体で強制する拡張は、実際に選択ミスが観測された場合の別案件とする。

## 8. タイムライン考慮

次のsubagent起動より前に反映する。実ホストやサービスへの変更は無く、停止時間は発生しない。

## リスク

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| modelを省略してCLI既定へ戻る | Medium | Medium | Coordinator Roleとrunbookで`--model`明示を起動契約にする |
| Testerをlowへ落とし、実ホスト結果を誤判定する | Low | High | lowをローカル・完全手順化・明示指定の3条件に限定する |

| ADR-011と新ADRが両方「現在値」を主張する | Medium | Medium | ADR-011側へsupersede先を明示する |
