# implement: Proxmox稼働中バージョンの固定Notionページ更新

## 実装

- `playbooks/proxmox_running_versions.yml` は `proxmox` でread-only収集し、独立したlocalhost playで固定ページを更新する。play-levelの`ignore_unreachable: true`により、到達不能nodeを後段のページ描画まで保持する。
- `roles/proxmox_running_versions` を新設した。収集器は稼働kernel、所有package版、dpkgのDebian版比較による最新boot可能kernel package、pve-manager、pve-qemu-kvm installed版を取得する。取得・構文エラーは推測せずnode `error`として扱う。
- Notion moduleは、空ページまたは前回中断で1〜3個の管理済みcode blockだけを受け入れ、`updating` headerを最初に書く。node block更新後にのみ`complete` headerへ替えるため、途中失敗は機械読者に無効として残る。非管理block混在や4個以上のblockはfail-closedする。
- 最新apply reportは既存roleの実ファイル名`<JST timestamp>_<node>_apply.json`だけを対象にし、`run_timestamp` / `result` / `reboot_done`が揃わなければ3値すべて`unknown`とする。FAILEDは事実として表示し、単独では実行失敗にしない。
- `--check`、`skip_notifications=true`、`CLAUDECODE`検出時はmodule内のtoken読込・HTTP前gateで公開を抑止し、予定本文をdebug出力する。収集error、全node unreachable、または公開失敗は、抑止条件がなければcommon_slack経由でalertsを1通に集約して非0終了する。
- Semaphore templateとinactive daily 07:00 JST scheduleを追加した。既存scheduleの`active`はoperator-ownedなので、初回readback後の有効化はYoshinobuがUIで行う。UI有効化後のカタログ`active: true`追随は別commitである。

## 差し戻し対応（_006 diff review / _007 test result）

- Minor 1: `PATCH /blocks/<page>/children`によるappendだけは`retry=False`にした。appendは応答喪失後に同じrequestを再送すると重複blockを作り得る非冪等操作であるため、通信断・5xxでは静的エラーで停止し、次回にページを読み直す。既存blockへの同内容PATCHと空paragraphのDELETEは再試行可能なままにした。
- Minor 2 / 実ページ観測: 子block 0件は従来どおり初期状態として扱う。加えて、ただ1個のparagraphで`rich_text: []`または空textだけのものはNotion editorの空placeholderとしてDELETEしてから管理code blockを3個作る。空でないparagraph、他の非code block、4個以上のblockは従来どおり`managed_blocks_invalid`で停止する。実ページの`<empty-block/>`がどちらの表現でも初回更新できる。
- Minor 3: kernel候補を`^proxmox-kernel-[0-9][^ ]*-pve(?:-signed)?$`へ変更し、ABIが数字で始まらない同名風packageを除外するfixtureを追加した。
- Minor 4: 通常公開だけを`reports_base_dir/proxmox-running-versions/.notion-page.lock`の非ブロッキング`flock`で直列化した。競合時はtoken/Notion I/Oより先に`publication_busy`で停止する。check / skip_notifications / AI sessionの抑止時はlock directoryも作らない。
