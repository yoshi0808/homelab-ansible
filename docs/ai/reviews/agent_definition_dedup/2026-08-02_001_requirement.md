# requirement: `.claude/agents/` と `docs/ai/roles/` の重複解消

日付: 2026-08-02 (JST)
起点: Yoshinobuの問い「`docs/ai/roles/` と `.claude/agents/` は分離しておくべきか。重複した項目はないか」

## 背景

`docs/ai/role-routing-index.md`「Agent定義との関係」は、`.claude/agents/<role>.md` を harness向けの実行機構に限り、役割の規範は `docs/ai/roles/<role>.md` を正本とすると既に宣言していた。実態はその宣言どおりになっておらず、agent定義4本の body(計約60行)がほぼ全て規範の複製か、agent定義にしか正本の無い規範だった。

ずれた経緯は commit `411affa`「Slim down role docs and centralize subagent common rules」が subagent共通ルールを `docs/ai/core.md` へ集約したとき、`.claude/agents/` を変更対象に含めなかったこと。同じく「規範文書に経緯・`docs/ai/reviews/` 参照を書かない」方針も `docs/ai/roles/` にだけ適用されていた。

## 決定

**分離は維持する。** frontmatter (`name` / `description` / `model` / `effort`) は harness が機械的に読む値であり `docs/` 側に置けないため、ファイルとしての分離は harness の制約から必要である。body は Coordinator における `CLAUDE.md` と同じ位置づけ(harness が起動時に自動で読ませる入口)なので、`CLAUDE.md` と同様に正本を指すだけの形へ揃える。

**Implementer の実ホスト到達範囲は「全面禁止」を正本とする**(2026-08-02 Yoshinobu決定)。`.claude/agents/implementer.md` の全面禁止と `docs/ai/roles/implementer.md` の承認制が食い違っていた。`docs/ai/role-routing-index.md` の「Testerが実ホスト検証を担う唯一のRole」と整合する側を採った。

## 受入条件

| AC | 内容 |
|---|---|
| AC1 | agent定義4本の body に、正本へのポインタと成果物ファイル名の対応以外が残っていない |
| AC2 | 変更前の agent定義の全行が、昇格先または既存正本へ1対1で対応づく(対応先の無い行がゼロ) |
| AC3 | 実ホスト名の列挙が `.claude/settings.json` と `docs/ai/roles/coordinator.md` の2箇所だけになる |
| AC4 | 削除した節を指す宙ぶらりん参照がリポジトリ内に無い |
| AC5 | 縮退後の定義で起動した subagent が、`docs/ai/core.md` と自分の Role文書を実際に読んでから作業に入る |

## scope外

- `docs/ai/role-routing-index.md` のモデル配分表(frontmatterの値を写しているが、「根拠」列と medium確定の経緯を持つため記録としての価値がある)
- frontmatter の `description`(harness のルーティングが読むため機構上必要)
- `.claude/settings.json`(承認境界の実強制)
