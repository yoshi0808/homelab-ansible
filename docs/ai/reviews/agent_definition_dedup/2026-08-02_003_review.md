## Critical Issues

### 1. このReviewerセッション自体が、diff前の`.claude/agents/reviewer.md`で起動されている(AC5は未検証のまま)

この会話の冒頭でsubagentとして与えられた役割定義(システムプロンプト冒頭のブロック)は、`git show HEAD:.claude/agents/reviewer.md`の8〜23行目と**一字一句一致**する——「## subagentとしての事情」節、`実host(pve1 / pve2 / monnie / authy / sophos-fw / cloudkey / quory)へのansibleコマンド実行はしない」の全列挙、decoy 3条件の旧文言をすべて含む、縮退**前**の内容である。一方、作業ツリーの`.claude/agents/reviewer.md`は既に新しい4行構成になっている(`cat`で確認済み)。

つまり、**このReviewer起動は今回のdiffが適用された定義ではなく、HEAD時点(diff前)の定義で行われた。** これは以下を意味する。

- AC5「縮退後の定義で起動した subagent が、`docs/ai/core.md` と自分の Role文書を実際に読んでから作業に入る」は、**このセッションでは検証できていない**。私が`docs/ai/core.md`と`docs/ai/roles/reviewer.md`を読んだのは、依頼文が明示的に指示したためであり、縮退後の`.claude/agents/reviewer.md`の4行(「役割の正本は次の2つで...着手時に必ず読むこと」)に導かれた結果ではない——私に渡された定義はそもそも縮退後のものではなかった。
- より重要な運用上の含意として、**Coordinatorが同一セッション内でagent定義ファイルを編集しても、その後に起動するsubagentへ即座に反映されない(少なくとも今回はされなかった)可能性がある。** `docs/ai/role-routing-index.md`「セッション途中に作成した定義が登録されるかは、harnessの版に依存する」は新規Role追加時の挙動を述べているが、既存Role定義の**編集**が同一セッション内のsubagent起動へ反映されるかどうかは別問題であり、今回はされない側の実例が観測された。
- 結論として、**AC5はこのReviewer起動をもって満たされたと扱えない。** Coordinatorは、今回のagent定義変更をcommitした後(または新しいセッションで)改めてsubagentを1体起動し、その起動時システムプロンプトが新しい4行構成になっているかを確認する必要がある。

対象: `.claude/agents/reviewer.md`(および他3本も同様の懸念)、AC5の検証手順そのもの。

## Suggestions

### 2. Jinja検証の具体性が一段落ちている(意味の劣化ではないが確認)

`.claude/agents/implementer.md`旧L20「Jinjaの出力は`repr`相当で型まで確認し」が、`docs/ai/roles/implementer.md`では「Jinjaの出力は型まで確認し」へ変わり、「`repr`相当」が落ちている。実施内容は「日付・事故経緯は落とした」とだけ記載されているが、`repr`相当という**確認手段の具体性**も落ちている。文字列と`None`はどちらも「型」という言葉だけでは区別が付きにくいため、`repr`相当という具体的な確認方法を復元するか、代替の具体的な確認手段を明記した方がよい。実害は無いと判断する(下流task経由の完走確認という本体の規範は残っている)。

対象: `docs/ai/roles/implementer.md` L12。

### 3. AC3の検証コマンドが実際の主張範囲より狭い

`002_implement.md`のAC3検証は`grep -rln "sophos-fw" .claude/ docs/ai/roles/ docs/ai/core.md`のみで、他の保護対象ホスト名(`pve1`/`pve2`/`authy`)や非保護ホスト名(`monnie`/`quory`/`cloudkey`)は検査されていない。独自に7ホスト名すべてを同じ範囲で再検査した結果、`.claude/settings.json`と`docs/ai/roles/coordinator.md`以外への残存は無かった(`docs/ai/core.md`に`quory`/`monnie`の言及が残るが、これは「開発と本番の境界」節の既存記述で今回のdiff対象外、かつ「実ホストへの非冪等操作の承認」の対象列挙とは別文脈)。**結論としてAC3は満たされている**が、検証コマンドの代表性の低さは今後同種の縮退作業で再現しうるので、次回は対象ホスト名リストを網羅する形にした方がよい。

### 4. `実ホスト検証はTesterの役である(docs/ai/role-routing-index.md)`の引用がやや緩い

`docs/ai/roles/implementer.md` L35、`docs/ai/roles/reviewer.md` L48が「実ホスト検証はTesterの役である」の根拠として`docs/ai/role-routing-index.md`を挙げているが、同ファイル本文に「唯一のRole」に相当する明文の一文は無い(該当する言い回しは`.claude/agents/tester.md`のfrontmatter `description`にのみ存在する)。`role-routing-index.md` L16「実ホストへの`--check`/dry-run実行を含め、`docs/ai/roles/tester.md`の禁止事項がそのまま適用される」がTesterの役割を示唆してはいるが、引用として厳密ではない。実害は小さい(参照先ファイルは実在し、記述の趣旨とも矛盾しない)。
