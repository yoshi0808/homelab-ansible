# requirement: `role-routing-index.md` から経緯・根拠を落とす

日付: 2026-08-02 (JST)
起点: Yoshinobu「role-routing-index.mdに過去経緯をわざわざ書く必要もなく、今の求めるものを書くべき」(2026-08-02)

## 1. 問題定義

2026-08-01に `docs/ai/roles/` 5本から経緯・根拠・`docs/ai/reviews/` と `docs/ai/memory/lessons/` への参照を全廃したが、**`docs/ai/role-routing-index.md` は対象から外れていた**。同ファイルは全Roleが作業開始時に読む(`docs/ai/core.md`「作業時に読む情報」の3番目)にもかかわらず、日付つきの経緯・試行の実績・lessonsへの参照を保持している。

判断軸はYoshinobuの表明(2026-08-02)。

> ベースラインがどんどん変わる状況下において、どのベースラインなのかの前提がわからない中での履歴は混乱を招くだけです

**「その履歴が有用か」ではなく「読み手が前提となるベースラインを特定できるか」で判断する。** このリポジトリは短期間に規範が大幅改訂されるため特定できず、特定できない履歴は誤った前提で読まれる分だけ無いより悪い。

## 2. ゴール

`docs/ai/role-routing-index.md` を、**いま行動するために要る事実だけ**にする。履歴は「変更履歴」に相当する場所と `git log` が持つ。

## 3. 非ゴール

- **他の規範文書へ広げない。** 本案件は `role-routing-index.md` 単独で1周し、落とし方の型を固めることが目的である。Policy群・`memory-classification.md`・`context-classification.md`・`skills/` への適用は別案件とする(2026-08-02、Yoshinobuと合意した進め方)。
- Roleの責務・権限・実現方式そのものを変えない。**落とすのは経緯と根拠であって、指示ではない。**
- `docs/ai/reviews/` や `docs/ai/memory/` の既存記録を書き換えない。

### 工程の判断: Testerを立てない(2026-08-02、Coordinator)

**本案件はTester役を起動しない。** 理由は次の3点。

1. 変更対象が文書2本のみで、**実行される経路が1つも無い**。AC1〜AC4はすべて読解と突合であり、これは独立Reviewerの職掌そのものである。
2. AC5は `scripts/git-pre-commit-check.sh` と `scripts/check-doc-consistency.py` の実行だが、**前者はcommit前に必ず通す門であり、Testerの有無にかかわらず実行される**。Coordinatorがstage後に実行する。
3. 本案件の主要リスク(経緯と一緒に指示を落とす)に効くのは実行検証ではなく**逐行突合による独立レビュー**であり、それはリスク欄2で必須と定めて実施済みである。

工程の重さは変更のリスクに合わせる。実行経路の無い変更にTesterを通すと、工程が増えるだけで検出力は上がらない。
