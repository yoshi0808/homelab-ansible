# Code Review: incident-capture collection_errors journal要約

日付: 2026-09-02

### Summary

前回までのblocking 3件（物理行数上限の回避、非信頼なspool由来値のjournal混入、warning/errorの既定画面に要約が現れないseverity）と、実装記録の禁止IPv4リテラルはすべて是正された。境界値とend-to-endのnegative testを独立に再現し、既存の終了コード・`_runs/`・バンドル記録が変わらないことも確認した。AC1〜AC8を妨げる残存findingはない。

### Critical Issues

なし。

### Suggestions

- `_redact_untrusted_what()`は既知の`WHAT_PREFIX_*`へ一致しない値を通すfail-open設計である。現時点の全`what`生成経路は確認済みでAC7を満たすが、将来spool由来値を連結する経路を専用prefixなしで追加すると静かに漏れる。この保守上の前提は実装記録§6へ明記されており、今回はnon-blockingの残存リスクとして受容できる。

### What Looks Good

- 前回Major #1は解消した。`_truncate_for_journal()`は`splitlines()`でLF / CR / CRLF等を1物理行へ正規化してから200文字へ切り詰める。run 7件＋bundle 8件の全`what`へ各改行形式を入れた独立テストで、ヘッダ1行＋先頭10件＋省略通知1行の計12物理行だった。1件に1000個のLFを入れた場合も2物理行だった。10件は11行、11件は省略通知を含む12行となり、切り詰めの事実と件数も表示される。
- 前回Major #2は解消した。非信頼値を連結する5経路は共通の`WHAT_PREFIX_*`から構成され、journal表示直前に固定カテゴリへ置換される。5 prefixすべてへ秘密マーカー、LF / CRLF、制御文字を入れた単体テストで後続値が出ないことを確認した。さらに壊れたspoolファイル名と正常spoolの`play_host` / `play_name`へ同様の値を入れて`main()`を実行し、exit 2のままjournalには一切現れず、3種類の固定カテゴリで何が起きたかを判別できた。2026-09-01型の「相関ジョブ無し」「named investigate operation無し」も区別され、AC2とAC7の両立を保っている。
- 実装記録はnegative testへ非例外IPv4形式の試験値を実行時に構成したことを、値そのものを転記せず説明している。何を検証したかは維持され、本案件のrequirement・implement・両レビュー記録・対象コードを検索して、禁止IPリテラルが残っていないことを確認した。
- redactionは表示側だけである。上記end-to-endテストでは、journalから除外された非信頼値がバンドルの`summary.json`とrun reportには従来どおり保持されていた。`log_collection_errors_to_journal()`への入力も呼出し前後で不変であり、生成側の5変更は既存リテラルを同値の定数へ分けただけである。
- warning severityの是正は構成と整合する。新要約の全行は先頭が`<4>`で、systemdの既定`SyslogLevelPrefix=yes`によりpriority 4となる。Alloy側のseverity 4から`warning`への分類、およびGrafanaダッシュボードの既定`[warning, error]`フィルタと一致する。unit全体の既定levelや既存`EXIT_INTERNAL_ERROR`行は変更していない。
- AC4〜AC6の非退行を維持している。空入力は0 bytesで、`main()`も既存の`has_errors`が真のときだけ要約を呼ぶ。journal呼出しをheartbeat後へ置いたため、要約失敗がheartbeatを失わせる順序でもない。終了コード算出、run report、bundle書出し、通知条件、named operation、保持処理には変更がない。
- AC8 / scope: 新しい外部呼出し、shell文字列、SSH、Ansible、読取語彙、副作用は追加されていない。実ホスト、Semaphore、Loki、Slackへの接続と、git add / commit / pushは実行していない。

### Verdict

**Approve**（blockingなし）
