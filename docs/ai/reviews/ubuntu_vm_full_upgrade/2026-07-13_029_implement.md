# ubuntu_vm_full_upgrade — quory QDevice unit名修正: corosync-qdevice → corosync-qnetd（implement）

- 日付: 2026-07-13
- 担当: implementer
- 発端: Phase C（quory）事後検証（`docs/ai/reviews/ubuntu_vm_full_upgrade/2026-07-12_027_test_result.md`
  quory §5/§6）。quory の QDevice は**サーバー側デーモン `corosync-qnetd`**
  （TCP 5403）であり、`corosync-qdevice` はクラスタノード側（pve1/pve2）の
  デーモンで quory には unit も package も存在しないことが実機で確定した。

## 実装概要

同根のバグ2件（+同根の表記1件）を修正した。いずれも unit/パターン名の
置換のみで、チェック方式（wait_for_active のリトライ設計、判定ロジック、
実行経路）は一切変えていない。

## 変更内容の要約と設計判断

- **チェック方式は不変**: `wait_for_active corosync-qnetd 3 5`（3回×5秒、
  chrony の後に実行する順序、タイムアウト予算 ~90s < TimeoutStartSec=120）は
  従来設計のまま。unit 名と表示ラベルのみ変更。
- **Slack本文の桁揃え**: `corosync-qnetd  :`（16桁パディング）で
  chrony/semaphore 行との整列を維持。
- **defaults の `'corosync'` パターンは残置**: 完全一致フラグメントで
  quory に `corosync` package が現れない限り無害（誤検知なし）。今回の
  依頼範囲は qdevice→qnetd の置換のみ。
- **配置作業は本修正に含まない**: 027 §6 の「script が実機 /usr/local/sbin に
  未配置」問題は Ansible 管理外の手動配置（script ヘッダの手順）であり、
  implementer は実ホストに触れない（core.md §17)。修正済み script の quory への
  配置と実機検証は tester / Yoshinobu の作業として残る。
