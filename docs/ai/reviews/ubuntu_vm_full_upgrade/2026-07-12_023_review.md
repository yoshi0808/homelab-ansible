## 結論

`must-fix` なし。review 021 の must-fix と suggestion はどちらも適切に対応されており、本変更は commit 可能と判断する。

- `apt-cache policy` はローカルの APT キャッシュを読む read-only 補助収集であり、Yoshinobu 判断で改訂された requirement 019 の範囲内である。パッケージ状態変更やネットワーク再取得は追加されていない。
- phased パッケージ名がある場合のみ1回のバッチ実行とし、各パッケージごとのコマンド起動を避けている。
- `phased_detail` は `name` / `installed` / `candidate` を保存し、レポート JSON と通知で旧→候補バージョンを表示するため、review 021 の要件欠落は解消している。
- NO_UPDATES の条件式は変更されておらず、`phased_detail` は `status_reason` の文言分岐にのみ使われる。Status 判定、important 分類、MAJOR 件数閾値に影響しない。

## パーサ確認

`LC_ALL=C apt-cache policy <pkg...>` のバッチ出力に対し、実装は次の点で妥当である。

- 列0から始まり `:` で終わる行だけをパッケージセクションの開始とするため、インデントされた Version table 行をヘッダと誤認しない。
- `pkg:arch:` 形式でも末尾のセクション区切り `:` だけを除くため、`phased_names` の `pkg:arch` と一致する。
- `Installed:` / `Candidate:` をセクション内で個別に抽出し、`(none)` を空値に正規化している。
- 防御的に値末尾の `(phased N%)` も除いている。
- 解決できない名前や値欠落時はエントリ自体を落とさず空値とし、通知で `?` として明示する。phasing 件数の整合性を壊さない。
