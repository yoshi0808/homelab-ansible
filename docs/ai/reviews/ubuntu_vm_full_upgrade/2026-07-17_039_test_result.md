## 結論

**PASS（非阻害の観測事項 1 件あり）。**

- monnie の実データで Prometheus `3.12.0 → 3.13.1` を検出し、`update_available`、
  rc `0/0`、HTTP status `200/200` を report JSON に保存した。
- 無効 latest URL では `state=failed`, latest rc `-1` となる一方、playbook は
  `failed=0` で完走し、apt 基礎 Status は変化しなかった。
- 一時 hold は通知/reportへ 1 件として現れ、unhold 後は空へ戻った。最終
  `apt-mark showhold` も空で、原状復帰済み。
- `dry_run=false --check` では非 apt GET が skip され、破壊的 apply も skip された。
- 既存の候補件数、phasing、package detail、Status、`#patches` routing に回帰なし。
- 通常 APPLY（`dry_run=false` の非 check 実行）は行っていない。

観測事項: 初回 `dry_run=true` は更新された
`/usr/local/sbin/ubuntu-full-upgrade-simulate.sh` の copy task が `changed` になった。
package install/update、service操作、rebootは無いが、厳密には HTTP GET と apt simulation
だけの「完全 read-only」ではない。以後の実行では同 task は `ok` だった。また既存設計どおり
`apt-get update` は package index cache を更新する。この点は今回の機能回帰を阻害しないが、
tester-gate の説明では semi-safe な状態更新として扱うのが正確である。
