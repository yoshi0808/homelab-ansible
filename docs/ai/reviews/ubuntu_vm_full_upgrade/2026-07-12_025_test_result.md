## T-3: report JSON 突合

実行した主な機械確認:

```bash
jq -e 'all(.phased_detail[];
  (keys|sort)==["candidate","installed","name"])' <report>

jq -e 'all(.inst_detail[]; (keys|sort)==["name","new","old"])
  and all(.remv_detail[]; (keys|sort)==["name","version"])' <report>

jq -e '([.inst_detail[].name]|sort)==(.inst|sort)
  and ([.remv_detail[].name]|sort)==(.remv|sort)' <report>
```

結果:

| node | install | remove | phased | Status |
| --- | ---: | ---: | ---: | --- |
| ansy | 0 | 0 | 2 | `NO_UPDATES` |
| authy | 30 | 0 | 2 | `UPGRADE_READY` |
| monnie | 23 | 0 | 2 | `REVIEW_REQUIRED` |
| quory | 39 | 0 | 2 | `REVIEW_REQUIRED` |

- `phased_detail`: 全entryが `name` / `installed` / `candidate` を持つ
- `inst_detail`: 従来どおり `name` / `old` / `new`
- `remv_detail`: 当日は空。schemaは実装上、従来どおり
  `name` / `version`
- `inst_detail.name` と `inst`、`remv_detail.name` と `remv` は全4reportで一致
- 第1弾report `ansy_20260712T111841.json` とのtop-level key比較で、
  欠落した従来fieldはゼロ、追加は `phased_detail` のみ
- 通知本文の件数式はreportと同じsimulationオブジェクトの
  `inst` / `remv` / `phased_detail` の length を直接使うため、
  上表の件数と一致

## T-4: monnie 件数・version整合

実行コマンド（read-only）:

```bash
ssh -F /dev/null -i ~/.ssh/id_ann ann@monnie.internal \
  'LC_ALL=C apt list --upgradable 2>/dev/null'

ssh -F /dev/null -i ~/.ssh/id_ann ann@monnie.internal \
  'LC_ALL=C apt-cache policy \
   python3-software-properties software-properties-common'
```

名前集合と old/candidate version は `comm` / `diff` で機械突合し、
どちらも差分出力は空だった。

- `apt list --upgradable`: 25件
- `inst_detail` の upgrade分（`old` あり）: 23件
- `inst_detail` の新規install分（`old` なし）: 0件
- `phased_detail`: 2件
- `23 + 2 = 25`、名前集合も一致
- JSONの23 upgradeと2 phasedの全25件で installed/candidate が
  `apt list` の old/new と一致

phasing保留の裏取り:

```text
python3-software-properties:
  Installed: 0.120
  Candidate: 0.120.1
  0.120.1 500 (phased 10%)

software-properties-common:
  Installed: 0.120
  Candidate: 0.120.1
  0.120.1 500 (phased 10%)
```

2件とも JSON の `installed=0.120` / `candidate=0.120.1` と一致し、
monnie の apt で deferred検出と policyパースが機能した。
