# ubuntu_vm_full_upgrade — ansy/quory の Ansible 管理方式を host_vars へ反映

対象: `docs/ai/reviews/ubuntu_vm_full_upgrade/2026-07-11_009_test_result.md`(A-4)

tester が Phase A で確定した実地値(`ansy`/`quory` とも `/usr/bin/ansible` は
`ansible-core` パッケージが dpkg 所有 = apt 管理)を反映した。

## 変更内容

- `inventories/homelab/host_vars/ansy.yml`(新規): 既存の host_vars ディレクトリに
  ansy 用のファイルがまだ存在しなかったため新規作成
- `inventories/homelab/host_vars/quory.yml`(更新): 既存の
  `ansible_connection`定義に続けて追記

両ファイルに以下を設定した(変数名・値は test_result.md A-4 が提示した
提案値と一致):

```yaml
ubuntu_vm_full_upgrade_ansible_managed_by: apt
```

これにより `roles/ubuntu_vm_full_upgrade/tasks/classify.yml` の
`managed_by_note`ロジック(2026-07-11_004実装で追加)が「apt管理: 判定対象」を
表示するようになり、月次dry-run通知・レポートの「管理方式未確認」表示が
解消される。authy/monnieはこの変数を参照しない(`ubuntu_vm_full_upgrade_products`で
`managed_by_note: true`が付いているのはansy/quoryのAnsible関連product
エントリのみ)ため変更していない。

## 検証(ローカル、実ホスト非依存)

実ホストへの接続・`ansible-playbook`の実実行・ssh直接実行・git commit/pushは
行っていない(core.md §17)。

```
$ ansible-playbook playbooks/ubuntu_vm_full_upgrade.yml --syntax-check
$ python3 -c "import yaml; yaml.safe_load(open('inventories/homelab/host_vars/ansy.yml')); yaml.safe_load(open('inventories/homelab/host_vars/quory.yml'))"
$ bash scripts/check-tester-gate.sh
[tester-gate-lint] OK (33 playbooks)
$ git diff --check
```

`ansible-inventory`(read-onlyのローカルinventory照会。実ホストへは接続しない)で
両ホストの変数解決結果を確認した。

```
$ ansible-inventory -i inventories/homelab/hosts.yml --host ansy | grep ubuntu_vm_full_upgrade_ansible_managed_by
"ubuntu_vm_full_upgrade_ansible_managed_by": "apt"

$ ansible-inventory -i inventories/homelab/hosts.yml --host quory | grep ubuntu_vm_full_upgrade_ansible_managed_by
"ubuntu_vm_full_upgrade_ansible_managed_by": "apt"
```

いずれも期待通り`apt`が解決された。
