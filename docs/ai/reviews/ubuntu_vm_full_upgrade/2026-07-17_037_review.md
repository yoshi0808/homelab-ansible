## Findings

### must-fix: 数値regexを通過する非SemVer値がfail-quietにならない

- `roles/ubuntu_vm_full_upgrade/tasks/evaluate_nonapt_product.yml:35-39`
- `roles/ubuntu_vm_full_upgrade/tasks/evaluate_nonapt_product.yml:48-54`

比較可能判定の`^[0-9]+(?:[.][0-9]+)+$`は、`1.2`、`1.2.3` + `.4`（連結した4要素版）、先頭ゼロを持つ
`01.2.3`なども許可する。しかし後段は`version_type='semver'`を使用しており、これらの
少なくとも`1.2`はAnsibleのSemVer parserに拒否される。reviewerがlocalhostで
`'1.2' is version('1.3', '<', version_type='semver')`を実行したところ、
`Version comparison failed: invalid semantic version '1.2'`でtask失敗を再現した。

したがってendpointがdotted numericだがSemVerとして不正なversionを返すと、期待する
`state: failed`へ落ちずplaybookが中断する。これは「取得失敗・解析不能・比較不能は
Status/reasonを変えずfail-quiet」というrequirementに反する。

比較ガードをSemVer parserが確実に受理するstable形式（例: 先頭ゼロを制限した3要素）へ
揃え、ガード外の値が必ず`failed` resultとして記録されるよう修正が必要である。修正後は
少なくとも`1.2`、`1.2.3` + `.4`（連結した4要素版）、`01.2.3`を比較不能mockへ追加し、taskが失敗せず
Status/reason非関与となることを確認すること。

## 重点確認結果

### A. 034 must-fix修正

`docs/ai/prompts/autonomous_recovery_policy.md:247`は現在の実装を正確に記述している。

- `cert_renew.yml`はTTLなしglobal pause後にdeployする。
- resumeは正常経路の後続taskだけで、`always` / `rescue`にはない。
- deploy失敗時はglobal pauseが残留する。
- 全targetの再開には人間による`homelab-monitoring-resume`が必要である。

よって034のmust-fixは解消済み。

### B. 非aptチェック

- aptの従来Status/reason式は内容を変えず`ubuntu_vm_full_upgrade_apt_status` /
  `_apt_status_reason`へ分離されている。MAJOR、important、remove後継、apt失敗BLOCKEDの
  判定順と条件に変更はない。
- confirmed `update_available`がある場合だけ、apt `NO_UPDATES` / `UPGRADE_READY`を
  `REVIEW_REQUIRED`へ昇格する。`BLOCKED` / `MAJOR_UPGRADE_DETECTED` /
  `REVIEW_REQUIRED`を降格しない。
- `failed` / 比較不能resultは`ubuntu_vm_full_upgrade_nonapt_updates`へ選択されず、
  Status/reasonへ影響しない構造である。ただし上記findingのparser例外経路は未防御。
- collectorはcurrent/latestともHTTP GET、`changed_when: false`、`failed_when: false`。
  response評価は別task fileに分離され、registry loopは`dry_run | bool`でガードされる。
- node通知は更新あり・最新・失敗の3形式を持ち、report JSONへ`nonapt`を追加する。
  既存apt件数、phasing、package detail、product impact表示は保持される。
- 033由来のhold / `hold_collection_rc` reportとhold非空時だけの通知行も残り、036の
  nonapt行と共存する。classifyはholdを参照しない。
- monnie/prometheus registry、policy v1.5、playbook headerは、dry-run限定・read-only・
  自動更新なし・失敗時非関与という実装境界と一致する。
