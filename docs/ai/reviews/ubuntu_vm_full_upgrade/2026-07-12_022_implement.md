## 変更内容の要約と設計判断

### 1. apt-cache policy 収集（改訂制約の範囲内）

- 019 改訂制約どおり **read-only のローカルキャッシュ読取のみ**:
  `apt-cache policy` はネットワーク再取得もパッケージ状態変更もしない。
  `apt-get update` 等の再実行は追加していない。deferred セクションが
  存在しない（phased 0件の）通常月は実行自体をスキップする。
- shell の責務は収集 + JSON 整形のみを維持（core.md §7）: パースは
  Installed/Candidate 行の値抽出と `(none)` → 空文字の置換だけで、
  判定・分類は一切しない。
- 実フォーマットは ansy 上の実出力（`LC_ALL=C apt-cache policy
  python3-software-properties software-properties-common`、read-only）で
  確認してからパーサを書いた: セクションヘッダは列0の `<pkg>:`、
  Installed/Candidate 行はクリーンな値（`(phased N%)` 注記は Version table
  側のみ）、未解決パッケージはセクション自体が出ない。防御として
  値行末尾の `(phased N%)` 剥がしも入れてある（他の apt バージョンで
  Candidate 行に付くケースへの保険）。
- **キー名を installed/candidate にした理由**: inst_detail の old/new と
  同じキー名にすると、通知テンプレートの種別判別（`'new' in d` で
  inst と判定）が壊れ、保留行が `(phasing保留)` マーカーなしの通常行として
  表示されてしまうため。apt-cache policy の用語をそのまま使い、
  自己記述的に区別できる形にした。
- 値が取れなかった場合（セクション欠落等）は `?` 表示に退化する
  （名前と保留の事実は必ず出る）。

### 2. NO_UPDATES 理由文言（判定は不変）

- Status 判定式は無変更。status_reason の NO_UPDATES 分岐のみ
  phased_detail の有無で文言を出し分ける。
- classify.yml ヘッダの「phased は判定入力にしない」コメントに、
  「唯一の例外は文言（判定ではない）」の断り書きを追記し、019 制約との
  整合を明文化した。

## 実行した確認コマンドと結果

実ホストへの接続・ssh直接実行・実ホスト向けansible実行・git commit/push は
行っていない（core.md §17）。`apt-cache policy` の実行はローカル(ansy)での
read-only 確認のみ。

1. **shell**: `bash -n` OK。Python ヒアドキュメントを sed で逐語抽出し、
   実フォーマットの fixture（実在セクション / `Installed: (none)` /
   `Candidate: 2.0 (phased 20%)` 注記付き / セクション欠落名）で実行 →
   installed/candidate とも期待どおり（注記剥がし・(none)→空文字・
   欠落→空文字を含む）。
2. **テンプレート/文言（core.md §17 例外の使い捨て localhost プレイブック、
   検証後削除済み）**: builder タスクと classify「Determine Status」の
   status/status_reason 式を実ファイルから yaml.safe_load で逐語抽出して実行。
   - 混在ケース（inst+remv+phased 2件、うち1件は値欠落）: 上記表示例どおり。
   - NO_UPDATES × phased あり → 「今回のfull-upgrade適用候補なし
     (phasing保留あり)」、phased なし → 「更新候補なし」。
     Status はいずれも NO_UPDATES（assert で機械検証、合格）。
3. **静的チェック**: `ansible-playbook playbooks/ubuntu_vm_full_upgrade.yml
   --syntax-check` OK / `bash scripts/check-tester-gate.sh` OK（33 playbooks）/
   `git diff --check` OK。
