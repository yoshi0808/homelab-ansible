## 検証方針

呼び出し元は2つあり、両方で解決することが受入条件。

1. **role呼び出し**: `playbooks/monitoring_healthcheck.yml`（`roles:` でrole解決、`playbook_dir` = `playbooks/`）
2. **path include呼び出し**: `playbooks/ubuntu_nightly.yml:453` の `include_tasks: "{{ playbook_dir }}/../roles/monitoring_healthcheck/tasks/check.yml"`（`playbook_dir` はincludeするplaybookの置き場所で決まる）

`ubuntu_nightly.yml` は本体を `--check` なしで実行できず（reboot を含む禁止事項）、かつ `Run monitoring healthcheck` を含むブロック自体が `when: not ansible_check_mode` でガードされているため、**`ubuntu_nightly.yml` を `--check` で実行すると対象タスクごとskipされ、「skipを成立と誤読する」罠に直接落ちる。** これを避けるため、`playbooks/` 直下（`playbook_dir` を一致させるため）に使い捨てplaybookを1本置き、`ubuntu_nightly.yml` と同じ形の `include_tasks: "{{ playbook_dir }}/../roles/monitoring_healthcheck/tasks/check.yml"` だけを実行した。中身:

```yaml
---
- name: Tester throwaway - mimic ubuntu_nightly path-include caller
  hosts: monnie
  gather_facts: true
  become: true
  tasks:
    - name: Run monitoring healthcheck (path include, mimics ubuntu_nightly caller)
      ansible.builtin.include_tasks: "{{ playbook_dir }}/../roles/monitoring_healthcheck/tasks/check.yml"
```

置き場所: `playbooks/_tester_tmp_healthcheck_src_pathcaller.yml`（検証後に削除済み。`git status` に痕跡なし、確認済み）。commitはしていない。

対象実装（`check.yml` 本体）は変更していない。

## 未検証のまま残った範囲

- **実際の `ubuntu_nightly.yml` 本体を通した end-to-end 実行**は行っていない（reboot を含むため`--check`なし実行が禁止、`--check`では対象ブロックごとskipされ検証にならないため）。今回の使い捨てplaybookは `include_tasks` の相対パス解決という**この変更が壊した/直した機構だけ**を同じ形で再現したものであり、`ubuntu_nightly.yml` の他の部分（recovery_mute設定、Slack通知、reboot、post-reboot wait_for等）との結合は確認していない。次にmonnieが実際にreboot-required判定を出す夜（Semaphore job）が最初のend-to-end確認の機会になる。
- `playbooks/monitoring_healthcheck.yml` 経由の本番実行（sandboxでなくmonnie本体への非`--check`実行）は行っていない（承認境界外）。role呼び出し側の「本当に成功で終わる」姿はTest A（sandbox）でのみ確認しており、rc/成功判定はsandboxでの代替確認である。
- `roles/recovery_push/tasks/drill_setup.yml`（diffのコメントが「同じ形」として言及している別ファイル）は今回のdiffに含まれておらず、確認対象外とした。
