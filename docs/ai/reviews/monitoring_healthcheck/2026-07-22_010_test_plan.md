# Test Plan: monitoring_healthcheck disk usage check

Date: 2026-07-22

Tester: tester (Codex)

## Target

- `roles/monitoring_healthcheck/files/monitoring-healthcheck.sh`
- `roles/monitoring_healthcheck/tasks/check.yml`
- Read-only confirmation only: `playbooks/monitoring_healthcheck.yml`

`playbooks/monitoring_healthcheck.yml` is concurrently owned by the techlead2 team and must not be edited.

## Safety classification

- The playbook header declares `# tester-gate: safe-readonly`.
- The role performs read-only health observations, while its normal playbook path also performs an idempotent script copy, local report write, optional Slack notification, and critical-result failure.
- The caller suppresses the notification include when `skip_notifications=true`; `common_slack` also guards notification sending with `skip_notifications` (and retains a legacy `tester_mode` guard). The current marker reason and execution path are aligned for notification suppression.
- No patch, restart, reboot, migration, firewall, inventory, or other destructive operation is in scope.
- The requested behavior can be verified without an inventory-host run. Therefore no real-host playbook execution is planned. This avoids remote script placement, local runtime-report creation, notification risk, and environment-dependent failure while the playbook is concurrently owned elsewhere.

## Verification boundary

### Static verification

1. Run `bash -n` on the collection script.
2. Run `git diff --check` for the two role implementation files.
3. Run Ansible syntax-check for `playbooks/monitoring_healthcheck.yml` using temporary Ansible directories. This is read-only parsing; the playbook will not be edited or normally executed.
4. Run `scripts/check-tester-gate.sh` and confirm the marker remains valid.
5. Inspect the current diff for shell/Ansible responsibility separation and unchanged existing service, port, memory, notification, report-save, and fail paths.

### Local shell fixture verification

Run the real `monitoring-healthcheck.sh` with `systemctl`, `ss`, `free`, and `df` replaced by local exported Bash fixture functions. Validate JSON with `jq` for:

- Use%=79, 80, 89, and 90.
- Reserved-block semantics fixture where `used_bytes / total_bytes` differs from the supplied `df` Use%; `disk.used_percent` must preserve the Use% field.
- `df` command failure.
- malformed Use% without `%`.
- failure cases must produce `collection_ok=false` and zero-valued disk fields.

The harness writes only below `/tmp` and does not access inventory hosts.

### Localhost source-task classification verification

Use a temporary localhost playbook that statically imports the actual `roles/monitoring_healthcheck/tasks/check.yml`, starts at `Classify criticals and warnings`, supplies complete fixture data as extra vars, and asserts the resulting report status and disk warning/critical counts for:

- 79%: OK, no disk warning or critical.
- 80%: WARNING, one disk warning.
- 89%: WARNING, one disk warning.
- 90%: CRITICAL, one disk critical and no disk warning.
- collection failure with zero fallback: CRITICAL, one disk collection critical and no disk warning.

Starting at the classification task skips the source file's copy and command tasks; only `set_fact`, report construction, debug, and assertions run on localhost.

- No APPLY, SSH, service change, remote file copy, Slack notification, runtime report creation, commit, or push.
- No edit to `playbooks/monitoring_healthcheck.yml` or unrelated concurrent changes.
