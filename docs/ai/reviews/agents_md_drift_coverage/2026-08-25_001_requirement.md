# Requirement: Codex の道具一覧(AGENTS.md)をドリフト検査の対象にする

作成: 2026-08-25 / Coordinator

## 1. 問題定義

**quory の Codex が読む道具一覧が、本番で repo と食い違っても誰も気づかない。**

`roles/recovery_exec/templates/AGENTS.md.j2` は `recovery_exec_workspace/AGENTS.md` として quory へ配られ、**Codex はこれを「呼んでよいコマンドの一覧」として読む。** 本文は「**Call only the commands listed below.** Anything not listed is outside this agent's remit」と指示している。

**この一覧が誤っていれば、Codex の所見が誤り、それを読む人が誤る。**(Yoshinobu、2026-08-25:「私が誤った codex の情報を元にミスリードするじゃないか」)

**そして検知の経路が無い。**

- **ドリフト検査の対象は `copy` 配備物に限る**(`roles/deployment_drift_check/defaults/main.yml` 冒頭)。`template` 配備物は「期待値を得るのに描画が要るため Tier 2 として後続で扱う」とされ、**Tier 2 はまだ無い。**
- `deployed-hash` の固定リストにも入っていない。
- 結果として、**配備が失敗して古いまま残っても、誰かが quory 上で書き換えても、観測されない。**

## 2. いま食い違ってはいない(2026-08-25 実測)

**本案件は現に壊れているものを直すのではなく、壊れたときに気づけるようにするものである。**

| 測ったこと | 結果 |
|---|---|
| class G の dispatch の arm 12本が AGENTS.md に載っているか | **全て載っている** |
| class P の dispatch の arm 27本が載っているか | **全て載っている** |
| 配布先 | **quory 1台のみ**(`recovery_exec_setup.yml` は `hosts: control_nodes`) |

**Codex は呼び出す側である。** quory に居て、authy / monnie(class G)や pve(class P)へ forced command で出ていく。**したがって全クラスのコマンドが1つの AGENTS.md に載っているのは正しい姿であり、ドリフトではない。**

## 3. ゴール

**AGENTS.md を Tier 1 のドリフト検査の対象にする。配備される内容は1バイトも変えない。**

## 4. 非ゴール

- **AGENTS.md の内容を変えること。** コマンドの説明も一覧も触らない。**変えてよいのは配り方だけである。**
- **Tier 2(描画して比較する検査)を作ること。** 本案件は対象を1つ Tier 1 へ移すだけで、新しい検査層は作らない。
- **`deployed-hash` の固定リストへ足すこと。** dispatch スクリプトの再変更と再配備をもう1回要するのに対し、得られるのは「人がその場で確かめられる」だけである。**日次のドリフト検査が自動で見るなら、そちらで足りる。** 必要になったら別途。
- **他の `template` 配備物(sudoers、unit本体、authorized_keys)を移すこと。** それらは実際に Jinja 変数を持ち、静的化できない。

## 5. 要件

### P0

**P0-1. 唯一の Jinja 構文(8〜14行目の `{# #}` コメント)を取り除き、`roles/recovery_exec/files/AGENTS.md` として静的ファイルにする。**

当該コメントは repo の読み手だけに見せ、**配備先へ出力しないための作り**である(コメント自身がそう明記している)。**素朴に `copy` へ変えると、この内部メモが Codex の読むファイルへ流れ込む。**

**移し先は2箇所に分ける**(Yoshinobu 判断、2026-08-25)。

- **配備タスクの直上**(`roles/recovery_exec/tasks/main.yml`)へ**1行**。「execpolicy が強制すると書き戻さないこと」という趣旨と、Incident への参照。
- **詳細と経緯は参照先の Incident**(`docs/ai/memory/incidents/2026-07-31_codex-execpolicy-allowlist-not-enforcing.md`)へ寄せる。**経緯の正本はそちらである。**

**P0-2. 配備タスクを `ansible.builtin.template` から `ansible.builtin.copy` へ変える。** `owner` / `group` / `mode` / `become` / `when` は現行のまま。

**P0-3. `roles/deployment_drift_check/defaults/main.yml` のカタログへ追加する。** 既存 entry と同じ形(`hosts` / `src` / `dest` / `playbook`)。

### P1

**P1-1. `playbooks/README.md` に変更が要るか確認する。** playbook は増えないため不要の見込みだが、確認そのものを成果物に含める。

## 6. 受入条件

**AC1 — 配備される内容が1バイトも変わらない(本案件の核心)**
> **Given** 変更前の `AGENTS.md.j2` を Ansible 自身の設定で描画した結果と、
> **When** 新しい `roles/recovery_exec/files/AGENTS.md` を比較したとき、
> **Then** **`sha256sum` が一致する。**
> **目視やdiffの行数で判断しない** — `{# #}` を取り除いた跡に空行が残るかどうかは Jinja の `trim_blocks` / `lstrip_blocks` の設定次第であり、**1バイト違えば Codex が読むファイルが変わったことになる。**

**AC2 — Jinja が残っていない**
> **Given** 新しい静的ファイル、
> **Then** `{{` / `{%` / `{#` がいずれも **0件**である。`copy` 配備の適格条件を満たす。

**AC3 — 警告が失われていない**
> **Given** 変更後の repo、
> **Then** 「execpolicy が強制すると書き戻さない」という趣旨が、**配備タスクの直上**と **Incident 本文**の両方から辿れる。**どちらか一方だけになっていない。**

**AC4 — ドリフト検査が対象として認識する**
> **Given** quory へ配備した後、
> **When** `deployment_drift_check` を実行したとき、
> **Then** AGENTS.md がドリフト無しとして扱われる。終了コードは現行と変わらない。

**AC5 — 意図的に食い違わせたら検知される**
> **Given** カタログの `src` が指す repo 側ファイルと配備物が食い違う状態、
> **When** 検査を実行したとき、
> **Then** ドリフトとして報告される。**この検証は decoy で行い、quory 上の実ファイルを書き換えない。**
> **これを確かめないと「対象に足した」ことが「検知される」ことの証拠にならない。**

## 7. オープンクエスチョン

- **`{# #}` を取り除いた跡の空行の扱いが、描画結果と一致するか。** Ansible の Jinja 設定(`trim_blocks` 等)に依存するため、**AC1 は実際に描画して比較する以外に確かめる方法が無い。**
- **配備が要る。** `recovery_exec` を走らせる playbook は `hosts: control_nodes`(quory)。押下が1回。
