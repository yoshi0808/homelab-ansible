## D3の詳細(退行)

`main.yml` の `_notify_status` の条件が、元は「`abort_type != 'none'` または `_apply_failed` → `error`、そうでなく post-hc != OK → `warning`」だったのを、「`aborted` または post-hc != OK → `warning`、そうでなく `abort_type`/`_apply_failed` → `error`」へ並べ替えている。観測: 適用失敗(`F_FAILED=true`)かつpost-healthcheck `CRITICAL` の入力で、件名は`[FAILED]`、通知statusは`warning`(HEADの定義なら`error`)。適用が失敗してpost-healthcheckも異常な週は実際に起こりうる(applyが失敗したnodeの`always`はpost-healthcheckを走らせる)。`aborted`を`warning`にするためには、先頭に`aborted`を置くだけでよい。
