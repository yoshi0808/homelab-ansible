# requirement: ansy内のCodexの役を `codex exec` へ移す

状態: 合意済み(2026-10-12、Yoshinobu)

## 背景

2026-10-10、ansyの `new-session.sh --reset` でpane 1のImplementerが起動しなかった。agmsgがCodexのsandbox内で取ったactasロックの持ち主をPID 1と記録し、永久に「生存」と判定し続けたためである。最新版のagmsgでも直っていない。経緯と棚卸しは `docs/ai/reviews/agmsg_replacement/` にある。

同じ案件で、計画Reviewerを3回(新規1回・`resume` 2回)、Implementerを1回、`codex exec` で動かし、どちらも実用になることを確かめた(`agmsg_replacement/2026-10-10_001_inventory.md`「試行」節、`_005_trial_implementer.md`)。

Yoshinobuの判断(2026-10-12):

- ansy内の経路(CoordinatorとImplementer・計画Reviewer・Auditor)は `codex exec` / `resume` へ移す。
- ansyとquoryの経路(team `homelab-ops`、CoordinatorとOperator)はagmsgのまま残す。Slack通知への置き換えは、すり合わせの会話とOperatorの回答への自動の気づきを失うため採らない。
- Implementerへ指示するのはCoordinatorだけである。Yoshinobuは直接指示しない。

## 求めること

### R1. 役ごとの呼び出しを1つの入口にする

`scripts/codex-role.sh`(新規)を、Codexの役を起動する唯一の入口とする。

- 役の名前(`implementer` / `plan-reviewer` / `auditor`)を受け取り、その役のモデル・effort・sandboxを付けて `codex exec` を呼ぶ。
- **実行するCodexのバイナリを1箇所で明示し、PATHの解決に任せない。** 今のansyでは `codex` がagmsgのshim(`~/.agents/bin/codex`)に解決され、shimはagmsgの `run` 配下へ書こうとする。さらに実体が2つある — standaloneの `~/.local/bin/codex`(0.154.0、2026-10-10の試行はこれで動いた)と、`roles/codex_update_check` が週次で更新するnpm globalの `/usr/bin/codex`(0.162.0)。更新の仕組みに乗っている後者を使う。解決したパスが `~/.agents/` 配下なら、`codex` を呼ぶ前に非0で止める。
- **依頼文の先頭に、役の起動指示を必ず付ける。** 「あなたはこのリポジトリの<役>です。まず `docs/ai/core.md` と<役のRole文書>を読む」という形で、呼び出し側が書き忘れても役が渡るようにする。役の名前とRole文書の対応は明示して持つ: `implementer` → `docs/ai/roles/implementer.md`、`plan-reviewer` → `docs/ai/roles/reviewer.md`(計画Reviewerは独立したRole文書を持たない)、`auditor` → `docs/ai/roles/auditor.md`。
- **session idを、それを作った役に結びつける。** 新規起動のたびに、session idと役の対応を記録する(置き場はrepo外、Coordinatorのホームの下)。継続のときは、渡されたsession idの記録上の役と、指定された役が一致しなければ `codex` を呼ぶ前に止める。Implementerのセッションを計画Reviewerとして続ける、といった取り違えを起こせなくする(計画ReviewerとImplementerを別identityにする要件、`coordinator.md` の役の表)。
- **Auditorは入力を絞る。** Auditorへ渡せるのは、対象案件のフォルダのパスと、読み始める場所の指定だけとする(`docs/ai/roles/auditor.md` の依頼文の制限)。自由な依頼文は受け取らず、スクリプトがその2つから依頼文を組み立てる。Auditorの継続(`resume`)は受け付けない。
- 計画ReviewerとAuditorは読み取り専用のsandbox、Implementerは書き込み可のsandboxで動かす。
- 依頼文はファイルまたは標準入力で受け取る(Auditorを除く。下記)。最終メッセージを指定のファイルへ書き出す。session idを呼び出し側が取り出せる形で出す。
- 継続(`resume`)のときも、新規と同じモデル・effort・sandboxを必ず付ける。`codex exec resume` は初回の指定を引き継がず、`-s` も持たない(実測。`agmsg_replacement/2026-10-10_001_inventory.md`)。
- 未知の役名、依頼文が空、継続の指定に対象のsession idが無い、記録上の役と指定の役が違う、Auditorへの自由な依頼文や継続、といった入力は、`codex` を呼ぶ前に非0で止める。
- 承認の画面は無い前提で動かす(approvalは `never`)。

### R2. 役ごとの値の食い違いを機械で止める

R1のスクリプトが持つモデル・effortの値と、`docs/ai/roles/coordinator.md` のモデル・effort配分表が食い違ったら、`scripts/check-doc-consistency.py` が失敗する。既存のcheck2(`.claude/agents/*.md` と同表の照合)と同じ扱いにする。

### R3. ansy内のagmsg依存を外す(repo内)

- `.codex/rules/default.rules` で、`git add` / `git commit` / `git push` を禁止(`forbidden`)にする。**今は3つとも `allow` になっている**(ADR-013の時期にCodexがCoordinatorだった名残)。`git add` はCoordinatorだけ(`docs/ai/core.md`)、commit / pushはsubagentに不可(EXEC-030)という規範を、Implementerの能力として閉じる。
- 同じファイルから、Implementer向けのagmsg(`send.sh`、`remote.sh`)とtmuxの許可を外す。
- `scripts/session-context.py` から、agmsgでspawnした役(`AGMSG_SPAWNED`)を扱う分岐を外す。

### R4. 規範・Contextを現在の決定に合わせる

- `docs/ai/adr/016-*.md`(新規): ADR-015のうち「Implementerはpane 1に常駐し、計画ReviewerとAuditorはagmsgでspawnする」を置き換える決定を記録する。ADR-015は書き換えない(ADR-015「過去のADRと案件記録は当時の判断として書き換えない」)。
- `docs/ai/roles/coordinator.md`: 役の表、値の出どころ、モデル・effort配分表、Agent定義との関係を `codex exec` 前提へ直す。
- `docs/ai/status.md`: agmsgの行(`--reset` 後にImplementerが起動しない件)を、この案件の完了で消す。観測待ちが残るならその形に書き換える。
- `docs/ai/context/operations/agent-messaging.md`: ansy内(spawn / despawn、Codexのmonitor配送、pane 1、`new-session.sh` のImplementer起動)の記述を外し、homelab-opsの経路の記述を残す。`new-session.sh` の要件の正本はこの文書なので、pane 0だけを起動する形へ直す。

### R5. repo外の変更(Coordinatorが実施する)

- ansyの `new-session.sh` から、Implementerのspawnと `/agmsg actas coordinator` の初期入力を外す。
- agmsgのteam `homelab` の登録をすべて外す(現在は `coordinator`(claude-code)と `implementer`(codex))。team `homelab` はansy内の経路のためのもので、使わなくなる。`coordinator` の席がhomelab-opsの1つになり、セッション開始のhookが受信の監視を自分で始められるようにする。
- `~/.codex/config.toml` の `[sandbox_workspace_write].writable_roots` からagmsgのディレクトリ(`run` / `db` / `teams`)を外す。`codex exec` で動くImplementerがhomelab-opsへ送れないようにする(能力として閉じる)。
- ansyの `.codex/hooks.json`(gitignored)と `~/.codex/hooks.json` のagmsgのhookを外す。`codex exec` のセッションでもhookが走るため。
- agmsgのcodex用shimをPATHから外し、このprojectのcodexの配送モードを止める(`delivery.sh set off codex <project>`)。

## 受入条件

- AC1. `scripts/codex-role.sh` で、3つの役それぞれが指定どおりのモデル・effort・sandboxで起動する(`codex exec` の出力の `model:` / `sandbox:` 行で確かめる)。継続を許すImplementerと計画Reviewerは、継続の呼び出しでも同じ値で動く。
- AC1b. 3つの役それぞれについて、スクリプトが組み立てた起動指示が、対応する正しいRole文書のパスを指している。
- AC2. 不正な入力(未知の役、空の依頼文、継続先のsession idが無い)で、`codex` を呼ばずに非0で終わる。
- AC3. スクリプトの値と `coordinator.md` の表を、3つの役それぞれについてモデルとeffortを1つずつわざと食い違わせると、そのたびに `check-doc-consistency.py` が失敗する。そろえると通る。
- AC3b. 変更後、次がrepoの現行の規範・Context・スクリプトに残っていない(`git grep` で確かめる。`docs/ai/reviews/`、`docs/ai/memory/`、ADR-015以前のADR、Policyの変更履歴の表は対象外): `.codex/rules/default.rules` のagmsg・tmuxの許可、`session-context.py` の `AGMSG_SPAWNED`、ansy内の `spawn.sh` / `despawn.sh` / pane 1 / Codexのmonitor配送を現行として書いた記述。
- AC3c. ADR-016が、ADR-015のどの決定を置き換えるかを明記している。ADR-015の本文は変わっていない。
- AC4. Implementerとして起動したCodexが、`git add` / `git commit` / `git push` を実行できない。検証は、このrepoではなく使い捨てのgitリポジトリ(`/tmp` 配下。pushはローカルのbareリポジトリ宛て)で行い、同じ `.codex/rules/default.rules` を効かせる。
- AC4b. 継続の呼び出しで、記録上の役と違う役を指定すると、`codex` を呼ばずに非0で終わる。Auditorに自由な依頼文や継続を渡しても同様。
- AC4c. スクリプトが呼ぶのが `/usr/bin/codex` であり、`~/.agents/` 配下のshimを経由しない。
- AC5. Implementerへの差し戻しを `resume` で続けたとき、前回の作業ツリーの変更を前提に続きを行える。
- AC6. repo外の変更の後(AC1・AC5をこの状態で再実行して通ることを含む)、ansyで `new-session.sh --reset` を実行すると、pane 0だけが起動し、`actas` を打たずにhomelab-opsの受信の監視が始まる。
- AC7. R5の後、Implementerとして起動したCodexがagmsgの `send.sh` でメッセージを送れない。

## 範囲外

- homelab-ops(quoryとの経路)の変更。
- 差分ReviewerとTester(Claude Code subagent)の起動方式。
- agmsgのアンインストール。homelab-opsで使い続ける。
