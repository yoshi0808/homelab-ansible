日付: 2026-08-03 (JST)

## 1. なぜ改訂するか

2つの決定が、このPolicyが前提にしている構造を変えた。

| 決定 | 影響 |
|---|---|
| **`incident_sync` の退役**(2026-08-03、R14b) | quory → ansy の**転送段が消えた**。ansy 側にミラーが無くなる |
| **月次の `claude -p` を2本とも廃止**(2026-08-03) | **評価段の主体が、無人セッションから人 + 対話セッションへ移る。** タイマーが出すのは「きっかけ」だけになる |

**放置すると、このPolicyは存在しない段を定義したまま正本を名乗る。**

## 2. パイプラインの変化

```
現行  捕捉(quory) → 一次調査(quory) → 転送(quory→ansy) → 評価(ansy・無人LLM)
改訂  捕捉(quory) → 一次調査(quory) → 見直し(人 + 対話セッション)
```

**LLM を使う段は一次調査だけになる。** 一次調査は Codex(`codex-investigate-wrapper`、`incident-inspect` として quory 上で実行)であり、**改訂後この環境に無人の Claude Code セッションは1つも残らない。**

### 3.2 新設する(**最も重要な変更**)

| ID | 条項 |
|---|---|
| **IC-043**(新設) | **証拠は quory の1コピーしか存在しない。保持期間の満了が、そのまま証拠の喪失である。** 従来はansy側ミラーが第2のコピーであり、「保持期間内に転送が成立していること」が保全を担保していた(旧IC-015)。転送を退役させた以降、**担保するのは「保持期間内に人が見直すこと」だけである。** したがって月次のきっかけ通知は保全機構の一部であり、止めてはならない。**見直しの周期を保持期間より長くしない。** |

**この1点だけは、文書整理ではなく安全性の後退を伴う変更である。**

**2026-08-03、Yoshinobu が保持期間を 30日 → 90日 とすることで決着させた。** 提示した選択肢は「受け入れる」「保持期間を延ばす」「見直しの周期を上げる」の3つで、**保持期間側を延ばす**判断である。見直しは月次のままなので、**周期に対して約3倍の余裕**ができ、1回見落としても失われない。実装は `roles/incident_capture/defaults/main.yml` の `incident_capture_retention_days`。
