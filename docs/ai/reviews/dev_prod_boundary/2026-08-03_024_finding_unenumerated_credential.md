# finding: 数え落とした資格情報 — `ansy-to-proxmox`

日付: 2026-08-03 (JST)
発見: Phase 4 の受入検証(`..._023_test_result_phase4.md`、AC13 FAIL の根拠)
状態: **解消済み**

## 1. 何があったか

Phase 4 は「ansy から保護対象ホストへ届かなくする」ことを目的に、`~ann/.ssh/authorized_keys` から `ann@homelab-ansible` を削除した。削除は成功し、`ann` としての認証は4ホストすべてで成立しなくなった。

**それでも ansy から pve1 / pve2 へ root で入れた。**

```
$ ssh -i ~/.ssh/id_ansible -o IdentitiesOnly=yes root@pve1.internal 'id'
uid=0(root) gid=0(root) groups=0(root)
```

`~/.ssh/id_ansible`(コメント `ansy-to-proxmox`、2026-05-23 作成)は、requirement にも plan にも一度も登場しない鍵だった。forced command は付いておらず、**無制限の root シェル**が得られた。

## 2. なぜ見落としたか

requirement §4.1 はこう書いていた。

> 保護対象3ホストの `~ann/.ssh/authorized_keys` には既に2エントリある。……**鍵が分かれているため、本番に一切触れずに開発側だけを閉じられる。**

**数えたのは `ann` の `authorized_keys` だけである。`root` の側を一度も見ていない。**

つまり列挙の単位が「**ansy が置いた鍵**」になっていた。正しい単位は「**ansy から届く鍵**」である。この2つは、Ansible の接続 identity を `ann` に統一している環境では一致して見えるが、**人が手で作った鍵はその統一の外側にある。**

`id_ansible` が repo のどの inventory / group_vars からも参照されていなかったことは、発見を遅らせる方向に働いた — 「自動化の経路をすべて追えば網羅できる」という前提が成り立たなかった。**Yoshinobu が ansy を踏み台として使うために作った、人の利便のための鍵**だったためである(2026-08-03 本人確認)。

## 3. どう閉じたか

| 手順 | 実施 |
|---|---|
| ansy 側の秘密鍵 `id_ansible` / `.pub` を削除 | Coordinator(2026-08-03) |
| pve の `root` の `authorized_keys` から該当行を削除 | Yoshinobu(pve1 で実施) |
| 伝播の確認 | `/root/.ssh/authorized_keys` は `/etc/pve/priv/` 配下へのシンボリックリンクであり、**pmxcfs によりクラスタ全体で共有される**。pve1 で消せば pve2 からも消える。**1本の鍵で両ノードへ入れていたのも同じ理由**である |

**全鍵 × 全保護対象ホスト × (root / ann) の掃引を行い、到達ゼロを実測した。** 残る鍵は monnie 用の `id_ann`、dispatch 用3本、GitHub 用の計5本。

## 4. 手順上の誤り(Coordinator)

**秘密鍵を先に消し、公開鍵側の除去を後から依頼した。** その結果、除去が効いたことを実測する手段を自分で失った(dispatch のカタログに `root` の `authorized_keys` を読むチェックは無い)。伝播の確認は Yoshinobu の目視に依存することになった。

**閉じる作業では、検証手段を最後に手放す。** 今回は「穴を早く塞ぐ」を優先して、確認可能性を先に失った。順序を逆にしていれば、除去の前後で到達性を測れた。

## 5. 持ち帰るもの

1. **境界を閉じるとき数えるのは「自分が置いた鍵」ではなく「自分から届く鍵」である。** 列挙の起点を、自分の設定ファイルではなく相手側の受け口に置く。
2. **自動化の経路をすべて追っても網羅にならない。** 人が手で作った資格情報は、どの inventory にも現れない。
3. **能力の不在で境界を作る設計は、能力の列挙が完全であることに全面的に依存する。** 列挙が漏れれば、設計としては正しくても境界は成立しない。**そして漏れは「動いてしまう」という形でしか現れない** — 文書を読んでも見つからない。
4. **閉じる順序: 検証手段は最後に手放す。**
