## 実装内容

`journal-unit` の case ブロックを次のように変更した。

1. **arity 検査**: `[[ -n "$p1" && -n "$p2" && -z "$p3" ]] || deny_count` から `-z "$p3"` を外し、`[[ -n "$p1" && -n "$p2" ]] || deny_count` にした。`p1`/`p2` は引き続き必須、`p3` は任意。
2. **検証順序は変えていない**: `_is_valid_unit` → window の `case` → (新設)lines の検証、の順のまま。lines の検証は window の `case` の直後に追加した。
3. **lines の検証と既定値**:
   ```sh
   if [[ -z "$p3" ]]; then
     lines_value=300
   else
     [[ "$p3" =~ ^[0-9]{1,5}$ ]] && (( 10#$p3 >= 1 && 10#$p3 <= 10000 )) || deny_invalid lines
     lines_value=$((10#$p3))
   fi
   journalctl -u "$p1" --since "$since_value" -n "$lines_value" --no-pager
   ```
   `deny_invalid lines` は既存ヘルパーをそのまま再利用しており、`check="journal-unit"` の文脈で呼ぶと `denied: invalid lines for journal-unit` を出す(R2 の文言と一致)。
4. `10#$p3` で base-10 算術評価を強制した。理由: 正規表現 `^[0-9]{1,5}$` は `00300` のような先頭ゼロも通すが、bash の算術評価は先頭ゼロの数値を八進数として解釈するため(`10#` を付けないと `0300` → 8進で192 と誤読しうる)、値の意味を変えずに数値へ落とすために必要だった。

`read -r check p1 p2 p3 extra` の行自体は1文字も変更していない(R3)。4個目以降の operand(`extra` が非空)は、この行による既存の "too many parameters" 拒否がそのまま効く。
