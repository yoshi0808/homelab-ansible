## 1. 何を作るか

### 1.1 追加するチェック一覧(**D5: Yoshinobu 承認対象**)

**確定版の正本は `2026-08-03_008_phase3_check_catalog.md`。** 実機で enum とパスを確認して起こしたもので、Implementer はそちらから実装し、Reviewer は AC9 をそちらに対して検査する。以下は骨子のみ残す。

**すべて read。`pvesh create`/`set`/`delete`、`systemctl start`/`stop`、書込を行う語彙は1つも露出しない。**

#### A. quory class(新規 dispatch)— 障害バンドル参照(R14c)

| check | operand | 実行内容 |
|---|---|---|
| `bundle-list` | 無し | `reports/incidents/` 直下の `semaphore-<n>` を列挙 |
| `bundle-show <id> <file>` | `^semaphore-[0-9]{1,9}$` / F1 の4種 enum | 当該ファイルを `cat` |
| `investigation-list` | 無し | `_investigations/` の `<id>` を列挙 |
| `investigation-show <id> <ext>` | 同上 / `md`\|`json` | 当該ファイルを `cat` |
| ~~`bundle-grep <term>`~~ | — | **初期リリースから外す。** requirement R14c 自身が「operand設計が最も難しく、無理なら外して一覧+summaryで代替する」と許容している。任意文字列を operand に取る唯一のチェックになるため、必要性が実運用で確認できてから足す |

#### B. quory class — レポート参照(R13b / 必須①)

| check | operand | 実行内容 |
|---|---|---|
| `report-playbooks` | 無し | `recovery-reports-helper list-playbooks` |
| `report-list <playbook> [target]` | `^[a-zA-Z0-9_-]+$` ×2 | 同 `list-reports` |
| `report-show <playbook> [target] <file>` | 同上 + `^[a-zA-Z0-9_+-]+\.json$` | 同 `show-report` |

**これ1組で R13b(ラダー実行レポート)と必須①(配備物ハッシュ)の両方が読める** — ラダーは `recovery_investigations/<target>/`、ドリフトは `drift/latest.json` として、どちらも同じ `reports/` 配下にあるため。

#### C. quory class — 自ホストの状態(**提案。必須ではない**)

| check | operand | 実行内容 |
|---|---|---|
| `status` | 無し | 固定unit群の `systemctl status`(recovery-probe / recovery-io / homelab-incident-capture.timer / homelab-incident-investigate.timer / ansible-incident-sync 系) |
| `journal-unit <unit> <window>` | 固定unit enum / `30m`〜`24h` enum | `journalctl -u <unit> --since ... -n 300` |
| `failed` | 無し | `systemctl --failed` |
| `disk` / `memory` / `load` | 無し | 既存 generic dispatch と**同一語彙・同一実装** |
| `unit-cat <unit>` | 固定unit enum | `systemctl cat <unit>`(R12 が例示。配備された unit 本体の現物確認) |
| `semaphore-query <query>` | 固定query enum | `homelab-semaphore-query`(**Codex が既に持っている口**。R11「内容を同一とする」の直接の帰結) |

#### D. 既存 generic class(authy / monnie)/ pve class への追加(**提案**)

| check | operand | 実行内容 |
|---|---|---|
| `deployed-hash <name>` | class ごとの固定 name 表 | `sha256sum <対応する絶対パス>`。**パスは operand から取らず、name→パスの対応表を script 内に持つ**(traversal の余地が構造的に無い) |
| `unit-cat <unit>` | 固定unit enum | `systemctl cat <unit>` |

**`deployed-hash` の位置づけ**: 日次ドリフト検査(Phase 2)が期待値との突合まで済ませたものを B の `report-show` で読むのが**主**である。`deployed-hash` はその補助で、「いま目の前のファイルが本当にこの中身か」を調査中に即時確認するための口。日次レポートは最大24時間古い。

### 1.2 併せて直すもの(既存の口の欠陥。F4/F5)

| # | 対象 | 変更 | 理由 |
|---|---|---|---|
| G1 | `roles/recovery_exec/files/recovery-reports-helper` と `files/homelab-reports` の `FILE_RE` | `^[a-zA-Z0-9_-]+\.json$` → `^[a-zA-Z0-9_+-]+\.json$` | **`+` の1文字だけ足す。** `.` は足さない — 名前部に `.` を許すと `..` が入りうるため、traversal が構造的に不可能である性質を崩さない。この修正で JST タイムスタンプ名の全レポートが Codex からも読めるようになる(**Codex の調査能力が上がる。ゴール 2.4**) |
