# requirement: `journal-unit` に行数 operand を足す(D8)

日付: 2026-08-07 (JST)
Role: Coordinator
承認: Yoshinobu(2026-08-07、「3のカタログ改訂を進めてください」)
カタログ正本: `docs/ai/reviews/dev_prod_boundary/2026-08-03_008_phase3_check_catalog.md`

## 1. 問題定義

class Q の `journal-unit <unit> <window>` は `journalctl -u <unit> --since <window> -n 300 --no-pager` を発行し、**行数が 300 に固定されている**。`--since` を広げても返るのは窓内の末尾300行なので、**行数の多い unit では窓指定が実質的に効かない。**

実害が2回出ている。

| 日付 | 何に届かなかったか |
|---|---|
| 2026-08-06 | `recovery-io.service` が Slack 再接続を数秒おきに1行ずつ吐いており、24h を指定しても数分ぶんしか遡れなかった。いちばん欲しかった `_run_codex` の raw output に届かず、**代わりに人へ `journalctl` を打たせた**(`docs/ai/memory/incidents/2026-08-06_slack-token-leak-via-environ-dump.md` の「構造的な背景」表の1行目) |
| 2026-08-07 | `homelab-incident-investigate.service` は1分timerで3行/分を出す。一次調査の Slack 通知が落ちた理由は `post_artifact_actions` が stderr へ書くだけの設計で、**journal にしか残らない**。300行 ≒ 直近100分しか遡れず、**約10時間前の当該行に到達できなかった** |

**壊れているときほどログ量が増えるため、必要な場面でだけ効かなくなる**性質の穴である。

## 2. ゴール

- `journal-unit` で遡れる行数を、呼び出し側が指定できるようにする。
- **授権境界を広げない。** 新しい check・新しいコマンド語彙・新しい書込を1つも増やさない。

## 3. 非ゴール

- **`journal-ssh` は今回触らない。** 同じ穴を持つが、承認された文言は `journal-unit` である。カタログへ「次に問うこと」として1行だけ残す。
- **class P(pve1 / pve2)は対象外。** `sudoers-recovery-exec-pve-target.j2:81-86` が `journalctl -u <unit> --since * -n 300 --no-pager` を unit ごとのリテラル行として固定している。行数を可変にするには `-n *` へのワイルドカード拡大(sudo の fnmatch は空白をまたぐため実質的な緩和)か、値ごとに行を掛け算するかしかない。**授権境界を広げる変更**になり、かつ ansy から配備できない。
- **class G(authy / monnie)は対象外。** check の形が `journal-1h` / `journal-1d` のように窓ごとの別 check であり、`journal-unit <unit> <window>` という形を持たない。行数 operand が乗る場所が無い。
- 出力の後処理(grep・フィルタ)は足さない。任意文字列を operand に取る check を作らないという既存方針(カタログ §Q-A の `bundle-grep` 見送り)を崩さない。

## 4. ユーザーストーリー

Coordinator として、本番 quory の unit が壊れたときに、**バーストしているログの奥にある1行**へ dispatch のカタログだけで到達したい。到達できないと「このコマンドを打ってください」へ逃げることになり、2026-08-06 はそれが資格情報の流出につながった。

## 5. 要件

| # | 優先度 | 内容 |
|---|---|---|
| R1 | **P0** | `journal-unit <unit> <window> [lines]` の第3 operand を受け付ける。**省略時は現行どおり 300**(後方互換) |
| R2 | **P0** | `lines` は `^[0-9]{1,5}$` に一致し、かつ `1 <= lines <= 10000` であること。外れたら `denied: invalid lines for journal-unit` を stderr へ出して非ゼロ終了(I-6) |
| R3 | **P0** | `read -r check p1 p2 p3 extra` の行を**変更しない**。宣言 operand 数は3のまま(`report-show` が既に3を使う)。`journal-unit` の `[[ ... -z "$p3" ]]` を解くだけで、I-4 の「宣言数を超えた token は実行前に denied」は変わらないこと |
| R4 | **P0** | 発行するコマンドは `journalctl -u <unit> --since <since> -n <lines> --no-pager` のまま。**オプションを追加しない。** `<unit>` は既存 enum、`<since>` は既存の窓 enum から引いた固定文字列であり、operand 文字列をコマンドへ直接渡すのは `-n` の値だけであること(数値検証済み) |
| R5 | **P0** | カタログ `2026-08-03_008_phase3_check_catalog.md` に `## 8. 追加(D8、2026-08-07 承認)` を起こし、Q9 の記述を新しい形へ改める。**総数は変わらない**(check を増やしていない)ことを明記する |
| R6 | P1 | `docs/ai/status.md` の Next 行「**`journal-unit` が `-n 300` 固定で、ログ量の多い unit では窓指定が効かない**」を消す。class G / P に同じ穴が残ることは非ゴールとして本 requirement が持つので、status へ持ち越さない |
| R7 | P2 | 上限 10000 の根拠をスクリプト内のコメントに残す(このファイルへのポインタではなく、値の意味を1〜2行で) |

上限 10000 の根拠: `homelab-incident-investigate.service` は3行/分で24h ≒ 4320行。`recovery-io.service` の再接続バーストはそれより多い。**24時間ぶんの最も騒がしい unit を覆いつつ、1回の応答を有界に保つ**値として選んだ。

## 6. 受入条件

すべて ansy 上でスクリプトを直接起動して検査する(`SSH_ORIGINAL_COMMAND=<cmd> bash <script>`)。quory への配備は本案件の scope 外。

- **AC1(既定の後方互換)**: Given `journal-unit homelab-incident-investigate.service 24h`(第3 operand なし)、When 実行、Then 発行される `journalctl` の argv が `-n 300` を含み、**終了コードが 0**。
- **AC2(行数指定が効く)**: Given `journal-unit homelab-incident-investigate.service 24h 5000`、When 実行、Then argv が `-n 5000` を含み、**終了コードが 0**。
- **AC3(上限)**: Given `journal-unit <unit> 24h 10001`、When 実行、Then stderr に `denied: invalid lines for journal-unit`、**終了コードが非ゼロ**、`journalctl` は**1回も起動されない**。
- **AC4(下限とゼロ)**: Given `lines` が `0`、When 実行、Then AC3 と同じ形で拒否される。
- **AC5(非数値)**: Given `lines` が `abc` / `1e4` / `-5` / `300;id` / `+300`、When 実行、Then それぞれ AC3 と同じ形で拒否される。
- **AC6(arity が広がっていないこと)**: Given `journal-unit <unit> 24h 300 extra`(4 operand)、When 実行、Then `denied: too many parameters` で**非ゼロ終了**する(I-4 が生きていること)。
- **AC7(他 check の arity が変わっていないこと)**: Given `journal-ssh 24h 300` と `unit-cat <unit> x`、When 実行、Then いずれも `denied: invalid parameter count` で**非ゼロ終了**する。**`journal-ssh` に行数が付いていないことをここで確かめる**(非ゴールの実行時確認)。
- **AC8(unit / window の検証が先に効くこと)**: Given `journal-unit not-a-unit 24h 5000` と `journal-unit <unit> 99h 5000`、When 実行、Then それぞれ `denied: invalid unit` / `denied: invalid window` で非ゼロ終了する(行数の妥当性より前に落ちること)。
- **AC9(書込語彙が増えていないこと)**: Given 変更後のスクリプト全体、When レビュー、Then I-1 が挙げる語(`systemctl start/stop/restart/enable`、`qm start/stop`、`pvesh create/set/delete`、リダイレクト、`tee`、`rm`、`mv`、`cp`)が**1つも増えていない**こと。`eval` が無いこと(I-2)。
- **AC10(カタログとの一致)**: Given カタログ §8 と Q9 の記述、When 実装差分と突き合わせ、Then 既定値・上限・拒否メッセージ・operand の順序が文言レベルで一致すること。

**AC1 / AC2 の argv 確認方法**: ansy には quory の unit が存在しないため `journalctl` は「No entries」を返すが、それは argv 構築の検査を妨げない。`bash -x` のトレース、または PATH 上に `journalctl` を名乗る echo shim を置いて実引数を観測する形でよい(**shim は `/tmp` 配下に作り、検証後に消すこと**)。

## 7. オープンクエスチョン

- **OQ1**: `journal-ssh` にも同じ operand を足すか。**推奨は足す**(SSH ログもバースト系で、同じ2行の追加で済む)。ただし承認の文言は `journal-unit` だったため今回は入れず、カタログへ「次に問うこと」として残す。Yoshinobu の返答待ちであり、本案件のクローズを妨げない。
- **OQ2**: 行数を上げても **journald 自身の保持量**が上限になる。`lines=10000` は「24時間前に必ず届く」を意味しない。保持設定を見る check は現在カタログに無い。**今回は足さない** — 実際に足りなかった事例がまだ無く、想像上の需要である(D6 が「現に必要になった確認だけ」を基準にしたのと同じ判断)。
