## AC1 — `acl-status incident-inspect-root`

判定: **PASS**

コマンド:
```
ssh quory-investigate "acl-status incident-inspect-root"
```

生の出力（終了コード含む）:
```
# file: /var/lib/incident-inspect
# owner: incident-inspect
# group: incident-inspect
user::rwx
group::r-x
other::---

RC=0
```

owner/group/modeをgetfacl出力から読むと owner=`incident-inspect` / group=`incident-inspect` / mode相当 `750`（`rwx r-x ---`）。ACLエントリ（`user:`/`group:`個別行）は無し。終了コードは `0`。要件 AC1 の「`getfacl` 出力（owner/group/mode/ACLエントリ）が返る。終了コード0」を満たしている。

## AC2 — `acl-status incident-inspect-context`

判定: **PASS**（契約上、`Permission denied` で終わることも充足と明記されている）

コマンド:
```
ssh quory-investigate "acl-status incident-inspect-context"
```

生の出力（終了コード含む）:
```
getfacl: /var/lib/incident-inspect/semaphore-context: Permission denied
RC=1
```

`getfacl` の出力ではなく `Permission denied` で終わった。AC2 は「`getfacl` の出力が返るか、`Permission denied` で終わるかのいずれかである。どちらでも AC は充足する」と明記されているため、この結果は AC2 を満たす。**「読めなかった」を失敗として扱っていない。**

- AC3（arm総数29のまま、既存25 arm arity検査・拒否文言が1文字も変わっていないこと）のフル静的検証は再実行していない。Coordinatorの指示により「配備前にImplementer/Reviewerが独立に2回実行済み、再実行は求めない」との明示があったため。
- AC4の全パターン（表に無い名前、パスそのものを渡す等の網羅）は再実行していない。上記と同様の理由。`etc-passwd` 1パターンのみ配備物側で確認した。
- `/var/lib/incident-inspect` 配下の `workspace` など、要件が明示的にWon'tとした範囲は確認していない（要件範囲外）。
