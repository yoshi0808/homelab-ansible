# Finding: 先読みが書けない原因 — 親ディレクトリを `yoshi` が通れない

作成: 2026-08-25 / Coordinator

**本案件は観測手段を足すものであり、原因の断定は非ゴールに置いていた。** 観測できるようになった結果として原因が確定したため、ここへ記録する。**修正は本案件では行わない。**

## 確定した機構

3つが噛み合う。

| 観測 | 出所 |
|---|---|
| `/var/lib/incident-inspect` は `incident-inspect` 所有・`incident-inspect` グループ・mode相当 `750`(`rwx r-x ---`)・**ACLエントリなし** | `2026-08-25_004_test_result.md` AC1(本案件で足した `acl-status incident-inspect-root`) |
| `yoshi` を `incident-inspect` グループへ入れるタスクが**repoに存在しない** | `roles/incident_inspect/tasks/main.yml`・`roles/incident_investigate/tasks/main.yml` の検索 |
| 親ディレクトリへ `yoshi` の traverse を与える ACL も**存在しない** | 同上。ACL付与は2つだけ — `yoshi` へ token ファイルの `r`、`incident-inspect` へ**葉ディレクトリ**の `x` |

**したがって `yoshi` は owner でも group でもなく「other」に落ち、`---` すなわち traverse (`x`) を持たない。**

`/var/lib/incident-inspect` へ入れないため、**その下の `semaphore-context` が `yoshi` 所有・`0750` で正しく作られていても、辿り着けないので書けない。** これがジョブ #802(2026-08-22)の `[Errno 13] Permission denied` である。

## なぜ配備は `ok` を返したか

`roles/incident_investigate` の当該タスクは `become: true`(root)で走る。**root は権限ビットを無視するため、葉ディレクトリを作ることも、その所有者・mode が意図どおりであることを確認することもできる。**

**root から見て正しいことと、`yoshi` が使えることは別である。** ジョブ #838 の `ok` は前者しか意味していなかった。

## group 所属は確認していないが、確認は要らない

開発側から group 所属を見る手段は無い(dispatch の `users` は `name:uid:shell` しか返さない)。

**ただし確認は不要である。** `yoshi` が `incident-inspect` グループに居れば group の `r-x` で traverse できるため、`EACCES` は起きなかったはずである。**起きたこと自体が、通れないことの証明になっている。**

## 設計の穴

repo は traverse を**片方向にしか与えていない。**

- **与えている**: `incident-inspect` → 葉ディレクトリ(`x` のみ、least privilege)。sandbox 内の LLM に読ませるため
- **与えていない**: `yoshi` → 親ディレクトリ。**書き手が到達するための経路**

読み手のための経路だけが設計され、書き手のための経路が抜けている。

## 修正の方向(本案件では実施しない)

**既にある `incident-inspect` への付与の鏡像**になる — `/var/lib/incident-inspect` へ `yoshi` の `x` を与える(`r` は与えない)。

**採る前に確かめること**: 親へ `x` を与えると、`yoshi` は同じ親の下にある `workspace`(`incident-inspect` 所有)へも辿り着けるようになるか。`workspace` 自身の mode が `0750` で `yoshi` が「other」なら、そこは依然として入れない — **その前提が成り立つかを実装時に確認する。**

## AC2 の `Permission denied` について

`acl-status incident-inspect-context` が `Permission denied` を返したのは、**`dev-investigate` も同じ「other」に落ちる**ためであり、上の機構と同じことの裏側である。契約(AC2)はこれを充足として扱う — **読めなかったこと自体が、通れないことの直接の証拠である。**
