### What Looks Good

- 改行を含む出力上限: 前回の再現入力（本文`a\nb`の299 entries）は、noteを含む物理stdoutがちょうど300行、本文は全て`a b`の1行となり、上限内に収まった。LF / CRLF / 単独CR / Unicode改行 / 長文＋改行の各本文で0/1/299/300/301/500 entriesを与え、物理行数はいずれも1/2/300/300/300/300となった。各data行も`MAX_LINE_LENGTH=300`以下である。
- 切り詰めと出力性質: 300件以上ではnote 1行＋時刻昇順のdata 298行＋切り詰め通知1行の計300行となる。通知は`earliest 298 of >299 lines`と、表示した298件目の時刻までの読了範囲を示し、AC3の形式を満たす。AC4のnoteは0件時も切り詰め時も必ず先頭に残る。
- 既存2語の非退行: HEAD版と最新版へ同一mockを与え、`cmd_window` は0/1/299/300/301/500件、`cmd_count` は0/1/500/501系列の全てでrc/stdout/stderrが完全一致した。共通関数抽出後も`cmd_window`の通常出力と切り詰め通知の文言・数値は不変である。改行正規化も`cmd_errors`だけに閉じている。
- 定数の説明: ASTで関数ごとの参照名を照合し、`cmd_count`は`MAX_SERIES`のみ、`cmd_window` / `cmd_errors`は`QUERY_LIMIT` / `MAX_LINES` / `MAX_LINE_LENGTH`を参照することを確認した。catalog §9はL1とL2/L3の境界をこの実装どおりに記載している。
- 3者同期: helper / dispatch / wrapper、`AGENTS.md.j2`、catalogで、`loki-errors`のwindowは`1h` / `6h` / `12h` / `24h`に一致する。全job横断、`level="error"`固定、時刻昇順、level無し行がL3では見えないこと、L2の`any`がlevel無し本文への経路であることも一致する。`AGENTS.md.j2`はusageと切り詰め時の再問い合わせ方法まで説明し、AR-028を満たす。
- 認可境界: dispatchは3語を独立に再parse・正規表/allowlist検証し、固定helperへ引用付きargvで位置渡しする。`eval`、シェル文字列の再解釈、未引用展開は増えておらず、新語彙追加による既存2語の検証緩和もない。helper側の第二allowlistも同期している。
- selector: repository contract上の全sourceは非空`job`を持ち、`{job=~".+", level="error"}`は全jobのerror streamを対象とする。operandのLogQL補間がないため、ここからの注入経路もない。queryの`limit=QUERY_LIMIT+1`と`direction=forward`もmockで確認した。
- AC7/AC8: catalog §9は3語を問い合わせ語彙として`loki-helper`（deployed-hash対象）と区別する。EXEC-003はcatalog全体を指しつつLoki節が§9であることを示し、Policyの他の記述と矛盾しない。
- scope: `docs/ai/reviews/syslog_weekly_digest/`はレビュー対象外とした。対象変更に、本件と無関係の実装変更は見当たらない。実ホスト、SSH、本番Loki、Ansible、Slack通知、git add/commit/pushはいずれも実行していない。
