## 2. 問題定義

判断軸は前案件と同じ。**「その履歴が有用か」ではなく「読み手が前提となるベースラインを特定できるか」**で判断する。特定できない履歴は誤った前提で読まれる分だけ無いより悪い。

3本には加えて**計画書の足場**が残っている — 見出しの `TODO6-0` `TODO2-4` `Phase6` 等の番号、`docs/ai/reviews/agent_skills_reorganization_plan.md` への参照、pilot実施記録、「完了条件の確認」節。これらは当時の作業管理のための記述であり、**いま従うべき指示ではない**。

## 3. ゴール

3本を、**いま行動するために要る事実だけ**にする。

## 4. 非ゴール

- **分類のルールそのものを変えない。** 落とすのは経緯・根拠・計画書の足場であって、判定基準・行き先・タイミングの定義ではない。
- **Policy群・`skills/`・その他の規範文書へ広げない。** それらは次の案件とする。
- `docs/ai/reviews/` や `docs/ai/memory/` の既存記録を書き換えない。

## 5. 落とすもの / 残すもの

**この区別が本案件の核心である。** 3本は分類を定義する文書なので、`docs/ai/memory/lessons/` や `docs/ai/reviews/` への言及が**行き先の指定**である場合が多い。前案件でも同じ判断を要した。

| 落とす | 残す |
|---|---|
| 日付つきの注記(「(2026-07-29、Tech Lead廃止に伴い…)」「(2026-07-27追加)」) | その注記が伝えている**現在の規則**そのもの |
| 改訂の経緯(「旧ルール…は撤回した」「当初は…だったが」) | 改訂後の規則 |
| 過去の実例・事故の説明(「2026-07-27時点のauto-memory索引には矛盾が実在し」) | その実例から導かれた規則 |
| 計画書の足場(`TODO6-0`、`Phase6`、`agent_skills_reorganization_plan.md` への参照、pilot実施記録、「完了条件の確認」節) | — |
| **根拠**への参照(`docs/ai/memory/lessons/<file>` を「なぜそうするかはここ」として引くもの) | **行き先**の指定(「`lessons/` へ書く」「`docs/ai/reviews/<target>/` へ保存する」)、および**正本**の指定(「形式は `skills/incident-recording/SKILL.md` が正本」) |

### AC1の限界と、実装が当たった実例(2026-08-02、Coordinator追記)

AC1を `grep "2026-"` という**文字列検査**で書いたため、実装は「経緯ではない日付」にも当たった。`context-classification.md` の命名規則の例示 `radius_healthcheck/2026-07-21_020_final.md` は**実在するファイル名**であり経緯ではないが、検査を通すために `<日付>_020_final.md` へ書き換えられた。

**この書き換え自体は結果として妥当**である — その欄は命名の**パターン**を示す列であり、プレースホルダのほうが意図をよく伝える。**したがって差し戻さない。** ただし採否の理由は「検査を通すため」ではなく「例示として適切だから」であり、**判断はその順序でなされるべきだった**。

一般化すると、**測りやすい代理指標をACに書くと、実装がその指標に合わせて中身を歪める**。文字列検査をACに使うときは、何の代理なのかを併記する。

### 「Codex側」の記述の扱い(2026-08-02、Coordinator判断)

`context-classification.md` §6 の「Codex側」段落について、実装から「死んでいるように見える」と報告があったが、**本案件では落とさない。**

- Codexは開発工程からは外れたが、**運用工程では現役**である(`docs/ai/core.md`「開発と運用の分離」)。
- 同段落が述べているのは「Skillの自動検出に頼らず明示参照にする」という**現在も有効な設計上の制約**であって、経緯ではない。
- 要否は、`status.md` が既に起票している**「リポジトリ直下 `AGENTS.md` の要否判断」と同じ問い**に属する。本案件で先に決めると、その未決事項を経緯除去の副産物として片付けることになる。

日付つきの注記だけを落とし、内容は残す扱いが正しい。
