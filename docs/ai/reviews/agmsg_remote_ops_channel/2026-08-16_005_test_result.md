## 詳細

### T1 / AC1 — TLSチェーンとSemaphore無影響

ansy上で`openssl s_client -connect 127.0.0.1:8788 -servername ansy.internal -showcerts`を実行し、提示証明書が2枚(`CN=ansy.internal` ← `CN=Home-TLS-CA`)であることを確認した。トラストストアのルートCA(`/usr/local/share/ca-certificates/home-tls-root-ca.crt`、`CN=Home-RADIUS-CA`)のみを`-CAfile`に指定した検証は`Verify return code: 0 (ok)`。

Semaphore(:3000)は`systemctl show semaphore -p ActiveEnterTimestamp`が`2026-08-05 14:28:58`(本作業より11日前)を示し、HTTPS応答も200。段2の全作業を通じて再起動していないことを実測で確認した。

### T4 / R2・R11 — トラストストアの実態

`/etc/ssl/certs/home-tls-ca.pem`(中間CAを指すはずのsymlink)を`openssl x509`で開くと`No such file or directory`(リンク先ファイル`home-tls-ca.crt`が存在しない dangling symlink)。中間CAはトラストストアに存在しないというrequirement R11の前提を、implement記録の記述をなぞらず自分で確認した。

### T3 / R2・AC2 — 想定外の発信元からの実到達試行

`sandbox`(依頼文で明示的に使用許可された発信元)から`ann`ユーザーでSSHし、`curl -sk -m 5 https://ansy.internal:8788/v1/health`を実行。結果は`http_code=000`・`curl exit=28`(timeout、5秒待って応答なし)。IPv6での再試行も`exit=6`(名前解決不可、AAAAが無い)。

ufw側の実ルールは対象ポートについて1件のみで、送信元はquoryの解決アドレスに一致していることを確認した(実測したアドレス値そのものはrepoへ書かない — `docs/ai/core.md`「内部IPアドレスを...記載しない」)。`getent ahostsv4 quory.internal`の結果と、ufwルールのcommentに埋め込まれた由来(`agmsg_server (agmsg_remote_ops_channel R2) -- quory only`)が一致することも確認した。

**sandboxは壊していない。** SSH接続と`curl`のみで、sandbox側に状態変更は行っていない。

### T5 / R10・AC8 — 証明書置き換え検知の一般化再現

まず、実際にansyへ配備されている`agmsg-cert-reload.path`ユニットの内容を`cat`で直接確認し、`PathModified=`が証明書・秘密鍵の両パスを監視していることを確認した(実装記録の記述ではなく現物)。

そのうえで、本番の証明書・nginx configには一切触れない形の独立した再現実験を行った。`/tmp`配下に2つのdecoyファイルを作り、両方を`PathModified=`で監視するdecoyの`.path`/`.service`ユニット(サービス本体はタイムスタンプをログへ追記するだけ)を一時的に配備し、`systemctl enable --now`した。

- decoyファイルaのみ変更 → ログに1行追記(発火を確認)
- 続けてdecoyファイルbのみ変更 → ログに2行目を追記(発火を確認)

「監視対象のどちらが後から変わっても収束する」という設計の根幹(2つの`PathModified=`のうち独立にどちらのイベントでも起動する)を、実装記録の記述をなぞらず自分の手で再現した。終了後、decoyユニットを`disable --now`・ファイル削除・`daemon-reload`で後始末し、本番ユニット(`agmsg-cert-reload.path`)・nginx・Semaphoreが`active`のまま、`/etc/semaphore/tls/ansy.internal.crt`/`.key`のmtimeが不変であることを確認した。

**未検証:** `homelab_cert_renew`が実credentialで実際に証明書を書き換える瞬間そのものでの確認(次回の実更新は9月上旬)。requirement AC1-bと同型の理由で、この段では確認できない。また、AC8が本来求める「quory側から到達して検証が失敗しない」の部分も、quoryへの到達手段が無いため確認していない。
