案件: `agmsg_remote_ops_channel` / 作成: 2026-08-16 / Tester

対象: `roles/agmsg_server/`、`playbooks/agmsg_server_setup.yml`、`playbooks/README.md`(未追跡・未commit差分)。
判定対象: R1 / R2 / R10 / R11 / R15、AC1 / AC2 / AC8。AC1-b・AC3〜AC7・R3〜R9・R12〜R14・R16〜R18は対象外(段3・Yoshinobu区間)。

先行成果物(spike・implement記録)の記述は判定の入力にせず、現物(deployed済みのansy)を自分で確認する。Implementer/Reviewerが行った fixture 再演・mutation testing は再演しない。

## カバレッジ配分(test-strategy Skillの型)

### 1. dry-run(`--check`)

- tester-gate分類は`check-mode-native`(TS-023によりTester役は`--check`必須)。`scripts/safe-ansible-check.sh`経由で`-l ansy --check`を実行し、read-only診断(ufw健全性assert・quoryホスト名解決)が`--check`でも常に走り、破壊的taskが全skipで完走することを確認する。

### 2. apply(限定対象への実適用)

- 段2はすでにImplementerによりansyへ適用済み(常駐稼働中)。Testerが`--check`なしで再適用することはgate上できないため、**「現在のdeployed状態」を実機観測で直接検査する**ことをapply相当の検証に充てる。

### 3. 事後健全性チェック

- AC1: TLSハンドシェイクの現物観測(チェーン枚数、root-onlyでのverify、Semaphore無影響)。
- AC2: 許可されていない発信元(sandbox)からの実到達試行。
- AC8/R10: 証明書差し替え検知の一般化された再現(実credentialは使わない)。
- R11: 提示チェーンの現物確認、トラストストアに中間CAが無いことの確認。
- R15: 再起動を伴わない構成証跡(systemd enable状態、Dockerのrestart policy)。**実再起動はTester権限・依頼の両方で禁止のため実施しない**。
