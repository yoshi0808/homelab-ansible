## 12. Operatorセッションで実行する手順

Yoshinobuがquoryで`operator-channel`のOperatorセッションを起動し、次を順に実行する。

```
1. operator-channel list-pending
   → req-20260808T191118+0900-dd87c0e962a516ac が一覧に出るか(item 2)

2. operator-channel show-request req-20260808T191118+0900-dd87c0e962a516ac
   → purpose等が正しく表示されるか(item 2)

3. operator-channel accept-request req-20260808T191118+0900-dd87c0e962a516ac
   → StoreErrorが再発せず成功するか(item 3、b69948cの修正対象そのもの)

4. operator-channel reply-opres req-20260808T191118+0900-dd87c0e962a516ac
   (stdinへ無害なJSON、例: observed_facts=["縦方向試験3回目、accept成功を確認"], unconfirmed=[] 等)
   → 成功しOPRESが作成されるか(item 4)

5. (ansy側で)operator-channel-client get req-20260808T191118+0900-dd87c0e962a516ac
   → OPRESが取得でき、内容が一致するか(item 5)

6. operator-channel new-devreq
   (standaloneのDEVREQを1件、無害な内容で作成)
   → 成功するか(item 6前半)

7. (ansy側で)operator-channel-client list / get <新DEVREQのid>
   → 取得できるか(item 6後半)

8. operator-channel reply-opres req-20260808T191118+0900-dd87c0e962a516ac
   または operator-channel new-devreq へ、疑似secret(例: 適当なPEM形式の文字列)を含む内容を渡す
   → quory側で拒否され、検出値・tracebackが出ないことを確認する(item 7、item 9のcheckpoint 3部分)
```

各手順の出力(成功時のJSON、または拒否時のメッセージ)をそのままCoordinatorへ共有いただければ、item 2〜7の判定を完了できる。
