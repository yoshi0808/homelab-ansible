## 3. requirement §18.2(integration)の対応

`test_integration_roundtrip.py`が、ansy相当client / quory相当receiver+Operator CLIを同一プロセス内で結線し(SSHはfakeで内部呼び出しに置換)、次を確認する。

- submit → accept → OPRES作成 → pull の往復(`test_submit_accept_reply_pull`)
- standalone DEVREQの作成とpull(`test_standalone_devreq_reaches_ansy`)
- 4検査点すべてで同一fixtureが拒否されること(`test_dlp_blocks_the_same_fixture_at_all_four_inspection_points`)
- 再取得でmessageが変化しないこと(同上、決定的な再取得の検証を含む)

channel経路からSemaphore/systemctl/sudo/Git/任意pathへ到達できないことは、`ReachabilityBoundaryTests`/`R1BoundaryTests`(コード走査: `subprocess`/`os.system`/shell呼び出しの不在)で確認する。通信切断後の再試行で重複・上書きが起きないことは、request_idが常に受信側で新規採番される設計上の帰結として、atomic create衝突拒否(`test_second_create_with_same_id_conflicts`、`test_colliding_request_id_is_rejected_not_overwritten`)で裏付ける。

## 5. 既存`dev-investigate`25操作の非回帰

quoryのdispatcherは現時点で未配備(旧版)のため、変更後dispatcherを本番で動かして比較することはできない。代わりに:

1. `git show HEAD:roles/dev_investigate/files/recovery-investigate-dispatch-quory.sh`(変更前)と作業ツリー版(変更後)をローカルに複製する。
2. 25操作それぞれについて正常系・異常系入力を用意し、両バージョンへ同一`SSH_ORIGINAL_COMMAND`を与えてローカル実行し、終了コード・stderrを比較する。
3. quory固有の外部プログラム(`incident-bundle-helper`等)がansy上に存在しないケースは、両バージョンとも同一の`exec`失敗(同一rc)になることを確認する(絶対パスの解決不能はどちらのバージョンでも同一に起きるべき挙動であり、dispatch側のロジック差ではない)。
4. `ssh quory-investigate`経由で実際の本番dispatcher(現行・旧版)に対して代表的な読み取り専用操作を実行し、現在も正常に機能していること、および`operator-*`4操作が(未配備のため)`unknown command`で拒否されることを確認する。

## 6. requirement §19(完了条件28項目)の判定方針

実配備を要する項目(Semaphore登録・実行、quory上での実測、Operator起動)は**未判定のまま残す**。実配備を要さない項目(禁止事項の非実施確認、スコープ制約、mechanism-levelの動作、Git検査)はTesterが実測してPASS/FAILを判定する。分類はtest_resultの表で行う。
