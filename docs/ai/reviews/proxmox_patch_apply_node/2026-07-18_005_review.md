### cache root symlink と dot component を、最初のroot書き込みより前に拒否する

- `roles/proxmox_patch_apply_node/files/proxmox-patch-cache.sh:77`

#### A. cache helper の安全検査より先に `install -d` がsymlinkを辿る

`require_cache_root` は canonical path と `/mnt/pve/<storage>/proxmox-patch-cache` 境界を検査する。しかし、これは seed helper が呼ばれた時点で初めて実行される。その前にAnsibleは次を実行する。

```text
install -d -m 0750 -- <cache-root>/<date-key>
```

既存の `<cache-root>` がsymlinkなら、`install -d` はリンク先を辿って日付ディレクトリを作成する。mkdir成功後に helper がsymlinkを拒否しても、rootによる境界外の作成は既に完了している。

ローカルの `/tmp` fixtureでも、symlinkを中間componentにした `install -d` がリンク先へ mode `0750` の日付ディレクトリを作ることを確認した。したがって「helperが後から拒否する」だけでは、root writeを任意subtreeへ向けられないという要件を満たさない。

修正案:

- cache rootとdate directoryの non-symlink / canonical / exact-root 検査を、`install -d` より前に実施する。
- NAS accessはnon-criticalかつboundedである必要があるため、`prepare` のようなhelper operationに「検査 → 必要なdirectory作成 → 再検査」を集約し、既存の `timeout --kill-after` 内で実行するのが分かりやすい。
- cache rootがsymlink、non-directory、non-canonical、または検証済みmount root外なら、何も作成せずNAS unavailable warningへfallbackする。
- date directoryが既存symlinkの場合も、mode変更や子directory作成をせず拒否する。

#### B. 入力regexが `.` / `..` を単一componentとして許可する

mount pathの `[A-Za-z0-9._-]+` は `/mnt/pve/.` と `/mnt/pve/..` を許可する。log directoryの `^/var/log/[^/]+$` と許可文字検査も、末尾component `.` / `..` を許可する。

mount側は `findmnt` のexact target比較により通常はfallbackするが、「安全な単一storage component」という入力契約を満たしていない。より重大なのはlog側で、`/var/log/..` がassertを通り、`ansible.builtin.file state=directory owner=root mode=0750` の対象を親directoryへ正規化できる点である。

修正案:

- mount storage名とlog leaf名について、`.` と `..` を明示的に拒否する。
- 可能なら先頭・末尾を英数字に限定し、`.` / `_` / `-` は内部文字だけにする。
- cache/log pathはrootで触る前にcanonical pathが入力文字列と一致することを確認する。

## 003 review の対応確認

### Must-fix 1: hosts stale marker — 解消

- download phaseはmirror addressの有無に関係なく、apt前に `/etc/hosts` のregular non-symlinkとmarker無しを検査する。
- markerは自動削除せず、persistent logとstderrへmanual recovery要求を出してrc nonzeroとなる。
- backup/candidate作成とpinはaddress選択時だけである。
- Ansibleはdownload command直後にstdout/stderrを保持してから、SHA-256 / mode / uid / gidの復元比較へ進む。
- safety gate failureと復元不一致はいずれも `download_failed` を維持し、stderr excerptとlog pathを `_apply_error_msg`、Slack本文、reportへ残す。

### Must-fix 2: NAS hard timeout — 解消

- `findmnt`、path probe、directory作成、seed、publish、pruneの全commandが `timeout --kill-after=<grace> <bound>` 内にある。
- `failed_when: false`、warning fact、direct download/apply fallbackは維持されている。
- kernel uninterruptible sleepというuserspace timeoutの限界は残るが、TERM無視による無期限待機はKILL猶予で抑止される。

### Must-fix 3: helper copy/prune境界 — helper内部は解消、事前mkdirは未解消

- mount/cache rootの文字列上の関係、seed destination、publish source、prune sourceはoperationごとに固定されている。
- date keyはcache root直下の `20` で始まる8桁だけを許可する。
- copy sourceはregular non-symlink `.deb` に限定し、destination file symlinkは拒否する。
- `require_safe_directory` が既存symlink componentをcanonical化して入力との差で拒否する。
- ただし上記Must-fixのとおり、Ansibleの事前 `install -d` はこの検査より先である。

### Must-fix 4: check mode helper配備 — 解消

- 新規apt phase helperとNAS cache helperのcopyから `check_mode: false` が外れている。
- check modeではnative simulationとなり、後続のseed/download/publish/prune/apply blockは `not ansible_check_mode` でskipされる。
- 既存のpre/post collect helperとread-only collectionの `check_mode: false` は変更されていない。

### Suggestion: safety error observability — 解消

- hosts regular-file / marker拒否とrestore failureはpersistent logへappendし、同時にstderrへ出る。
- `_download_stderr` は復元比較前に保存される。
- download failureの `_apply_error_msg`、Slack本文、final reportにstderr excerptとpersistent log pathが接続されている。
