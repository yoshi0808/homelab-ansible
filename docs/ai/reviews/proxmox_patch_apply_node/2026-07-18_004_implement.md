## 対応内容

### 1. download 前の hosts safety gate

`proxmox-patch-apt-phase.sh` の download phase は、runtime mirror address の有無にかかわらず、apt 起動前に次を必ず確認するよう変更した。

- `/etc/hosts` が regular non-symlink file であること
- temporary mirror marker が残置していないこと

残置 marker は自動削除せず、persistent download log と stderr に manual recovery 要求を記録して失敗する。backup/candidate の作成と temporary pin の atomic replace だけを address 選択時に限定した。

Ansible は helper の stdout/stderr を hosts 復元比較より先に保持する。したがって pre-apt safety failure と復元不一致のいずれも、`download_failed` の通知、`_apply_error_msg`、最終 report に stderr excerpt と persistent log path を残す。

### 2. NAS command の hard bound

NAS に触れる全 command を次の形へ統一した。

```text
timeout --kill-after=<short-grace> <bound> command ...
```

対象は `findmnt`、path probe、cache directory 作成、seed、publish、prune。`failed_when: false`、warning、report 記録、direct repository download への fallback は維持した。短い KILL 猶予は default 5秒、assert 許可範囲は1〜30秒である。

### 3. mount/cache/helper の境界強化

- mount path を `/mnt/pve/<単一の安全な storage 名>` に限定した。
- cache root を mount path 直下の `proxmox-patch-cache` と完全一致させた。
- helper に検証済み cache root を明示的に渡すようにした。
- seed destination と publish source を `/var/cache/apt/archives` に固定した。
- prune source は検証済み cache root との完全一致を必須にした。
- date directory は cache root 直下の JST date key だけを許可した。
- copy source は regular non-symlink `.deb` のみに限定し、symlink destination も拒否した。

これにより root 実行の copy/prune が任意の system subtree を対象にできない構造にした。

### 4. check mode の書き込み除去

新規 apt phase helper と NAS cache helper の copy task から `check_mode: false` を除去した。check mode では Ansible native simulation となり、新規 helper を対象 node へ実配備しない。既存の read-only collect helper の契約は変更していない。
