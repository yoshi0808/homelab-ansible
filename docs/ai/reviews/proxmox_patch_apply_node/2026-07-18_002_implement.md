## 実装概要

既存の単一 `apt-get -y dist-upgrade` を、同一 destructive block 内の次の順序へ分割した。

1. 既存 NAS mount を read-only に確認し、当日（JST）の cache directory を作る。mount は行わない。
2. NAS cache が使用可能なら同日 `.deb` を local apt archives へ seed する。
3. Proxmox download host の runtime IPv4 candidates を複数回解決し、ping average RTT が最小の address を選ぶ。
4. 選択 address を download 中だけ `/etc/hosts` に pinし、`apt-get -y -d dist-upgrade` を実行する。
5. local apt archives を同日 NAS cache へ publishし、保持数を超えた古い date directory を簡易 pruneする。
6. `apt-get -y dist-upgrade` を local archivesから適用する。

download と apply は別 task・別 persistent logとなり、失敗時の `abort_type` はそれぞれ `download_failed` / `apply_failed` になる。

## 安全性とフォールバック

### 異なる package start line

NAS cache は正当性の前提にしていない。各 node の pre-apply collect が先に `apt-get update` と simulation を行い、download/apply はその node 自身の apt indexesに従う。seed は `.deb` を archivesへコピーするだけで、version/hashが対象 node の indexesと一致しない archiveは apt が使用せず、不足分を通常 repositoryから取得する。

したがって pve1/pve2 の installed version、hold、kernel generationが異なる場合も、共通 archiveだけcache hitし、node固有分だけ追加downloadになる。日付keyもJSTの `YYYYMMDD` で分離した。

### NAS は non-critical

- enabled flagで全体を無効化できる。
- `findmnt` で既存mountを確認するだけで、roleはmountしない。
- path probe、directory作成、seed、publish、pruneはbounded timeoutを持つ。
- mount/path/seed/publish/prune failureは警告とreportへ記録し、direct repository downloadとapplyを継続する。
- cache directoryとlog directoryはbroad pathを拒否するinput assertを追加した。

### mirror probe-and-pin と hosts 復元

- addressはruntime name resolutionからだけ得る。repoにaddress literalを保存しない。
- probe失敗時はnon-criticalとして通常DNS選択へ戻る。
- pin helperは `/etc/hosts` と同一directoryにbackup/candidateを作り、metadataを保持したcopyをatomic renameする。
- EXIT/HUP/INT/TERM trapはbackupをatomic renameで戻す。restore failureは専用fatal rcにしてdownload失敗とする。
- retained markerが既にある場合は新しいpinを重ねず停止する。
- Ansible側でもdownload前後のSHA-256、mode、uid、gidを比較し、完全復元できなければ`download_failed`で停止する。

### check mode

seed/download/publish/prune/applyを1つの `when: not ansible_check_mode` + `tags: [destructive]` blockへ入れた。既存のread-only precheck/re-dry-run/post-collectは `check_mode: false` の契約を維持し、rebootも従来どおり `not ansible_check_mode` でgateされる。実装検証で `--check` の実ホスト実行はしていない。

## ログとreport

対象nodeに以下をroot所有、directory `0750`、file `0640` で保存する。

- `/var/log/proxmox-patch/<run_ts>-download.log`
- `/var/log/proxmox-patch/<run_ts>-apply.log`

両logはapt stdout+stderrを統合して保存する。既存 report の `apply_output` は互換性のため残し、次を追加した。

- `download_bytes`
- `download_seconds`
- `cache_hit`
- `download_log`
- `mirror_host`
- `mirror_address`（runtime reportのみ）
- `mirror_rtt_ms`
- `nas_cache_available`
- `nas_cache_warnings`
- `apply_seconds`
- `apply_log`

Slack subject/bodyにもdownload failureの独立分岐、download統計、log path、NAS fallback、mirror結果を反映した。
