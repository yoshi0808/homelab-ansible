## 対応内容

### A. cache rootへの最初の書き込み前に検査

Ansibleが直接実行していた `install -d` を除去し、NAS helperへ `prepare` operationを追加した。`prepare` は既存の `timeout --kill-after` 内で次を順番に行う。

1. mount rootがcanonicalな既存non-symlink directoryであり、許可した単一storage componentに一致することを検査する。
2. cache rootがmount root直下の固定subtreeと完全一致し、canonicalかつnon-symlinkであることを検査する。
3. date directoryがcache root直下の正しいdate keyで、canonicalかつnon-symlinkであることを検査する。
4. cache root/date directoryが存在しない場合だけ、親を自動作成しない単一componentの `mkdir` で作成する。
5. 作成後にmount root、cache root、date directoryを再検査する。

既存cache rootがsymlink、non-directory、non-canonical、またはconfigured mount root外の場合は、directoryを作成せずrc nonzeroとなる。既存date directoryがsymlinkの場合も、mode変更や子directory作成をせず拒否する。Ansible側は従来どおり `failed_when: false` とし、prepare失敗をNAS unavailable warning/reportへ接続してdirect downloadへfallbackする。

seed/publish/pruneも、cache rootを既存canonical non-symlink directoryとして再確認してから処理する。

### B. dot componentとnon-canonical log pathの拒否

mount storage名とlog leaf名を、先頭・末尾が英数字で、`.`、`_`、`-` は内部だけに使用できる単一componentへ制限した。これにより `.`, `..`, hidden-style leaf、記号で始終端するleafをinput assertで拒否する。

persistent log directoryについては、rootの `file state=directory` より前にtarget上で `readlink -m` を実行し、canonical resultと入力文字列の完全一致を必須にした。不一致または解決失敗時は `download_failed` のままroot write前に停止する。したがって親directoryへ正規化される入力や既存symlinkを、ownership/mode変更の対象にしない。
