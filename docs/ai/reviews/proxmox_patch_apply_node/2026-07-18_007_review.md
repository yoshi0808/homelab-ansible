## A: cache rootへの最初の書き込み前検査

確認結果: **解消。**

- Ansibleによる直接の `install -d` は除去され、NAS helperの `prepare` operationへ集約されている。
- `prepare` 自体は `timeout --kill-after=<grace> <bound>` 内で実行され、失敗は `failed_when: false` のままNAS unavailable warning/reportとdirect download fallbackへ接続される。
- 最初の `mkdir` より前に、mount rootを既存canonical non-symlink directoryかつ `/mnt/pve/<safe-storage>` として検査する。
- cache rootはcanonical/non-symlink、許可pattern、`<mount-root>/proxmox-patch-cache` との完全一致を検査する。
- date directoryはcache root直下の単一date keyであり、canonical/non-symlinkであることを検査する。
- cache rootとdate directoryの作成は `mkdir` の単一path componentで行い、親を自動作成する `-p` や `install -d` を使わない。
- 既存symlink/non-directoryは作成前に拒否する。検査後のraceで同名entryが作られても、通常の `mkdir` は既存symlinkを辿らずEEXISTで停止する。
- cache root作成後、およびdate directory作成後に、mount/cache/dateのcanonical/non-symlink/exact-root検査を再実施する。
- seed/publish/pruneも毎回 `require_cache_root` を通し、既存canonical non-symlink directoryであることを再確認する。
- seed/publishのdate directoryも `require_date_directory` と `copy_debs` の検査を通る。prune sourceは検証済みcache rootとの完全一致を維持する。

以上から、cache rootやdate directoryがsymlink、non-directory、non-canonical、またはmount root外の場合に、helperが境界外を作成してから拒否する経路は解消している。

## B: dot componentとlog canonical gate

確認結果: **解消。**

- mount storage名は先頭・末尾が英数字で、`.`、`_`、`-` は内部だけに使える単一componentへ制限されている。
- log leaf名にも同じ始終端制約があり、`.`、`..`、hidden-style、記号始端/終端をinput assertで拒否する。
- persistent log directoryをrootで作成・chmodする前に、target側で `readlink -m -- <log-dir>` を実行する。
- canonical resultが入力文字列と完全一致しない場合、`_apply_abort_type` が `download_failed` に設定済みのblock内で停止する。
- 既存log directoryがsymlink、または途中componentがsymlinkならcanonical resultが変わるため、`ansible.builtin.file state=directory` に到達しない。
- `/var/log/..` はregexで拒否され、仮にcanonical化しても `/var` となるため、親directoryをfile taskの対象にする経路はない。
