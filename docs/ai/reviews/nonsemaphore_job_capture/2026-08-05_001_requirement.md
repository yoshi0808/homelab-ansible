# requirement(Semaphore外ジョブの失敗を捕捉する — 障害捕捉 Step 1 の R8)

2026-08-05 / Coordinator。`docs/ai/reviews/incident_auto_capture/2026-07-27_002_requirement.md` の **R8(P1、未実装)** を実施範囲とする。着手前にCoordinatorが現物で確認した事実を §2 に置く。

## 1. 問題定義

障害の自動捕捉(Step 1)は、**Semaphoreのジョブ行と、通知経路が書くspoolレコードを突き合わせる**形で成り立っている。**Semaphoreを経由しない本番ジョブは、この網に乗らない。**

該当するのは `ansible-cert-renew-quory.service`(月次、quory の systemd timer)である。**ここが失敗しても、誰にも何も届かない。**

さらに、**このtimerは日次ドリフト検査の unit カタログにも入っていない**。つまり「止まっていること」も検出されない。**失敗しても分からず、動かなくなっても分からない**状態が重なっている。

## 2. 着手前に確認した事実(2026-08-05、Coordinator)

| 事実 | 確認手段 |
|---|---|
| `ansible-cert-renew-quory.timer` は quory に配備され、`OnCalendar=*-*-01 00:35:00` / `Persistent=false` | `ssh quory-investigate "unit-cat ansible-cert-renew-quory.timer"` |
| `.service` は `Type=oneshot` / `User=yoshi` / `ExecStart=/usr/bin/flock -n <lock> /usr/bin/ansible-playbook playbooks/cert_renew_quory.yml`。**`OnFailure=` は無い** | `ssh quory-investigate "unit-cat ansible-cert-renew-quory.service"` |
| 実際に月次で動いている | `status` が返す `semaphore.service` の Active since が **2026-08-01 00:35:14 JST**(証明書更新後の再起動と一致) |
| 生成元は `roles/systemd_timers`(`templates/ansible-timer.service.j2`)。**catalogに他のエントリもあるが、現在有効なのは `cert-renew-quory` の1件のみ** | `roles/systemd_timers/defaults/main.yml` |
| **`playbooks/systemd_timers.yml` には Semaphore のテンプレートが無い** | `roles/semaphore_templates/defaults/main.yml` を `grep`(0件) |
| 同playbookは `connection: local` で、**対象ホスト自身から実行する**必要がある。`tester-gate: check-mode-native` | 同playbook L3 / L10 / L23 / L26 |

## 3. ゴール

- **Semaphoreを経由しない本番ジョブの失敗が、既存の捕捉の仕組みに乗る**
- そのtimerが**止まったら日次ドリフト検査で分かる**
- 上2つの変更を、**Yoshinobuがボタンを押すだけで配備できる**

## 4. 非ゴール

- 通知の新設。**捕捉であって通知ではない**。既存の経路に乗せるところまでが範囲
- 一次調査(`incident-investigate`)側の変更
- `cert_renew_quory.yml` 自体の変更
- 他のホスト(ansy)のtimerを対象にすること。**`ansible-knowledge-review.timer`(ansy)は対象外** — 失敗しても本番影響が無く、既にドリフト検査のunitカタログに入っている

## 5. 要件

**R1. 非Semaphoreジョブの失敗が捕捉される**

`ansible-cert-renew-quory.service` が失敗したとき、**その事実が障害捕捉の仕組みに残る**こと。

- **実装方法は指定しない。** ただし **`roles/systemd_timers` が生成する全ジョブに効く形**にすること — このroleのカタログにエントリを足した人が、捕捉の配線を別途書かなくてよいこと(現在有効なのは1件だが、増えたときに漏れる形にしない)
- **収集器を壊さないこと。** 既存の収集は Semaphore のジョブ行との突合を前提としており(`incident_capture_spool_correlation_tolerance_s`)、**対応するSemaphore行が存在しないレコードが入ったときの挙動を、実装前に現物で確かめること**。壊れるなら、壊れない形を選ぶ
- **正常な見送りを失敗として捕捉しないこと。** `ExecStart` は `flock -n` を通っており、**多重起動を排他した場合も非ゼロで終わる**。これは異常ではない。同種の区別は既に `homelab-incident-investigate.service` の `SuccessExitStatus=75` で行われている

**R2. timerの生存がドリフト検査に乗る**

`ansible-cert-renew-quory.timer` を `roles/deployment_drift_check/defaults/main.yml` の `deployment_drift_check_units` へ加える。

- 期待状態(`enabled` / `active`)は**現物に合わせる**(推定しない)
- **`playbook:` を持たせるかは、そのplaybookを流せば実際にその状態へ復元されるかで決める**(R1-a。同ファイル冒頭の判断基準)

**R3. 配備手段を用意する**

`playbooks/systemd_timers.yml` を `roles/semaphore_templates/defaults/main.yml` のカタログへ加える。

- `class` は「押したときにサービスが受ける影響の大きさ」で決める(同ファイルの基準)
- **`connection: local` で対象ホスト自身から実行する必要がある**という制約を、テンプレートの形(survey / arguments)で満たすこと。**満たせないなら、満たせない理由を記録して R3 を落とす**(その場合 R1/R2 の配備は手作業のままになる)

## 6. 受入条件

| # | 条件 |
|---|---|
| **AC1** | **Given** `roles/systemd_timers` が生成したserviceが**異常終了**した、**When** そのユニットが終了する、**Then** 障害捕捉の仕組みに**その事実が残る**(残り方は実装が決めてよいが、**残ったことを観測する手段を成果物に書くこと**) |
| **AC2** | **Given** 同じserviceが `flock` の排他で見送られた(多重起動)、**When** 同上、**Then** **失敗として捕捉されない** |
| **AC3** | **Given** 対応するSemaphoreジョブ行が存在しない捕捉レコード、**When** 収集器が動く、**Then** **収集器が異常終了しない**。既存の捕捉(Semaphore由来)が巻き込まれない |
| **AC4** | **Given** `ansible-cert-renew-quory.timer` が停止/無効化された、**When** 日次ドリフト検査が走る、**Then** finding が立つ |
| **AC5** | **Given** 正常な状態、**When** 日次ドリフト検査が走る、**Then** この追加による finding は**立たない**(誤検知しない) |
| **AC6** | R3 を満たす場合: **Given** カタログへ追加した状態で reconcile を `--check` で実行、**Then** 新規テンプレートとして差分に現れ、**書き込みは発行されない** |
| **AC7** | 既存の `systemd_timers` / `deployment_drift_check` / `semaphore_templates` の挙動が変わらない |

## 7. 制約

- **quory への配備はYoshinobuがSemaphoreから行う。** 実装・レビューの範囲は repo の変更までとする
- **`.service` テンプレートの変更は、既存の稼働中ユニットに影響する。** 配備するまで現物は変わらないが、配備後に `cert-renew` が動かなくなる形にしないこと
- Tester は quory へ到達できない。**実機検証は「配備後の初回発火」まで得られない**
