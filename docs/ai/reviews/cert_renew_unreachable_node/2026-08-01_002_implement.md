## 2. proxmox playへ追加した機構(P0-1)

```
Probe SSH reachability of this node   ansible.builtin.ping / ignore_unreachable / ignore_errors / become: false
Record node reachability             set_fact cert_host_unreachable
Warn that an unreachable node is skipped  debug(WARNING) / when: cert_host_unreachable
Drop the unreachable node from this play  meta: end_host / when: cert_host_unreachable
```

- `become: false` は `roles/proxmox_reachable_nodes` T2と同じ理由による。SSH接続性だけを見たいので、sudo障害を「到達不能」へ畳み込まない。SSHは通るがsudoが壊れているnodeは、後続の本体タスクで本物の失敗として出るのが正しい。
- `ignore_errors: true` を併記しているのは、`ping` がunreachable以外の理由(python interpreter不在など)で失敗したときにも判定ロジックへ落とすため。判定式は `unreachable` と `is failed` の論理和。
- `meta: end_host` を使うため、以降のタスクは到達不能nodeに対して一切接続を試みない。`set_fact` はcontroller側で完結するため、`end_host` で落ちたhostにも `cert_host_unreachable` factが残り、後続playの `hostvars[h]` から読める(decoyで実測、§4 AC1)。
- probeタスク自身が `ignore_unreachable: true` を持つため、**play-levelの `ignore_unreachable` は付けていない**。付けると、probeを通過した後(証明書配布・pveproxy再起動中)にnodeが落ちた場合まで緑になり、本物の障害を隠す。到達不能を許容するのはprobeの一点だけに限定した。

## 3. summary生成の変更(P0-3)

- 各hostの行: `{% if hostvars[h].cert_host_unreachable | default(false) | bool %}` を最初の分岐として追加し、`{{ h }}: skipped (host unreachable)` を出す。これが無いと `cert_needs_renewal is not defined` の分岐に落ちて `check FAILED` と表示され、`slack_status` が `error` になる。
- host loopの直後に、到達不能hostだけを回すloopを追加して `WARNING: {{ h }} was unreachable and its certificate was not renewed.` を出す。既存の `slack_status` / `slack_channel` 式(`'FAILED' in ...` / `'WARNING' in ...`)をそのまま利用し、通知側の式は変更していない。
- 到達不能hostが無い実行では、追加した `{% for ... if ... %}` は0回転する。Ansibleの Jinja環境は `trim_blocks=True` のため block tagの行は出力に現れず、**summaryは変更前とバイト一致する**(AC5)。

## 4. Coordinator自身の確認(decoy、実host不使用)

実施場所: scratchpad。inventoryは `ansible_host: 127.0.0.1` / `ansible_port: 1`(閉ポート=到達不能)と `ansible_connection: local`(到達可能)のみで構成し、実host名・実IPを含まない。実playbookそのものではなく、`serial: 1` のproxmox playと前後のplayの**構造を再現した最小playbook**に対して実行した(実playbookは `hostname == quory` をassertするため、ansyでは第1 playで停止する)。

| 確認 | 結果 |
|---|---|
| 変更前の構造(probe無し)で片hostが到達不能 | **playbook全体が打ち切られ、後続の cleanup / notify playが実行されない。`rc=4`**。requirement §1の主張の根拠 |
| 変更後の構造で片host到達不能 | 到達不能側は `end_host` で落ち、到達可能側は後続タスクを実行。cleanup / notify playとも実行。`rc=0`。後続playから `hostvars['decoy-a'].cert_host_unreachable == True` を読めた |
| 変更後の構造で両host到達不能 | 両hostとも落ち、cleanup / notify playは実行。`rc=0` |

上記は機構の確認であり、**受入条件(AC)の判定はTesterが独立に行う**(Coordinatorは自分でACを閉じない)。
