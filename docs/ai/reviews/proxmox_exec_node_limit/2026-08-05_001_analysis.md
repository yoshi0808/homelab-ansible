# `roles/proxmox_exec_node` のT1が `--limit` を拒否する件 — 調査と結論

2026-08-05 / Coordinator。`docs/ai/status.md` Next の申し送り(出所: `docs/ai/adr/008-proxmox-readonly-check-unreachable-node.md` Consequences)に対する調査である。**結論はコードを変えないことなので、変更は role 冒頭のコメント1箇所だけである。**

## 申し送りの内容

`roles/proxmox_reachable_nodes` を新設したとき、同型のassertを**厳密一致から部分集合へ緩めた**(2026-07-30の差分レビュー Critical #1。`--limit <node>` 単一node実行が壊れたため)。そのとき「`roles/proxmox_exec_node` のT1でも `--limit` が許容されるべきかは本ADRの対象外」として残された。

## 調べたこと

| 観点 | 結果 | 確認手段 |
|---|---|---|
| Policyが `--limit` を許可している対象 | **healthcheck(SB-021)と patch dry-run(SB-023)の2つだけ**。**どちらも `proxmox_exec_node` を使わない** | `git grep -n '\-\-limit' -- docs/ai/policies` |
| 呼び出し側6本(`recovery_vm_reboot` / `recovery_ha_failover` / `recovery_service_restart` / `unifi_backup_fetch` / `proxmox_backup_restore_verify` / `proxmox_patch_weekly_full`)が `-l` を要するか | **1本も要さない。** ヘッダの使用方法に `--limit` / `-l` の記載が**0件** | 各playbookを `grep` |
| Semaphoreのテンプレートが `-l` を渡しているか | **渡していない。** カタログの全エントリが `arguments: []` で、対象はsurvey変数(`target` / `target_node`)で受ける。唯一 `-l quory` を持っていた1件は2026-08-04に**無効果と実測して空へ揃えた** | `roles/semaphore_templates/defaults/main.yml` |
| **人以外の呼び出し元**(自律復旧ラダー)が `-l` を使うか | **使わない。** `recovery-probe.py` の `run_playbook()` は `ansible-playbook playbooks/<x>` に `-e` だけを足して起動する。**`--limit` を組み立てる経路がコード上に存在しない** | `roles/recovery_probe/files/recovery-probe.py` L181-187 |

## 結論 — 厳密一致のまま維持する

**緩める理由が無く、緩めると壊れるものがある。**

`proxmox_reachable_nodes` は到達性を**観測**するだけなので、対象が絞られれば観測結果が絞られるだけである。`proxmox_exec_node` は**変更をどのノードで実行するかを選ぶ**ため、候補集合が狭まると**選択そのものが変わる** — `--limit pve2` の下では、pve1を選ぶべき場面でもpve2しか選べない。**見た目が同じassertでも、緩和の意味が同じではない。**

## 処置

**コードは変えない。** 代わりに `roles/proxmox_exec_node/tasks/main.yml` の冒頭へ、**厳密一致が意図であること・姉妹roleに合わせて緩めてはならないこと・その理由**を書いた。

理由は、この申し送りが**放置されると必ず「不整合」に見える**からである。2つのroleが並んでいて、片方だけが厳密で、その差の理由がどこにも書かれていない状態だった(ADRは「対象外」と書き、`proxmox_patch_weekly_full` のコメントも「out of scope here」と書いており、**どちらも理由そのものは持っていない**)。次に見た人が善意で揃えると、実行ノードの選定が壊れる。

**「直さない理由をコード側にも明記し、将来の読み手が善意で直そうとしないようにする」**(`skills/ansible-implementation-style/SKILL.md`)の適用である。
