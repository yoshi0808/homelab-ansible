## Safety classification

`playbooks/proxmox_snapshot_check.yml` has the header marker
`tester-gate: safe-readonly`. Its reason says that the caller has no notification
suppression condition and that `roles/common_slack/tasks/notify.yml` supplies the
actual `tester_mode` / `skip_notifications` guard. The common task does contain that
guard: it only sends when both values are false and otherwise shows a debug message.

The marker therefore permits a normal read-only diagnostic run without `--check`.
However, the full play also performs an idempotent copy to `/usr/local/sbin` on the
target, executes the collector, saves a local report, and can enter the notification
path. None of those effects is needed to validate the changed threshold expressions.
The test will use `skip_notifications=true` (not the deprecated `tester_mode`) and a
localhost source-task harness with synthetic data and a report directory under
`/tmp`. No APPLY-class playbook is run.

## Verification boundary

### Static

- Confirm the current target diff and that the collector shell has no diff.
- Run `git diff --check` for the two target files.
- Run playbook syntax check with Ansible temporary paths under `/tmp`.
- Run the repository tester-gate lint.
- Inspect the marker and notification guard together.

### Local source-task harness

Import the actual `roles/proxmox_snapshot_check/tasks/main.yml` into a localhost-only
play. Start at `Validate snapshot age thresholds`, provide fixed synthetic
`proxmox_snapshot_data` and `ansible_facts.date_time`, save reports only below
`/tmp`, and set `skip_notifications=true`.

Test the exact boundary values using warning=604800 seconds and
critical=2592000 seconds:

| Age | Expected status | Warning count | Critical count |
|---|---|---:|---:|
| 7 days - 1 second | OK | 0 | 0 |
| 7 days | WARNING | 1 | 0 |
| 30 days - 1 second | WARNING | 1 | 0 |
| 30 days | CRITICAL | 0 | 1 |

Also verify:

- A mixed warning/critical fixture has disjoint lists, preserves the legacy
  `stale_count`, and has `warning_count + critical_count == stale_count`.
- Collection failure without stale snapshots remains WARNING.
- Equal warning and critical thresholds are rejected by the source assert.
- A CRITICAL report maps to `slack_status=critical`; OK does not enter the common
  notification include. No real notification is sent.

### Real hosts

Do not run the play against the `proxmox` inventory group. The changed behavior is
deterministic Ansible classification over collector JSON and can be covered with the
actual source tasks locally. A remote run would add script placement, live `pvesh`
collection, local report creation, and a notification-path risk without improving
the boundary proof. Runtime collection and real Slack delivery remain unverified.

## Stop conditions

- Stop without remote fallback if the localhost harness cannot isolate notification
  delivery or would require secrets.
- Do not edit `playbooks/proxmox_snapshot_check.yml` or any target implementation.
- Do not request additional host privileges, send notifications, commit, or push.
