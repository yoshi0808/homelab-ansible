日付: 2026-07-22

## 実装結果

既存の7日以上をstaleとする判定をwarningとして維持し、30日以上をcriticalとする二段階判定へ拡張した。

### defaults

`roles/proxmox_snapshot_check/defaults/main.yml`へ次を追加した。

```yaml
proxmox_snapshot_check_critical_threshold_seconds: 2592000
```

30日を選んだ理由は、既存の7日warningから十分な猶予を置きつつ、月単位で残存するsnapshotを明確にエスカレーションできるためである。既存warningの意味を変更せず、setupが例示した値とも一致する。単位は既存変数に合わせてsecondsとした。

### tasks

`roles/proxmox_snapshot_check/tasks/main.yml`を次のように変更した。

- critical閾値がwarning閾値より大きいことを`assert`で検証する。
- 既存の`_stale_entries`（7日以上の全stale）を次の排他的な2集合へ分割する。
  - warning: 7日以上、30日未満
  - critical: 30日以上
- `proxmox_snapshot_report`へcritical閾値とwarning / criticalの件数・一覧を追加する。
- 後方互換の`stale_count` / `stale_snapshots`は7日以上の全staleとして残す。
- statusをcritical優先の`CRITICAL` / `WARNING` / `OK`へ拡張する。
- `collection_ok: false`または`errors`非空で、critical snapshotがない場合は従来どおり`WARNING`とする。
- 複数hostのSemaphore summaryでCRITICALを最優先し、後続WARNING hostで降格しないようにする。
- Slackのstatus / title / whenを3値statusへ対応させ、本文ではwarning / critical snapshotを別々に表示する。

`roles/proxmox_snapshot_check/files/proxmox-snapshot-collect.sh`は変更していない。収集はshell、閾値判定・分類・reportはAnsibleという責務分離を維持した。
