# Test Result: proxmox_snapshot_check critical threshold

Date: 2026-07-22

Tester: tester (Codex)

## Result

**PASS.** The implementation satisfies the pilot3 acceptance criteria covered by
the approved read-only boundary. The actual source tasks classified all four exact
age boundaries correctly, kept warning and critical snapshots mutually exclusive,
preserved the legacy stale total, retained collection failure as WARNING, and
rejected an invalid equal-threshold configuration.

No real host execution, APPLY, Slack delivery, additional privilege request, commit,
or push was performed.

## Safety decision

The playbook marker is `tester-gate: safe-readonly`. Its comment says notification
suppression is implemented in `roles/common_slack/tasks/notify.yml`; inspection
confirmed that the send block only runs when both `tester_mode` and
`skip_notifications` are false. The harness used the current supported control
`skip_notifications=true`, not the deprecated `tester_mode` input.

Although a normal run is permitted for this marker, the full play would copy the
collector to `/usr/local/sbin`, execute live `pvesh` collection, save a local report,
and potentially enter the notification path. These effects were unnecessary for a
deterministic classification change. I replaced the real-host run with a
localhost-only import of the actual source task file, fixed synthetic facts, reports
under `/tmp`, and notification suppression.

## Local source-task harness

The temporary harness imported the current repository file
`roles/proxmox_snapshot_check/tasks/main.yml` and began at
`Validate snapshot age thresholds`. It used localhost, a fixed epoch of 2000000000,
warning=604800 seconds, critical=2592000 seconds, synthetic collector JSON,
`skip_notifications=true`, and `/tmp/proxmox-snapshot-pilot3/reports`.

Representative execution command (repeated independently for each fixture):

```text
ANSIBLE_LOCAL_TEMP=/tmp/ansible-local-tester-pilot3 ANSIBLE_REMOTE_TEMP=/tmp/ansible-remote-tester-pilot3 ansible-playbook -i localhost, /tmp/proxmox-snapshot-pilot3/playbooks/harness.yml --start-at-task 'Validate snapshot age thresholds' -e @/tmp/proxmox-snapshot-pilot3/fixtures/<fixture>.yml
```

The generated JSON reports were independently asserted with `jq -e` for status,
legacy stale count, warning count, critical count, collection state, and list
membership.

| Fixture | Expected | Actual | Result |
|---|---|---|---|
| 7 days - 1 second | OK, warning 0, critical 0 | OK, 0, 0 | PASS |
| 7 days | WARNING, warning 1, critical 0 | WARNING, 1, 0 | PASS |
| 30 days - 1 second | WARNING, warning 1, critical 0 | WARNING, 1, 0 | PASS |
| 30 days | CRITICAL, warning 0, critical 1 | CRITICAL, 0, 1 | PASS |
| warning + critical mixed | CRITICAL, stale 2 = 1 + 1 | CRITICAL, stale 2 = 1 + 1 | PASS |
| collection failure, no stale snapshot | WARNING | WARNING | PASS |

The mixed fixture also confirmed that the expected snapshot names appeared in only
their respective warning or critical lists. Thus the new lists are disjoint and
their combined count equals the backward-compatible `stale_count`.

The equal-threshold fixture used warning=critical=604800. The actual source assert
failed before classification with exit 2 and the expected message that the critical
threshold must be greater than the warning threshold: PASS.

For WARNING and CRITICAL fixtures, the common notification include displayed the
synthetic message through its suppression branch. All webhook variable loading and
Slack send tasks were skipped. CRITICAL mapped to `slack_status: critical`; WARNING
mapped to `warning`. For OK, the notification include itself was skipped.

Each successful harness run reported two changed tasks, both limited to creating its
fixture report directory and JSON file under `/tmp`. There were no repository or
remote-host writes.
