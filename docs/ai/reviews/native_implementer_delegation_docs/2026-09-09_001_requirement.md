# Requirement: Implementer委任経路の規範を現行化する

## 1. 問題定義

現行の`new-session.sh`は、Codex Coordinatorをtmux pane 0で動かし、Reviewer / Tester /
Auditorだけをagmsg経由のClaude Codeペインとして起動する。Implementerは常駐ペインを持たず、
CoordinatorがCodex native subagentとして都度委任する。

一方、`docs/ai/roles/coordinator.md`、`docs/ai/context/operations/agent-messaging.md`、
ADR-012、`docs/ai/status.md`はImplementerをagmsg経由のCodexとして記述しており、存在しない
monitor配送確認を残タスクとしている。

## 2. ゴール

- Implementerの起動経路をCodex native subagentとして一意に読めるようにする。
- agmsgの適用範囲をCoordinatorとReviewer / Tester / Auditor、remote Operatorへ限定する。
- model / effortの既定値は維持し、経路に合う指定方法へ直す。
- statusから存在しないImplementer monitor確認を除去する。

## 3. 非ゴール

- agmsg本体、team登録、tmux launcherを変更しない。
- Roleの責任分界、作る側 / 検める側のCLI分離、model / effort値を変更しない。
- Reviewer / Tester / AuditorまたはOperatorの配送方式を変更しない。

## 4. ユーザーストーリー

Coordinatorとして、Implementerを使うときにagmsg monitorの準備や配送確認を要求されず、
実在するnative subagent経路で迷わず委任したい。

## 5. 要件

### P0

| # | 要件 |
|---|---|
| P0-1 | Coordinator RoleはImplementerをCodex native subagentとして都度起動し、agmsg / tmux常駐を使わないと定める |
| P0-2 | agent-messaging Contextでlocal teamの登録rosterと現行launcherが使うactive経路を区別し、Implementerの旧登録が残っていても起動・配送には使わないこと、現行のactive経路がCoordinator / Reviewer / Tester / Auditorであることを記述する |
| P0-3 | ADR-012とCoordinator Roleのmodel指定方法を、Implementerはnative delegation、検める3Roleはagmsg spawnとして区別する |
| P0-4 | statusのImplementer monitor確認を削除し、旧agmsg構成を述べる現在地を現行化する |
| P0-5 | 作る側 / 検める側の独立性、既定model / effort、Coordinator monitor、checking Roleのagmsg配送を変更しない |

### P1

| # | 要件 |
|---|---|

### P2

- 過去の案件記録は当時の証跡として書き換えない。

## 6. 成功指標・受入条件

| AC | Given / When / Then |
|---|---|
| AC1 | Given Coordinator Role、When Implementerの起動欄を読む、Then native subagent・非agmsg・非常駐が一意に分かる |
| AC2 | Given agent-messaging Context、When local teamとmonitor/spawn手順を読む、Then Implementerの旧登録の有無とactive経路を混同せず、Implementerを起動・配送に使わないこと、checking RoleとCoordinatorの経路が一意に分かる |
| AC3 | Given model / effort節とADR-012、When起動方法を読む、Then Implementerはnative delegationで`gpt-5.6-luna` medium、複雑案件はhigh、検める3Roleはagmsg spawnでsonnet mediumと読める |
| AC4 | Given status、When Nowと現行体制の説明を読む、Then Implementer monitor確認が残タスクとして現れない |
| AC5 | Given変更後の現行規範群、When旧経路語を検索しdoc consistencyを実行、Then過去の案件記録以外にImplementerをagmsg経由とする断定が残らず、検査rc=0となる |

## 7. オープンクエスチョン

なし。現行launcherとCodex native subagentの実在に合わせる文書修正である。

## 8. タイムライン考慮

requirementとplan作成後に規範を修正し、別CLI Reviewerの規範レビュー、doc consistency、
旧語掃引を通してから確定する。
