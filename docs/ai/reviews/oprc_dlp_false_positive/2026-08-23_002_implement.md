## 2. R1 — candidate_pattern と min_length の変更(2026-08-23 3回目の差し戻しで `=` 除外を追加)

区切り文字 `/` `_` `-` `.` の4つを文字クラスから外した。あわせて `min_length` を20から16へ下げた(requirement §8、Yoshinobu承認済み。非ゴールは「`min_bits_per_char` を上げない」に限定され、`min_length` を下げることは検出を戻す方向として明示的に許可されている)。

**さらに `=` も文字クラスから外した(2026-08-23、Reviewer Highによる3回目の差し戻し、Yoshinobu承認済み)。** 当初は`+`とともに「base64のpadding・content文字であり区切りではない」という理由で残していたが、これは誤りだった。Reviewerが実repoから機械抽出したsystemd unit断片 `Description=Reload`(18文字)・`Description=Monthly`(19文字)・`LockPersonality=yes`(19文字)が、`min_length=16`でいずれも `high-entropy-string` としてBLOCKされることが判明した。**原因は`=`が候補の文字クラスに含まれていたため、`key=value`形式の断片がひと続きの候補として結合されていたこと。** `=`はbase64ではpaddingとして末尾にしか出現せず、`key=value`のような構造化text中では区切りとして働く2つの異なる文脈を1文字が兼ねていた。R1が`/``_``-``.`を区切りとして外した理由(「構造を持つ文字列は短い語の集まりとして候補から外れる」)がそのまま`=`にも当てはまる。

```
requirement提示時点(20260808):  candidate_pattern=[A-Za-z0-9+/_=.-]{20,}  min_length=20
1回目差し戻し後(R1のみ):        candidate_pattern=[A-Za-z0-9+=]{16,}      min_length=16  ← `=`を候補として残していた(誤り)
現在(3回目差し戻し反映後):      candidate_pattern=[A-Za-z0-9+]{16,}       min_length=16
```

`_scan_impl` は `finditer` で連続マッチを候補として切り出す(`oprc/dlp.py:259`)ため、区切り文字が文字クラスから外れた時点で、区切りをまたぐ候補は自動的に分割される。`rules`(パターン規則)は候補抽出と独立した別ループ(`oprc/dlp.py:249-251`)なので、この変更の影響を受けない。`candidate_pattern` の `{16,}` と `min_length: 16` は同じ下限を二重に持つ形になっている — `候補抽出`(regex)と`候補の採否`(entropy計算に進めるかのフィルタ、`oprc/dlp.py:261`)の両方が16文字を下限にしている。

### なぜ緩めすぎではないか

- **entropy自体の閾値(3.8 bits/char)は一切動かしていない。** `min_length` を下げても、断片が3.8 bits/char以上でなければ止まらない。
- **パターン規則13件は候補抽出と無関係な別ロジックであり、1件も変えていない。** §7の実測どおりすべて従来どおり発火する。
- **区切りを持たない一塊(base64・トークン・commit hash)は`candidate_pattern`の区切り除去による影響を受けない** — これらの文字列自体に `/` `_` `-` `.` `=` が含まれない限り、候補として抽出される長さは変わらない。`min_length` を16へ下げたことで、むしろこれらは16〜19文字の短い断片でも新たに検出対象へ入るようになった(検出力が上がる方向)。
- **`=` を外したことによる検出率への影響は小さい。** §3(C)の実測で、`=`除外の唯一の効き目はpadding付きtokenの末尾がわずかに短くなることに限られ、最悪ケース(20バイトのURL-safe)でも77.62%→75.03%の低下に留まる(§3(C))。実際に人がコピー&ペーストする秘密文字列はpaddingを含まない形が多く、その場合は§3(B)のとおり影響ゼロである。
- **`min_length` を16まで下げたことで誤検知が増えないと一般化はできない。** 当初のrequirement §8実測(語彙8種・0/8)と本記録の独自fixture(8種・0/8、§7)は、いずれも**自分で選んだ標本**でしかなかった(Reviewer 2026-08-23_006指摘Finding 1)。**手選びでない標本(§3(8)、対象拡張子に該当する全ディレクトリの追跡ファイル・`docs/ai/memory/`除外の1,737本)で再検証した結果、16〜19文字の候補130種のうち5種が実際にBLOCKした** — うち`UNREACHABLE+report`(18文字)は、この案件の対象範囲(区切りのある通常語彙)に該当する**正真の新規誤検知であり、0/8では見えていなかった**。requirement §8はこの5件を前提に採用根拠を書き直しており(Coordinator対応)、本記録もそれに合わせて「AC1の3具体例(Ansible変数名・aptパス・repoパス)は通る」以上の一般化はしない。詳細は§3(8)。
- **影響が及ぶのは「区切り文字を含む文字列」だけであり、これは要求の非ゴールにある「区切り文字を含む未知形式の秘密を見逃す」という承知済みのリスクと表裏一体である。** §3に再測した検出率のとおり、これは緩め過ぎの判定ではなく**数値を明示したうえでの受容判断**であり、その数値がここにある。
- **ただし、区切りを持たない語彙(PascalCase識別子・commit hashそのもの)は今回の変更と無関係に元から誤検知しうる。** §3(8a)の5ルート・376ファイル母集団で手分類した14件(例: `StrictHostKeyChecking`、`PrometheusVariableQueryEditor`)が代表例である。これらはいずれも `/``_``-``.``=` を1文字も含まないため、**今回のR1変更(区切り除去・min_length変更)より前から、変更前のruleset(min_length=20、`=`を含む旧candidate_pattern)でも同一の判定になっていた既存の問題であり、今回のスコープではない。**(§3(8b)の最終母集団1,737本で20文字以上を数え直すと263種・BLOCK57種であり、この14件はそのうちの手分類済みの一部にすぎない。全数の分類は本案件のスコープ外。)

## 3. §6/§8 の実測(2026-08-23 Reviewer指摘 H1 により訂正)

**訂正内容**: 初版は「出現間隔」と称して実際には「有限トークンを分割した断片の長さ」(先頭・末尾の打切り区間を含む)を測っており、用語が違うものを安全性の根拠にしていた。また `os.urandom()` を使いながら「seed固定・再現可能」と書いており、同じ標本を作り直せなかった。以下は両方を訂正した再測である。

**方法**: `random.Random(SEED)`(`SEED=20260823`)で完全に再現可能な乱数列を作り、`os.urandom` は使わない。エントロピー計算・候補抽出は自前で再実装せず、**実際に配備される `oprc/dlp._shannon_entropy()` と、実際に配備される `dlp-rules.json` をパースして得た compiled `candidate_pattern`** をそのままインポートして使う(数式の写し間違いで実装と記録が乖離するのを防ぐため)。スクリプト全文と実行結果は以下のとおりで、同じ環境で再実行すれば同じ数値が出る。

```python
#!/usr/bin/env python3
"""Reproducible measurement for oprc_dlp_false_positive H1. Run:
    python3 entropy_sim.py
Uses random.seed() (not os.urandom) so re-running reproduces the same
numbers. Imports the actual production code (oprc.dlp._shannon_entropy
and the compiled candidate_pattern from the deployed dlp-rules.json)
instead of reimplementing the entropy formula.
"""
import base64, random, statistics, sys

REPO_ROOT = "/home/yoshi/homelab-ansible"
sys.path.insert(0, REPO_ROOT + "/roles/operator_request_channel/files")
from oprc import dlp

SEED = 20260823
DELIMITER_STREAM_LEN = 2_000_000
N_PER_SIZE = 20_000
SIZES_BYTES = [20, 24, 32, 40, 48]

STD_ALPHABET = list("ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/")
URLSAFE_ALPHABET = list("ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-_")

def measure_delimiter_interval(alphabet, sep_chars, rng):
    # Position-to-position distance between consecutive delimiter chars in
    # one long uniform-random stream -- the alphabet's own property,
    # independent of any finite token's boundaries.
    stream = rng.choices(alphabet, k=DELIMITER_STREAM_LEN)
    positions = [i for i, c in enumerate(stream) if c in sep_chars]
    diffs = [b - a for a, b in zip(positions, positions[1:])]
    return statistics.mean(diffs), len(positions)

def split_fragment_lengths(token, sep_chars):
    lengths, cur = [], 0
    for ch in token:
        if ch in sep_chars:
            lengths.append(cur); cur = 0
        else:
            cur += 1
    lengths.append(cur)
    return lengths

def load_live_ruleset():
    with open(REPO_ROOT + "/roles/operator_request_channel/files/dlp-rules.json") as f:
        return dlp.parse_ruleset(f.read())

def still_detected(token, entropy_cfg, min_length_override=None):
    # min_length_override=20 reproduces the pre-fix threshold on an
    # identical token without touching candidate_pattern: candidate_pattern
    # is greedy, so [A-Za-z0-9+=]{16,} always matches the same maximal run
    # that [A-Za-z0-9+=]{20,} would (when that run is >=20 chars); filtering
    # by len(candidate) < min_length afterward reproduces the stricter
    # regex's result exactly.
    min_length = entropy_cfg["min_length"] if min_length_override is None else min_length_override
    for m in entropy_cfg["candidate_pattern"].finditer(token):
        cand = m.group(0)
        if len(cand) < min_length:
            continue
        if dlp._shannon_entropy(cand) >= entropy_cfg["min_bits_per_char"]:
            return True
    return False

def main():
    rng = random.Random(SEED)
    ruleset = load_live_ruleset()
    entropy_cfg = ruleset["entropy"]
    print("live entropy config: min_length={} min_bits_per_char={} candidate_pattern={!r}".format(
        entropy_cfg["min_length"], entropy_cfg["min_bits_per_char"],
        entropy_cfg["candidate_pattern"].pattern))
    print()

    print("=== delimiter interval (unbounded stream, alphabet property only) ===")
    for label, alphabet, sep in [("standard base64 ('/')", STD_ALPHABET, set("/")),
                                  ("url-safe base64 ('-'/'_')", URLSAFE_ALPHABET, set("-_"))]:
        mean_gap, n_delims = measure_delimiter_interval(alphabet, sep, rng)
        print("  {}: mean position-to-position interval = {:.2f} chars (n_delimiters={} out of {} stream chars)".format(
            label, mean_gap, n_delims, DELIMITER_STREAM_LEN))
    print()

    print("=== split-fragment length and detection rate per secret size (N={} trials/size, seed={}) ===".format(
        N_PER_SIZE, SEED))
    print("{:<10} {:>6} {:>16} {:>14} {:>14} {:>14}".format(
        "kind", "bytes", "mean_frag_len", "detect@16_%", "detect@20_%", "n_trials"))
    for kind, encode_fn, sep_chars in [
        ("standard", lambda b: base64.b64encode(b).decode("ascii").rstrip("="), set("/")),
        ("urlsafe", lambda b: base64.urlsafe_b64encode(b).decode("ascii").rstrip("="), set("-_")),
    ]:
        for nbytes in SIZES_BYTES:
            frag_lengths, hits16, hits20 = [], 0, 0
            for _ in range(N_PER_SIZE):
                data = bytes(rng.getrandbits(8) for _ in range(nbytes))
                token = encode_fn(data)
                frag_lengths.extend(split_fragment_lengths(token, sep_chars))
                if still_detected(token, entropy_cfg):
                    hits16 += 1
                if still_detected(token, entropy_cfg, min_length_override=20):
                    hits20 += 1
            print("{:<10} {:>6} {:>16.2f} {:>13.2f}% {:>13.2f}% {:>14}".format(
                kind, nbytes, statistics.mean(frag_lengths),
                100.0 * hits16 / N_PER_SIZE, 100.0 * hits20 / N_PER_SIZE, N_PER_SIZE))
    print()

    print("=== aggregate across all 5 sizes (equal weight per size) ===")
    for kind, encode_fn, sep_chars in [
        ("standard", lambda b: base64.b64encode(b).decode("ascii").rstrip("="), set("/")),
        ("urlsafe", lambda b: base64.urlsafe_b64encode(b).decode("ascii").rstrip("="), set("-_")),
    ]:
        total_hits16 = total_hits20 = total_trials = 0
        for nbytes in SIZES_BYTES:
            for _ in range(N_PER_SIZE):
                data = bytes(rng.getrandbits(8) for _ in range(nbytes))
                token = encode_fn(data)
                total_trials += 1
                if still_detected(token, entropy_cfg):
                    total_hits16 += 1
                if still_detected(token, entropy_cfg, min_length_override=20):
                    total_hits20 += 1
        print("  {}: detect_rate@16(shipped) = {:.2f}%  detect_rate@20(pre-fix) = {:.2f}%  (n={})".format(
            kind, 100.0 * total_hits16 / total_trials, 100.0 * total_hits20 / total_trials, total_trials))

if __name__ == "__main__":
    main()
```

### (1) 「出現間隔」と「分割片長」は別の数字である

**真の出現間隔**(区切り文字自体がアルファベット中に占める割合だけで決まる、無限長ストリームでの位置差)は、標準base64(`/` 1文字/64)で **63.66文字**、URL-safe base64(`-`/`_` 2文字/64)で **32.03文字** — 解析値(標準1/(1/64)=64、URL-safe 1/(2/64)=32)とほぼ一致する。**これは初版が「平均間隔」と呼んでいた25.45/18.07とは異なる数字であり、初版の値は正しくは「分割片長」(有限トークンを実際に区切って得られる断片の長さ、先頭・末尾の打切り区間を含む)である。** 上表の `mean_frag_len` 列がこれに当たる(標準18.98〜31.46文字、URL-safe14.46〜20.64文字、サイズが小さいほど短くなる — トークン全体が短いので打切りの影響が相対的に大きいため)。

### (3) 4つのcheckpointで見逃し率が独立に下がるわけではない

送信前・受入前・持ち出し前・取り込み前の4つのDLP検査点(`docs/ai/context/operations/operator-request-channel.md` §4)は、**同一payload・同一rulesetに対する決定的な判定である。** ある20バイトのURL-safe秘密がcheckpoint 1(ansy送信前)を通過したなら、同じruleset・同じpayloadで動くcheckpoint 2(quory受入前)も同じ判定(通過)になる — 独立な4回の抽選ではなく、**1回の判定結果が4箇所で複製される。** 見逃し率を「4回のうち1回でも止まればよい」という前提で割り引いて読まない。

### (4) commit hash(40hex)は変更の影響を受けない

```python
Finding 1 on 2026-08-23_007_review.md): the previous version of this
script filtered `git ls-files` by extension only, which let it read

2026-08-23_009_review.md Finding 3 additionally pointed out that this
script never counted candidates >=20 chars, so a claim elsewhere in this
record that ">=20-char BLOCKs stay at 44/14 no matter how far the corpus

No randomness involved -- this is a deterministic sweep, not a
simulation, so there is no seed to fix.

REPO_ROOT = "/home/yoshi/homelab-ansible"
sys.path.insert(0, REPO_ROOT + "/roles/operator_request_channel/files")
from oprc import dlp

EXTS = {".yml", ".yaml", ".j2", ".md", ".sh", ".py", ".json", ".cfg", ".service", ".timer"}
EXCLUDE_PREFIXES = ("docs/ai/memory/",)

def main():
    with open(REPO_ROOT + "/roles/operator_request_channel/files/dlp-rules.json") as f:
        ruleset = dlp.parse_ruleset(f.read())
    ec = ruleset["entropy"]
    pattern = ec["candidate_pattern"]
    min_length = ec["min_length"]
    min_bits = ec["min_bits_per_char"]

        ["git", "-C", REPO_ROOT, "ls-files"], capture_output=True, text=True, check=True
    ).stdout.splitlines()
    files = [
        f for f in files
        if os.path.splitext(f)[1] in EXTS and not f.startswith(EXCLUDE_PREFIXES)
    ]

    seen = {}
    for rel in files:
        path = os.path.join(REPO_ROOT, rel)
        try:
            with open(path, "r", encoding="utf-8", errors="ignore") as fh:
                text = fh.read()
        except OSError:
            continue
        for m in pattern.finditer(text):
            cand = m.group(0)
            if len(cand) < min_length:
                continue
            if cand not in seen:
```
