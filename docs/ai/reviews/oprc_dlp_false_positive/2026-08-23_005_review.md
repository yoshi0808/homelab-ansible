## `=` / Base64 Check

- standard Base64 と URL-safe Base64 は、単一encoded datumでは末尾に0〜2個の `=` paddingを持つだけで、中間には置かない。中間に `=` が見える文字列は、独立にpaddingされた複数segmentや `key=value` 等を連結した構造であり、単一のstandard/URL-safe Base64 tokenではない。
- 別seed・standard/URL-safe各10,000 tokenで、`[A-Za-z0-9+]{16,}` が padded と `rstrip('=')` から抽出する候補列を比較し、両方とも mismatch 0を確認した。したがって前回 Medium 2のpadding条件差は構造的に解消している。
- 埋め込み測定の20B padded tokenは、`=`あり→なしで standard 89.22%→87.69%、URL-safe 77.62%→75.03%。除外コストが末尾1〜2文字の境界効果に限られる説明と整合する。
- ただし `+` はstandard Base64の本体文字なので、Finding 1の反例を理由に機械的に除外すれば検出率へ別の影響が出る。採否は新しいmatched-pair測定を伴って決める必要がある。
