## 指摘

### must-fix: 長い／折返された承認対象を固定14行・12行・8行の窓で見逃す

- 対象: `scripts/tmux-ask-watch.sh:140-149`, `scripts/tmux-ask-watch.sh:168-187`
- テスト不足: `scripts/tests/test-tmux-ask-watch.sh:29-48`

検出は次の固定上限を持つ。

- 質問は最終非空行から14行以内だけ探索する。
- Codex の選択肢は質問から12行以内だけ探索する。
- Claude の `Bash command` header は質問前8行以内だけ探索する。

コマンドが複数行、長い引数、shell の折返し表示、heredoc 等でこれを超えると、実際には
選択待ちの承認 UI でも `extract_ask` が空になる。

追加確認では次の両方が未検出だった。

1. Codex 形式: 質問と選択肢の間に13行のコマンド表示。
2. Claude 形式: `Bash command` header と質問の間に9行のコマンド表示。

`CAPTURE_LINES` の範囲内で末尾近傍の既知 indicator から逆向きに対応する質問・header を
探索するなど、承認対象の表示長と独立した検出にする必要がある。誤検出防止は完全一致の質問、
選択肢構造、承認対象の存在確認で維持できる。

少なくとも以下を positive fixture として追加すること。

- 13行以上または端末折返し相当の Codex command block。
- 9行以上の Claude `Bash command` block。

## 実 UI 検出と誤検出耐性

- 既存 `positive-codex.txt`: 検出 OK。
- 既存 `positive-claude.txt`: 検出 OK。
- 通常質問、indicator 不足、選択肢のみ、tutorial＋Yes/No、generic proceed＋Yes/No:
  すべて非検出で OK。
- ただし positive fixture は1行 command の簡略形だけであり、上記の表示長境界をカバーしない。

## fingerprint

- 同じ command で進捗行と選択カーソルだけが異なる fixture: 同一 hash、OK。
- command 本文が異なる fixture: 異なる hash、OK。
- command 本文はローカルの hash 入力にだけ使われ、通知本文には転載されない。

## capture-pane 異常時の state

- pane が再列挙でも存在する一時エラー: 旧 hash を維持し、scan は非0終了、OK。
- pane が再列挙で消滅済み: 旧 hash を削除、OK。
- `list-panes` 再確認自体が失敗した場合も pane 消滅とは決めつけず旧 hash を維持する、OK。

## 通知非漏洩・読み取り専用性

- 通知本文は検証済み pane ID と12桁の16進 fingerprint、および固定文だけ。
- capture の command / 質問、任意入力の session 名は通知へ含めないテストが成功。
- mock 統合経路でも `EXAMPLE_SECRET` が send log にないことを確認。
- tmux サブコマンドは `list-panes` / `capture-pane -p` だけ。
- `send-keys`、`run-shell`、キー入力、承認操作はない。
- capture を shell code として評価しない。
