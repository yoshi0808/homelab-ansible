現状は **commit 不可**。前回5件のうち3件は解消したが、誤検出と fingerprint の問題は
未解消で、追加テストにより再現した。`must-fix` 2件、`suggestion` 1件がある。

## 指摘

### must-fix: 通常会話＋番号付き Yes/No を承認 UI と誤検出する

- 対象: `scripts/tmux-ask-watch.sh:131-160`
- テスト不足: `scripts/tests/test-tmux-ask-watch.sh:29-38`

質問 regex は `would you like to run` まで一致すれば後続文字を問わず、indicator も
`1. Yes` のような1行が末尾14行内のどこかにあれば成立する。このため、実際の承認 UI
ではない次の通常会話が `extract_ask` から出力される。

```text
Here is a normal tutorial response.
Would you like to run through another example?
1. Yes
2. No
```

再現結果:

```text
question:would you like to run through another example?
choice:1. yes
choice:2. no
```

質問文を既知 UI の完全な文型へ寄せ、indicator は質問より後かつ近傍にある既知の複数選択肢
またはキー案内との組み合わせを要求する必要がある。上記ケースを negative fixture として
追加すること。

### must-fix: 異なるコマンドの承認要求が同一 fingerprint になり、通知を見逃す

- 対象: `scripts/tmux-ask-watch.sh:145-160`, `scripts/tmux-ask-watch.sh:267-274`
- テスト不足: `scripts/tests/test-tmux-ask-watch.sh:35-38`

正規化出力が質問と選択肢だけで、承認対象のコマンド本文を完全に除外している。Codex の
承認 UI は質問・選択肢が共通なので、コマンドだけが異なる2要求は同じ hash になる。

次の2入力で `extract_ask` の出力が同一になることを確認した。

```text
Would you like to run the following command?
command-one
1. Yes, proceed
2. No
```

```text
Would you like to run the following command?
command-two
1. Yes, proceed
2. No
```

poll 間隔内に最初の承認が解消され、同じ pane に別コマンドの承認が表示された場合、watcher は
hash の変化を観測できず通知を見逃す。前回の「周辺表示の変化で再通知」を避けつつ、承認対象の
安定した本文はローカル fingerprint に含める必要がある。通知本文を固定文のまま維持すれば、
コマンド本文を hash 入力に使っても直接の秘密情報混入は起きない。

少なくとも次の2回帰テストを追加すること。

- 同じコマンドで進捗行・カーソルだけが違う fixture: fingerprint は同一。
- コマンド本文が異なる fixture: fingerprint は異なる。

### suggestion: `capture-pane` の全失敗をペイン消滅として扱い、旧 state を消す

- 対象: `scripts/tmux-ask-watch.sh:255-280`
- 関連テスト: `scripts/tests/test-tmux-ask-watch.sh:133-134`

`list-panes` に現れた pane の `capture-pane` が失敗すると、理由を記録せず
`CURRENT_HASH` から除外し、scan 終了時に旧 hash を消す。実際の pane 消滅なら妥当だが、
一時的な tmux/socket/permission エラーでも次回復旧時に同じ承認を再通知する。

少なくとも stderr を保持して警告することを推奨する。信頼性を優先するなら、capture 失敗後に
pane の存在を再確認し、消滅が確認できない場合は旧 hash を維持するか scan 自体を失敗させる。
テストも pane 消滅だけでなく、一時的 capture error の state 方針を明示すべきである。

## 安全性確認

- tmux サブコマンドは `list-panes` / `capture-pane -p` のみ。
- `send-keys`、`run-shell`、キー入力、承認操作はない。
- capture 内容を shell code として評価しない。
- `notify_ask` は capture / session の文字列を通知へ入れない。
- state file は `umask 077`、一時ファイル `0600`、同一ディレクトリ内 `mv` で更新する。
- state lock は同一 state file の複数 watcher を拒否する。
- dry-run は state file / lock file / agmsg を変更しない。
