## 指摘

### must-fix: command 行中の key 案内文字列を stale indicator と誤認する

- 対象: `scripts/tmux-ask-watch.sh:143-145`, `scripts/tmux-ask-watch.sh:191-200`
- 関連: `scripts/tmux-ask-watch.sh:164-180`, `scripts/tmux-ask-watch.sh:236-244`
- テスト不足: `scripts/tests/test-tmux-ask-watch.sh:29-40`

choice は `normalize_choice` で UI 行頭構造へ限定されたが、`is_key_indicator` は引き続き
次の行中部分一致である。

```text
/press enter to confirm|esc(ape)? to cancel/
```

このため shell command、引数、文字列リテラル、説明文に key 案内相当文字列が含まれると、
question への逆探索中に `stale_boundary=1` となり、正規 ASK 全体が棄却される。

次の有効な Codex 形式が未検出になることを確認した。

```text
Would you like to run the following command?
$ printf Press Enter to confirm
1. Yes, proceed
2. No
```

key indicator も `normalize_choice` と同様に、既知カーソル・空白を正規化した後の既知 UI 行構造
だけを受理する共通関数へまとめる必要がある。その関数を末尾 indicator 抽出、stale boundary、
fingerprint 出力の全箇所で一貫して使うこと。

上記ケースを positive fixture として追加し、次を同時に維持すること。

- command 内の key 案内相当文字列は command として扱い、ASK を検出する。
- 実際の過去 key indicator 行は stale boundary として機能する。
- 実際の末尾 key-only UI をサポート対象にするなら、その positive fixture も追加する。
