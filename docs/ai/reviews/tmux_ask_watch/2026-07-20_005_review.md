## 指摘

### must-fix: command 行中の `1. Yes` を stale indicator と誤認して正規 ASK を見逃す

- 対象: `scripts/tmux-ask-watch.sh:132-136`, `scripts/tmux-ask-watch.sh:177-186`
- テスト不足: `scripts/tests/test-tmux-ask-watch.sh:29-39`

`is_choice` は次の部分一致で判定する。

```text
/(^| )[123][.)] *(yes|no|allow|approve)/
```

この判定は UI 選択肢だけでなく、shell command、引数、文字列リテラル、説明文の途中にある
`1. Yes` にも一致する。末尾 indicator から question へ逆探索する途中で command 行が
この条件に一致すると、`stale_boundary=1` となり正規の承認 UI 全体を棄却する。

次の有効な Codex 形式が未検出になることを確認した。

```text
Would you like to run the following command?
$ printf menu: 1. Yes or 2. No
1. Yes, proceed
2. No
```

UI indicator の判定は行中の部分一致ではなく、行頭の空白と既知カーソル記号だけを除いた後に
`1.` / `2.` / `3.` が始まる構造へ限定する必要がある。同じ厳密な判定を、末尾 indicator 群の
抽出、stale boundary、fingerprint の choice 正規化で一貫して使うこと。

上記ケースを positive fixture として追加し、次を同時に維持すること。

- command 内に選択肢相当文字列があっても検出する。
- stale approval の本物の旧 indicator 群は境界として棄却する。
- 選択カーソル位置の変化で fingerprint が変わらない。
