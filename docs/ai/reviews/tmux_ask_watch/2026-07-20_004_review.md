## 指摘

### must-fix: 末尾の通常 Yes/No を古い承認質問へ結び付けて誤通知する

- 対象: `scripts/tmux-ask-watch.sh:149-208`
- テスト不足: `scripts/tests/fixtures/tmux-ask-watch/negative-stale-approval.txt`
- 関連 assertion: `scripts/tests/test-tmux-ask-watch.sh:38`

末尾の連続 indicator 群を確定した後、最も近い既知 question まで距離・構造境界なしで
逆向き探索する。question と現在の indicator の間に、過去の選択肢、完了出力、通常会話が
あっても、Codex 分岐ではそれらをすべて command block として受理する。

次の capture が承認 UI として抽出されることを確認した。

```text
Would you like to run the following command?
old-command
1. Yes, proceed
2. No
Command completed successfully.
Choose whether to continue the tutorial:
1. Yes
2. No
```

再現結果では `old-command` から通常会話までが `command:` とされ、末尾の `1. Yes / 2. No`
が現在の承認選択肢として出力された。したがって処理済みの古い質問が capture 範囲に残る限り、
通常回答末尾の選択肢で誤通知し得る。

現行 `negative-stale-approval.txt` は古い選択肢の後が通常文で終わるため、末尾 indicator の
探索が即座に止まる簡単なケースしか検証していない。

固定の短い行数上限へ戻さず、構造境界を追加する必要がある。例えば:

- 古い question と現在 indicator の間に別の既知 choice/key indicator 群があれば、対応候補を
  stale として棄却する。
- Claude 形式は command が question より前なので、question と現在 indicator の間に通常出力を
  許さず、空行・既知 UI 装飾だけを許可する。
- Codex 形式は question 後の command block 先頭・終端の既知構造を確認し、完了後の通常出力を
  command として取り込まない。

上記再現ケースを negative fixture として追加すること。長文 positive fixture との両立も
回帰テストで維持する必要がある。
