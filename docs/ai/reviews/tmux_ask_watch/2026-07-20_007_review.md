## 検出ロジック

- 標準 Codex / Claude UI: 検出。
- Codex 14行 command / Claude 10行 command: 検出。
- command 内 `1. Yes / 2. No`: command として扱い、ASK を検出。
- command 内 `Press Enter to confirm`: command として扱い、ASK を検出。
- key-only approval: 検出。
- 通常質問、indicator 不足、選択肢のみ、tutorial/generic Yes/No: 非検出。
- stale approval 後が通常文、通常 Yes/No、key indicator を経由するケース: 非検出。

choice と key indicator は、既知カーソルを除去した後の行頭・行全体 UI 構造へ限定されている。
そのため command 本文との語彙衝突を避けながら、過去 indicator 群を逆探索の構造境界として
利用できている。

## fingerprint

- 同一 command で進捗行と選択カーソルだけが異なる場合: 同一 hash。
- command 本文が異なる場合: 異なる hash。
- 長文 command と command 内 choice/key 文字列も fingerprint 入力に保持される。
- capture 本文はローカル hash 入力にのみ使い、通知へ転載しない。

## 通知・秘密情報

- 通知本文は検証済み pane ID、12桁の16進 fingerprint、固定文だけ。
- command、質問、任意 session 名は通知へ含めない。
- `EXAMPLE_SECRET` を含む fixture の mock send log に平文漏洩なし。
- capture を shell code として評価しない。

## state・競合・異常系

- state file は `umask 077`、一時ファイル `0600`、同一ディレクトリ内 `mv` で更新。
- state file 単位の non-blocking `flock` により複数 watcher を拒否。
- tmux server 不在は空 state として成功扱い。
- 予期しない `list-panes` エラーは旧 state を保持して非0終了。
- `capture-pane` 一時エラーは pane 再確認後、旧 state を保持して非0終了。
- pane 消滅が確認できた場合だけ旧 state を削除。
- dry-run は通知、state、lock file を変更しない。

## 読み取り専用性

- tmux サブコマンドは `list-panes` / `capture-pane -p` のみ。
- `send-keys`、`run-shell`、キー入力、承認操作はない。
- 書き込みは一時作業領域、state file、agmsg 通知に限定される。
