# requirement(pre-commit検査の拡張と、staged定義の一本化)

2026-08-05 / Coordinator。`docs/ai/status.md` Next の2項目を1案件にまとめたもの。**同じファイル群(`scripts/` と pre-commit 経路)を触るため、別々に走らせると衝突する**という理由で束ねている。

## 1. 問題定義

**(a) 新しい playbook を足しても、Semaphore のボタンが無いことに誰も気づかない。**

2026-08-04 に setup 系9本で実際に起きた。playbook は repo にあるのに、押す手段が Semaphore に無い状態が長期間続いていた。**`roles/semaphore_templates/defaults/main.yml` のカタログが正本になった今、突合は機械的にできる。**

**(b) 「staged とは何か」の実装が2つある。**

`scripts/git-pre-commit-check.sh` は `git -c core.quotepath=false diff --cached --name-only --diff-filter=ACMR` で一覧を取り、**引用符が残るパスを検査不能として拒否する**(安全側で停止)。一方 `scripts/check-deploy-needed.py` は `git_staged_paths()` で**自前に `git diff --cached` を叩き直している**。**片方だけが安全側の扱いを持っており、両者が食い違いうる。**

## 2. ゴール

- 新しい playbook にボタンが無いことを、commit 時に**気づける**
- staged の定義を1つにし、安全側の扱いが全経路へ効く

## 3. 非ゴール

- **ブロックすること。** (a) は助言に留める — **template が不要な playbook が現に存在する**(他のplaybookから `import_playbook` されるもの、単発の手動用など)。ブロックすると正しい commit が止まる
- pre-commit が行う既存の判定内容を変えること。(b) は取得経路の一本化であって、判定の変更ではない
- Semaphore 側の実物との突合。それは日次ドリフト検査(R9、2026-08-04実装)が持つ

## 4. 要件

**R1. 新規 playbook にカタログ定義が無ければ助言する**

staged に**新しく追加された** `playbooks/*.yml` があり、`roles/semaphore_templates/defaults/main.yml` の `semaphore_templates_catalog` にその `playbook:` を持つエントリが無ければ、**警告を出す。終了コードは変えない。**

- `scripts/check-deploy-needed.py` は既に「**助言する側(R4/R6、常に0)**」と「**ブロックする側**」を明示的に分けて書いてある。その流儀に従う
- 出力は、**何をすればボタンになるか**が分かること(カタログへエントリを足し、reconcile を流す、という2段であること)
- **既存 playbook の変更では出さない。** ボタンの有無は既に決着しているため

**R2. staged 一覧の取得を1箇所にする**

「どのファイルが staged か」の定義を1つにし、**シェル側が持っている安全側の扱い(`core.quotepath=false`、引用符が残るパスの拒否)が、Python 側の判定にも効く**ようにする。

- **実装方法は指定しない。** シェルが取得して渡す形でも、Python 側へ寄せて共通化する形でもよい
- **判定内容を変えない。** これは取得経路の統一であって、何を検査するかの変更ではない

## 5. 受入条件

| # | 条件 |
|---|---|
| AC1 | **Given** カタログに定義が無い新規 `playbooks/x.yml` を stage、**When** pre-commit を実行、**Then** 警告が出て、**終了コードは 0**(commit は通る) |
| AC2 | **Given** カタログに定義がある新規 playbook を stage、**When** 同上、**Then** その警告は出ない |
| AC3 | **Given** 既存 playbook の変更だけを stage、**When** 同上、**Then** その警告は出ない |
| AC4 | staged 一覧の取得が**1箇所**になっており、引用符が残るパスに対して**シェルと Python が同じ判断**をする(片方だけが通す状態にならない) |
| AC5 | **既存のすべての検査の挙動が変わらない** — gitleaks / 危険ファイル名 / IPv4リテラル / tester-gate / doc-consistency / deploy-needed(R4・R6・ブロック側)/ staged YAML |
| AC6 | `scripts/tests/fixtures/` の既存 fixture で回帰が無い |
| AC7 | `python3` が無い環境での既存の振る舞い(ERROR を出して止まる)を変えない |

## 6. 制約

**pre-commit は全 commit の入口である。壊れると何も commit できなくなる。** 変更後は、既存 fixture と実際の staged 状態の両方で経路を通してから報告すること。

## 7. オープンクエスチョン

| # | 内容 | 扱い |
|---|---|---|
| OQ1 | R1 の対象を「新規追加(A)」に限るか、rename(R)も含めるか | 実装判断。**含める場合、旧名でカタログに載っているエントリを新名の追加として二重に警告しない**こと |
| OQ2 | `playbooks/*.yml` のうち、`import_playbook` されるだけで単独では押さないものをどう扱うか | 助言に留める設計なので**除外リストは作らない**。作ると、そのリスト自体が腐る |
