## 2. R2の実装判断 — どちらへ寄せたか

**「シェルが取得して渡す」側を選んだ。** シェル(`git-pre-commit-check.sh`)は元々 `staged_files` を `-c core.quotepath=false` 付きで取得し、quoted-pathをfail-closedで弾く処理を先頭に持っていた。この計算結果をそのまま `check-deploy-needed.py --staged-paths -` へ標準入力で渡し、Python側の `git_staged_paths()` は渡された値があればそれをそのまま使う(`git diff --cached` を叩き直さない)。

理由:
- AC7(python3が無い環境でも既存のシェル側検査は動く)を壊さない。staged一覧の取得自体をPython側へ完全に寄せると、シェルの早い段階の検査(gitleaks・危険ファイル名・IPv4リテラル・vault-header)まで暗黙にpython3依存になりかねない設計変更になり、リスクが大きい。
- 既存の「シェルが安全側の扱いを先に決める」構造(quoted-pathで即 `exit 1`)を変えずに済む。実際のpre-commitフローでは、Pythonへ渡る時点で既にquoted-pathは弾かれている。
- `check-deploy-needed.py` を単体実行するフィクスチャハーネス(`scripts/tests/fixtures/deploy_needed/run-fixture-checks.sh`)は `--staged-paths` を渡さない従来どおりの呼び方のままで動く(後方互換、AC6)。この経路のために、自前導出側にも `-c core.quotepath=false` とquoted-path fail-closedを追加し、**渡されても渡されなくても同じ安全側判断になる**ようにした(AC4)。

## 3. R1の実装判断

- 別スクリプトを新設せず、`check-deploy-needed.py` へ第3の独立した検査として追加した。理由: 依頼文の「主な対象」が `git-pre-commit-check.sh` と `check-deploy-needed.py` の2本のみを名指ししていたこと、既にこのファイルが「advisory(R4/R6)とblocking(R5)を明示的に分けて書く」流儀を確立していたこと。ただし**参照するカタログが別物**(`roles/semaphore_templates/defaults/main.yml` の `semaphore_templates_catalog`、R4/R5/R6が読む `roles/deployment_drift_check` カタログとは無関係)であることをdocstring・関数docstring双方に明記し、既存のR4/R5/R6(`deploy_awareness` 案件のR番号)と関数名・見出しが混同されないようにした(`check_new_playbook_catalog_advisory` という記述的な名前にし、`check_r1` のような番号名は使わなかった)。
- **OQ1(rename対応)**: 含めない判断。`--diff-filter=A` のみで判定し、`R`(rename)は対象外。理由は要件が示す通り「含める場合は旧名エントリとの二重警告回避ロジックが要る」ため、そのロジックを持たないぶんリスクが低い。`git mv` による実際のrenameで検証済み(§5参照)、警告は出ない。**【Coordinator追記 2026-08-05】この検証が覆うのは「gitがrenameと判定した場合」だけである。** renameと大きな内容書き換えが同一commitに入るとgitの類似度しきい値(既定50%)を下回り、`D`+`A`として報告されるため、**旧名にカタログ定義があっても新名で警告が出る**(独立レビューが再現)。助言のみで止めないため受容するが、**「検証済み」の範囲は100%一致のrenameに限られる。**
- **OQ2(除外リスト)**: 作らない。要件どおり、`import_playbook` 専用・単発手動用のplaybookも無差別に助言対象とする。
- python3が存在しない環境での扱い: R1はシェル側の既存ガード(`if ! command -v python3; then ERROR; exit 1; fi`)にそのまま乗る。R1自体は「ブロックしない」設計だが、python3不在は既存のR4/R5/R6と同じ理由でブロックされる(既存挙動の一部であり、R1が新たにブロック条件を増やしたわけではない)。
