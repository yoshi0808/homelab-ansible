## 食い違い・気になる点(事実のみ)
1. `(+N more)` の単位が2種類ある。pve の `services_restart_required` は1行内でプロセスを省略(`(+11 more)`)、authy は行(ライブラリ)の省略(単独行 `(+1 more)`)、authy の ld-linux/libc 行は行内プロセスの省略(`(+5 more)`)。key_reference は「上限超過時の末尾は `(+N more)`」とだけ書く。読み手が省略の単位を取り違える余地。
2. `services_restart_required` の `count=N` は「ライブラリ数」で、ページ上は「プロセス数」に見えうる(pve は count=1 に対し21プロセス)。key_reference は先頭を `count=N; ...` とのみ記す。
3. quory の `services_restart_required` に `/usr/lib/node_modules/@openai/.../bin/codex -> codex`(unit なし)があり、「引けなければ unit を省く」の仕様どおり。重みの判断材料として unit 無しが混ざる点のみ記録。
4. `repo`: pve は `no-subscription`、Ubuntu は `n/a`、`pve_manager` 等の非 pve は `n/a`。`none`/`unknown`/`n/a` の使い分けは key_reference と一致(`unknown` は今回の値に1件も無い)。`last_apply_*` と `reboot_*` は pve で `false`、非 pve で `n/a`。
5. ISO 8601: `updated_at`、`last_apply_at`、`collected_at` はすべて `+09:00` 付きで一致(AC10 相当を目視)。
6. `last_apply_upgraded` は pve1/pve2 とも同じ4件(libcares2、vim-common、vim-tiny、zlib1g)で、zlib1g の更新が `services_restart_required` の libz と整合。突き合わせ(apt 履歴)は本テストでは未実施。
7. quory・authy・monnie の `package_count`(9・8・8)は、各 part の行数と一致(目視)。Ubuntu の固定一覧は `pkg-list` の版と一致(quory/authy/monnie)。fetch 結果に truncated/unknown_block の注記は無かった。
