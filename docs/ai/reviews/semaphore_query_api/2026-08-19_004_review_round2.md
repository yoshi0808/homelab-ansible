## What Looks Good

- API応答shape、missing field、PLAY RECAP欠落、redirectの前回再現ケースはすべてfail-closedへ変わり、正常系queryの処理とdispatch契約は維持されている。dispatchとsandbox wrapperは無変更だった。
- 旧ACLは新token ACLの付与後に明示撤去され、途中中断後の再実行でも「新旧どちらのreadも無い」状態を経由しない。
- R13の新規token ACLは`incident_investigate_run_user`へのreadだけで、directory writeやtoken内容のlog出力を伴わない。query実行はshell文字列ではなく`subprocess.run([bin_path, *args])`である。
- R14の取得queryは`task-output` / `task-hosts` / `task-errors`の固定3種、task idは`semaphore-<digits>` directory名から整数化された値、runtime workspaceはroot管理config、出力filenameはコード定数であり、Semaphore/log本文からURL・query名・filesystem pathを組み立てる経路は無い。
- 3 queryは独立に取得され、非ゼロ/timeoutは`(fetch failed: ...)`、正常な空は`(empty)`としてfile内で区別される。contextとbundleを非信頼データとして扱い、埋め込まれた命令へ従わない指示もprompt/AGENTSの両方に残っている。
- `--sandbox read-only`、`network_access=false`、鍵なしというincident-inspect側の既存境界は緩めていない。AGENTSは`homelab-semaphore-query`の実行を案内せず、先読みfileと既存`homelab-reports`だけを案内する。
- 指定された既存`run_semaphore_query()` / `process_bundle()`の先読み経路を拡張しており、同じsubprocess/error handlingを別helperへ重複実装していない。
- Reviewer環境で3 Python fileの`py_compile`、`git diff --check`、5 setup playbookの`ansible-playbook --syntax-check`は成功した。実ホストへのAnsible実行は行っていない。
