## What Looks Good

- `ubuntu_vm_full_upgrade_sim.simulation.inst_detail`はapply前に同一hostで定義済みで、upgrade候補の再利用経路は成立する。
- apt実行は`argv`化され、`--force-confold`、`NEEDRESTART_MODE=l`、timeout/kill-afterの引数境界は明確。
- `failed_when: false`後のrcは0、124/137、その他で全域が処理される。`changed_when: true`も部分適用を保守的に表す。
- `default(..., true)`は実装者報告どおり、定義済み空文字列にもfallbackを適用する現物になっている。
- post query失敗、pre query失敗、post parse失敗、post file missing/unreadable、post pathのbaseline欠落はJSONの`indeterminate`へ入り、1件でもrc=1になる。
- obsoleteを独立分類し、自由文解析を避けて`LC_ALL=C`で`dpkg-query`を実行する構造は妥当。
- check-mode外側ゲートは`ubuntu_vm_full_upgrade_is_apply_target and not ansible_check_mode`のままで、新規snapshot/copy/diffも`apply.yml`内に閉じる。
- security観点では固定実行ファイル+`argv`でshellを介さず、秘密値露出、危険なdelegate/lookup追加もない。
- 指定された既存simulation factと共通Slack roleを再利用しており、指定資産の再利用漏れはない。
