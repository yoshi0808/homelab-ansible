# requirement: 確認が効かない3経路を塞ぐ(手動applyの確認欄・SAFEのPrometheus・置換先の無い重要remove)

作成: 2026-09-26 / Coordinator
起点: `docs/ai/reviews/playbook_catalog_policy_audit/2026-09-26_005_summary.md` の「高」3件(`_002` F06、`_001` F1-1、`_002` F01)。計画はYoshinobu合意済み(2026-09-26)。

## 1. 問題定義

確認や停止のための仕組みはあるのに、それが働かない経路が3つある。

1. **Proxmox手動applyの確認文字列が、最初から入力されている。** `roles/semaphore_templates/defaults/main.yml` の `UN-SAFE:Proxmox patch apply (Manual)` は、`proxmox_patch_apply_manual_confirm` の `default_value` が `MAJOR_UPGRADE_DETECTED`。`roles/proxmox_patch_apply_node/tasks/main.yml` の確認判定は「確認文字列 == 再dry-runのStatus」だけを見るため、再dry-runが `MAJOR_UPGRADE_DETECTED` の週に既定値のまま押すと、人が何も選ばずに適用へ進む。Policy(`proxmox_operations_policy.md` SB-027「検出されたStatusに一致する明示的確認文字列…を必須とする」)の「明示的」が成立していない
2. **SAFEのボタンでPrometheusを更新・巻き戻しできる。** `SAFE:Prometheus update check`(`variant: check`)のsurveyは `prometheus_update_check_operation` に `inspect` / `update` / `rollback` を並べており、`update` / `rollback` を選ぶと確認なしで実行される。update / rollbackには既に `UN-SAFE:Prometheus update(Manual)` / `UNSAFE:Prometheus rollback(Manual)` がある
3. **置換先の無い重要removeが `BLOCKED` にならない。** dry-run(`roles/proxmox_patch_dryrun/tasks/main.yml` の最終Status)も、apply直前の再dry-run(`roles/proxmox_patch_apply_node/tasks/main.yml` の `_redryrun_status`)も、removeがあれば置換関係を問わず `MAINTENANCE_REQUIRED` にする。Policy SB-042 / SB-043 / SB-062 は「後継不明の重要remove、中核packageが消えるだけに見える状態」を `BLOCKED` とし、手動でも適用しないと定める。いまは手動apply(確認文字列 `MAINTENANCE_REQUIRED`)で適用できる

## 2. ゴール

- 手動applyは、実行するたびに人が確認文字列を選ばなければ進まない
- SAFEに分類したボタンからは、Prometheusの状態を変える操作に到達できない
- 置換先の無い重要removeを含む更新は、dry-runでも再dry-runでも `BLOCKED` になり、自動・手動のどちらでも適用されない。通知でその理由(消えるpackage名)が分かる

## 3. 非ゴール

- **自動適用の判断(2026-08-01のwidened policy)は変えない。** removeのある更新を自動で適用しない現行の扱いはそのまま
- `playbooks/proxmox_patch_weekly_full.yml` は変えない。`BLOCKED` の週は既存の経路(dry-run段で失敗して止まる)に乗る
- `BLOCKED` 時にscheduleを止める仕組み(`_002` F05)、AIの出力を最終Statusに採用している件(`_002` F02 / F03)は、別案件(Proxmoxパッチの判定と停止)で扱う
- 重要コンポーネント一覧の中身は変えない
- Prometheusの `UN-SAFE` / `UNSAFE` の2つのボタンは変えない
- Semaphoreのボタンの名前は変えない(改名は非対応)

## 4. ユーザーストーリー

- Yoshinobuとして、手動applyのボタンを押したとき、どのStatusに同意するのかを毎回自分で選びたい。既定値のまま押して適用が始まることを避けたい
- Yoshinobuとして、SAFEと付いたボタンは何を選んでも状態を変えないと信じて押したい
- Yoshinobuとして、Proxmoxの中核packageが後継なしに消える更新は、自分が確認文字列を選んでも適用されないでほしい。通知で何が消えるのかを知りたい

## 8. タイムライン・配備

- R1・R2: 本番のSemaphoreへ反映するには、quoryで `SEMI-SAFE: Semaphore templates setup` を Dry Run → 本実行で押す(Yoshinobu)。**実行しなければ本番のボタンは変わらない**。反映後、SemaphoreのUIで確認欄が未選択のまま起動できないことをYoshinobuが一度確かめる(ansyからは観測できない)
- R3〜R7: repoへのpushで、quoryの作業ツリー自動同期により反映される(`docs/ai/context/operations/code-delivery-to-production.md`)。本番での初回観測は次の金曜のdry-run(`BLOCKED` が出ないこと=回帰なし)
