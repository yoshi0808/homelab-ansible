### 新たに壊れたものが無いかの確認

- **MD保存2taskの排他化がNO_UPDATES / apt失敗BLOCKED / 通常(Codex narrative)の各経路を変えていないか**: 3経路とも`when`条件と保存内容を上表の通りトレースした。
  - NO_UPDATES: `_pre_status != NEEDS_CLASSIFICATION` が真なので、常にminimal task側のみ実行され、`_final_status == 'NO_UPDATES'`分岐(変更前と同一文言)を通る。
  - apt失敗BLOCKED: 同様に`_pre_status != NEEDS_CLASSIFICATION`が真(`_pre_status`の定義上、apt失敗は`NEEDS_CLASSIFICATION`を経由しない)。minimal task側のみ実行され、`_blocked_important_removes`は未計算のため`default([])`で空、`elif _final_status == 'BLOCKED' and (... > 0)`は偽、次の`elif _final_status == 'BLOCKED'`(apt失敗の既存文言)に落ちる。Slack通知側も`_blocked_important_removes`空でelse分岐(既存文言)。AC4dの回帰要件どおり文言は変更前と一致する。
  - 通常(Codex narrative): `_pre_status == NEEDS_CLASSIFICATION`かつ`_blocked_important_removes`が空のときはCodex task側のみ実行され、変更前と同じ経路。
  - いずれも二重保存・無保存は発生しない(排他が成立している)。
- **`regex_escape`適用が既存の重要コンポーネント検出(`_important_updates`等)の結果を変えていないか**: 現行の接頭辞一覧(`proxmox-kernel-`, `libpve-`, `firmware-`)は正規表現メタ文字を含まないため、`regex_escape`適用前後で`match`の判定結果は変わらない。`python3 roles/semaphore_templates/tests/task_flow/test_catalog_safety.py`と`ansible-playbook --syntax-check`(dry-run/apply両playbook)を独立に再実行しpassを確認した。また、下記の独立再現で`_blocked_important_removes`の判定自体(接頭辞照合を含む)がAC4a/AC5/AC6/AC6b/AC7相当の入力に対し期待どおりの結果を返すことを確認した。
