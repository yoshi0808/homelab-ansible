## 反映した指摘

### 指摘1 [must-fix] 制限なしの全体実行が ansy の assert で失敗する問題を修正

対象: `roles/recovery_exec/tasks/main.yml`

reviewer提案の2段構造をそのまま採用した。

1. **assert対象を変更**: 「実行ホストが正規配布元か」ではなく「正規配布元が
   このrunのホスト集合(`ansible_play_hosts_all`)に含まれるか」を
   `recovery_exec_setup_targets=true` の場合にassertする。これにより
   `-l ansy`(quoryが含まれない)は fail するが、制限なし実行
   (`ansible_play_hosts_all` に ansy と quory 両方が含まれる)では ansy 側も
   assert を通過する。
2. **target_setup includeを正規配布元1ホストのみに限定**: 既存の
   `when: recovery_exec_setup_targets | default(true) | bool` に
   `inventory_hostname == recovery_exec_setup_authoritative_host` を追加。
   これにより制限なし実行でも target への配布は quory のみが行い、ansy は
   ローカルセットアップ完了後に配布をスキップする(fail しない)。

### 指摘2 [must-fix] 許可主体を quory に明示固定(group所属への依存を解消)

対象: `roles/recovery_exec/defaults/main.yml`, `roles/recovery_exec/tasks/main.yml`

新しいdefault変数 `recovery_exec_setup_authoritative_host: quory` を追加し、
assert・target_setup includeの両方をこの変数(quory固定)で判定するように変更した。
`inventory_hostname in groups['control_nodes']` という group 所属ベースの判定は
撤去した。これにより、将来 `control_nodes` グループに別ホストが追加されても、
そのホストが targets へ配布できるようになることはなく(常に quory のみ)、
「構造的に不可能」がinventory構成の変化に対しても保たれる。

### 指摘3 [suggestion] tester-gate 理由文の保証範囲を実態に合わせて修正

対象: `playbooks/recovery_exec_setup.yml`

「単一ホストへの影響も他制御ノードへの横方向影響もない状態が保証される」という
過大な表現を修正し、「このガードが防ぐのはtarget authorized_keysの排他的横方向
上書きのみであり、recovery-execユーザー作成・鍵生成・wrapper配置・sudoers・ACL
といった単一ホスト内のローカル変更はguardの前段で従来どおり実行される」という
実態に即した説明に改めた。risk-accepted継続の根拠を「ローカル変更(2026-07-06の
既存判断)+ 横方向影響防止(今回のガード)」の組み合わせとして明記した。

## 期待挙動4パターンの検証(ローカル、実ホスト非依存)

指摘1・2の修正ロジックを、実際の `main.yml` と同一の条件式で
`hosts: dev_nodes:control_nodes`、`connection: local`(実SSH接続なし)、
target配布は `debug` でシミュレートする使い捨て playbook を作成し、実inventory
(`inventories/homelab/hosts.yml`)に対して4パターンを実行・確認した(確認後に
削除)。

| 実行 | 期待 | 結果 |
| --- | --- | --- |
| `-l ansy`(targets既定true) | fail | **fail**(`ansy: authoritative host not in play set ['ansy']`) |
| `-l ansy -e recovery_exec_setup_targets=false` | success、配布なし | **success**、distribution task は skipped |
| `-l quory`(targets既定true) | success、quoryから配布 | **success**、`DISTRIBUTED from quory` |
| 制限なし(全体実行、targets既定true) | success、ansy/quory両方成功、配布はquoryのみ | **success**(ansy/quory ok=2/3件)、`DISTRIBUTED from quory` のみ・ansyはdistribution taskをskip |

4パターンすべて期待通りの結果を確認した。
