# Requirement

自律復旧パイプラインの調査コマンド拡充(read-only)。実機テストは含まない(コード追加 + syntax確認まで)。

参照:
- docs/ai/prompts/core.md
- docs/ai/prompts/autonomous_recovery_policy.md

## 前提・制約

- read-only 調査コマンド追加のみ。本番に実害が出る操作(サービス再起動、VM操作、DB書き込み、ファイル削除等)は行わない。
- 実装はコード追加 + syntax確認までとする。実機テスト(SSHして叩く、sudo sqlite3 を本番で実行する等)は tester に依頼する。

## ① authy / monnie の汎用調査コマンド拡充

`roles/recovery_exec/defaults/main.yml` の各ターゲットの `investigate_extra` に「調子が悪い時にまず見る」汎用調査を追加。対象ホスト側の `recovery-investigate-dispatch.sh` の case 文許可リストにも対応させる。

追加したいチェック(authy/monnie 共通):

- journalctl -u <service> --since / -p priority 指定でのログ確認(期間・優先度はwrapper側で許可リスト照合。自由文字列で渡させない)
- systemctl status <service> の全文
- dmesg -T の末尾(OOM killer等のカーネルレベル異常確認)
- df -h / free -h / uptime(ディスク・メモリ・負荷)
- ss -tlnp(listen全体)

§4.4 のルール(パラメータはwrapper側でcase文照合、$SSH_ORIGINAL_COMMAND を未検証でeval/変数展開しない)を厳守する。

## ② reports/ の JSON レポート調査(quory ローカル)

`~/homelab-ansible/reports/<playbook>/` 配下の JSON レポートを調査できる wrapper を新規作成。Semaphore経由でもansible直でも同じパスに出力される固定構造。

コマンド:

- list-playbooks: reports/ 直下のディレクトリ一覧
- list-reports <playbook>: 指定playbookのレポートをファイル名(タイムスタンプ)降順で一覧(最新が上)
- show-report <playbook> <filename>: 指定レポートJSONを表示(jqで整形可)

セキュリティ:

- ベースパスは ~/homelab-ansible/reports/ に固定(引数で受けない)
- playbook名は [a-zA-Z0-9_-]+ のみ許可(スラッシュ・ドット禁止=トラバーサル防止)
- filename も同様に検証。最終的に reports/<検証済み>/<検証済み> の外へ出ないこと

## ③ Semaphore 失敗タスクの原因解析(本命)

quory の `/var/lib/semaphore/semaphore.db`(SQLite)を read-only で引いて、失敗タスクの原因を返す wrapper を新規作成。

権限:

- semaphore.db は yoshi:yoshi 0600 のため recovery-exec から直接読めない。
- sudoers で recovery-exec に以下だけを許可(DBパス・-readonly を固定):
  `recovery-exec ALL=(root) NOPASSWD: /usr/bin/sqlite3 -readonly /var/lib/semaphore/semaphore.db *`
- wrapper から sqlite3 を呼ぶ際は、SQLをシェル文字列連結せず配列(exec)で渡す(シェル経由の注入を原理的に潰す。Sophosの時の教訓と同じ)。

Codex には SQL を自由に書かせない。定型クエリのみ、Codex は「クエリ名」と task_id / 件数のパラメータだけ選ぶ:

- `recent-failed <n>`:
  ```sql
  SELECT t.id, tpl.name AS template, tpl.playbook, t.status,
         substr(t.start,1,19) AS start
  FROM task t
  LEFT JOIN project__template tpl ON t.template_id = tpl.id
  WHERE t.status IN ('error','stopped')
  ORDER BY t.id DESC LIMIT <n>;
  ```
- `task-errors <id>`:
  ```sql
  SELECT task, host, substr(error,1,500) AS error_head
  FROM task__ansible_error WHERE task_id = <id>;
  ```
- `task-hosts <id>`:
  ```sql
  SELECT * FROM task__ansible_host WHERE task_id = <id>;
  ```
- `task-output <id>`:
  ```sql
  SELECT time, output FROM task__output
  WHERE task_id = <id> ORDER BY time;
  ```

パラメータ(n, id)は整数のみ許可(正規表現で検証、非整数は拒否)。
