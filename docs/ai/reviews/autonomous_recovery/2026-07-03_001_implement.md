## 設計要点

### push 経路全体

```
authy: freeradius.service crash
monnie: grafana-server / prometheus / loki / unpoller のいずれか crash
  ↓ OnFailure=recovery-trigger@%n.service  (systemd drop-in)
  ↓ recovery-trigger@<service>.service  (Type=oneshot)
  ↓ /usr/local/sbin/recovery-push.sh
  ↓ ssh recovery-exec@quory.internal  (push-key, StrictHostKeyChecking)
  ↓ forced command: /usr/local/sbin/recovery-push-dispatch.sh <target>
      ① mute チェック → muted: log + exit 0
      ② push session lock (mkdir /var/lib/homelab-recovery/push/<target>.lock)
         → 既にロック中: log + exit 0 (並走抑止)
      ③ exec codex-exec-wrapper exec --cd <workspace>
             "<target> でサービス障害を OnFailure で検知しました。調査・復旧してください。"
  ↓ Codex(AGENTS.md):
      homelab-investigate-<target> status
      → homelab-recover-<target>  (authy=freeradius 再起動 / monnie=全 4 サービス再起動)
      → re-investigate + 日本語で報告(Slack への返信は recovery-io 経由)
```

### SSH キー管理

- キーペアは **各 VM 上で生成**(authy / monnie 上で `ssh-keygen`)
- 秘密鍵: `/etc/homelab-recovery/push-key` (root:root 0600) — VM 外に出ない
- 公開鍵: Ansible が slurp して quory の authorized_keys テンプレートに展開
- 強制コマンド: `command="/usr/local/sbin/recovery-push-dispatch.sh <target>",no-pty,...`
  → ターゲット名は authorized_keys に埋め込み。VM からのパラメータ注入不可(§4.3)

### mute との連動

`recovery-push-dispatch.sh` が `/var/lib/homelab-recovery/mute/<target>.json` を確認し、
mute 中は Codex を呼ばずに即 exit。mute ファイルは 0644(recovery-exec が world-read 可)。

### push session lock

`/var/lib/homelab-recovery/push/<target>.lock` ディレクトリを `mkdir` でアトミック生成。
既存なら skip(Codex セッションが既に実行中)。EXIT trap で必ず削除。

monnie は 4 サービス全てに drop-in を配置するが、Codex セッションは 1 つに絞られる。
`homelab-recover-monnie` は全 4 サービスを一括で restart する(Yoshinobu 確認済み)。

### 既存との分離

- `roles/recovery_exec/templates/authorized_keys.j2` はそのまま(VM 上のファイル、変更なし)
- quory の `/home/recovery-exec/.ssh/authorized_keys` は **新規**(push 受信専用、2 エントリ)

## 追記(2026-07-03: 002_review must-fix 対応)

**must-fix 対応**: `roles/recovery_exec/tasks/main.yml` の quory 側 recovery-exec ユーザーを
`shell: /usr/sbin/nologin` → `shell: /bin/sh` に変更した。

理由: OpenSSH が forced command を実行するとき `execve(shell, [shell, "-c", cmd], env)` を
使うため、nologin のままでは dispatch script まで到達できない(nologin は引数を無視して即 exit)。

セキュリティ境界はそのまま維持:
- incoming push には `command=...` forced command + `no-pty,no-port-forwarding,...` を設定
- push キーが漏れても dispatch script の固定コマンド以外は実行不可
- recovery-exec は quory 上で sudo 権限を持たない(recovery-io が sudo して呼ぶ側)
- 対象 VM(authy/monnie)側の recovery-exec は元から /bin/sh のため変更なし
