## 実装概要

pve1/pve2 の read-only 調査経路へ、パラメータ付きの 9 named check を追加した。
quory 側 wrapper を一次フィルタ、pve 側 forced-command dispatch を本ゲートとする
二段検証を実装し、両層で同じ regex / allowlist とパラメータ数を検証する。

dispatch は `SSH_ORIGINAL_COMMAND` を `check p1 p2 extra` に再パースし、過剰トークン、
改行、未定義 check、不正なパラメータを sudo 到達前に拒否する。sudo 呼び出しは
固定の絶対パス・read-only 動詞と検証済みオペランドを位置引数として組み立て、
`eval` や sudo コマンド文字列の再解釈を使用しない。

## 変更内容

### pve 側 dispatch（本ゲート）

- `read -r check p1 p2 extra <<<"$cmd"` で forced command を独立に再パースする。
- 4 トークン以上、改行 / CR、既存の引数なし check への追加引数を拒否する。
- 次の検証を関数化し、各 case arm で正確なパラメータ数を確認してから適用する。
  - vmid: `^[1-9][0-9]{2,8}$`
  - job-id: `^[1-9][0-9]{2,8}-[0-9]{1,3}$`
  - UPID: requirement C 節の構造 regex
  - storage: `^[a-zA-Z][a-zA-Z0-9._-]{0,31}$`
  - limit: `^[0-9]{1,4}$` かつ 1..2000（10 進数として評価）
  - unit / window: 固定集合の完全一致
- 9 check を追加した。
  - `replication-read <job-id>`
  - `vm-status <vmid>`
  - `vm-config <vmid>`
  - `vm-tasks <vmid> <limit>`
  - `task-log <UPID>`
  - `storage-status-one <storage>`
  - `zfs-list-vm <vmid>`
  - `vm-conf-stat <vmid>`
  - `journal-unit <unit> <window>`
- `zfs-list-vm` は既存の `sudo -n /usr/sbin/zfs list` の出力だけを非特権の
  `/usr/bin/grep -E --` で絞り込む。sudo 失敗を無一致として隠さないよう、先に
  command substitution を完了してから grep の無一致（exit 1）のみ `|| true` とした。
- `journal-unit` は window を固定の `--since` 値へ変換し、unit ごとの case arm で
  unit 名をリテラル固定した journalctl argv を実行する。

### quory 側 wrapper（一次フィルタ）

- 呼び出し形式を `<check> [<param1> [<param2>]]` へ拡張した。
- dispatch と同じ regex / allowlist / exact arity を SSH 前に適用する。
- 検証済みの値だけを SSH が要求する単一 remote-command 引数へ整形する。
- ホスト、鍵、known_hosts、SSH オプションは従来どおりテンプレート内で固定した。

### sudoers

- Phase 1 の固定行は変更せず、Phase 2 の read-only 動詞を固定したルールを追記した。
- `qm status *` / `qm config *` のように `*` を検証済みオペランド位置だけに置き、
  `qm *`、`pvenode task *`、`journalctl -u *` のような動詞 / unit のワイルドカード化は
  行っていない。
- journal unit は 5 unit を別々の行に固定し、可変なのは検証・マップ済みの
  `--since` オペランドだけとした。行数 300 と `--no-pager` は固定した。
- pre-deploy の絶対パス確認 NOTE を `qm` / `pvenode` / `stat` を含む一覧へ更新した。

### AGENTS.md

- 9 check の呼び出し形式、用途、unit / window allowlist、VMID / storage の形式を追記した。
- VM レプリケーション障害時に `replication-read`、`vm-status`、`vm-tasks`、
  `task-log`、`zfs-list-vm` を使う調査順を追記した。
- pve1/pve2 は investigate-only である既存の禁止事項を維持した。

### ローカル環境では完了できない確認

- `shellcheck` はローカルに未導入のため未実行。
- ローカルの `visudo -cf roles/recovery_exec/templates/sudoers-recovery-exec-pve-target.j2`
  は失敗した。ローカルは sudo 1.9.17p2 の `sudo-rs` parser であり、同環境の
  `sudoers(5)` が command argument 内 wildcard を末尾の単一 `*` 以外禁止しているためである。
  requirement は Proxmox/Debian 側の従来 sudo の fnmatch 動作を前提としているため、
  ローカル parser に合わせて承認済みルールを弱化・変更していない。
- `roles/recovery_exec/tasks/target_setup.yml` の sudoers template task には既存の
  `validate: /usr/sbin/visudo -cf %s` があり、配備時に pve1/pve2 自身の parser が
  不受理なら配置前に停止する。tester 工程で対象側の構文受理を必ず確認する。
