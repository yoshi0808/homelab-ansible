# Implement (追加: sudo廃止 → ACL直読みへの再設計)

対象: 2026-07-05_026_requirement.md 〜 2026-07-05_032_final.md で確定・commit(`f52a3b4`)された②③の権限昇格方式。

## 発覚した問題

Yoshinobuが確定後にSlackから実際にCodexセッション経由で `homelab-semaphore-query recent-failed 5` を実行したところ、以下のエラーで失敗した。

```text
sudo: The "no new privileges" flag is set, which prevents sudo from running as root.
```

## 原因

`roles/recovery_exec/templates/codex-exec-wrapper.j2` は Codex を `codex exec --sandbox workspace-write ...` で起動する。このサンドボックスは `no_new_privileges` を設定しており、これは sudo・setuid・ファイルcapability経由の権限昇格を **sudoersの設定に関わらず一律ブロックする**(Linuxカーネルの `no_new_privileges` prctl の仕様)。②`homelab-reports`(`sudo -n -u yoshi ...`)・③`homelab-semaphore-query`(`sudo -n ...`)はどちらもこの経路で失敗する。

この問題は 2026-07-05_028/029_review.md(reviewer)・2026-07-05_031_test_result.md(tester)のいずれでも検出されなかった。tester は Ansible ad-hoc の `command` モジュール経由(通常の sudo が効く環境)で検証しており、Codex サンドボックス内の実際の実行パスを通していなかったため。「テストが通った」ことと「本番の実行経路(Codexサンドボックス経由)を通った」ことは別だった。

Yoshinobuの整理: この修正(sudo廃止)により、副次的に「tester dry-run(サンドボックス外)と本番実行(サンドボックス内)の挙動差」も解消される。昇格という環境依存処理自体が無くなるため。

## 事前確認: WALモード(sudo/ACLとは別問題として先に確認)

sudo/ACLの問題とは別に、`semaphore.db` がWALモードだと `-wal`/`-shm` 副ファイルの権限も別途必要になる可能性があったため、実装前に read-only で確認した(docs/ai/reviews/autonomous_recovery/2026-07-05_033_wal_investigation.md、tester実施)。

結果: `journal_mode=delete`(WALではない)。`-wal`/`-shm` ファイルは存在しない。したがって副ファイルの権限問題は無く、ACLは本体ファイルのみで足りる。

## 修正内容

sudoによる権限昇格を全廃し、POSIX ACL(`ansible.posix.acl`、対象ユーザー自身への直接付与)に置き換えた。ACLは新たな身分への昇格を伴わないため `no_new_privileges` の影響を受けない。

### ② homelab-reports / recovery-reports-helper

- `homelab-reports`: `exec sudo -n -u yoshi recovery-reports-helper "$@"` → `exec recovery-reports-helper "$@"`(sudo削除)。
- `recovery-reports-helper`: recovery-exec自身として直接実行する前提のコメントに更新(処理ロジック自体は変更なし)。
- `roles/recovery_exec/tasks/main.yml`: `ansible.posix.acl` で `/home/yoshi` に `recovery-exec:x`(traverse のみ)を付与。`reports/` 以下は既に 0755/644 で読めるため、これだけで足りる。
- `acl` パッケージ(`setfacl`/`getfacl`)インストールタスクを追加(未インストールだったことをローカル確認済み)。

### ③ homelab-semaphore-query

- `exec sudo -n "$SQLITE" -readonly "$DB" "$sql"` → `exec "$SQLITE" -readonly "$DB" "$sql"`(sudo削除)。
- `roles/recovery_exec/tasks/main.yml`: `ansible.posix.acl` で `/var/lib/semaphore` に `recovery-exec:x`、`semaphore.db` に `recovery-exec:r` を付与。

### sudoers全廃

- `recovery-exec ALL=(yoshi) NOPASSWD: recovery-reports-helper *` と `recovery-exec ALL=(root) NOPASSWD: /usr/bin/sqlite3 ...` の両方が不要になった。
- `roles/recovery_exec/templates/sudoers-recovery-exec-quory.j2` を削除(git rm相当)。
- `roles/recovery_exec/tasks/main.yml`: 該当のsudoers配備タスクを削除し、代わりに `/etc/sudoers.d/recovery-exec-investigate` を削除する legacy-cleanup タスクを追加(既存の `homelab-mute-exec` 等のlegacy除去と同じパターン)。

### ドキュメント更新

- `docs/ai/prompts/autonomous_recovery_policy.md`: §4.3・§4.4をACL方式に書き換え、新設の §4.5「なぜsudoを使わないか」に原因・教訓を記録。§6にも `no_new_privileges` の一般的注意("Codexが呼ぶwrapperは権限昇格を前提に設計しない")を追記。

## 動作確認(ローカル、ansy)

sudo自体はCodexサンドボックス外(通常のshell)では普通に動くため、ACL方式が機能することをローカルで直接検証した(実際のCodexサンドボックス経由での確認はこの後 tester に依頼する)。

```bash
# reports/ 相当: /home/yoshi へのACL付与前後の比較
sudo -u recovery-exec cat /home/yoshi/homelab-ansible/reports/radius-health/<file>.json   # before: Permission denied
sudo setfacl -m u:recovery-exec:x /home/yoshi
sudo -u recovery-exec cat /home/yoshi/homelab-ansible/reports/radius-health/<file>.json   # after: 成功
sudo setfacl -x u:recovery-exec /home/yoshi   # テスト後に戻した

# semaphore.db相当: 0600ファイルへのACL付与前後の比較(/tmp直下、ダミーファイル)
sudo -u recovery-exec cat /tmp/fakedb_acltest.sqlite   # before: Permission denied
setfacl -m u:recovery-exec:r /tmp/fakedb_acltest.sqlite
sudo -u recovery-exec cat /tmp/fakedb_acltest.sqlite   # after: 成功(exit=0)
```

```bash
bash -n roles/recovery_exec/files/homelab-reports roles/recovery_exec/files/recovery-reports-helper roles/recovery_exec/files/homelab-semaphore-query
ansible-playbook playbooks/recovery_exec_setup.yml --syntax-check
scripts/check-tester-gate.sh
```

いずれも成功。
