## 実装概要

PVE の定期 replication job は `pvescheduler` / `pvestatd` の systemd journal に
実行ログを出さず、実ログは `/var/log/pve/replicate/` 配下の JobID 名ファイルに
保存されることが tester の追加調査で確定した。

既存の `journal-replication` check 名は、quory 側 wrapper・pve 側 forced-command・
AGENTS の呼び出し規約に既に使われているため、変更による churn を避けて維持した。
名前は維持するが、実装と AGENTS の説明では systemd journal ではなく固定ディレクトリの
replication job log を直接読むことを明示した。

## 作成・更新したファイル

- `roles/recovery_exec/templates/recovery-investigate-dispatch-pve.sh.j2`
  - `journal-replication` arm を `journalctl -u pvescheduler -u pvestatd` から、
    `/var/log/pve/replicate/*` の regular file を列挙して各ファイル末尾 200 行を
    `/usr/bin/tail` で直接読む固定処理へ変更。
  - SSH client からの追加パラメータは受け取らず、Phase 1 の parameterless named check を維持。
  - directory に対象ファイルが無い場合はメッセージを出して正常終了する。
  - 既存ファイルが読めない、または `tail` が失敗した場合は `set -e` により失敗を隠さない。
  - replication log は world-readable のため、この arm では sudo を使わない。
- `roles/recovery_exec/templates/sudoers-recovery-exec-pve-target.j2`
  - `journal-replication` 用だった `pvescheduler` / `pvestatd` journalctl の固定 sudo 行を削除。
  - 残る sudoers 行は引き続き完全な固定コマンドで、ワイルドカードは追加していない。
  - pre-deploy unit 確認コメントを、残存する `pve-cluster` / `corosync` /
    `pvedaemon` journal check のみに合わせた。
- `roles/recovery_exec/templates/homelab-investigate-pve.sh.j2`
  - allowlist を確認。check 名を `journal-replication` のまま維持したため変更不要。
- `roles/recovery_exec/templates/AGENTS.md.j2`
  - PVE 節の `journal-replication` 説明のみを、`/var/log/pve/replicate/` 配下の
    per-job log を直接読み、各末尾 200 行を返す実装に更新。
  - mute 節には触れていない。
- `docs/ai/reviews/autonomous_recovery/2026-07-14_014_implement.md`
  - 本実装記録を作成。

## 未対応事項・注意点

- 実ホストには接触していない。pve2-first の配備・実ログ確認と pve1 の回帰確認は
  tester 工程で行う。
- SSH、git commit / git push、ansible-playbook、Ansible ad-hoc は実行していない。
- check 名は歴史的に `journal-replication` のままだが、取得元は journal ではない。
  この判断は呼び出し側の churn を抑えるためであり、AGENTS に明記済み。
- 各 job log を最大 200 行ずつ返すため、job 数に比例して出力量は増える。
  Phase 1 の固定・parameterless check として、job-id 指定や動的引数は追加していない。
