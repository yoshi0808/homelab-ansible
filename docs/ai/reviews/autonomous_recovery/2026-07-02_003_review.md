## 指摘

### must-fix: sophos-fw stopped 時の処理が要求仕様と不一致

- 対象: `roles/recovery_probe/files/recovery-probe.py:260`
- 要求: `docs/ai/reviews/autonomous_recovery/2026-07-02_001_requirement.md:36`

要求仕様では、pvesh 確証後の分岐として `stopped → reboot ではなく start` と明記されています。一方、実装は `vm_status == "stopped"` で通知をキューして return し、自動 start を行いません。

これは sophos-fw 経路を E-1 で「検知 → 確証 → ラダー起動までフル実装」とした要求に対する未実装です。実装記録では「HA 補完前提でエスカレーションのみ」と説明されていますが、要求ファイル側にその仕様変更・Yoshinobu 承認が反映されていません。

対応案:

- 要求どおり stopped 時に deterministic start を実装する。
- もしくは「stopped は E-1 では自動 start せずエスカレーションのみ」に仕様変更し、Yoshinobu 承認済みとして requirement / implement に明記する。

どちらかが必要です。

### suggestion: 通知キューファイル名がミリ秒 timestamp だけで衝突し得る

- 対象: `roles/recovery_probe/files/recovery-probe.py:133`

`queue_notify()` は `int(time.time() * 1000)` だけでファイル名を作っています。1 daemon cycle 内で複数 target が同時に通知になった場合や、同じ分岐で短時間に通知が連続した場合、同一ミリ秒で上書きして通知を失う可能性があります。

`time_ns()`、UUID、または target/status を含む一意名にすると安全です。通知キューは監査証跡に近いので、低確率でも上書きしない設計を推奨します。

### nit: ignored `__pycache__` が role 配下に残っている

- 対象: `roles/recovery_probe/files/__pycache__/recovery-probe.cpython-314.pyc`

`git status --untracked-files=all` には出ていないため gitignore 対象と思われますが、role 配下に生成物が残っています。commit 対象ではないなら機能影響はありません。レビュー・配布前に削除しておくと作業ツリーの見通しがよくなります。

## レビュー観点への回答

1. probe daemon ロジック
   mute が判定前にカウンタリセットされる点、lock に `mkdir` を使う点、drill 時に `tester_mode=true` を付ける点は妥当です。一方、stopped 分岐は要求と不一致です。

2. セキュリティ
   systemd は `User=yoshi`、daemon/config は root 所有、状態ディレクトリは yoshi 所有という構成は、repo / vault / SSH 鍵を使う前提では妥当です。CLI の set/clear が root 必須なのも妥当です。

3. 通知 flush のコスト
   1 通知 = 1 `ansible-playbook` 実行は重いですが、通知頻度は低く、Slack vault / common_slack の既存経路を再利用できるので E-1 として許容できます。

4. sophos-fw stopped 時の判断
   現状の「エスカレーションのみ」は要求仕様と食い違っています。must-fix 参照。

5. HTTPError も到達扱い
   ネットワーク到達性の判定としては妥当です。Slack 送信可否そのものではなく、外部に HTTP 応答が返るかを見る用途なので許容できます。

6. lint / tester_mode 整合
   `recovery_probe_setup.yml` は `tester_gate` 付き、`recovery_probe_notify.yml` は `role-guarded` で lint を通っています。drill 通知は probe が notify playbook に `tester_mode` を渡さないため、drill 通知が抑止されない整理も実装と一致しています。
