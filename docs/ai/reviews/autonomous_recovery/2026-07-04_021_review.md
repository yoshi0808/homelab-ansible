## 判定

理由:

- ansy から `cert_renew.yml` が quory-only assert で停止するのは、CA 秘密鍵を ansy に置かないための意図した安全設計である。
- Phase 1-4 で、quory 上の `homelab-monitoring-pause` / `resume` / `status`、workspace permission、`yoshi` の flag 読み取り、`recovery-probe --once` の global pause skip は実機確認済み。
- `cert_renew.yml` 側の変更は、monnie play 内で旧 `homelab-mute` 呼び出しを `homelab-monitoring-pause` / `resume` に置換する小さな配線変更であり、`delegate_to: localhost` と `cert_needs_renewal` 条件も維持されている。
- `--list-tasks` と静的確認により、pause/resume タスクが monnie play に存在することは確認済み。

したがって、Phase 5 は「quory 上での check-mode runtime 確認が未実施」という残リスクとして記録すれば足りる。commit 前の必須ブロッカーにはしない。

## 指摘

### must-fix: commit 対象のレビュー証跡を 019/020 系に揃える

現時点の `git status` では、旧実装を検証していた `017_test_plan.md` / `018_test_result.md` が staged のまま、新しい `019_review.md` / `019_test_plan.md` / `020_test_result.md` は untracked になっている。

commit 前に以下を行うこと。

- `docs/ai/reviews/autonomous_recovery/2026-07-04_019_test_plan.md`

### suggestion: 初回の実 cert_renew 前に quory 上で静的または check-mode 確認を行う

commit の blocker ではないが、初回の `cert_renew.yml` 実運用前に quory 上の同じソースで追加確認すると安心できる。

ただし、tester_mode を付けると monnie play の tester_gate で pause/resume タスク前に止まるため、Phase 5 exact command の代替として扱う場合は、その制約を test_result に明記する。
