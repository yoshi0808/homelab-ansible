## Phase 1: 事故経路のブロック確認

3. `-l ansy`（`recovery_exec_setup_targets` デフォルト true のまま）で実行
   - 期待: **assert で fail**（authoritative host が play 対象に含まれない）
   - targets の authorized_keys fingerprint が Phase 0 から**不変**であることを確認

## Phase 2: 確立済み運用の非退行確認

4. `-l ansy -e recovery_exec_setup_targets=false` で実行
   - 期待: 成功。ローカル setup のみ実行、target 配布タスクは skip、targets 不変

## Phase 3: 明示上書き攻撃のブロック確認

5. `-l ansy -e recovery_exec_setup_authoritative_host=ansy`（targets デフォルト true）で実行
   - 期待: **fail**（変数は削除済みでリテラル quory 固定のため、-e 指定は安全境界に
     影響しない）。targets 不変

## Phase 4: 正規実行の非退行確認

6. `-l quory` で実行
   - 期待: 成功。quory から targets へ配布（quory 鍵での上書き = 内容は現状と同一）
   - 実行後、targets の fingerprint が引き続き quory 鍵であること
   - `homelab-investigate-monnie status` / `homelab-investigate-pve1 cluster-status` /
     `homelab-investigate-pve2 cluster-status` が成功すること（調査経路の非退行）

## Phase 5: 全体実行の非退行確認（must-fix 1 の修正検証）

7. 制限なし（`-l` なし、targets デフォルト true）で実行
   - 期待: **成功**（ansy/quory 両ホストとも failed=0）。配布タスクは quory のみが実行し、
     ansy は skip。実行後の targets fingerprint は quory 鍵のまま（ansy 鍵が混入しないこと）
   - 実行後、investigate wrapper の疎通を再確認

## 合否基準

- Phase 1・3 が fail（ブロック）かつ targets 不変、Phase 2・4・5 が成功かつ
  targets が常に quory 鍵のみ: 合格
- いずれかで想定外の挙動（特に targets への ansy 鍵の混入）: 即中断し、
  fingerprint を記録して claude へ返す。混入が起きた場合の復旧手順は
  `recovery_exec_setup.yml -l quory` の再実行（7/11 の修復と同じ）
