# Slack/Codex からの個別ノード mute（TTL 付き）— 要求仕様

- 日付: 2026-07-14
- 起案: claude（要件定義・ハブ役）/ 承認: Yoshinobu（本文の最終確認は claude→implementer 送付前に実施）
- 優先度: 通常（残タスク。autonomous_recovery の「Slack mute は次期」として先送りしていた分）

## 目的

Slack（`@Homelab` メンション、自然言語）から、個別ノード（`authy` / `monnie` /
`sophos-fw`）を **N 分間 mute** できるようにする。現状 Slack/Codex 経由でできるのは
グローバル pause（全 target 一括・TTL 無し、`homelab-monitoring-pause`）のみで、
target 単位・TTL 付きの mute は人間が quory 上で `sudo homelab-mute set` を叩く経路
しか無い。手作業（evacuate/patch 等）の巻き添えで誤発動を止めたいときに、Slack から
自然言語で完結できるようにする。

## 背景（現状の制約）

- 対象別 mute の実体は既に存在する（policy §7）。ファイル形式
  `/var/lib/homelab-recovery/mute/<target>.json`（`{"until": ISO8601, "reason": ...}`）、
  セマンティクスは `max(既存 until, now + N分)` で有効窓を短縮しない。書き込みは
  `roles/recovery_mute/tasks/set.yml`（playbook 自動 mute）と
  `roles/recovery_mute/files/homelab-mute`（人間 CLI、set/status/clear）が担う。
- Codex はこの mute を操作できない。理由は2つ:
  1. execpolicy（`roles/recovery_exec/templates/codex-config.toml.j2`）の allow に
     `homelab-mute` 系が無い（allow は investigate / reports / semaphore-query /
     recover / monitoring-{pause,resume,status} のみ）。
  2. `homelab-mute` の set/clear は root 必須。Codex は `--sandbox workspace-write`
     の `no_new_privileges` 下で動くため sudo/setuid での昇格が一律失敗する（§4.5）。

## 決定事項（Yoshinobu 承認済み・2026-07-14）

- 公開する mute 操作: **set + status + clear**（status は read-only）。
- Codex 経由 set の **TTL 上限は 240 分（4h）**。上限超過は拒否またはクランプ（実装判断、
  ただし「黙って 240 に丸める」より「拒否して理由を返す」方を推奨。人間が Slack で
  誤入力に気づけるため）。
- playbook 自動 mute（evacuate/patch 等、既存の sudo/set.yml 経路）は従来どおり無制限。
  本上限は Codex 経由の手動 mute にのみ課す。

## 対象ファイル

- `roles/recovery_exec/`（Codex 用 wrapper の配布・execpolicy・AGENTS.md・ACL 付与）
  - `templates/codex-config.toml.j2`（execpolicy に mute 系を追加）
  - `templates/AGENTS.md.j2`（Codex に mute 能力と使い分けを説明。追記しないと Codex が
    この機能の存在を認識しない）
  - 新規 wrapper スクリプト（下記）と、その配布タスク
- mute ディレクトリへの POSIX ACL 付与タスク（recovery-exec に write を許可）
- `playbooks/recovery_exec_setup.yml`（上記 role 変更の適用経路。tester-gate 現状維持で
  よいか実装時に理由文を再評価）

## 実施項目

1. **Codex 用 mute wrapper を新設**（execpolicy allow の粒度に合わせ、既存
   `homelab-monitoring-{pause,resume,status}` と同じく verb ごとに分ける方式を推奨）:
   - `homelab-mute-set <target> <minutes> [reason...]`
   - `homelab-mute-status`
   - `homelab-mute-clear <target>`
   これらは **recovery-exec として（sudo 無しで）** mute ファイルを直接読み書きする。
   単一 subcommand 型（`homelab-mute` 流用）にしない理由: 既存人間 CLI は root 必須で、
   execpolicy の command 名一致で「Codex が触れてよい経路」と「人間 sudo 経路」を
   物理的に分離したいため。命名・分割の最終形は実装判断に委ねる。
2. **mute ファイルの書き込み権限を sudo ではなく POSIX ACL で付与**（§4.5 の踏襲）。
   `/var/lib/homelab-recovery/mute/` に `recovery-exec` の rwx を `ansible.posix.acl`
   で付与する。sudo/setuid は使わない（`no_new_privileges` で失敗するため）。
   書き込みは既存 CLI と同じく `mktemp` → `chmod 0644` → `mv` の atomic 置換とし、
   readers（recovery-probe = yoshi、push-dispatch）が 0644 で読める状態を維持する。
3. **入力検証**（client/NL 由来の値を eval・変数展開せずデータとして扱う。policy §10）:
   - target は `authy` / `monnie` / `sophos-fw` の allowlist 照合。
   - minutes は正整数、かつ **1..240** の範囲。範囲外・非整数は拒否して理由を返す。
   - reason は単一の argv 値として JSON にそのまま格納（既存 CLI と同じく python の
     `json.dumps` 経由。シェル再解釈しない）。省略時は固定文字列
     （例: `Slack manual mute (Codex)`）。
   - set のセマンティクスは既存と同一（`max(既存 until, now + N分)` で短縮しない=延長のみ。
     Yoshinobu 承認・2026-07-14）。playbook 自動 mute（evacuate 2h 等）を人間の短い mute が
     誤って縮めないため。短縮したい場合は clear → set。
   - **set は実行後に「今から有効期限までの残り分数」を返す**（例:
     `muted: monnie 残り 50 分 (until <ISO8601>)`）。延長のみのため、短い N を指定しても
     既存の長い窓が優先されることがある。人間が Slack 上で実際の有効窓を誤解しないよう、
     指定 N ではなく **max 適用後の実効残り分数** を返す（status の残り分数計算と同一ロジック）。
4. **execpolicy に追加**（`codex-config.toml.j2`）: 新設 wrapper 名を `policy = "allow"`
   で列挙する。それ以外は既存の `default_policy = "deny"` のまま。
5. **AGENTS.md に追記**: 「個別 target を N 分 mute / 状態確認 / 解除」の3能力と、
   グローバル pause（`homelab-monitoring-pause`、TTL 無し全 target）との使い分けを
   Codex に明示する。上限 240 分にも触れる。

## 確認項目（tester 工程で検証）

- Slack（または wrapper 直叩き）で `monnie` を N 分 mute → mute ファイルが作成され、
  `recovery-probe` が当該 target を `muted — skip` し、連続失敗カウンタがリセットされる。
- status が3 target の状態を返す。clear で当該 target の mute が解除される。
- **上限**: 240 を超える minutes は拒否（またはクランプ）される。
- **短縮しない + 残り分数表示**: 既に長い mute（例: evacuate の 2h）が有効なとき、短い N の
  set が既存 until を短縮せず、かつ set の出力が「指定 N」ではなく「max 適用後の実効残り
  分数」を返すこと（短い N を打っても残り 2h 相当が表示される）。
- **権限**: recovery-exec が sudo 無しで mute ファイルを書けること（ACL 経路）。逆に
  mute ディレクトリ以外への書き込み権限が増えていないこと。
- **execpolicy**: Codex が新 wrapper を呼べ、かつ mute 以外の新規コマンドは
  依然 deny のままであること。
- グローバル pause（既存）と対象別 mute（新規）が独立して機能すること。

## 制約

- sudo/setuid での権限昇格を Codex 実行経路に持ち込まない（§4.5 / §6）。
- client/NL 由来の値を許可リスト照合せずに eval・変数展開しない（§10）。
- 秘密情報・IP をリポジトリに書かない。
- shell は収集・実行のみ、判定・制御は可能な範囲で上位で行う（core.md §7）。
- 実ホスト検証は tester 工程。implementer は実ホストに触れない。
