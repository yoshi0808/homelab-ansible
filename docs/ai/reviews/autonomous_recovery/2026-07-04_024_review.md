## 指摘

### must-fix: イレギュラー対応の target 再セットアップ手順が ansy 通常実行を再び許している

`docs/ai/prompts/autonomous_recovery_deploy_runbook.md:153` 以降の「targetノード(authy/monnie)が停止中だった場合の再セットアップ」で、以下の手順が残っている。

```bash
ansible-playbook playbooks/recovery_exec_setup.yml -l <quory|ansy>
```

直後に `recovery_exec_setup_targets` は既定 `true` と書いているため、この手順で `-l ansy` を選ぶと、023 で指摘したのと同じく authy/monnie の `authorized_keys` が ansy 鍵で上書きされる。

通常の復旧手順としては、target 側の再セットアップは quory 本番鍵を正とするべき。

推奨修正:

```bash
# 本番復旧: quory 鍵を authy/monnie に再配布する
ansible-playbook playbooks/recovery_exec_setup.yml -l quory
```

ansy から再セットアップするケースを残すなら、通常手順ではなく明示的な開発例外として分ける。

```bash
# 開発例外: ansy 鍵で一時的に target 側を上書きする
ansible-playbook playbooks/recovery_exec_setup.yml -l ansy

# 検証後、必ず quory 鍵へ戻す
ansible-playbook playbooks/recovery_exec_setup.yml -l quory
```

または、単に ansy ローカルの再配置だけが目的なら以下にする。

```bash
ansible-playbook playbooks/recovery_exec_setup.yml -l ansy \
  -e recovery_exec_setup_targets=false
```

### nit: `ansy 開発: target側のauthorized_keysには触らない(既定)` の「既定」は誤読される

`docs/ai/prompts/autonomous_recovery_deploy_runbook.md:23` は `-e recovery_exec_setup_targets=false` を付けることで target 側に触らない、という意味では正しい。

ただし変数の既定値自体は `true` なので、「既定」と書くと `-e` なしでも安全に見える。例えば以下の方が正確。

```text
# ansy 開発: target側のauthorized_keysには触らない(明示的に false)
```
