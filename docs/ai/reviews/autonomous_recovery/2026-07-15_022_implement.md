## 変更内容

### must-fix 1: 正本 policy と実装の同期

`autonomous_recovery_policy.md` §4.6 を次の実態へ更新した。

- pve調査はクラスタ/HAだけでなく、レプリケーション、VM/task、storage/ZFS、journalを
  含む read-only investigation であること。
- 引数なし固定12 checkと、検証済みパラメータを取る9 checkを全て列挙した。
- wrapperは一次フィルタ、本ゲートはpve側forced-command dispatchであり、
  `SSH_ORIGINAL_COMMAND`を独立に再パース・再検証する二段設計であること。
- dispatchがexact arity、regex / allowlist、limit範囲、過剰トークンを検証し、
  sudoへは固定path・固定read-only動詞・検証済みオペランドを位置固定で渡すこと。
- sudoers wildcardはパラメータ付きcheckのオペランド位置だけに限定し、
  `qm *` / `pvenode task *` / `journalctl -u *`を禁止すること。
- pve1/pve2はinvestigate-onlyであり、復旧actionを追加しないこと。
- 初期3 checkのforced-command実績と、追加checkのpath / unit / target側grammarを
  testerで確認する境界を区別した。

§6 は「3 checkのみ」という旧記述を削除し、Codexが呼べるpve調査は§4.6の固定12 +
パラメータ付き9 read-only checkだけで、二段検証を通らないコマンドは実行できない
記述へ更新した。wrapperの対象説明もクラスタ/HAだけでなく全調査カテゴリへ同期した。

role側では次の stale metadata を更新した。

- `defaults/main.yml`: pve専用鍵とpve targetsのコメントを全read-only調査カテゴリ、
  固定12 + パラメータ付き9 checkへ同期。
- `target_setup.yml`: セクションコメント、着地アカウントのcomment、sudoers配備task名を
  汎用のProxmox read-only investigation表現へ更新。
