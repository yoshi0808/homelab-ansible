## 結論

must-fix はありません。

pve1/pve2 向けの追加は read-only investigate に閉じており、pve 向け recovery wrapper / action key / action_services は追加されていません。Codex execpolicy に追加されるのも `homelab-investigate-pve1` / `homelab-investigate-pve2` のみです。

特に依頼された3点について:

- `roles/recovery_exec/templates/recovery-investigate-dispatch-pve.sh.j2` は、named check を case で固定3値に照合したあと、各分岐で固定文字列の `sudo -n ...` を直接実行しています。呼び出し元入力を使って sudo コマンドを連結・展開する経路は見当たりません。
- `roles/recovery_exec/templates/sudoers-recovery-exec-pve-target.j2` の3本は、dispatch script が sudo に渡す command path + 引数列と一致しています。`sudo -n` 自体は sudoers の照合対象コマンドではないため、sudoers 側に無いのは正常です。
- `authorized_keys-pve.j2` は `no-pty`、wrapper は `ssh -T` で tty 無し前提です。sudo 側も `-n` を使っており、tty や password prompt に依存しない設計になっています。`requiretty` がある環境では失敗し得ますが、これは requirement / policy / implement の未検証リスクとして扱われており、コード上の矛盾はありません。

## 指摘

### nit: sudoers テンプレート側にも `requiretty` 確認メモを置くとよい

- `roles/recovery_exec/templates/sudoers-recovery-exec-pve-target.j2:6`

requirement と implement には、forced command 経由・tty 無しの sudo が Proxmox 側で通るかを初回デプロイ後に確認する、と明記されています。一方、sudoers テンプレート内の NOTE は `ha-manager` の path 確認だけで、`requiretty` / tty 無し sudo の確認には触れていません。

実装上の問題ではありません。`authorized_keys` の `no-pty` と wrapper の `ssh -T` は意図通りで、`sudo -n` も非対話前提として妥当です。ただ、将来この sudoers ファイルだけを見た時に初回確認事項が抜けやすいため、同じ NOTE に「forced command + no-pty で `sudo -n` が通ることを最初に確認する」程度を追記するとよいです。
