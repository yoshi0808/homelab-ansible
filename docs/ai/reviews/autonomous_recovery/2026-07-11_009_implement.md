## 反映した指摘

### 指摘1 [must-fix] authoritative host が extra vars で上書き可能な問題を修正

対象: `roles/recovery_exec/defaults/main.yml`, `roles/recovery_exec/tasks/main.yml`

`recovery_exec_setup_authoritative_host: quory` は role defaults であり、
Ansible の変数優先順位上 `-e recovery_exec_setup_authoritative_host=ansy` で
容易に上書きできた。これは assert と include の両方の許可条件を通してしまい、
`-l ansy -e recovery_exec_setup_authoritative_host=ansy` で元のインシデントと
同じ横方向上書きを再現できる、という致命的な抜け穴だった(前回私自身が候補1
[デフォルトのみの変更]を「-e明示指定で貫通するため不十分」として却下した
基準と全く同じ理由での指摘)。

**修正**: `recovery_exec_setup_authoritative_host` 変数を defaults から削除し、
assert・includeの両方で `quory` をリテラル文字列として直接使用するよう変更した。

- `roles/recovery_exec/defaults/main.yml`: `recovery_exec_setup_authoritative_host`
  変数を削除。代わりに、正規配布元の識別子を意図的に変数化しない理由
  (role defaultはextra varsで上書き可能なため、trust anchorとして使えない)を
  コメントで明記
- `roles/recovery_exec/tasks/main.yml`:
  - assertの条件: `recovery_exec_setup_authoritative_host in ansible_play_hosts_all`
    → `'quory' in ansible_play_hosts_all`(リテラル)
  - includeの条件: `inventory_hostname == recovery_exec_setup_authoritative_host`
    → `inventory_hostname == 'quory'`(リテラル)
  - コメントで、group membership・変数化の両方を検討して却下した経緯
    (2ラウンドのレビューで指摘された具体的な抜け穴)を明記し、「`-l`/`-e`の
    どんな組み合わせでもリダイレクトできないのはリテラル固定だけ」という
    結論を記載
- `playbooks/recovery_exec_setup.yml`: tester-gate理由文から、削除した変数名
  (`recovery_exec_setup_authoritative_host`)への言及を除去し、最終形
  (quoryをコード上でリテラル固定)を反映

これで「配布元はコード上の固定値であり、ユーザーが `-e`/`-l` のどんな組み合わせ
でも変更できない」という trust anchor の要件を満たす。

## 検証(ローカル、実ホスト非依存)

前回の4パターンに加え、今回のmust-fixが指摘した具体的な攻撃パターン
(`-e recovery_exec_setup_authoritative_host=ansy` による上書き試行)を含めて
5パターンを、`main.yml`と同一の条件式を用いた使い捨てplaybook
(`hosts: dev_nodes:control_nodes`, `connection: local` = 実SSH接続なし)で
実inventoryに対し検証した(確認後に削除)。

| 実行 | 期待 | 結果 |
| --- | --- | --- |
| `-l ansy`(targets既定true) | fail | **fail** |
| **`-l ansy -e recovery_exec_setup_authoritative_host=ansy`(指摘された抜け穴の再現試行)** | **fail(変数はもう存在せず無視される)** | **fail**(`BLOCKED on ansy: quory not in play set ['ansy']`。存在しない変数を渡しても何の効果もなく、リテラル`quory`判定のみが効くことを確認) |
| `-l ansy -e recovery_exec_setup_targets=false` | success、配布なし | **success**、distribution skipped |
| `-l quory` | success、quoryから配布 | **success**、`DISTRIBUTED from quory` |
| 制限なし(全体実行) | success、ansy/quory両方成功、配布はquoryのみ | **success**、`DISTRIBUTED from quory`のみ・ansyはskip |

5パターンすべて期待通りの結果を確認した。特に2番目のケースは、今回のmust-fixが
指摘した具体的な抜け穴(変数の-e上書き)を実際に試行し、リテラル固定後は
その試行が完全に無効(変数は存在せず、条件式にも一切現れない)であることを
直接確認したものである。
