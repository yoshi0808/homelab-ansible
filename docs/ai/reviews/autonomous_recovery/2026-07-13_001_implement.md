# Slack通知・レポート時刻のJST統一（UTC取り残し修正）（implement）

- 日付: 2026-07-13
- 担当: implementer
- 発端: Yoshinobu が実機通知で発見。リポの時刻表記は JST（+09:00）が慣例
  （例: `roles/recovery_push/files/recovery-push-dispatch.sh:16`、
  `roles/recovery_service_restart/tasks/main.yml:12,160`）だが、一部が
  `date -u`（UTC）のまま取り残されていた。表示タイムゾーンのみの修正で
  ロジック変更なし。

## 変更内容

すべて `date -u +%Y-%m-%dT%H:%M:%SZ` → `TZ='Asia/Tokyo' date '+%Y-%m-%dT%H:%M:%S+09:00'`
（姉妹実装と同形）への置換のみ。

| ファイル | 箇所 | 依頼区分 |
| --- | --- | --- |
| `scripts/quory_post_upgrade_check/quory-post-upgrade-check.sh` | Slack本文の `Time:` 行（1箇所） | 依頼どおり（修正1） |
| `roles/recovery_ha_failover/tasks/main.yml` | `_rhf_started_at`（Slack通知・レポート・レポートファイル名の元）と `completed_at`（レポートJSONのみ）の2箇所 | 依頼どおり（修正2） |
| `roles/recovery_vm_reboot/tasks/main.yml` | `_rvr_started_at` / `completed_at` の2箇所 | **追加対応**（下記） |

### 追加対応: recovery_vm_reboot（依頼2件の外、同一クラス）

依頼の確認手順にある repo 全体の `date -u` スイープで、復旧ラダー第2段
`recovery_vm_reboot` に ha_failover と**完全同一パターン**の取り残し2行
（started_at / completed_at、同じ replace チェーンのファイル名生成）を発見した。
修正しないとラダーが「第1段 JST / 第2段 UTC / 第3段 JST」と不整合になるため
併せて修正した。スコープ外と判断される場合はこのファイルの2行のみ戻せる。

### ファイル名生成への影響（安全確認）

`_rhf_started_at` / `_rvr_started_at` はレポートファイル名にも使われる
（`replace(':','') | replace('-','') | replace('T','_')`）。+09:00 形式では
ファイル名が `20260713_201530+0900.json` 形式になるが、これは
`recovery_service_restart`（150-151行）が全く同じ replace チェーンで既に
運用している形式であり、姉妹ロールと同一挙動になるだけで問題ない
（依頼文の注意事項どおり）。
