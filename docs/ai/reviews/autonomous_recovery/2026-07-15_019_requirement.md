- 前提: Phase 1（2026-07-14_002）= 実機 PASS・commit 済み。本 Phase 2 は **§4.6 の「引数ゼロ・ワイルドカード無し」原則を、read-only 調査に限って明示的に緩和** する。

## 目的

Phase 1 で固定（引数ゼロ）の pve 調査 12 named check を入れたが、monnie 復元時のような
「特定 VM / 特定レプリジョブ / 特定ストレージ / 特定タスク」を掘るには **パラメータ付き**の
read-only 調査が要る。本 Phase 2 で、クライアント（Codex/Slack）から **検証済みパラメータ**を
1〜2 個受け取れるよう dispatch を拡張し、対応する sudoers を **オペランドのみワイルドカード化**する。

## セキュリティ設計（本 Phase の核。ここを review/tester で重点確認）

### 原則 A: 二段検証（wrapper = 一次フィルタ、dispatch = 本ゲート）
- `homelab-investigate-pveN <check> [<param1> [<param2>]]`。
- **wrapper**（`homelab-investigate-pve.sh.j2`, quory 側）: check 名と各パラメータを allowlist/regex で
  検証してから `ssh ... "recovery-exec@host" "$check $param1 $param2"`（単一文字列）で送る。
- **dispatch**（`recovery-investigate-dispatch-pve.sh.j2`, pve 側 forced-command）:
  `SSH_ORIGINAL_COMMAND` を **独立に再パース・再検証**する。forced-command である dispatch が
  唯一の権限境界なので、quory が侵害されて任意の SSH_ORIGINAL_COMMAND を送っても、dispatch の
  検証を通らない限り sudo に到達しない。**wrapper の検証は利便性、dispatch の検証がセキュリティ**。
- dispatch のパース: `read -r check p1 p2 extra <<<"$cmd"`。`extra` が非空なら即 `denied`
  （各 check の宣言パラメータ数ちょうどのみ許可。過剰トークン拒否）。

### 原則 B: 動詞は固定、オペランドのみワイルドカード
- sudoers 側は **read-only サブコマンド（動詞）を必ず固定**し、`*` は **ID オペランド位置のみ**に置く。
  例: `qm status *`（`status` 固定・○） は許すが `qm *`（動詞可変・×）は絶対に作らない。
- これにより「wildcard で別サブコマンド（`qm set`/`qm destroy` 等の書込系）に化ける」経路を構造的に排除。
- `sudo` の `*` は fnmatch でスペースを跨いで一致する（FNM_PATHNAME 無し）ため、`*` 単体では
  途中に余分なオプション（`-o export` 等）を差し込める。これは **dispatch が argv を位置固定で
  組み立てる**こと（`sudo -n <path> <fixed verb> "$validated_operand"`）で封じる。→ 二重防御。

### 原則 C: パラメータ regex（dispatch と wrapper で同一。option-injection ガード込み）
すべて先頭が `-` にならない charset（＝オプションに化けない）で、シェルメタ文字を含まない：

| param | 用途 | 検証（`[[ =~ ]]`, 完全一致アンカ） | 備考 |
|---|---|---|---|
| `vmid` | qm/stat/task | `^[1-9][0-9]{2,8}$`（>=100） | Proxmox の最小 VMID は 100 |
| `job-id` | pvesr read | `^[1-9][0-9]{2,8}-[0-9]{1,3}$` | `<vmid>-<index>` 形式（例 `211-0`） |
| `UPID` | task log | `^UPID:[A-Za-z0-9._-]+:[0-9A-Fa-f]{8}:[0-9A-Fa-f]{8}:[0-9A-Fa-f]{8}:[A-Za-z0-9_-]+:[0-9]*:[A-Za-z0-9._-]+@[A-Za-z0-9._-]+:$` | 先頭 `UPID:` 固定＝オプション化不能。構造検証 |
| `storage` | pvesm | `^[a-zA-Z][a-zA-Z0-9._-]{0,31}$` | PVE storage-id 命名に準拠 |
| `limit`(N) | task list | `^[0-9]{1,4}$` かつ 1..2000 | 数値のみ・上限キャップ |
| `unit` | journal | 固定 allowlist の**完全一致**（regex ではなく集合） | 下記 §journal |
| `window` | journal | 固定トークン集合の完全一致→内部で `--since` 値へマップ | 下記 §journal |

- 検証失敗は `denied: invalid <param> for <check>` で **exit 1**（sudo に渡さない）。
- vmid の path 構成（stat）は `/etc/pve/qemu-server/<vmid>.conf`。vmid が純数字なので traversal 不能。

## スコープ（Phase 2 で追加する named check）

pve1/pve2 両ノードに同一追加。命名は既存の hyphen 形式に揃える。**Phase 1 の bare check とは
別名**にして allowlist を曖昧にしない（`storage-status`(bare) と `storage-status-one <s>` は別 check）。

| named check（案） | クライアント例 | dispatch の実行 | パラメータ |
|---|---|---|---|
| `replication-read <job-id>` | `... replication-read 211-0` | `sudo -n /usr/bin/pvesr read <job-id>` | job-id |
| `vm-status <vmid>` | `... vm-status 211` | `sudo -n /usr/bin/qm status <vmid>` | vmid |
| `vm-config <vmid>` | `... vm-config 211` | `sudo -n /usr/bin/qm config <vmid>` | vmid |
| `vm-tasks <vmid> <limit>` | `... vm-tasks 211 25` | `sudo -n /usr/bin/pvenode task list --vmid <vmid> --limit <limit>` | vmid, limit |
| `task-log <UPID>` | `... task-log UPID:pve1:...:` | `sudo -n /usr/bin/pvenode task log <UPID>` | UPID |
| `storage-status-one <storage>` | `... storage-status-one local-zfs` | `sudo -n /usr/sbin/pvesm status --storage <storage>` | storage |
| `zfs-list-vm <vmid>` | `... zfs-list-vm 211` | `sudo -n /usr/sbin/zfs list`（**Phase1 の既存 rule を流用**）→ dispatch 内で `grep -E -- "[-/]vm-<vmid>-|[-/]subvol-<vmid>-"`（`|| true` で無一致時も 0） | vmid |
| `vm-conf-stat <vmid>` | `... vm-conf-stat 211` | `sudo -n /usr/bin/stat /etc/pve/qemu-server/<vmid>.conf` | vmid |
| `journal-unit <unit> <window>` | `... journal-unit pvesr 2h` | `sudo -n /usr/bin/journalctl -u <unit> --since <mapped> -n 300 --no-pager` | unit, window |

- **zfs-list-vm** は新 sudoers を **作らない**（Phase1 の `zfs list` を sudo で回し、非特権の
  dispatch 内 grep で VM 名フィルタ）。これがワイルドカード追加ゼロで「対象 VM で制限」を満たす最小手。
- **journal-unit**: 行数は **300 固定**（＝行数を「制限」）、window は allowlist 制、unit は allowlist 制。
  - unit allowlist（推奨初期値、tester が実在確認して最終確定）: `pvesr pvestatd pve-cluster corosync pvedaemon`。
    「pve 上に実在し、レプリ/quorum/VM 切り分けに寄与する」ユニットのみ（Phase1 と同基準）。**`-u <任意>` は不可**。
  - window トークン→`--since` 値マップ（allowlist）: `30m→-30 min` / `1h→-1 hours` / `2h→-2 hours` /
    `6h→-6 hours` / `12h→-12 hours` / `24h→-24 hours`。上記以外は `denied`。

## sudoers ワイルドカード化（§4.6 の明示的緩和。1:1 コメント付きで列挙）

`sudoers-recovery-exec-pve-target.j2` に以下を **追記**（Phase1 の固定行は不変）。**動詞固定・オペランドのみ `*`**：

```
# --- Phase 2: read-only parameterized checks (verb pinned, operand wildcard only). ---
# Each `*` is the operand position; the dispatch script regex-validates the operand
# before building argv positionally (defense in depth). No verb is ever wildcarded.
recovery-exec ALL=(root) NOPASSWD: /usr/bin/pvesr read *
recovery-exec ALL=(root) NOPASSWD: /usr/bin/qm status *
recovery-exec ALL=(root) NOPASSWD: /usr/bin/qm config *
recovery-exec ALL=(root) NOPASSWD: /usr/bin/pvenode task list --vmid * --limit *
recovery-exec ALL=(root) NOPASSWD: /usr/bin/pvenode task log *
recovery-exec ALL=(root) NOPASSWD: /usr/sbin/pvesm status --storage *
recovery-exec ALL=(root) NOPASSWD: /usr/bin/stat /etc/pve/qemu-server/[0-9]*.conf
# journal-unit: unit is PINNED per line (never `-u *`); only --since is wildcarded, -n fixed.
recovery-exec ALL=(root) NOPASSWD: /usr/bin/journalctl -u pvesr --since * -n 300 --no-pager
recovery-exec ALL=(root) NOPASSWD: /usr/bin/journalctl -u pvestatd --since * -n 300 --no-pager
recovery-exec ALL=(root) NOPASSWD: /usr/bin/journalctl -u pve-cluster --since * -n 300 --no-pager
recovery-exec ALL=(root) NOPASSWD: /usr/bin/journalctl -u corosync --since * -n 300 --no-pager
recovery-exec ALL=(root) NOPASSWD: /usr/bin/journalctl -u pvedaemon --since * -n 300 --no-pager
```

- `stat` の `[0-9]*.conf`: fnmatch のクラス。dispatch が vmid=純数字を保証するので argv は必ず
  `/etc/pve/qemu-server/<digits>.conf`。sudoers 側は最終防壁として先頭数字・末尾 `.conf` を要求。
- `pvenode` / `qm` / `stat` の絶対パスは **pre-deploy 実在確認**（下記）。`/usr/bin` 想定だが要確認。

## 実施項目

1. 上表 9 named check を **dispatch / wrapper / sudoers / AGENTS.md の4箇所**へ整合追加（allowlist 一致）。
2. dispatch: `SSH_ORIGINAL_COMMAND` を再パースし、**過剰トークン拒否 + 各 param を §C の regex/allowlist で検証**。
   検証後に `sudo -n <path> <verb> "$operand"` を **位置固定**で組む（文字列連結や `eval` を使わない）。
3. wrapper: 同じ検証をミラー（一次フィルタ）。ホストは従来どおりハードコード。
4. sudoers: **動詞固定・オペランドのみ `*`**。`qm *` 等の動詞ワイルドカードを作らないことを NOTE 明記。
5. **pre-deploy 実在確認**を implement/NOTE に明記（Phase1 の `command -v` NOTE を踏襲）:
   - `command -v pvesr qm pvenode pvesm zpool zfs stat journalctl`（特に `qm`/`pvenode`/`stat` の絶対パス）
   - `journalctl -u <unit>` の unit 実在（`systemctl list-units --all`。存在しない unit は exit0 空出力で **黙って失敗**する点は Phase1 と同じ罠）
   - forced-command + no-pty での `sudo -n` 成功（Phase1 実績あり・同経路）
6. tester-gate 分類は `recovery_exec_setup.yml` の現状踏襲（read-only 調査の追加で本番影響の性質は不変）。

## 確認項目（tester 工程）

- pve1/pve2 双方で新 9 check が期待 read-only 出力を返すこと（実在 VMID / storage / job-id を使う）。
- **不正パラメータが `denied` で拒否**されること（重点）:
  - option-injection: `vm-status -h` / `vm-status --help` / `task-log -x`
  - traversal/メタ: `vm-conf-stat 0` `vm-conf-stat 1/../../etc/shadow` `replication-read 211-0;id` `storage-status-one a b`
  - 範囲外: `vm-tasks 211 99999`（limit 上限超）/ `journal-unit sshd 2h`（unit 非 allowlist）/ `journal-unit pvesr 99h`（window 非 allowlist）
  - 過剰トークン: `vm-status 211 extra`
- sudoers に **動詞ワイルドカードが無い**こと（`qm *` `pvenode task *` 等が存在しない）、`*` は列挙した
  オペランド位置のみであること（`sudo -l` 相当で目視）。
- 既存 12 check（Phase1）と 3 旧 check が回帰していないこと。
- Codex（Slack）から自然言語で「VM 211 のレプリが失敗、状態とタスク履歴を見て」に対し、Codex が
  `replication-read` / `vm-status` / `vm-tasks` / `task-log` を使って一次切り分けできること（AGENTS.md 反映確認）。

## 制約

- pve1/pve2 に復旧アクション（`homelab-recover-*` 相当）を一切追加しない。調査のみ（§2/§4.6）。
- `ann` の鍵・権限は使わない。pve 専用鍵 `id_recovery_investigate_pve` 経路のまま（§4.6）。
- 動詞ワイルドカード（`qm *` 等）・`-u <任意>` の journalctl・`eval`・文字列連結での sudo 組み立て、いずれも禁止。
- 秘密情報・IP をリポジトリに書かない。実ホスト検証は tester 工程（実 VMID/UPID はコミットに残さない）。

## 除外（本 Phase では扱わない）

- 復旧アクション、書込系サブコマンド、任意ユニット journalctl、可変行数 journalctl（300 固定）。
- Phase 1 bare check の引数オーバーロード（別名の新 check として追加するため不要）。
