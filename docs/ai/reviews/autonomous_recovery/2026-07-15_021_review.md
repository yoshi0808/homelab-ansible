## 重点確認結果

### dispatch の本ゲート

- `SSH_ORIGINAL_COMMAND` に LF / CR があれば parse 前に拒否する。
- `read -r check p1 p2 extra` と `extra` 検査により、4トークン目以降を拒否する。
- 各 case arm が exact arity を再確認し、既存の引数なし check への追加引数も拒否する。
- vmid / job-id / UPID / storage / limit は完全一致 regex または範囲検査、unit / window は
  固定集合で検査される。先頭 `-`、slash、shell metachar、範囲外値、非 allowlist 値は
  sudo 到達前に拒否される。
- 入力文字列を `eval`、`bash -c`、再 shell parse する経路はない。

### wrapper と dispatch の一致

新規9 checkについて、check 名、arity、vmid / job-id / UPID / storage / limit の検証、
unit 5種、window 6種は wrapper と dispatch で一致している。wrapper が構築する remote
command は検証済み token のみで、dispatch はそれを独立に再検証する。

### sudo argv / sudoers

- dispatch は絶対 command path、固定 read-only 動詞、quoted 済み検証 operand を位置引数で
  渡す。sudo command の文字列連結や `eval` はない。
- sudoers に `qm *`、`pvenode task *`、`journalctl -u *` はない。
- `qm status` / `qm config` / `pvesr read` / `pvenode task list|log` /
  `pvesm status --storage` は動詞または subcommand が固定されている。
- journalctl は unit ごとに5行へ分離され、可変なのは dispatch 内部で allowlist token から
  生成した `--since` operandのみ。`-n 300 --no-pager` は固定されている。
- `zfs-list-vm` は既存の固定 `zfs list` ruleを再利用し、非特権 grep の無一致だけを許容する。

## sudoers grammar の評価

ローカルの `/usr/sbin/visudo -cf` では、sudo-rs の制約により非末尾 wildcard と
`[0-9]*.conf` が不受理になることを reviewer でも再現した。これは implement の報告と一致する。

一方、requirement が前提にする従来 sudo の sudoers は command arguments を1本の文字列として
fnmatchするため、非末尾 wildcard を含む記法自体は想定される grammar である。ただし、現在の
リポジトリ内には pve1/pve2 の `visudo` 実装・versionがこの Phase 2 templateを受理した証跡は
ない。`target_setup.yml` の `validate: /usr/sbin/visudo -cf %s` は不受理時に配置を止めるため
fail-safeだが、機能可否は未確定である。tester は APPLY 前または同工程で、両 target 上の
`visudo -cf` 受理結果を必須 gateとして記録すること。少なくとも現段階で、ローカル sudo-rs
不受理を理由に operand validationを弱める変更は妥当ではない。
