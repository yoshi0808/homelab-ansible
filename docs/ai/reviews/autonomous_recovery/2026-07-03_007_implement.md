## 設計

### drill ユニット

```ini
[Unit]
Description=Recovery push drill — authy (always fails, triggers OnFailure push)
OnFailure=recovery-trigger@%p.service

[Service]
Type=oneshot
ExecStart=/bin/false
```

- `ExecStart=/bin/false` で常に失敗
- `OnFailure=recovery-trigger@%p.service` → `recovery-trigger@recovery-drill-authy.service`
  → recovery-push.sh → SSH → dispatch.sh authy
- `dispatch.sh authy` の forced command は target 固定なので、
  drill ユニット名は関係なく authy の Codex セッションが起動する

### テスト手順(概要)

```bash
# 1. drill ユニット発火
ansible authy -b -m ansible.builtin.systemd \
  -a "name=recovery-drill-authy.service state=started"
# → 即 fail → OnFailure → push → quory dispatch.log に "firing: Codex" 記録

# 2. Codex セッション完了を待機
#    dispatch.log に "session ended" が出るまで待つ(Codex が investigate して終了)
#    Codex は homelab-investigate-authy status を実行し、freeradius が正常なため
#    homelab-recover-authy は呼ばない

# 3. 検証
#    - dispatch.log: "firing: Codex investigation for authy" + "session ended"
#    - authy の recover-action.sh が呼ばれていないこと
#      (recovery-exec の action key の last-used 等で確認)
```

### Codex 出力について

push path の Codex 出力は dispatch.sh の stdout → SSH セッションを通じて
recovery-push.sh(authy 側)に返るが、authy 側は受け取っても捨てている。
Slack への報告はない(push path に recovery-io を経由しないため)。

drill の合否確認は dispatch.log の "firing / session ended" と、
Codex が investigate のみで終了している(recover を呼ばない)ことで判断する。
