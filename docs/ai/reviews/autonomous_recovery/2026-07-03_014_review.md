## レビュー観点

1. `cert_renew.yml` 以外の mute 必要 playbook 見落とし
   - `recovery_push_targets` の対象サービスは authy=`freeradius`、monnie=`grafana-server/prometheus/loki/unpoller`。
   - 通常運用 playbook で該当サービスを restart しているのは `cert_renew.yml` の `grafana-server` のみ。
   - `time_sync_ntp_reference.yml` は chrony 対象、`ubuntu_nightly.yml` は needrestart レポート、`recovery_service_restart.yml` は復旧セッション側の操作なので、追加 mute 不要という判断は妥当。

2. `delegate_to: localhost` での `homelab-mute` 実行
   - `cert_renew.yml` は quory 実行を冒頭で assert している。
   - monnie play は `become: true` なので、delegate された `homelab-mute` も quory localhost 上で root 権限実行される前提と整合する。

3. mute 5 分
   - `deploy_grafana.yml` は `grafana-server` restart 後に port 3000 の `wait_for timeout=30` と TLS SAN 確認まで実施する。
   - 通常の cert deploy/restart の誤発火抑止として 5 分は十分な余裕がある。
   - 異常終了時も mute は TTL で自然失効するため、過剰に長く残らない。

4. `cert_needs_renewal=false` 時の挙動
   - mute set/clear と `deploy_grafana.yml` 内の restart は同じ `cert_needs_renewal | default(false) | bool` 条件で揃っている。
   - 証明書更新不要時に mute だけ発火する経路は見当たらない。
