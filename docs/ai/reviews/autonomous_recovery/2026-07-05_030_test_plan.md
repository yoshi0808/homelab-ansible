## 前提・スコープ

- 対象は全てread-only調査コマンドの追加。復旧アクション(homelab-recover-*、systemctl restart等)・VM操作・DB書き込みは一切対象外であり、tester は実行しない。
- `ansy` は本ロールの正規開発デプロイ先(playbook冒頭コメントに明記)。確認したところ `recovery-exec` ユーザー・`homelab-investigate-{authy,monnie}` 等は既にansy上にデプロイ済みで、今回の変更を反映するための再実行は通常の開発イテレーションであり、新規のリスクではない。
- `quory` は本番Semaphore実行基盤であり、`semaphore.db`(③の対象)はquory上にしか存在しない。③の実機検証にはquoryへのデプロイが必須。
- Phase 2(quory)はSemaphore UIやAnsible本番実行そのものには触れず、`recovery_exec`ロール(read-only wrapper + narrow sudoers)の配備のみ。ただしquoryは共有の本番自動化基盤のため、実行前にYoshinobuの明示確認を得ること。

## tester の実行義務(§18再掲)

- playbook実行時は必ず `-e tester_mode=true` を重ねる、が**本ロール(recovery_exec_setup.yml)はpre_tasksのtester_gateが`tester_gate_end: host`でデプロイ前に停止する設計**のため、tester_mode=trueでの実行は「差分プレビュー」のみに使い、実デプロイ確認は下記Phase 1/2の非tester_mode実行(通常運用として許容される開発イテレーション)で行う。
- `--syntax-check` は tester_mode の有無に関わらず必ず先に通す。
- 復旧・変更系コマンド(homelab-recover-*, systemctl restart等)は一切実行しない。

## Phase 1: ansy(開発環境)への反映 + ①②の実機確認

```bash
ansible-playbook playbooks/recovery_exec_setup.yml -l ansy
```

デプロイ確認:
- `sudo visudo -cf /etc/sudoers.d/recovery-exec-investigate` が通ること(ansible側のvalidateで既に保証されるが確認)。
- `/usr/local/bin/homelab-reports` `/usr/local/sbin/recovery-reports-helper` `/usr/local/bin/homelab-semaphore-query` が root:root 0755 で配置されていること。

① investigate 拡充(authy/monnie 実SSH経由。`recovery-exec` として実行):

```bash
sudo -u recovery-exec /usr/local/bin/homelab-investigate-authy dmesg
sudo -u recovery-exec /usr/local/bin/homelab-investigate-authy journal-freeradius
sudo -u recovery-exec /usr/local/bin/homelab-investigate-authy journal-freeradius-1h
sudo -u recovery-exec /usr/local/bin/homelab-investigate-authy journal-freeradius-24h
sudo -u recovery-exec /usr/local/bin/homelab-investigate-authy journal-freeradius-err
sudo -u recovery-exec /usr/local/bin/homelab-investigate-authy journal-freeradius-warn
sudo -u recovery-exec /usr/local/bin/homelab-investigate-monnie dmesg
sudo -u recovery-exec /usr/local/bin/homelab-investigate-monnie journal-prometheus-1h
# 拒否系(否定確認)
sudo -u recovery-exec /usr/local/bin/homelab-investigate-authy journal-freeradius-1d   # 許可外の期間 → denied
sudo -u recovery-exec /usr/local/bin/homelab-investigate-authy '; id'                  # denied
```

期待結果: 許可コマンドは対象ホスト(authy/monnie)から実データが返る。許可外文字列は quory/ansy 側 wrapper で `denied: unknown check` として弾かれ、対象ホストへの SSH 接続自体発生しないこと。

② reports/ 調査(`recovery-exec` として実行。sudoでyoshiに昇格):

```bash
sudo -u recovery-exec /usr/local/bin/homelab-reports list-playbooks
sudo -u recovery-exec /usr/local/bin/homelab-reports list-reports recovery_investigations
sudo -u recovery-exec /usr/local/bin/homelab-reports list-reports recovery_investigations sophos-fw
sudo -u recovery-exec /usr/local/bin/homelab-reports show-report recovery_investigations sophos-fw <実在ファイル名>
sudo -u recovery-exec /usr/local/bin/homelab-reports list-reports radius-health   # .jsonのみ出ること
# 拒否系
sudo -u recovery-exec /usr/local/bin/homelab-reports show-report recovery_investigations '..' 'x.json'   # denied
sudo -u recovery-exec /usr/local/bin/homelab-reports list-reports 'bad;name'                              # denied
```

期待結果: `recovery-exec` は `/home/yoshi` に直接は入れないが、sudo経由(`sudo -n -u yoshi ...`)で正しくreportsを読めること。拒否系はいずれもファイルアクセス前に弾かれること。

## Phase 2: quory への反映 + ③の実機確認(要Yoshinobu事前確認)

```bash
ansible-playbook playbooks/recovery_exec_setup.yml -l quory
```

デプロイ確認: Phase 1と同様(sudoers validate, wrapper配置)。加えて `/etc/sudoers.d/recovery-exec-investigate` の2エントリ(yoshi宛・root宛)が両方とも存在すること。

③ Semaphore失敗タスク解析(`recovery-exec` として実行。sudoでrootに昇格し `sqlite3 -readonly`):

```bash
sudo -u recovery-exec /usr/local/bin/homelab-semaphore-query recent-failed 3
# 上記で得たidのうち1件を使って
sudo -u recovery-exec /usr/local/bin/homelab-semaphore-query task-errors <id>
sudo -u recovery-exec /usr/local/bin/homelab-semaphore-query task-hosts <id>
sudo -u recovery-exec /usr/local/bin/homelab-semaphore-query task-output <id> | head -20
# 拒否系
sudo -u recovery-exec /usr/local/bin/homelab-semaphore-query recent-failed 0        # 範囲外 → denied
sudo -u recovery-exec /usr/local/bin/homelab-semaphore-query recent-failed 999      # 範囲外 → denied
sudo -u recovery-exec /usr/local/bin/homelab-semaphore-query recent-failed "1; DROP TABLE task"   # 非整数 → denied
# 書き込み不可の確認(read-onlyであることの直接確認。安全な代表クエリのみ)
sudo -u recovery-exec sudo -n /usr/bin/sqlite3 -readonly /var/lib/semaphore/semaphore.db "SELECT 1;"
```

期待結果: 定型クエリのみ実行でき、整数以外・範囲外パラメータは denied。`-readonly` のため万一の書き込み系SQLも失敗すること(参考確認のみ、実際に破壊的SQLを試す必要はない)。
