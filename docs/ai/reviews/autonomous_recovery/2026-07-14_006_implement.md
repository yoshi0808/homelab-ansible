## 概要

reviewer 指摘の 2 件を修正した。いずれも「実運用の並行・再適用でだけ表面化する」問題で、
requirement の安全要件(sudo 無し ACL 書き込み / max で短縮しない)を並行時にも保証する。

- **F1**: mute dir への `chmod/mode 0755` が、named-user ACL の **mask** を r-x に戻し、
  recovery-exec の実効 write を落とす問題。全 dir-writer を **0775** に統一して mask を rwx に保つ。
- **F2**: `read(existing until) → max() → write` が writer 間で排他されておらず、並行時に
  長い自動 mute を短い手動 mute が lost-update で短縮し得る問題。全 writer で **target 毎の
  共有 flock** を導入し、read/max/write(と clear)を単一クリティカルセクションに入れる。

## F1: ACL mask を壊さない(0755 → 0775)

### 原因(実測で確認)

POSIX ACL では named user の実効権限は `mask` に制約され、mask はディレクトリの
group-class permission bits に対応する。`setfacl -m u:recovery-exec:rwx` 後、mask=rwx に
なり `stat` は 0775 を示す。ここで後続の `chmod 0755`(人間 CLI 毎回 / ansible `file: mode:0755`
が 0775 を「0755 に直す」再適用)が走ると mask=r-x に戻り、ACL entry が rwx でも実効は r-x。
以後 wrapper の `mktemp`/`rm` が permission denied になる。

実測(scratchpad):
```
setfacl u:X:rwx (dir 0755) → mask::rwx, stat 775, X effective rwx
chmod 0755            → mask::r-x, X effective r-x   ← バグ
chmod 0775            → mask::rwx, group::r-x 不変, X effective rwx  ← 採用
```

### 修正

全 dir-writer の mode/chmod を **0775** に統一(自己修復。mask が万一 r-x でも次回 0775 で rwx に戻る)。
mask 有りなので `chmod 0775` は mask だけを rwx にし、`group::` は r-x のまま=root 以外に
write は広がらない(唯一の write 主体は root と ACL の recovery-exec)。

- `roles/recovery_exec/tasks/main.yml`: ensure-dir を 0775。ACL rwx grant は維持。
- `roles/recovery_mute/tasks/set.yml`: ensure-dir を 0775。
- `roles/recovery_mute/tasks/deploy_cli.yml`: ensure-dir を 0775。
- `roles/recovery_mute/files/homelab-mute`: `chmod 0755` → `chmod 0775`。

## F2: writer 間の read-modify-write 競合(共有 flock)

### 設計

- **target 毎の共有ロックファイル** `/var/lib/homelab-recovery/mute/.<target>.lock` を導入。
  全 writer がこの同一パスを flock してから read/max/write(clear は rm)を行う。
- ロックファイルは recovery_exec setup が **0644 root:root** で事前作成(world-readable)。
  `flock(1)` は対象を **O_RDONLY|O_CREAT** で開く(strace で確認)ため、recovery-exec は
  root 所有の 0644 ロックを O_RDONLY で開いて LOCK_EX を取れる(ロック自体に write ACL は不要)。
- shell writer は保険として「無ければ umask 022 で作成」も持つ(setup 前・別ホスト経路の堅牢化)。
- fd 9 に open し `flock 9`。ロックはプロセス終了(fd クローズ)で解放。

### 修正した writer(全 4 系統)

- `roles/recovery_exec/files/homelab-mute-set`: read→max→write を flock で囲む。
- `roles/recovery_exec/files/homelab-mute-clear`: rm を flock で囲む。
- `roles/recovery_mute/files/homelab-mute`(人間 CLI): set の read→max→write と clear の rm を flock で囲む。
- `roles/recovery_mute/tasks/set.yml`(自動 mute): 従来の slurp/set_fact/copy(reader-atomic だが
  **writer-atomic でない**)を、**単一の flock'd shell タスク**へ置換。read→max→write を
  `mktemp → chmod 0644 → mv` の atomic write で行う。ロックファイル ensure タスクを前段に追加。

### set.yml を人間 CLI 呼び出しに寄せなかった理由

set.yml を `homelab-mute set` 呼び出しに置換すればロジック統一できるが、set.yml は各種 patch/
evacuate playbook から自動 mute として呼ばれる**安全機構**であり、`homelab-mute` CLI 配備順への
新規ランタイム依存を持ち込むと CLI 未配備時に patch playbook を巻き込み失敗させ得る。
自己完結性を優先し、小さな read-max-write を flock 下で複製する方式にした。ロックは共有される
(コード共有ではなくロックファイル共有=reviewer の「共通 lock」要件)ため排他性は担保される。
