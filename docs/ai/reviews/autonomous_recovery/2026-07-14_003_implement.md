## 実装概要

Codex(Slack `@Homelab` 経由)から個別ノード(`authy` / `monnie` / `sophos-fw`)を
N 分だけ mute できるようにした。既存のグローバル pause(全 target・TTL 無し)とは別に、
target 単位・TTL 付きの mute を、**sudo を使わず POSIX ACL** で recovery-exec に権限付与
して実現する(Codex サンドボックスの `no_new_privileges` で sudo が一律失敗するため。
policy §4.5 / §6)。

人間用 CLI(`roles/recovery_mute/files/homelab-mute`、root 必須の単一 subcommand 型)は
一切変更していない。Codex 経路は別コマンド名の verb 分割 wrapper 3 本として新設し、
execpolicy の command 名一致で「Codex が触れてよい mute 経路」と「人間 sudo 経路」を
物理的に分離した。

mute ファイル形式・格納先・max セマンティクスは既存(set.yml / homelab-mute)と完全互換:
`/var/lib/homelab-recovery/mute/<target>.json` = `{"until": ISO8601 %:z, "reason": ...}`。

## 変更内容の要約(requirement 実施項目との対応)

1. **Codex 用 mute wrapper 新設**: verb ごとに分割(推奨方式)。recovery-exec として
   sudo 無しで mute ファイルを直接読み書き。書き込みは既存 CLI と同じ
   `mktemp → chmod 0644 → mv` の atomic 置換。recovery-exec が作った tmp を rename する
   ため、rename/rm はディレクトリの write+exec(ACL 付与済み)のみで成立し、既存の
   root 所有 auto-mute ファイルも上書き/削除できる(mute dir は sticky bit 無し)。
2. **ACL で書き込み権限付与**: `ansible.posix.acl` で `/var/lib/homelab-recovery/mute/`
   に recovery-exec rwx。sudo/setuid は不使用。付与範囲は mute dir のみで、他パスへの
   書き込みは増やしていない。files は 0644/world-readable を維持し、readers
   (recovery-probe = yoshi、recovery-push-dispatch)がそのまま読める。
3. **入力検証**: target は allowlist(`authy`/`monnie`/`sophos-fw`)照合。minutes は正整数
   かつ **1..240**、範囲外・非整数は拒否して理由を返す(240 超は「黙って丸めず拒否」を採用)。
   reason は単一 argv → python `json.dumps`(シェル再解釈しない)。省略時は既定
   `Slack manual mute (Codex)`。set は `max(既存 until, now+N)` で短縮せず(延長のみ)、
   実行後に **max 適用後の実効残り分数** を返す(status と同一の残り分数ロジック)。
4. **execpolicy 追加**: 上記 3 コマンドを allow 列挙(§4)。
5. **AGENTS.md 追記**: 個別 mute の 3 能力とグローバル pause との使い分け、上限 240 分を明記(§5)。

## 実行した確認コマンド / 結果

実ホストには一切触れていない。検証は ansy ローカルで、実 mute パス
(`/var/lib/homelab-recovery/mute`)ではなく **scratchpad の使い捨て MUTE_DIR** に
向けたスクリプトのコピーで実施(実スクリプトは無改変。core.md §17 の副作用なし
ロジック検証に相当)。検証後、使い捨てコピーは削除済み。

- `bash -n` 構文チェック(3 本): 全 OK。
- 使い捨て MUTE_DIR でのロジックテスト(16 シナリオ)全て期待どおり:
  - fresh set → until/残り分数正しい。status が MUTED(50m) 表示。
  - 短い N の set が既存 until を **短縮しない**(残り 50 分のまま。max セマンティクス)。
    reason は最新 set の値に更新される(既存 set.yml / homelab-mute と同挙動)。
  - 240 への延長 OK。
  - `0` / `241` / 非整数 `5x` / 未知 target `pve1` → いずれも exit=1 で拒否・理由表示。
  - reason 省略 → 既定 `Slack manual mute (Codex)` が JSON に格納。
  - clear で解除、二重 clear は `not muted`、未知 target の clear は拒否。
  - 生成ファイル mode = 0644。
- `codex-config.toml.j2` / `AGENTS.md.j2` の Jinja parse: 両方 OK(追加は素の TOML/
  Markdown のみで新規 Jinja 構文なし)。
- 新規/編集ファイルに IP リテラルが混入していないこと: OK(grep でゼロ)。
- git diff レビュー: 3 追跡ファイルの差分は意図した surgical 変更のみ。implementer2 の
  作業(pve 診断)との競合なし。

## 注意点(claude に判断を仰ぐ点あり)

1. **AGENTS.md の許可ツール列挙行の編集**: requirement の担当範囲は「監視制御/mute
   セクションのみ」だが、Prohibitions 節の
   「Do NOT call tools other than …」列挙に `homelab-mute-*` を足さないと、AGENTS.md が
   「mute 能力を説明しつつ、その呼び出しを禁止する」自己矛盾状態になり、Codex が新
   wrapper を使わない恐れがある。機能的に必須と判断し、当該 1 行のみ targeted Edit で
   追記した(pve 診断=implementer2 の領域には触れていない)。この 1 行が指定セクション
   外である点を明示報告する。不可なら差し戻し可能。
2. **tester-gate マーカーの再評価**: requirement 対象ファイルに
   `playbooks/recovery_exec_setup.yml`(tester-gate 現状維持でよいか再評価)が挙がって
   いた。再評価の結論: **`risk-accepted` を維持**、playbook ヘッダは無変更。理由: 今回の
   追加は wrapper の copy 配布・mute dir 作成・mute dir への ACL 付与のみで、サービス
   再起動を一切伴わず、単一ホスト内のローカル変更に閉じる。ACL は recovery-exec 自身の
   uid にビットを足すだけで昇格を伴わない。既存 risk-accepted の根拠(recovery-exec の
   ユーザー/鍵/wrapper/ACL 整備、service restart なし)にそのまま収まる。横方向クロバー
   懸念のある target authorized_keys 配布は別タスクで既に quory リテラル固定ガード済みで、
   今回の変更はそこに触れない。
3. mute の allowlist は静的 3 target(`authy`/`monnie`/`sophos-fw`)をハードコード。
   `recovery_exec_targets`(authy/monnie のみ、sophos-fw を含まない)ではなく、既存
   human CLI / policy §7 の mute 対象(sophos-fw を含む)に合わせたため、テンプレート化
   せず静的 files/ に置いた(homelab-monitoring-* / homelab-mute と同じ配置方針)。
