## 前回 findings の確認

### F1 create-only 0755 + ACL mask: 解消

- `roles/recovery_exec/tasks/main.yml`
- `roles/recovery_mute/tasks/deploy_cli.yml`
- `roles/recovery_mute/tasks/set.yml`

上記 Ansible 経路は `mkdir -m 0755 -p` と `creates:` の組合せになり、directory が無い場合だけ
root 権限で作成する。既存 directory には chmod 相当の変更を行わない。

`roles/recovery_mute/files/homelab-mute` も `mkdir -m 0755 -p` のみで、毎回の `chmod` は無い。
CLI は root 実行を要求するため、新規作成時の所有者も `root:root` となる。

したがって以下の双方を満たす。

- ACL 無し: `root:root 0755`、group/other は `r-x`
- ACL 有り: ACL task が named user を `rwx` で追加して `mask::rwx` を成立させ、
  group/other は `r-x` のまま

後続の deploy/set/CLI 再適用は既存 directory の mode を変更しないため、ACL mask と
`recovery-exec` の effective `rwx` をリセットしない。

### lock の説明: 解消

set/clear/人間 CLI/Ansible task のコメントは実コードどおり、必要時の空ファイル作成、
read-only fd の open、既存 fd への exclusive flock を説明している。通常の事前作成は
`0644 root:root`、wrapper fallback が先なら `recovery-exec` 所有になり得る点も明記され、
「常に root-owned」または「flock が O_RDONLY|O_CREAT で開く」という誤説明は残っていない。
