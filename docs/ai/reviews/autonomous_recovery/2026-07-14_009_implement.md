## must-fix: F1 の作り直し(0775 一律 → 作成時のみ 0755 + ACL mask)

### 前修正(006)の欠陥

006 は全 dir-writer を **0775 一律**にした。これは named ACL が既にあるホストでは
「group bits = ACL mask」なので mask を rwx に保ち害はないが、**ACL が無いホスト/時点**では
group bits が通常の `ACL_GROUP_OBJ` に対応するため、owning group(root)に実 write を広げる。

- `recovery_probe_setup.yml` は `dev_nodes:control_nodes` に `deploy_cli.yml` を流すが、
  ansy には recovery-exec の named ACL を張る `recovery_exec_setup` が無い → ansy の mute dir は
  恒常的に `root:root 0775`(group write 有り)になる。
- quory でも ACL task 適用前は同じ状態。

= 006 の「0775 でも group:: は r-x のまま」という主張は ACL 前提でしか成立しない。前回 F1 の
目的は「mask 維持」であって「通常 group 権限の拡張」ではなかった。

### 作り直した方式(作成時のみ 0755・以後 chmod しない)

- mute dir は **作成時のみ 0755**。以後 mode を再適用しない(`mkdir -m 0755 -p` +
  ansible `creates:` の create-only。`mkdir -m` は umask に依存せず作成時だけ 0755 を付け、
  既存 dir には触れない=ACL mask を壊さない。実測確認済み)。
- `recovery_exec` の named ACL 付与が `mask::rwx` を成立させる(mode bits は触らず、
  group::/other:: は r-x のまま)。
- 全 writer(recovery_exec setup / deploy_cli.yml / set.yml / 人間 CLI homelab-mute)を
  create-only へ統一。人間 CLI は毎回の `chmod 0775` を撤去し `mkdir -m 0755 -p` に変更。

### 到達する最終状態(両プロファイルで実測確認)

```
ansy (ACL 無し): root:root 0755 — group r-x / other r-x / group write 無し / mask 無し
quory (ACL 有り): group::r-x, mask::rwx, user:recovery-exec:rwx(effective rwx), other::r-x
```

create-only の再適用(deploy_cli/set.yml/人間 CLI の再実行相当=`mkdir -m 0755 -p` 再実行)を
quory プロファイルに対して行っても mask::rwx と user effective rwx が保たれ、リセットされない
ことを確認した。

## nit: lock の open/create 説明を実コードに合わせる

実コードは「無ければ `: > "$lf"` で空作成 → `exec 9<"$lf"` で **read-only オープン** →
`flock 9` で既存 fd に **排他ロック**(local fs では open mode に依らず取得可)」であり、
「`flock(1)` が `O_RDONLY|O_CREAT` で開く」わけではない。また fallback 作成時は
recovery-exec 所有になり得るので「常に 0644 root:root」ではない。機能は変えず、以下の
コメント文言のみ実装に合わせて訂正した:

- `roles/recovery_exec/files/homelab-mute-set`(acquire_lock コメント)
- `roles/recovery_exec/files/homelab-mute-clear`(acquire_lock コメント)
- `roles/recovery_mute/files/homelab-mute`(acquire_lock コメント)
- `roles/recovery_mute/tasks/set.yml`(flock'd shell 内コメント)
- `roles/recovery_exec/tasks/main.yml`(lock 事前作成タスクのコメント。「pre-create は
  0644 root だが、wrapper の fallback が先なら recovery-exec 所有になり得る」旨に訂正)
