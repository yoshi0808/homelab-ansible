## 根本原因メモ

`roles/recovery_push/files/recovery-push-dispatch.sh` は lock 作成後に以下の trap を設定している。

```bash
trap 'rmdir "${LOCK_DIR}" 2>/dev/null || true; log "session ended"' EXIT
```

しかし Codex 起動時に shell builtin の `exec` を使っている。

```bash
exec "${WRAPPER}" exec --cd "${WORKSPACE}" \
    "${TARGET} でサービス障害を OnFailure で検知しました。調査・復旧してください。"
```

`exec` により shell process が wrapper に置き換わるため、shell の `EXIT` trap が実行されない。
そのため Codex が正常終了しても:

- `${TARGET}.lock` が削除されない
- `dispatch.log` に `session ended` が記録されない

今回の authy drill の観測結果と一致する。

## 総合判定

E-3 は push 経路と Codex 調査までは成立しているが、dispatcher の終了処理が動かないため **完了条件未達**。

修正候補:

- `exec "${WRAPPER}" ...` を通常実行に変更し、終了コードを保持してから trap または明示 cleanup を実行する
- 例: `"${WRAPPER}" exec ...; rc=$?; exit "$rc"`

この修正後に authy drill を再実行し、`session ended` と lock 解放を確認してから monnie drill に進むのが妥当。
