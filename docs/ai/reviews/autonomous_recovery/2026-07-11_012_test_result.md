changed になる既存挙動で、本安全化の合否には影響しない。

## 観測事項

- guard は role のローカル setup 後、target distribution 直前に置かれている。従って
  Phase 1/3 は ansy local setup を実行した後に期待どおり fail する。
- `ansible.builtin.shell` による fingerprint 読み取りは Ansible 表示上 `CHANGED` になるが、
  実際のコマンドは `ssh-keygen -lf` の read-only 処理で authorized_keys を変更しない。
- known_hosts の既存非冪等表示は本テストの対象外。

## 未検証事項

- 実 recovery action（service restart）は本安全化の対象外であり実行していない。
  action key の正しさは authorized_keys fingerprint で確認した。
- 将来 inventory hostname `quory` 自体を変更するケースは、リテラル trust anchor のコード
  更新が必要。本要求仕様では hostname 固定が意図された設計。
