# 観測: 先読みが実際に書けた

日付: 2026-09-03
対象: requirement の受入条件(2026-08-25 の traverse ACL 付与、commit `bbf2afa`)
結果: **充足。案件をクローズする。**

## 観測

2026-09-03、Semaphoreジョブ **#938**(monnie の月次apply、`SIGTTOU` で停止し `kill -9` で終了)が失敗し、**一次調査が自然に動いた。** 意図的に起こせない条件が成立した形である。

成果物は `ssh quory-investigate "investigation-show semaphore-938 json"` で取得した。

| 受入条件 | 結果 |
|---|---|
| `notes` に `failed to write pre-fetched Semaphore context file` が**現れない** | **現れない。** 入っているのはモデルの所見1件だけ |
| `observations` にSemaphoreのジョブ出力・ホスト結果・エラー本文が引用されている | **引用されている。** 開始/終了時刻、対象別の実行状況、失敗タスクの特定、そして **「Semaphoreのエラーは apt-get full-upgrade が rc=-9 で失敗したことを示している」** |
| — | `evidence_refs` に4本すべて — `semaphore-errors.log` / `semaphore-hosts.log` / `semaphore-log.log` / `summary.json` |

**2026-08-22 の #802 との対比が結論を出している。** あのとき `notes` は `Permission denied` を記録し、所見は「失敗タスクや直接エラーは特定不能」で終わり、`known_condition.suspected` も先読み欠落を理由に `false` へ落ちていた。**今回は同じ経路で中身を読めている。**

なお `rc=-9` は SIGKILL であり、復旧のために人が送ったものである。一次調査はそれを正しく指している。

## 今回も `known_condition.suspected` は `false` だが、理由が違う

理由は「今回読めた証拠はジョブ938専用のSemaphore出力とsummary.jsonのみで、過去同種事象との照合情報やper-host詳細スナップショットが無い」ことである。**先読みの失敗ではない。** per-host調査が省略されたのは、証拠バンドルの `collection_errors`(pve1 計画停止に伴う spool 単独レコード)により `play_host` が定まらなかったためで、これは設計どおりの挙動である。

## 残る弱点(本案件では直さない)

- **`workspace` の本番現物を開発側から観測する手段が無い。** `acl-status` の表に arm が無く、repo 側の定義までしか言えない
- **`acl-status semaphore-db` は恒久的に `Permission denied` になった**(`dev-investigate` が traverse を失ったため)。異常ではないが、ACLが付け直されていないかを開発側から観測する手段は失われている
- **先読みが空でも「調査したがわからなかった」と同じ見た目で通知が出る。** 通知が運ぶのは verdict / confidence / known_condition で `notes` は運ばない。**今回は先読みが成功したため顕在化していない**
