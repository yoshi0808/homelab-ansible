# Requirement: 一次調査の先読みファイルが書けるようにする

作成: 2026-08-25 / Coordinator

## 1. 問題定義

**一次調査の先読み機構が、2026-08-19 の導入以来1度も動いていない。**

書き手(`homelab-incident-investigate.service`、`User=yoshi`)が `/var/lib/incident-inspect/semaphore-context/` へ書けず、`[Errno 13] Permission denied` で失敗する。**原因は確定している**(`docs/ai/reviews/investigate_acl_observation/2026-08-25_005_finding.md`)。

```
/var/lib/incident-inspect   owner/group = incident-inspect   mode 750 (rwx r-x ---)   ACLなし
```

`yoshi` は owner でも group でもなく **other に落ちて `---`**、すなわち traverse (`x`) を持たない。**親へ入れないため、葉の `semaphore-context` が `yoshi` 所有・`0750` で正しく作られていても辿り着けない。**

**repo は traverse を片方向にしか与えていない。** `incident-inspect` へ葉の `x` は与えているが(sandbox 内の LLM に読ませるため)、**書き手が親を通るための経路が無い。**

## 2. 実害

**8/22 のジョブ #802 で、一次調査は「失敗タスクや直接エラーは特定不能」で終わった。**

一次調査の LLM は **SSH鍵を持たず dispatch を1つも呼べない**(`roles/incident_inspect/templates/AGENTS.md.j2`「What is not available, and why」)。**読めるのは先読みファイルと reports だけである。** その先読みが空だったため、代わりの手段が無かった。

## 3. ゴール

**`yoshi` が `/var/lib/incident-inspect/semaphore-context/` へ書けるようにする。**

## 4. 非ゴール

- **先読みディレクトリを `incident-inspect` の木の外へ移すこと。** 構造としてはそちらが自然だが(書き手が経路全体を所有し、読み手が ACL で traverse をもらう)、パスは `incident-investigate.py` の設定、一次調査の AGENTS.md、2つの role の defaults、`acl-status` の arm が参照しており影響が広い。**まず最短で直す。** 構造の整理が要るなら別案件。
- **一次調査の LLM に dispatch を持たせること。** 封じ込めは 2026-07-31 に構造で閉じた境界であり、**広げない**(Yoshinobu、2026-08-25「権限を広げたいという話では無い」)。
- **先読みが失敗したときの通知の見え方を直すこと。** 「調査できなかった」が「調査したがわからなかった」と同じ形で通知される問題は別にある(`docs/ai/status.md`)。**本案件は書けるようにするだけ。**
- `/var/lib/incident-inspect` の mode そのものを変えること。**ACL で足りる。**

## 5. 要件

### P0

**P0-1. `/var/lib/incident-inspect` へ `yoshi` の traverse を ACL で与える。**

- **`x` のみ。`r` は与えない。** 書き手は渡された正確なパスへ書くだけで、親の列挙を必要としない。既にある `incident-inspect` への付与(葉に対する `x` のみ)と同じ形にする。
- **どの role が付けるか**: このディレクトリを作るのは `roles/incident_inspect` だが、traverse を必要とするのは `roles/incident_investigate` の実行主体である。**既存の ACL 付与2件がどちらの role に置かれているかに合わせる**(`roles/incident_investigate/tasks/main.yml` に `yoshi` への token 読み取り付与と `incident-inspect` への葉の traverse 付与がある)。
- **付与の理由をコメントに残す。** 何を守っているかが後から読んで分かること。

**P0-2. `workspace` が閉じたままであることを確かめる。**

親へ traverse を与えると、`yoshi` は同じ親の下の `/var/lib/incident-inspect/workspace` にも到達を試みられるようになる。**repo 側の定義では `incident-inspect` 所有の `0750` であり、`yoshi` は other のままで入れないはず**である(`roles/incident_inspect/tasks/main.yml`)。**この前提が本番で成り立っていることを確認する。**

### P1

**P1-1. `docs/ai/status.md` の「壊れている」行を、修正済み・観測待ちへ更新する。** 本案件のクローズ時に Coordinator が行う。

## 6. 受入条件

**AC1 — 親を通れるようになる**
> **Given** quory へ配備した後、
> **When** `ssh quory-investigate "acl-status incident-inspect-root"` を実行したとき、
> **Then** `user:yoshi:--x` の ACL エントリが現れる。`r` は含まない。終了コード `0`。

**AC2 — 葉が読めるようになる(通れたことの裏側)**
> **Given** 同上、
> **When** `acl-status incident-inspect-context` を実行したとき、
> **Then** **`Permission denied` ではなく `getfacl` の出力が返る。**
> **配備前は `Permission denied` だった**(`docs/ai/reviews/investigate_acl_observation/2026-08-25_004_test_result.md` AC2)。**この変化が、traverse が効いたことの直接の証拠である。**
> ただし `dev-investigate` と `yoshi` は別の identity である。**これは「`yoshi` が書ける」ことの証明ではない** — AC3 が要る。

**AC3 — 実際に書ける(本案件の核心)**
> **Given** 配備後、次に Semaphore ジョブが失敗して一次調査が動いたとき、
> **Then** 成果物の `notes` に `failed to write pre-fetched Semaphore context file` が**現れない**。`observations` に Semaphore のジョブ出力・ホスト結果・エラー本文が引用されている。`known_condition` が先読み欠落を理由に `false` へ落ちていない。
> **意図的に起こせない** — Semaphore ジョブの失敗が要る。**観測待ちとして `docs/ai/status.md` へ置く。**

**AC4 — `workspace` は閉じたまま**
> **Given** 配備後、
> **Then** `yoshi` が `/var/lib/incident-inspect/workspace` へ到達できない。**確認手段が開発側に無い場合は、その旨を残す**(`acl-status` の表に `workspace` の arm は無い)。

**AC5 — 冪等**
> **Given** 配備を2回連続で実行したとき、
> **Then** 2回目は当該タスクが `changed` を返さない。

**AC6 — 配備物側**
> **Given** quory へ配備した後、
> **Then** `deployed-hash incident-investigate` が repo と一致する。**本案件は同 role の `tasks/main.yml` を変えるが、`incident-investigate.py` も同じ setup で配られる** — 2026-08-25 の IP 表記の変更(`a8aabf1`)がこの配備で入る。

## 7. オープンクエスチョン

- **`workspace` の現物の mode を開発側から確認できない。** `acl-status` の表に arm が無い。AC4 は repo 側の定義と、配備が `ok` を返すことまでしか確かめられない可能性がある。**確かめられない場合は残存リスクとして記録する。**
- **AC3 は意図的に起こせない。** 次に Semaphore ジョブが失敗するまで確定しない。
