## 実装内容

`roles/incident_investigate/tasks/main.yml` に、既存の「`incident-inspect` が葉(`semaphore-context`)を通る」grantの直後へ、鏡像となる新task「`yoshi` が親(`/var/lib/incident-inspect`)を通る」grantを追加した。

```yaml
- name: Grant yoshi ACL traverse on the incident-inspect root directory (mirrors the grant above; x only, no r — least privilege)
  ansible.posix.acl:
    path: "{{ incident_investigate_inspect_root }}"
    entity: "{{ incident_investigate_run_user }}"
    etype: user
    permissions: x
    state: present
  become: true
  when: not ansible_check_mode
  tags: [destructive]
```

`incident_investigate_inspect_root: /var/lib/incident-inspect` を新規変数として `defaults/main.yml` に追加した。既存の `incident_investigate_semaphore_context_dir` / `incident_investigate_inspect_workspace` の共通の親であることと、mode/所有者が `incident-inspect` の副作用として決まっていること(finding参照)をコメントに残した。

## P0各項の充足状況

**P0-1(ACLで `x` のみ付与)** — 満たしている。差分上、`permissions: x` のみで `r` を含まない。既存の「`incident-inspect` への葉の `x` のみ付与」と同型。付与理由はtask直前のコメントに残した(`/var/lib/incident-inspect` が `incident-inspect` 所有・`0750` で `yoshi` が other に落ちること、実害として2026-08-19以来 `[Errno 13] Permission denied` が起きていたこと)。

**P0-2(`workspace` は閉じたまま)** — **repo側の定義で確かめられる範囲**: `roles/incident_inspect/tasks/main.yml` と `roles/incident_investigate/tasks/main.yml` の全 `ansible.posix.acl` taskを列挙し、`incident_inspect_workspace`(`/var/lib/incident-inspect/workspace`)を対象にした付与が1件も無いことを確認した(grepで裏取り済み)。`workspace` 自体は `roles/incident_inspect/tasks/main.yml` が `owner: incident-inspect, group: incident-inspect, mode: "0750"` で作成しており、`yoshi` はここでも owner でも group でもなく other のまま — 親への traverse を追加しても、`workspace` 自身への `x` が無ければ POSIX的に入れない。**repoの定義上、`workspace` は変更していない。**
**確かめられない範囲**: 本番 `workspace` の現物のmode/所有者/ACLが、この repo 定義どおり配備されているか。`acl-status` にこの arm が無く(requirement 7節オープンクエスチョンと同じ)、Implementerは実ホストへ触れないため確認できない。AC4として観測手段の要否も含めCoordinator/Testerへ持ち越す。

**P0-1のコメント要件(付与理由を残す)** — 満たしている。上記の通りtask直前に理由・実害・鏡像である旨を記載。
