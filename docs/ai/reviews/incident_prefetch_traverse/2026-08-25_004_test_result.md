## AC2 — negative check(対象外identityの到達範囲が広がっていないこと)

**PASS。**

```
$ ssh quory-investigate "acl-status incident-inspect-context"
getfacl: /var/lib/incident-inspect/semaphore-context: Permission denied
rc=1
```

`acl-status` を実行している identity は `dev-investigate`(`~/.ssh/config` の `Host quory-investigate` エントリで `User dev-investigate` を確認)。今回の付与は `yoshi` にのみ traverse を与えるものであり、`dev-investigate` は対象外の identity である。`Permission denied` のまま(=読めるようになっていない)ことを確認した。訂正後のAC2の記述と一致する。

## AC4 — workspace は閉じたまま

**quory本番の`workspace`の現物ACL/modeは、開発側の手段では確認できない。** `acl-status` の対応表(`roles/dev_investigate/files/recovery-investigate-dispatch-quory.sh` の `acl-status)` arm、`yoshi-home` / `semaphore-dir` / `semaphore-db` / `reports-root` / `incident-inspect-root` / `incident-inspect-context` の6エントリ)に `workspace` の arm が無いため、`ssh quory-investigate "acl-status ..."` では到達できない。dispatchのカタログに無い手段を自分で組み立てることはしていない(execution_boundary_policy EXEC-043)。

確認できたのは**repo側の定義**のみ。

```
$ grep -n "workspace" roles/incident_inspect/tasks/main.yml
102:- name: Create Codex workspace directory (incident-inspect only; no group write)
104:    path: "{{ incident_inspect_workspace }}"
116:    dest: "{{ incident_inspect_workspace }}/AGENTS.md"
```

`roles/incident_inspect/tasks/main.yml` 102-111行目で、`{{ incident_inspect_workspace }}` は `owner`/`group` とも `incident_inspect_user`(=`incident-inspect`)、`mode: "0750"` として定義されている。`yoshi` への ACL 付与は `roles/incident_investigate/tasks/main.yml` にあり(実装本体 `bbf2afa`)、そこに `workspace` を対象にした付与は無い。repo定義上は `yoshi` が other のまま到達できないはずだが、**これは repo の定義を読んだだけであり、quory本番の現物ACL・mode・親traverseの実測ではない。**

**未確認事項として記録する**: 本番の `/var/lib/incident-inspect/workspace` の実際のパーミッション・ACLは、今回の検証範囲では測れていない。requirement §7 が既に述べているとおり、開発側からの確認手段自体が存在しない。
