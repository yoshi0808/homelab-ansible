## 5. AC4: 全候補ノード到達不能(decoy)

### 検証手法と、フルplaybookでなくroleを直接呼んだ理由

3本の実playbookは`roles/proxmox_reachable_nodes`の直後に`proxmox_healthcheck`等の本体roleを`become: true`で呼び、実Proxmox専用スクリプト(`pvesh`等)をコピー・実行する。decoy(localhost/loopback)へこれを本実行すると、ansy自身へ`become`でスクリプトを書き込み・実行することになり、「decoyで実システムに影響するモジュールを使わない」という許可条件に抵触する。そのため**AC4・AC6・AC7は`roles/proxmox_reachable_nodes`単体を呼ぶ最小playbookで検証した**(3本のplaybookが`roles:`リスト先頭でこのroleを呼ぶ契約になっているため、ここで検出すべき不具合はplaybook側でなくrole側にある。§0でも明記した設計上の理由)。

### decoy inventory(実host名・実IPv4を含まない、scratchpad配下、repo外)

```yaml
all:
  children:
    proxmox:
      hosts:
        decoy-a:
          ansible_host: 127.0.0.1
          ansible_port: 1
          ansible_connection: ssh
          ansible_ssh_common_args: "-o ConnectTimeout=3 -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o BatchMode=yes"
        decoy-b:
          ansible_host: 127.0.0.1
          ansible_port: 2
          ansible_connection: ssh
          ansible_ssh_common_args: "-o ConnectTimeout=3 -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o BatchMode=yes"

```
