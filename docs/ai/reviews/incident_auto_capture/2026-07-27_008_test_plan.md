## 現状認識(着手前に確認した事実)

- `roles/common_slack/tasks/capture.yml`・`notify.yml`のblock/rescue化は既にcommit済み・quory pull済みで本番稼働中(Coordinator申し送りどおり)。したがってAC1は「新規に導入する」検証ではなく「**既に本番へ出ているものが安全か**」の事後確認になる。
- `roles/incident_capture/`(収集器)・`playbooks/incident_capture_setup.yml`はcommit済みだがquoryへ**未配備**。W5でのタスクの1つとして配備する(`incident_capture_service_enabled: false`のまま、timerは起動しない)。
- Reviewer指摘のCritical(collector `_spool/`のowner未指定→root:root化/ pre-commitの非ASCIIファイル名無警告スキップ)は、現物確認により両方とも修正済みであることを確認した(`roles/incident_capture/tasks/main.yml:38-42` に`owner: yoshi`、`scripts/git-pre-commit-check.sh:6-24`に`core.quotepath=false`+quoted-path fail-closed)。
- 収集器は`last_failed_task_id`のstateをローカルファイル(`/var/lib/homelab-recovery/incident-capture/state.json`)に持ち、初期値0。**quoryでの初回実行は、既存の全recent-failedジョブ(最大50件)を「新規」として処理する**。これはAC2(replay)の`When`をそのまま満たす — 新しい失敗を起こす必要も、stateを人為的に巻き戻す必要もない。

## 実施順序と優先度

1. AC1(本番挙動が変わっていないこと)— 最優先。既存T1の安全性確認
2. pre-commitゲート回帰(`/tmp`使い捨てrepo、`git commit`しない)
3. 収集器の配備(risk-accepted、timer無効のまま)→ AC6 / AC5 / AC7
4. AC2(replay、配備直後の初回実行で自然に満たされる)/ AC3 / AC4
5. AC8(コスト実測、`ubuntu_nightly.yml`)

時間が足りない場合は下位から残し、実施有無を明示する。
