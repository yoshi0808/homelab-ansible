## 4. Q-U2-1(reports/不在ホストでの挙動)に関する技術的な訂正 — 実装は変更せず、報告のみ

計画§4 U2の制約欄はこう書いている:

> `mkdir -m 0755 -p` は `-p` により親も作りうる。**`reports/` 自体が存在しないホストでは親がroot所有で作られる**(現行の `file` タスクも同じ露出を持つ。`ansible/modules/file.py:638-663` が中間ディレクトリにも同じ属性を適用する)。今回この露出を**広げない**こと。

`ansible/modules/file.py`(このマシンの `/usr/lib/python3/dist-packages/ansible/modules/file.py`)の `ensure_directory()` を実際に読んだところ、**引用の括弧内の理由づけと結論が逆だった**:

- `ensure_directory()` は `prev_state == 'absent'` のとき、対象パスを `/` から `strip('/').split('/')` で分解し、**存在しない各コンポーネントに対して `os.mkdir()` した直後に `set_fs_attributes_if_different()` でタスクの `owner`/`mode` をその都度適用する**(614-663行、コメント自身が「Something like mkdir -p with mode applied to all of the newly created directories」と明記)。
- つまり**旧・現行いずれの `file` タスク(`owner: yoshi`, `mode: "0755"` 指定)でも、`reports/` が存在しなければ `reports/` 自体も `owner: yoshi` で作られる。root所有にはならない。**
- 一方、**私の新実装**(`command: mkdir -m 0755 -p` を `become: true` で実行し、後続の `file` タスクは葉ディレクトリ(`reports/incidents`)にしか触れない)では、`reports/` が存在しない場合、`mkdir -p` を実行するプロセスの実効UID(`become: true` によりroot)がそのまま `reports/` の所有者になる。**後続の `file` タスクは既存ディレクトリ(`reports/incidents`)の属性しか強制しないため、親(`reports/`)のowner=rootはそのまま残る。**

**結論: 「reports/不在ホストでの挙動」について、計画の想定(現行も新実装も同じ露出=root所有)とは異なり、実際には「現行はyoshi所有、新実装はroot所有」という一段階の違いが生まれる。** これは所有者がrootになる分、mode自体は同じ0755のまま(group/otherの権限ビットは変わらない)なので、パーミッション"広さ"としては変わらないが、**所有者の変化自体が挙動の変化**である。

**この変化を実装で回避しなかった理由**:

1. **現実には到達しない経路である可能性が高い。** `reports/` は `.gitignore` が `reports/**/*.json` 等のみを除外しており、`reports/` 自体および `reports/radius-health/README.md` 等の一部ファイルはgit管理下にある。**通常の `git clone`/`git pull` を経た任意のホストでは、`reports/` は必ず(少なくとも空でなく)存在する。** ゼロから `reports/` が存在しない状態でこのroleが走る経路を、リポジトリの構成から見つけられなかった。
2. **Coordinatorの決定(Q-U2-1)は「現状の露出を維持する形で実装し、変更が要るなら別単位で行う」であり、私の裁量で `mkdir -p` の代わりに(親も含めて再帰的にowner適用する)別の実装へ変えることは、計画§2(固定済みインターフェース、C1・D3・D4)を超える設計変更になる。** D3は「`mkdir -m 0755 -p <dir>` + `creates:`」という形そのものを名指しで指定しており、`recovery_mute` の先例と完全に一致させることが目的の一部。
3. 実害の方向も「より制限的(root所有)」であり、「より緩い露出」ではない。RSK-06(reports/直下へACLを広げない)には抵触しない。

**未解決事項として明記する**: 実装は計画どおり `mkdir -m 0755 -p` + `creates:` のまま変更していない。**ただし計画の当該箇所の技術的根拠(`file.py:638-663` の解釈)は誤りであり、実際には新実装の方が「reports/不在時、親をroot所有にする」という、旧実装には無かった挙動を持ち込む。** 実運用上この経路に到達する可能性は低いと判断したが、**Reviewer(U3)がこの点を独立に確認し、Coordinatorへ正確な事実として引き継ぐこと**を求める。「現状の露出を維持する」という決定の前提事実そのものが変わるため、Q-U2-1の再確認が必要かどうかはCoordinatorの判断に委ねる。
