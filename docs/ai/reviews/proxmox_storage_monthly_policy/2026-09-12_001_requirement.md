# Proxmoxストレージ月次点検のPolicy補完

状態: 要件確定。2026-09-12のYoshinobuとの対話を反映。

## 1. 問題定義

`proxmox_storage_monthly.yml`は本番稼働しているが、専用Policyがなく、既存`proxmox_operations_policy.md`の入口一覧にも載っていない。デバイス非変更、部分失敗、記録、公開、保持、collect/replayの規範がrequirementとContextに留まっている。

## 2. ゴール

既存Proxmox Operations Policyを、このplaybookの許可・禁止・停止条件の正本として完成させる。

## 3. 非ゴール

新しいPolicyファイル、実装変更、schedule変更、scrub/self-test/修復機能は追加しない。00:40のSemaphore反復ドリフトは別案件とする。

## 4. ユーザーストーリー

管理者とAIはPolicyだけを読んで、月次点検で許される観測・記録・公開と、禁止されるデバイス操作、失敗時の終了条件を判断できる。

## 5. 要件

### P0 / Must

- SB-020の入口一覧へ`proxmox_storage_monthly.yml`を追加し、read-only収集と付随する書込を区別する。
- scrub/trim/self-test/修復、pool/device設定変更を禁止する。
- 全対象hostを結果に含め、収集不能・履歴破損・保存/Notion失敗を成功扱いしない。
- JSON正本、Notion参照コピー、Slack短報の関係を定める。
- collect/replayの許可範囲と、古いreportによる巻戻し拒否を定める。
- 保持削除と通知抑止の境界を定める。

### P1 / Should

- 既存Policyの一般read-only点検と異なる部分だけを追加し、Contextや実装値を複製しない。

## 6. 成功指標・受入条件

- AC1: Given Policyだけを読む、When SB-020を確認、Then月次点検が自動実行可能なsemi-safe入口で、host/deviceを変更しないと判断できる。
- AC2: Given 片host収集不能または履歴/保存/Notion失敗、When終了条件を確認、Then利用可能な証拠を残して非0終了し、全体OKにしないと一意に分かる。
- AC3: Given ZFS/NVMeの健康異常だが収集・保存・公開が完了、When終了条件を確認、Then健康状態は警告/異常として通知しつつ処理自体はrc0となることが分かる。
- AC4: Given collect/replay、When許可範囲を確認、Thenreplayが実hostへ収集せず保存済みJSONから再公開し、古いreportで新しい月次ページを巻き戻さないことが分かる。
- AC5: Given保持期限または検証実行、When削除・通知条件を確認、Then比較基準/未公開記録を削除せず、native checkと通知抑止で外部送信しないことが分かる。
- AC6: Given変更後、When文書整合検査と独立規範レビュー、Then参照切れ・Policy内矛盾・Contextとの規範競合がなく、各検査rc=0またはApproveとなる。
