## Safety classification and side-effect boundary

`playbooks/radius_healthcheck.yml` のヘッダは `# tester-gate: safe-readonly` である。今回の変更本体は `df -B1 -P /` による観測、JSON整形、Ansibleでの判定・report/debug追加であり、patch、restart、reboot、migration、firewall、inventory変更を含まない。

ただしplaybookの通常実行全体は、対象hostの `/usr/local/sbin/radius-healthcheck.sh` へのcopy、localhostへのreport directory/file作成、critical/warning時の条件付きSlack通知を含む。通知は現行コードでは `skip_notifications` で抑止され、ヘッダ理由に残る `tester_mode` は廃止済みの古い表現である。したがってmarkerだけを根拠に実host実行を当然視しない。

今回の受入条件は、ローカル実値、mock `df` fixture、Ansible syntax、source taskを使うlocalhost一時harnessで十分に検証できる。実host固有のservice/port/journal状態はdisk差分の成立条件ではなく、通常実行すると上記copy/report/notificationの副作用が増えるため、実host playbookは実施しない。`skip_notifications=true` を付けてもcopyとreport出力は残るため、この判断は変わらない。

## Planned checks

### 1. Static and repository checks

- `bash -n` で変更shellの構文を確認する。
- YAML parseと `ansible-playbook --syntax-check` を実行する。syntax-checkはhostへ接続せず、playbook taskを実行しない。
- `git diff --check` と対象diffを確認し、変更が指定2ファイルだけであること、playbook/main.ymlが未変更であることを確認する。
- `scripts/check-tester-gate.sh` でmarker lintを確認し、playbookヘッダが `safe-readonly` のままであることを確認する。
- `ansible-lint` を対象playbook/check/mainへ実行する。新規変更行の違反0件と、既存9件を位置・rule別に分離して記録する。

### 2. Shell collection and JSON fixtures

- ansy上のread-onlyな `df -B1 -P /` 実値と、shell JSONのdisk total/used/available/Use%が一致することを確認する。JSON全体や不要なhost情報は成果物へ転載しない。
- `df` command failureと不正Use% fixtureで `collection_ok=false`、disk数値が全て0になることを確認する。
- 79/80/89/90% fixtureがJSONへ同じ整数で保持されることを確認する。
- 予約領域・切り上げfixture（105/79/20/80%、105/89/10/90%）で `total != used + available` でもdf Use%の80/90を保持することを確認する。

mockはexportしたshell functionとして一時的にchild processへ渡し、repository fileは作成・変更しない。

### 3. Ansible classification, report, and debug

`/tmp` の一時playbookからsourceの `tasks/check.yml` をstatic importし、`--start-at-task "Classify criticals and warnings"` でcopy/run/parse taskを飛ばす。事前に安全なfixture `radius_health` を与え、source taskそのものについて次をassertする。

- 79: OK、warning/criticalなし。
- 80 / 89: WARNING、disk warningのみ。
- 90: CRITICAL、disk criticalのみ。
- collection failure: CRITICAL、collection failureのみ。
- `radius_report.disk` に5項目が保持され、result statusと整合する。
- sourceのdebug taskがdisk summaryを表示する。

一時harnessはlocalhost、`gather_facts: false`、変更moduleなしとし、検証後に削除する。実host、remote copy、report保存、Slack通知、main.ymlのfail taskは実行しない。

## Stop conditions

- markerが `safe-readonly` でない、または対象playbook/main.ymlに未申告diffがあれば停止する。
- fixtureがsource taskを実行せず判定式の再実装だけになる場合は、Ansible判定済みと扱わない。
- network接続、権限昇格、実host変更、通知、report生成が必要になる場合は停止してownerへ返す。
- 秘密値や内部IPを成果物へ記録しない。

実行コマンド、exit/result、期待値との差、実hostを省略した理由、未検証事項、指定Contextの過不足、責務重複、Skill不採用、Knowledge候補を `2026-07-21_019_test_result.md` に記録する。
