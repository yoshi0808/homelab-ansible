## Code Review: capture check mode inheritance (diff)

### Summary

`capture.yml`の書込み3taskへ`check_mode: "{{ ansible_check_mode }}"`を直書きする方式と、`set_fact`のキー名を動的に切り替えて`_capture_written_id`を`--check`下では触らせない設計は、いずれも独立再現で成立を確認した。requirement R1〜R3、AC1〜AC5相当をfixtureで満たしており、ADR-004・IC-008/009/010/027に抵触する変更は無い。scopeもrequirementどおり`capture.yml`とテスト新設に閉じている。Blocking findingは無い。AC2の「件数不変」がテストコードとして自動assertされておらず目視比較止まりである点をMinorとして残す。

### Critical Issues

なし。

### Major Issues

なし。計画査読M1(set_factがcheck modeでも値を設定してしまう問題)は、書込み印を`_capture_written_id`から別名の no-op fact(`_capture_check_mode_noop`)へ動的キーで逃がす方式で解消されており、上記の独立再現で実際に`_capture_written_id`が`--check`下で変更されない(既存値保持・未定義なら未定義のまま)ことを確認した。

### What Looks Good

- R2: ヘッダコメントと不変条件コメントが、新しい継承規則(taskへの明示指定でcaller由来のcheck_modeを打ち消す)へ書き換わっており、実装と一致している。
- R3 / M1解消: 「書いた」印を`_capture_written_id`から`_capture_check_mode_noop`へ動的キーで逃がす設計は、`--check`下で`_capture_written_id`に一切触れないため、既存値の保持(未定義なら未定義、既存値があればそれを保つ)を"何もしない"ことで自然に満たす。`when:`によるtask skipを使っていないため、recapの`ok`/`skipped`内訳も変えない(独立再現・fixture実行の両方で確認)。
- notify.yml側の変更はゼロで、footerの式(`capture: <id>` / `_capture_written_id is defined`)はfixtureのassertでも再現しており一致する。ADR-004 (a-2)「notify.ymlの既存行は1行も変更しない」を維持している。
- ADR-004 (c-2) / IC-008(状態・チャネル等を条件にした`when:`を追加しない)、IC-009(捕捉は抑止ゲートより前のまま、フラグとして記録するだけ)、IC-027(caller側の`check_mode: false`自体は変更していない)のいずれも、diffはこれらへ触れていない。
