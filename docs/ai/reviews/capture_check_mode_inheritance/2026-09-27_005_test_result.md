## 残存リスク
- `check_mode: "{{ ansible_check_mode }}"` は「CLIの `--check` 値のみに従う」設計であり、呼び出し側が意図的に `check_mode: true` を指定して捕捉だけを止めたいケース(`--check` ではない通常実行中)には効かない(実測済み、意図通り)。これは要件R1の明示的な設計(「値の出どころは `ansible_check_mode`」)であり、欠陥ではないが、将来「通常実行中でも捕捉だけ止めたい」要求が出た場合は別途の指定が要る、という制約として記録しておく。
- 動的キー名の `set_fact`(`"{{ '_capture_check_mode_noop' if ... else '_capture_written_id' }}"`)は本リポジトリで初出のパターン。今回の全ケースで意図通り動作することを実測したが、Ansibleのバージョンに依存する挙動(モジュール引数のキーがJinjaテンプレートされる)である点は留意点として残す。
