## 実装結果

### 1. monnie journal の自己ノイズ抑止

- `alloy_observability_journal_drop_units` を defaults に追加し、正規の full unit 名を列挙した。
  - `loki.service`
  - `alloy.service`
  - `grafana-server.service`
  - `prometheus.service`
  - `promtail.service`
- `system` journal source の後段だけに `loki.process "system_pipeline"` を追加した。
- journal の既存 relabel 後の `job=ubuntu-nodes`, `host=monnie`, `unit=<exact unit>`, `level=~"info|debug"` を `stage.match action="drop"` で破棄する。warning/error は selector に一致せず Loki へ進む。
- unit ごとに exact selector を生成するため、`.` を regex wildcard として誤解釈する余地と、Jinja→River→LogQL の不要な backslash 層を増やしていない。
- tester が実 unit 名の差異を見つけた場合は defaults のリストだけを修正できる。file source にはこの pipeline を接続していない。

Requirement の「stage.drop（selector 相当）」は、Alloy 公式仕様では label selector を受ける `stage.match` の `action = "drop"` が対応する。`stage.drop` は extracted map/本文条件用で label selector を持たないため、claude 確認のうえ公式構文を採用した。

### 2. 正規化 file の message-only 化

- `alloy_file_sources` に `strip_normalized_prefix` を追加した。
- `true` は receiver 正規化形式を持つ `pve_nodes`, `sophos_fw`, `ubuntu_nodes` の3 sourceだけ。既存の `unifi`, `network_devices` は `false`。
- 既存の level/host stage の後で次を実行する。
  1. `<level> <host> <RFC3339 timestamp> <message>` から named capture `message` を抽出。
  2. `stage.output { source = "message" }` で保存本文を message のみに置換。
- monnie journal は raw サービスログのままで、本文変換を行わない。
- input assert は prefix strip を normalized-level source にだけ許可する。render contract は message capture/output が正確に3個あることを検査する。

### 3. Grafana dashboard

`2026-07-17_grafana_infra_syslog_all_dashboard.json` の logs query を次のとおり更新した。

- Loki `maxLines`: `1500`（要求範囲1000--2000）。Grafana の Line limit は query が返すログ行数の上限であり、logs panel の表示上限になる。
- `level` multi variable の current: `warning` + `error`。
- `host`, `search`, query の `line_format "{{ .host }} | {{ __line__ }}"` は不変。

Loki retention、Loki/UFW、rsyslog receiver/送信側は変更していない。容量・retention は適用後の実測に基づく別レビューとし、policy に明記した。
