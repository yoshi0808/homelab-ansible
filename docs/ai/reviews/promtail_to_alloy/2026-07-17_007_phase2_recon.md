# Promtail → Grafana Alloy Phase 2 — read-only 前提調査

- 日付: 2026-07-17
- 担当: `tester`
- 対象: `monnie`, `pve1`, `pve2`
- 実施範囲: read-only 採取のみ

## 結論

Phase 2 の主要な前提は次のとおり。

1. monnie の Loki HTTP port 3100 は localhost 限定ではなく、IPv4/IPv6 wildcard で
   listen している。Loki config も `http_listen_address` を明示せず、
   `http_listen_port: 3100`、`auth_enabled: false`。
2. pve1/pve2 から monnie の TCP 3100 は timeout。control の TCP 22 は成功するため、
   monnie 自体への network path / name resolution は存在する。
3. monnie の UFW は active、incoming default deny。許可 rule に TCP 3100 が無い。
   現時点の到達不能は Loki bind ではなく firewall policy と整合する。
4. pve1/pve2 は Debian GNU/Linux 13 (trixie)。Grafana apt repository は無く、現行
   apt cache の `apt-cache policy alloy` は package stanza / candidate を返さない。
5. monnie の rsyslog input は `/etc/rsyslog.d/10-unifi.conf` の UDP 514 だけ。
   他の `.conf` に `imudp` / `imtcp` input は無い。

したがって pve local Alloy → monnie Loki の設計には、少なくとも次が必要になる。

- pve1/pve2 への Grafana repository / signing key の明示的な管理、または別の承認済み
  package delivery 方法。
- monnie firewall で pve1/pve2 から Loki TCP 3100 への到達を許可する設計。
  source scope は必要最小限とし、実 address は inventory / name resolution から扱う。
- Loki HTTP bind の変更は現状不要。`auth_enabled: false` のため current endpoint は tenant
  auth header を要求しないが、remote exposure の risk は requirement で明示判断が必要。

IP address は本ファイルですべてマスクした。書込、package操作、設定変更、firewall変更、
service restart は一切実施していない。

## 1. monnie Loki

### service / config path

`systemctl cat/show loki.service`:

```text
unit: /etc/systemd/system/loki.service
user: loki
ExecStart=/usr/bin/loki -config.file /etc/loki/config.yml
ActiveState=active
SubState=running
```

drop-in:

```text
/etc/systemd/system/loki.service.d/recovery-trigger.conf
OnFailure=recovery-trigger@%p.service
```

active config path は `/etc/loki/config.yml`。採取時 metadata は `root:root 0664`。

### server / auth config

```yaml
auth_enabled: false

server:
  http_listen_port: 3100
  grpc_listen_port: 9096
  log_level: info
  grpc_server_max_concurrent_streams: 1000

common:
  instance_addr: <MASKED_LOOPBACK_ADDRESS>
```

- `http_listen_address`: 未指定
- `grpc_listen_address`: 未指定
- `ss -ltnp`: Loki process が TCP 3100 を wildcard bind
- `common.instance_addr` は ring / instance 用の loopback 値であり、HTTP 3100 の bind を
  localhost に限定していない。実 socket が wildcard bind であることを優先する。
- `auth_enabled: false`: current push endpoint は multi-tenant auth header を要求しない。

### remote push のための現状差分

Loki process 自体は remote 接続を受けられる bind。pve 側 TCP test が timeout する直接の
観測差分は monnie firewall であり、Loki の `http_listen_address` 変更ではない。

monnie UFW:

```text
status: active
default incoming: deny
default outgoing: allow
current inbound allows: TCP 22, UDP 514, TCP 3000 (IPv4/IPv6)
TCP 3100 allow: 無し
```

Phase 2 APPLY では、pve1/pve2 source から monnie TCP 3100 への firewall rule が必要。
全 source への無制限公開が必要という事実は無く、scope は requirement で決める。

## 3. monnie rsyslog inputs

`/etc/rsyslog.d` の `.conf` files:

```text
10-unifi.conf
20-ufw.conf
21-cloudinit.conf
50-default.conf
```

input scan:

- `10-unifi.conf`: `imudp`, UDP 514 input
- `20-ufw.conf`: additional `imudp` / `imtcp` input 無し
- `21-cloudinit.conf`: additional `imudp` / `imtcp` input 無し
- `50-default.conf`: additional `imudp` / `imtcp` input 無し
- `/etc/rsyslog.conf`: UDP/TCP 514 example は comment のみで active input ではない

現状の network syslog receiver は UniFi 用 UDP 514 の1 input。Sophos source を同 listener
へ追加する場合、listener 自体を増やす必要はない。routing / source match / destination file /
label contract の追加が設計対象になる。

## 4. pve → monnie network reachability

pve1/pve2 双方で `/usr/bin/nc` を使用し、TCP connection establishment のみ確認した。

```bash
nc -z -v -w 3 monnie.internal 22
nc -z -v -w 3 monnie.internal 3100
```

| source | monnie TCP 22 | monnie TCP 3100 |
| --- | --- | --- |
| pve1 | rc=0, open | rc=1, timeout |
| pve2 | rc=0, open | rc=1, timeout |

resolved monnie address は双方で同一だったが、実値はマスクした。TCP 22 success により
host / route / DNS の全面障害ではない。TCP 3100 timeout と UFW rule 不在の組み合わせから、
Phase 2 preflight では firewall 適用前後の到達性を明示 gate にする必要がある。

## Phase 2 implementation / tester gate 候補

1. pve package source
   - Debian 13 / Proxmox と整合する Grafana repository/keyを明示管理。
   - repo追加前後の `apt-cache policy alloy` origin/candidateを確認。
2. monnie firewall
   - pve source に限定した TCP 3100 allow。
   - 適用前 timeout → 適用後 TCP success を確認。
3. Loki
   - current wildcard bind / HTTP 3100 / `auth_enabled=false` を意図として明記。
   - remote exposure の許容範囲を人間 gate に残す。
4. pve Alloy
   - package auto-start抑止、unit/user/storage contract、config native validateを cutover前にassert。
   - pveは既存 tailer cutoverではないため、journald read permissionとLoki実データを主 gateにする。
5. Sophos rsyslog
   - existing UDP 514 inputを再利用し、source allowlist / output file / Alloy source / labelsを追加。
   - UniFi routingの非回帰を確認。
