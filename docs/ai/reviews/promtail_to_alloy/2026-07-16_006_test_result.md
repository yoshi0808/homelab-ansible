## post-APPLY gate

### 1. installed package / unit contract

Package:

```text
alloy 1.17.1-1
```

`systemctl cat/show alloy.service` の正本:

```text
FragmentPath=/usr/lib/systemd/system/alloy.service
User=alloy
EnvironmentFile=/etc/default/alloy
WorkingDirectory=/var/lib/alloy
ExecStart=/usr/bin/alloy run $CUSTOM_ARGS --storage.path=/var/lib/alloy/data $CONFIG_FILE
```

running process:

```text
/usr/bin/alloy run --server.http.listen-addr=localhost:12345 \
  --storage.path=/var/lib/alloy/data /etc/alloy/config.alloy
```

storage path の正本は package unit と実 process の双方で `/var/lib/alloy/data`。
requirement / role default と一致した。

### 2. config / storage / ownership

```text
/var/lib/alloy                 alloy:alloy 0750
/var/lib/alloy/data            alloy:alloy 0750
/etc/alloy                     root:alloy 0750
/etc/alloy/config.alloy        root:alloy 0640
/etc/default/alloy             root:root 0644
```

実 storage data:

```text
/var/lib/alloy/data/loki.source.file.unifi/positions.yml
/var/lib/alloy/data/loki.source.file.network_devices/positions.yml
/var/lib/alloy/data/loki.source.journal.system/positions.yml
/var/lib/alloy/data/alloy_seed.json
```

各 positions file は `alloy:alloy 0600`。3 source が実際に state を生成している。

### 3. native validation / readiness

```bash
/usr/bin/alloy validate /etc/alloy/config.alloy
```

- exit 0、validation error 無し。
- `http://localhost:12345/-/ready`: `Alloy is ready.`
- listener は loopback `localhost:12345` に限定。

### 4. service exclusivity

```text
alloy_active=active
alloy_enabled=enabled
promtail_active=inactive
promtail_enabled=disabled
```

- Alloy process: 1
- Promtail process: 0
- Alloy journal は2つの file source について `start tailing file` を記録。
- Promtail と Alloy の同時 tail は無い。

### 5. Alloy user / journald permission

```text
user=alloy
primary_group=alloy
supplementary_groups=adm,systemd-journal
```

service active だけでなく、Loki に cutover 後 timestamp の
`{job="system", host="monnie", unit=~".+"}` stream が存在することを確認した。
複数 stream で非空 `unit` label と実 log entry を取得したため、journald 実読可否は PASS。
role への追加 `adm` 対応は不要（package user が既に所属していた）。

### 6. Loki 3-stream contract

Loki `query_range` を `since=20m`, `direction=backward` で read-only query した。
log body は結果 file に残さず、label / count / newest timestamp だけを確認した。

| selector | post-cutover result |
| --- | --- |
| `{job="unifi", host="uckg2"}` | success、実 entry あり |
| `{job="network-devices", host=~".+"}` | success、regex由来の複数 device host labelで実 entryあり |
| `{job="system", host="monnie", unit=~".+"}` | success、複数 unit labelで実 entryあり |

各 newest timestamp は Alloy start 後だった。したがって Promtail 由来の過去データが
query に残っているだけではなく、Alloy cutover 後の送信を確認できた。

### 7. Loki / rsyslog 非回帰

Loki:

- service: `active` / `running` / `enabled`
- `query_range`: 3 selector すべて `status=success`
- 最初の `/ready` probe は HTTP 503
  `Pattern Ingester not ready: waiting for 15s after being ready` を返した。
- 再確認では HTTP 200 `ready`。startup settling による一時状態で、継続障害ではない。
- recent Loki warning/error journal: 無し。

rsyslog:

- `active` / `enabled`
- UDP 514 を IPv4 / IPv6 wildcard で listen 継続
- `/var/log/unifi.log`: 採取間で +1176 bytes
- `/var/log/unifi-devices.log`: 採取間で +6335 bytes
- owner/mode は双方 `syslog:syslog 0644` を維持

rsyslog receiver、source routing、Loki ingestion は cutover 後も継続している。

## 非ブロッキング観測

```text
level=error msg="failed to register collector with remote server" service=remotecfg err="noop client"
```

remote config を使用しない local deployment の startup 時に1回だけ記録され、その後は
Alloy ready、全 component evaluation、3-stream push、HTTP listener、positions生成が成功した。
現時点では Phase 1 blocker とは判定しないが、将来 Alloy log の継続監視時に同 error が
反復しないか確認する価値がある。

## 実行した read-only post-check 概要

```text
dpkg-query -W alloy
systemctl cat/show/is-active/is-enabled alloy.service
systemctl is-active/is-enabled promtail
pgrep -a alloy / promtail
id alloy
stat/find on /var/lib/alloy, /etc/alloy, source log files
/usr/bin/alloy validate /etc/alloy/config.alloy
curl Alloy /-/ready
curl Loki /ready
Loki query_range for 3 selectors
ss -ltnup / ss -lunp
journalctl -u alloy / loki
```

Loki readiness の HTTP status/body を分離採取する際、一時 output file を `/tmp` に作成して
同 command 内で削除した。config / service / package / persistent data への変更は無い。
