## Findings

### must-fix: pveの無条件`stop`が既存FRR/Postfix規則を無効化する

- `docs/ai/reviews/promtail_to_alloy/2026-07-17_009_implement.md:107-128`
- 前提事実: `docs/ai/reviews/promtail_to_alloy/2026-07-17_010_pve_syslog_recon.md:33-40`

参照設定は`10-monnie-forward.conf`で全facility/priorityを転送した直後に無条件`stop`し、
文書自身が既存`45-frr.conf`、`postfix.conf`より先に評価すると明記している。rsyslogは
include fileを辞書順、ruleを上から順に評価し、`stop`はそのmessageの後続処理を即時終了する。
したがってDebianの汎用重複file出力だけでなく、導入前から存在するFRR/Postfix固有ruleも
一切実行されない。010は両fileの存在だけを確認し、内容・期待出力を調査していないため、
「journald保持が続く」だけではpveローカルのサービス別ログ契約に副作用がないと証明できない。

適用前に両既存configの内容と必要なローカルactionを調査し、それらを保持したうえで汎用重複
だけを抑止できる構造へ参照設定を直す必要がある。安全な切り分けができない場合は、まず
`stop`を外してローカル重複を許容する方がログ欠落より安全である。公式の処理順・`stop`仕様:
[rsyslog: Order Matters](https://docs.rsyslog.com/doc/getting_started/beginner_tutorials/05-order-matters.html),
[rsyslog: Basic Structure](https://docs.rsyslog.com/doc/configuration/basic_structure.html)。

### must-fix: source-IP重複検査が既存UniFi allowlistとの衝突をfail-closedにしない

- `roles/alloy/tasks/main.yml:86-101`
- `roles/alloy/tasks/main.yml:103-151`
- `roles/alloy/templates/observability-sources.rsyslog.j2:14-44`

重複assertが比較するのは`alloy_remote_syslog_allowed_ipv4s`、すなわちpve1/pve2/Sophosの
実行時DNS結果だけである。既存`10-unifi.conf`は`stat`するだけで内容を読まず、その中の
CloudKey/switch/AP source IPとは比較しない。

新規sender名が既存UniFi senderと同じIPv4へ解決してもdeployは通る。実行順は
`10-unifi.conf`→`15-observability-sources.conf`で、既存UniFi matchは書込み後`stop`するため、
そのpve/Sophos messageはUniFi fileへ誤振り分けされ、新規routeへ到達しない。これは曖昧な
allowlistを拒否するという実装説明と、UniFi非回帰・新規source正確性の双方に反する。

target上で既存UniFi allowlistのsource IP集合も取得し、新規解決結果との積集合が空であることを
deploy前にassertする必要がある。少なくとも現在のroute namespace全体でIP identityが一意で
なければfail-closedにすること。

### suggestion: rsyslog候補を全体構成として検証し、restart失敗時の復旧を用意する

- `roles/alloy/tasks/main.yml:153-188`

templateの`validate: rsyslogd -N1 -f %s`は新規snippet単体だけを検証するため、既存
`10-unifi.conf`等とのtemplate名・ruleset・include上の相互作用は検出しない。配備後restartが
失敗した場合も旧snippetを戻すrescueがなく、UDP514 receiverが停止した状態でroleが終わり得る。
現差分に具体的な構文衝突は見つからないためsuggestionとするが、本番受信点としては候補を
全体構成に組み込んだ`rsyslogd -N1`と、restart失敗時の旧config復元を推奨する。

### suggestion: DNS変更後のrole再実行条件を正本policyにも明記する

- `docs/ai/reviews/promtail_to_alloy/2026-07-17_009_implement.md:275-286`
- `docs/ai/prompts/log_observability_policy.md:66-75`

実行時解決失敗はcommand failure、空/不正出力はassert、remote sender間の重複はglobal assertで
停止するため、その範囲ではfail-closedである。また009はDHCP/DNS変更後にrole再実行が必要と
記載している。ただし配備後のrsyslog configは解決済みIPを保持し自動再解決しないという運用条件が、
正本policyには無い。DNSベース管理の重要な更新手順なので§4 rsyslog方針にも同期するとよい。

## 重点確認結果

### monnie rsyslog / UniFi連鎖

- rsyslogの辞書順により既存`10-unifi.conf`が新規`15-observability-sources.conf`より先に実行される。
- UniFi sourceは10側の既存`stop`で終了するため、15側で二重処理されない。
- 新規pve/Sophos sourceは10を通過して15で専用fileへ書かれ、`stop`する。
- 未知sourceは10/15のどちらにも一致せず、後続`20-ufw.conf` / `21-cloudinit.conf` /
  `50-default.conf`へ進む。専用Alloy fileへ混入しない。
- ただし上記must-fixのとおり、既存UniFi IPとの衝突時だけは10側が先に捕捉する。

### severity / host / journal

- rsyslog templateの行形式は`<4値level> <hostname> <RFC3339 timestamp> ...`で、Alloyの
  `^(?P<level>error|warning|info|debug)\\s`と一致する。
- pve host regex `^\\S+ (?P<host>\\S+) `は同じ行の2番目tokenを抽出する。
- `RSYSLOG_SyslogProtocol23Format`はRFC5424に近いversion付きformatで、rsyslogの既定parser
  chainはRFC5424をRFC3164より先に試す。PRI由来severityとHOSTNAMEをmonnie側で利用する構成は
  妥当。[reserved templates](https://docs.rsyslog.com/doc/reference/templates/templates-reserved-names.html),
  [default parser chain](https://docs.rsyslog.com/doc/configuration/ruleset/rsconf1_rulesetparser.html)。
- Alloy公式仕様どおりjournalの`PRIORITY`は`__journal_priority`（0--7）を生成する。4本の
  relabel ruleは0--3/4/5--6/7を`error/warning/info/debug`へ正しく置換し、既存unit relabelも
  維持する。[loki.source.journal](https://grafana.com/docs/alloy/latest/reference/components/loki/loki.source.journal/),
  [loki.relabel](https://grafana.com/docs/alloy/latest/reference/components/loki/loki.relabel/)。
- file pipelineのnamed capture→extracted map→`stage.labels`も公式schemaと一致する。
  [loki.process](https://grafana.com/docs/alloy/latest/reference/components/loki/loki.process/)。

### 入力契約 / rotation / 除外

- 動的host抽出と静的`labels.host`の同時指定禁止、および確実level抽出とbest-effort抽出の
  同時指定禁止の2相互排他assertが存在し、defaultsの4 sourceは全て通る。
- pve/Sophos fileは不存在を許容し、既存UniFi fileだけ存在・regular・world-readableを要求する。
- logrotateは新規2pathだけを対象にweekly/rotate 4/compress/delaycompress/missingok/
  notifempty/`su syslog syslog`/sharedscriptsを設定し、postrotateでrsyslogへHUPする。
- role/playbookにpve targetやLoki/UFW変更taskはなく、Loki write先はlocalhostのまま。
- 対象差分にIPv4 literalは無い。`alloy_setup.yml`のtester-gateは`check-mode-native`で、
  APPLYの人間ゲートとrsyslog/Alloy restartをheaderに明記する。
- 同居する`ubuntu_vm_full_upgrade`差分はレビュー対象外とし、変更していない。
