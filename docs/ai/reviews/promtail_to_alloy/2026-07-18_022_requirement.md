## 課題と是正

### ① monnie の journal が観測スタック自身のログを取り込み自己ループ（最重要・量の主犯）

- 事象: monnie の `loki.source.journal`（`job=ubuntu-nodes, host=monnie`）が **loki / alloy / grafana / prometheus 自身のサービスログ**を収集。Loki は「取り込んだ」ことをログに出す→journal→alloy→Loki の**自己参照ループ**でログ量が想定以上に膨張。`pattern-ingester / metric-aggregation "successfully pushed"` 等の内部 info が代表例。
- 是正: monnie の journal 収集で、**観測スタック自身の unit の info/debug を drop**（warning/error は残す＝Loki/Grafana 障害時のアラート用）。
  - 対象 unit（実名は pre-deploy で tester が確認・確定）: `loki`, `alloy`, `grafana-server`, `prometheus`（+ 廃止予定 `promtail` も残っていれば）。
  - 実装: `loki.source.journal` の後段に `loki.process` の `stage.drop`（selector 相当）で「unit が観測スタックに一致 かつ level が info/debug」を drop。unit ラベルは既存の `__journal__systemd_unit` relabel 結果、level は既存の priority→4値マップ結果を使う（新規の抽出は増やさない）。
  - **他ノード（ansy/quory/authy=file 経由、pve/sophos）には影響させない**。この drop は monnie journal source 限定。

### ② ログ本文にホスト名・時刻が二重表示（file 系ソース）

- 事象: pve/ansy 等の file 系ログは、rsyslog 受信テンプレートが本文を `<level> <host> <RFC3339時刻> <本文>` 形式で書くため、ダッシュボードの line_format が付ける左端 host と合わせて host/時刻が二重に見える。
- 是正（**収集層で解決**。ダッシュボードだけでは journal 系=接頭辞無しと file 系=接頭辞有りの混在で綺麗に扱えないため）:
  - alloy の **file 系 source** で、level/host を**ラベルに抽出したうえで、保存するログ行本体は「メッセージ部分のみ」に整形**する（`<level> <host> <RFC3339時刻>` の接頭辞を行本体から除く）。level/host は既にラベルなので情報は失わない。
  - 実装: file 系の regex に**メッセージ部分の named capture** を足し、`stage.output` 相当でその capture を行本体に設定する（既存の level/host 抽出契約は維持）。journal 系（monnie）は接頭辞が無いのでそのまま（変更しない＝raw サービスログのまま表示で可）。
  - これにより、ダッシュボードは `line_format "{{ .host }} | {{ __line__ }}"` のままで「host（左）＋メッセージ本体（重複なし）」になる。

### ③ ダッシュボードの表示上限で遡れない＋既定を WARN 以上に

- 事象: ログパネルの表示件数上限に達し、Last 3h でも数分前までしか遡れない。①の是正で量は激減する見込みだが、上限とレベル既定も調整する。
- 是正（`2026-07-17_grafana_infra_syslog_all_dashboard.json` を更新。既存 JSON は壊さず、同ファイル更新でよい）:
  - ログパネルの**表示上限を引き上げる**（例: 1000〜2000。適正値は実装判断）。クエリ側 limit も併せて調整。
  - `level` 変数の**既定を warning+error** にする（Info は変数で切り替え可能なまま）。`host` 変数・`search` は現状維持。②の line_format はそのまま（②の是正後は本体がメッセージのみになる）。
  - 方針メモ: Yoshinobu は Loki 容量・VM Disk 容量に注意したい（想定以上の量だった）。まず本是正を適用し、事後に Disk/Loki 設定（retention 等）を別途見直す（本 requirement のスコープ外だが implement/policy に注記）。
