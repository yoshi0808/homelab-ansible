# Requirement: dispatchへread-only語彙を2つ追加する(pkg-list / schedule-list)

作成日: 2026-09-14
起案: Yoshinobu(2026-09-14、`apt list --installed`をforced commandへ足したいという提案)

## 1. 問題定義

**開発側から本番の「何が入っているか」を読む手段が無い。** 2026-09-14、Yoshinobuはproxmoxとquoryの導入パッケージを調べる必要が生じ、Operator Request Channelを経由した。dispatchのカタログにパッケージ照会の語彙が無いためである。read-onlyの問いに人の起動を挟むと、Operatorセッションが立つまで答が得られない。

**scheduleは書けるが読み返せない。** 同日、`semaphore_templates_setup`(#1098)でscheduleを1件作成したあと、`active`と次回実行時刻を開発側から確認できなかった。`semaphore-query`のenumにschedule系が無く、カタログ自身も「quory自身のscheduleを読む手段は現在無い」と書いている(`roles/semaphore_templates/defaults/main.yml`)。**scheduleをas-codeで書き込む機構を持ちながら、書いた結果を読む経路だけが無い。**

## 2. ゴール

dispatchに**状態を変えない**語彙を2つ足し、上の2つの問いを開発側だけで閉じられるようにする。

## 3. 非ゴール(やらないと決めたこと)

- **`/var/log/apt/term.log` / `history.log` の読み取りは本案件に含めない。** 実際に必要になった穴である(2026-09-03のSIGTTOU事故で中身を見られなかった。`root:adm 0640`でOperatorの`ann`でも拒否)が、**読み取り専用でも権限設計(sudoers か ACL)を伴う**ため、語彙追加と混ぜない。必要になった時点で別案件を立てる。
- **`pkg-policy`(導入版と候補版の比較)は作らない。** `apt-cache policy`はapt同様に安定インターフェースではなく、安定な代替を作ると`apt-get -s`の再実装になる。**その問いは`ubuntu_vm_full_upgrade`の`operation=inspect`が月次で既に答えている。**
- pip / Ansible collection の一覧は扱わない(Yoshinobu、2026-09-14)。
- scheduleの**作成・変更・削除**は扱わない。書き込みの正本は`roles/semaphore_templates`のreconcileであり、dispatchへ書込語彙を持たせない(`docs/ai/core.md`「開発と本番の境界」)。
- 既存語彙のrename・削除は行わない。

## 4. ユーザーストーリー

- Coordinatorとして、あるパッケージが本番ホストに入っているかを、Operatorの起動を待たずに確かめたい。
- Coordinatorとして、schedule適用の直後に、書いた内容が実際にSemaphoreへ入ったかを読み返したい。

## 5. 要件

### P0(必須)

- **P0-1 `pkg-list [pattern]`** を class Q(quory)・class P(pve1 / pve2)・class G(authy / monnie)の3 dispatchへ同じ形で追加する。
  - 実装は `dpkg-query -W -f '${binary:Package}\t${Version}\t${db:Status-Abbrev}\n'`。**`apt list --installed`は使わない** — aptは非tty実行で「does not have a stable CLI interface」を警告する。
  - `pattern`は省略可。省略時は全件。指定時は`dpkg-query`のglobとして渡す。
  - `pattern`の検証は `^[A-Za-z0-9._+*-]{1,64}$`。外れた入力は**実行せず**非ゼロ終了する。
  - 余計な引数(arity超過)は既存語彙と同じく拒否する。
- **P0-2 `semaphore-query schedule-list <n>`** を追加する。触るのは2箇所 — `roles/recovery_exec/files/homelab-semaphore-query`(`QUERIES`とディスパッチ)と、class Q dispatchの`semaphore-query`のenum。
  - **`template-list`と同型にする**: `GET /project/<id>/schedules` を引き、**APIが返したオブジェクトを1行1 JSONで出す**(フィールド名を推測して組み替えない)。`id`昇順、先頭`n`件。`n`は既存と同じ`1..200`。
  - 範囲外・非数の`n`は`usage`で非ゼロ終了する(既存と同じ)。
- **P0-3 語彙カタログの更新。** `docs/ai/reviews/dev_prod_boundary/2026-08-03_008_phase3_check_catalog.md` へ、§8 / §9 と同じ形式で追加分の節を足し、総数を更新する。

### P1(あるとよい)

- `pkg-list`のヘルプ・usage文字列に新語彙が載ること(既存の一覧表示に倣う)。

### P2 / Won't

- 出力の上限行数の導入。**入れない** — 全件が知りたいという動機そのものが出発点であり、既定で切ると問いに答えられない。

## 6. 受入条件

- **AC1** Given quoryのdispatch、When `pkg-list` を引数なしで実行、Then **rc=0**、1行1パッケージで `名前 / バージョン / status` が出る。
- **AC2** Given 同上、When `pkg-list nvme*` のように正常patternを与える、Then rc=0で一致分だけが出る。**一致0件でもrc=0で空出力**(「該当なし」は正当な結果であり失敗ではない)。
- **AC3** Given 同上、When `pkg-list 'a;b'` / 空白入り / 65文字以上 など検証を外れる入力を与える、Then **非ゼロ終了**し、`dpkg-query`を実行しない。
- **AC4** Given 同上、When `pkg-list a b`(引数過多)、Then 既存のarity拒否と同じく非ゼロ終了する。
- **AC5** Given quoryのdispatch、When `semaphore-query schedule-list 200`、Then rc=0で1行1 JSON、`id`昇順で出る。When `n=0` / `n=201` / 非数、Then 非ゼロ終了する。
- **AC6** Given 日次ドリフト検査の⑩ dispatch probe、When 既存probe 2本を実行、Then **これまでどおり非ゼロで拒否される**(省略可能引数の追加でarity検査が緩んでいないこと)。
- **AC7** Given 配備後、When `deployed-hash` で該当スクリプトのsha256をrepo現物と突き合わせる、Then 一致する。**翌日のドリフト検査が差分を出さない。**
- **AC8** Given 本案件のcommit、When カタログ文書を読む、Then 追加した2語彙が引数・検証・実行内容つきで載っており、総数が更新されている。

## 7. オープンクエスチョン

- **【2026-09-14 解決】`GET /project/<id>/schedules`(一覧)が返すのは `active` / `cron_format` / `delete_after_run` / `id` / `name` / `project_id` / `repository_id` / `template_id` / `tpl_name` / `type` である(ansyのSemaphoreで実測、`2026-09-14_004_test_result.md`)。`task_params` は含まれず、次回実行時刻に相当するフィールドも無い。したがって `schedule-list` で読めるのは `active` と `cron` までであり、次回実行時刻は引き続きUIでしか見られない。以下は起案時点の記述である。**
- **`GET /project/<id>/schedules`(一覧)が何を返すかは未確認。** `roles/semaphore_templates`のコメントは「`task_params`は単体取得endpointにしか現れない」と書いており、一覧の形はそれと別である。**次回実行時刻をSemaphoreがAPIで返すかどうかも未確認。** 返さないなら、この語彙で読めるのは`active`・`cron`・`template_id`等までであり、**それを事実として記録する**(返らないものを推測で合成しない)。
  - 確かめる場所は**ansyのSemaphore**である(`docs/ai/policies/execution_boundary_policy.md` EXEC-052、鍵を持たずどこへも到達しないAPI検証用インスタンス)。Implementerは実ホストへ到達しないため、この確認はTesterが行う。

## 8. タイムライン考慮

- **commitと配備を離さない。** 3本のdispatchと`homelab-semaphore-query`は配備物であり、`roles/deployment_drift_check/defaults/main.yml` がrepo現物と配備物をsha256で突き合わせている。repoだけ変えると翌日のドリフト検査が差分として鳴る。
- 配備の入口は class Q が `playbooks/dev_investigate_setup.yml`、class P / G の dispatch と `homelab-semaphore-query` が `playbooks/recovery_exec_setup.yml`(`roles/recovery_exec/tasks/main.yml:442` が helper を、`tasks/target_setup.yml:283` が pve dispatch を配る)。**いずれもquoryのSemaphoreから実行するもので、開発側からは到達しない**(Yoshinobuの操作)。**この対応はImplementerが現物で確かめ直すこと** — 本requirementの記述を根拠にしない。
