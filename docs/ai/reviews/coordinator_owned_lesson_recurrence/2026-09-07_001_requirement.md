# requirement: lessons再発記録をCoordinator管理へ移す

作成: 2026-09-07 / Coordinator

決定: 2026-09-07、Yoshinobuが「Claudeはこれまで全てsubagentとして動いていた」
ことを確認し、提示したCoordinator主体への移管方針で独立案件として進めることを
承認した。

## 1. 問題定義

`.claude/settings.json`のプロジェクト共通`SessionEnd` hookは、Roleを区別せず
Claude Codeのセッション終了時に`scripts/session-recurrence-record.py`を起動する。
同scriptはtranscriptをLLMで分類し、`docs/ai/memory/lessons/`へ直接追記する。

これまでClaude Codeはすべてsubagentとして使っていたため、Reviewer等の終了時にも
共通hookが動く。結果として、Coordinatorが統合を判断する前にsubagent由来の差分が
共有worktreeへ残り、記録責任と差分の所有者が曖昧になる。2026-09-07の着手時には、
Reviewerの終了に由来する再発記録1行が未commit差分として残っていた。

## 2. ゴール

1. Claude subagentの終了が`docs/ai/memory/`を変更しない状態にする。
2. lessonへの再発記録の採否と追記責任をCoordinatorへ一本化する。
3. 既存の再発記録を履歴として保ちながら、現行規範と実装を新しい責任分担へ揃える。

## 3. 非ゴール

| やらないこと | 理由 |
|---|---|
| Claude Codeの`SessionStart` hook撤去 | `docs/ai/status.md`を読むread-only経路で、本件の共有worktree変更とは別問題 |
| 過去にcommit済みの再発記録の削除・再判定 | 当時の観測履歴であり、責任分担の変更は過去へ遡及させない |
| 月次Knowledge振り返りの再設計 | 再発記録の集計はCoordinator管理へ移した後も利用できる |
| Reviewer / Tester / Implementer / AuditorにKnowledgeを読ませる | `docs/ai/core.md`の既存境界を維持する |
| 再発判定を別の自動hookや常駐処理へ移植する | Coordinator主体という目的に反する |

## 4. ユーザーストーリー

- Coordinatorとして、subagentの成果物を統合してから、確認済みの規範違反だけを
  lessonへ記録したい。
- Reviewerとして、セッション終了処理が自分の成果物以外を共有worktreeへ残さない
  状態でレビューを返したい。
- リポジトリ利用者として、未commit差分の作成主体と採否を明確に追跡したい。

## 5. 要件

### P0 (Must)

| # | 要件 |
|---|---|
| P0-1 | `.claude/settings.json`から`SessionEnd`の再発記録hookを撤去し、同hook専用のtimeout環境変数も撤去する |
| P0-2 | `scripts/session-recurrence-record.py`を廃止し、現行の実行経路から参照されない状態にする |
| P0-3 | `docs/ai/memory-classification.md`の再発記録契約を、Coordinatorだけが確認済み事実を記録する形へ変更する。subagentの報告は証拠であり、自動採用しない |
| P0-4 | `docs/ai/roles/coordinator.md`に、統合時に規範違反の再発を判定し、該当時だけ再発記録を更新する責任を置く |
| P0-5 | 既存lesson 12本の`## 再発記録`節から「機械だけが書く」という旧責任主体を除去し、新しい正本へのポインタだけに揃える |
| P0-6 | 自動hookが生成した未commitの2026-09-06行は採用せず削除する。他の既存行は変更しない |
| P0-7 | `docs/ai/status.md`から稼働中のSessionEnd hookを前提とする現在地を除き、本案件の未完了事項があればそれだけを残す |

### P1 (Should)

| # | 要件 |
|---|---|
| P1-1 | Coordinatorは、Policy違反、安全機構による停止、明示された規範・依頼の不履行という既存3分類を維持する |
| P1-2 | 過去のreview記録、commit履歴、月次測定値は履歴として書き換えない |

### P2 (Could)

- なし。

### Won't

- Role名を推測する条件分岐を旧hookへ追加して延命しない。
- subagentごとの一時候補ファイルを新設しない。

### リスクレジスタ

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| 自動検出を外すことでCoordinator自身の違反を見落とす | Medium | Medium | closeout・統合時のCoordinator責任として明文化し、Incident/Reviewer/Tester報告と自分の実行結果を確認する |
| 旧hookへのlive参照が残り、次セッションで誤った前提を読む | Medium | Medium | 撤回語とscript名をlive文書・設定・コードから機械検索し、独立した規範レビューを行う |

## 7. オープンクエスチョン

なし。過去の自動記録は維持し、今回の未commit行だけを採用しない方針はYoshinobu確認済み。

## 8. タイムライン考慮

- 緊急変更ではないが、撤去前に新たなClaude subagentを起動すると同じ差分が増え得る。
- Coordinatorがrequirement・計画・実装を先に完了する。
- 撤去後に新規Claude Reviewerを起動し、規範レビューとAC2の実測を兼ねる。
- Reviewer指摘を反映後、検査、Auditor、commit / pushの順で閉じる。
