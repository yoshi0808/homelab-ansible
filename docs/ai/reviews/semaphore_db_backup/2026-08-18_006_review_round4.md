# Code Review: semaphore_db_backup round4

## Summary

round3 High #1とSuggestions #1/#2、cleanup変更、取り直された証跡を重点的に再照合した。実host名を含まないrole fixtureへの切替とPlay 1の静的照合は妥当であり、round3 High #1 / Suggestion #2はclosedと判断する。cleanupも通常のmodule failureでは3件を独立試行し、末尾assertでrun failureを復元する。

しかし、修正理由が明示する`UNREACHABLE`は`ignore_errors`の対象外であり、さらにAnsibleのblockはunreachable hostで`always`/`rescue`を起動しない。現在の実装とreconstructionはこの経路を扱えておらず、後続cleanup・失敗通知が未実行になるためRequest Changesとする。
