# requirement: `timeout` が作るプロセスグループが apt を停止させるのを止める

日付: 2026-09-03
状態: 起案(Yoshinobu合意済み、2026-09-03)

## 1. 背景

2026-09-03 08:09、monnie への月次 full-upgrade(Semaphoreジョブ #938)が `Run apt full-upgrade` で停止し、**自力では二度と終わらない状態になった**。

**これは2026-08-22の conffile プロンプト停止(ジョブ #802)の再発ではない。** その修正は成功しており、**その修正が入れた `timeout` 自身が今回の停止を作っている。**

## 2. 確定した機構

| 観測 | 値 |
|---|---|
| Ansibleのpython | `pts/1`、STAT `S+` — **フォアグラウンドのプロセスグループ**(PGID 301963) |
| `timeout` | 同じ `pts/1`、**自分で新しいプロセスグループ(PGID 301965)を作っている**、STAT `T` |
| `apt-get` | 同グループ、STAT `T`。`SigCgt` に **SIGWINCH** を持つ(端末があると認識して進捗表示をしている) |
| `TracerPid` | 両者 0(ptraceではない) |
| 子プロセス | `dpkg` / `dracut` / `update-initramfs` はいずれも残っていない |
| term.log 末尾 | `dracut のトリガを処理しています` → `update-initramfs: Generating /boot/initrd.img-7.0.0-30-generic` |
| conffile プロンプト | **1つも出ていない**(`--force-confold` は効いている) |

**機構は次のとおり。**

1. playbook は `become: true` で走るため、**Ansibleが制御端末(pty)を割り当てる**
2. `timeout` は配下をまとめて kill するために `setpgid` で**新しいプロセスグループ**を作る
3. そのグループは同じ端末を持つが**フォアグラウンドではない**
4. **バックグラウンドのプロセスグループが制御端末に触ると `SIGTTOU` / `SIGTTIN` で停止させられる。** 特に `tcsetattr` 系の端末設定呼び出しは、`tostop` の設定に関係なく**必ず** `SIGTTOU` を発生させる
5. `timeout` 自身も同じグループなので一緒に停止する。**停止中のプロセスは `SIGKILL` と `SIGCONT` 以外を処理しない**ため、**設定した3600秒のアラームは永久に発火しない**

**したがって「`timeout` を入れたから必ず終わる」という前提は、この失敗モードでは成立しない。**

## 3. 目的

**apply が端末に起因して停止しないようにし、あわせて時間上限が実際に効くようにする。**

## 4. 受入条件

- **AC1**: apply の apt 実行が、**バックグラウンドのプロセスグループとして端末に触る状態に置かれない**
- **AC2**: 時間上限が**実際に発火する**。上限を超えたときに終了し、`rc` が記録に残る
- **AC3**: conffile の保持(`--force-confold`)、`DEBIAN_FRONTEND` / `NEEDRESTART_MODE` の設定は現状のまま変えない。**2026-08-22 の修正を後退させない**
- **AC4**: 停止・失敗のいずれでも、**何が起きたかがjournalまたはジョブ出力から読める**。無言で終わらない
- **AC5**: `--check` で副作用なく完走する

## 5. 有力な実装(確定ではない)

`timeout` に **`--foreground`** を付ける。GNU coreutils のこのオプションは「シェルから直接でない文脈で、コマンドに端末の読み書きと TTY シグナルを許す」ためのもので、**新しいプロセスグループを作らない**。あわせて stdin を `/dev/null` にする。

**引き換えに孫プロセスはタイムアウトの対象外になる**(`--foreground` の既知の制約)。無期限停止と比べれば軽い代償だが、**AC2 が本当に満たされるかは実測で確かめる**。

**別案として、端末そのものを外す**(`setsid` を挟む、あるいは `become` の pty 割り当てを避ける)方向もある。**どちらを採るかは実装前に決める。**

## 6. 未決

- `--foreground` を付けたとき、**apt が端末へ書いても停止しないこと**を実測でどう確かめるか。decoy では pty の条件を再現しにくい
- **同じ形が他にあるか。** repo 内で `timeout` をこの形で使っているのは `roles/ubuntu_vm_full_upgrade/tasks/apply.yml` の1箇所だけである(確認済み)が、**`become: true` + 長時間コマンドという組み合わせは他にもありうる**
- 上限値(3600秒)を見直すか

## 7. 今回の停止からの復旧(2026-09-03、Yoshinobuが実施)

1. `kill -9` で `apt-get` と `timeout` を終了(ジョブ #938 はここで失敗して終わる)
2. `dpkg --configure -a` — **端末の前景で走るため同じ停止は起きない**
3. `unpoller` / `alloy` / `loki` の版と稼働、`prometheus` の targets を確認

**initramfs は完了している見込み**(43 MB、08:10、生成プロセスは残っていない)。**確認するまで monnie を再起動しない。**
