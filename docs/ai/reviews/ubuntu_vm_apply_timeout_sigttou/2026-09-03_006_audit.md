## 指摘

### 1. Incident記録の状態欄が、closeoutの結論と食い違っている(**クローズを妨げる**)

`docs/ai/memory/incidents/2026-09-03_apt-stalled-by-the-timeout-added-to-prevent-stalls.md` の状態欄は「解決済み(復旧完了、**恒久対策は未実施**)」のままである。しかし closeout(005)は、恒久対策(`setsid -w`、commit `41a55ae`)が実装され、独立レビューがApproveし、**quory/authy/ansyの3台で本番実績も確認済み**と結論している。

これは「差分の外側の陳腐化」に当たる。この案件の変更(diff外の正本)である Incident 記録が、closeoutの確定した結論を反映しないまま古い状態を主張している。次に読む者(特に月次振り返り)が「恒久対策はまだ入っていない」と誤って認識しうる。

### 2. requirementの未決事項の1つが、どの成果物でも扱われないまま消えている(非ブロッキング)

requirement(001)§6は3件の「未決」を挙げている。

1. `--foreground` の実測方法 → `--foreground`案自体が撤回されたため実質解消(implement §2・§3.2 e)
2. 同じ形(`become: true` + 長時間コマンド + `timeout`)が他にあるか → closeout §5 最終項目で明示的に「repo内は当該1箇所」「将来増えたら再発しうる」と引き継がれている
3. **上限値(3600秒)を見直すか** → implement・review・closeoutのいずれにも言及がない

3番目は、解決された形跡も、「今回は扱わない」という明示もない。Auditorの基準(「未解決の明示」「黙って落ちている項目がないか」)に照らすと黙って落ちた項目にあたる。ただし AC1〜AC5 はいずれもこの値の見直しを要求しておらず、closeoutの結論(3600秒は不変、AC3で明示的に維持)とも矛盾しない。**案件のゴールには無関係であり、クローズを妨げない。**

### 3. `--foreground`案を否決した最初のレビュー(F1/F2)そのものは記録に残っていない(非ブロッキング)

implement(003)は「`--foreground`案は独立レビュー(`_004_review_codex.md` F1)で否決され、`setsid -w`へ差し替えた」と書き、review(004)も「旧F1」「F2」として2件を過去形で参照する。しかし repo のcommit履歴には `_003_implement.md` と `_004_review_codex.md` の両方が**最初から`setsid -w`版の内容で1コミットとして追加**されており(`41a55ae`)、`--foreground`案を対象にした最初のレビュー(F1/F2がblockingとして立った時点の記録)そのものは、案件フォルダにもgit履歴にも存在しない。

現在の記述だけからでも、implement §2(`--foreground`が却下される理由の技術的説明)と§3.2の負のコントロール実験(e: `--foreground`が3秒の上限に対し6.07秒かかることを再現)によって、F1が指していた不具合そのものは再構成できる。したがって再構成は成立しているが、「いつ・誰が・何を根拠にF1/F2を立てたか」を示す一次記録は無く、決定の追跡としては最初の一段が欠けている。**クローズを妨げないが、案件途中で実装方式を差し替えたときは、差し替え前のレビュー結果も1本の成果物として残すことが望ましい。**
