## エディションは変わっていない(2026-08-19 実測)

`.deb` は `semaphore_` と `semaphore_community_` の2種類が公開されており、取り違えると版と一緒にエディションまで入れ替わる。**quory は前後とも非 community 版である**ことを、両版のバイナリの sha256 を upstream の `.deb` から展開したものと照合して確定した(2.18.4 / 2.19.8 とも一致、community 版とは不一致)。

**入れる前だけでなく、入れた後のバイナリでも照合する。** 入れる前の照合は「どちらの `.deb` を取るべきか」を決めるためのもので、**入れた後に意図した方が入ったことの確認にはならない。**

## AC5 の誤判定と、その原因

**2.19.8 は SQLite を WAL モードへ切り替える。** 上げる前は `journal_mode=delete`、上げた後は `wal` で、`semaphore.db-shm` と `semaphore.db-wal` が現れる。**この2ファイルに ACL は付かない。**

WAL モードでは読み手も `-shm` を読み書きできる必要があるため、`semaphore.db` に `r--` を持つだけの3識別子はデータベースを開けない。**quory の3識別子(`recovery-exec` / `incident-inspect` / `dev-investigate`)とも不通である**(`acl-status semaphore-db` / `acl-status semaphore-dir` で確認。ディレクトリは `--x` で traverse のみ)。

**ファイル個別に ACL を足しても直らない。** ansy で実測したところ、停止中に `journal_mode=delete` を設定しても**起動時に必ず WAL へ戻され、`-shm` / `-wal` は ACL なしで作り直される。**

**誤判定の構造**: 検証を利用者の識別子ではなく所有者で通した。`docs/ai/memory/lessons/verify-through-the-consuming-filter.md` と同じ形である。**上げる前の 18:50 には `ssh quory-investigate "semaphore-query recent-failed 3"` が通っていた**ので、消費側で測っていれば版上げ直後に検出できた。

**影響範囲は読み取りの間接経路だけである。** Semaphore 本体(UI / API / schedule 実行)は正常で、AC4 / AC6 / AC7 の結果は変わらない。

## SQLite 直読みはサポートされた接し方ではない

**Semaphore が公開している口は API であり、ストレージの内部形式は上流が自由に変えてよい部分である**(Yoshinobu、2026-08-19)。WAL への切り替えはその実装判断だった。**したがって「直読みを復旧させる」方向の対処は、次の版上げで別の形で壊れる。**

API での代替可能性を ansy で実測した(2026-08-19)。

| 現行クエリ | API |
|---|---|
| `recent-failed` / `running` / `task-time` | **`GET /project/{id}/tasks`**。`status` / `start` / `end` / `playbook` / `tpl_alias` を持つ |
| `task-output` | **`GET /project/{id}/tasks/{task_id}/output`** |
| `template-list` | **`GET /project/{id}/templates`** |
| `task-hosts` / `task-errors` | **無い。** `/tasks/{id}/hosts` と `/errors` は 404。2.19 で追加された `/stages` は stage 単位で、**ホストごとの ok/changed/unreachable もエラー本文も持たない** |

失われるのは後者2つの**構造**であって情報ではない。`task-output` に Ansible の `PLAY RECAP` と `fatal:` 行が入るため、テキストからの導出はできる。

**管理者権限を渡さずに済む。** Semaphore は project 単位のロールを持ち(`project__user.role`)、`guest` は読み取り専用である。**quory の Operator へは既に guest アカウントの API トークンを渡す形が実装済みで、同じ方法が使える**(Yoshinobu、2026-08-19)。
