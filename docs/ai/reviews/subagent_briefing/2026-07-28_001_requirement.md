## 2. ゴール

1. `skills/subagent-briefing/SKILL.md` を新設し、Coordinatorが依頼文を書くたびに参照できる**型**にする。
2. **既存正本の規範を複製しない。** 型は「何をどの順で書くか / 何を書かないか」だけを定め、規範そのものは参照する。
3. Claude Codeから**自動検出される状態**にする(`.claude/skills/` への相対symlink。配置規約は `docs/ai/context-classification.md` §6が正本)。

## 3. 非ゴール

- `docs/ai/roles/coordinator.md` 等、既存正本の規範本文の改訂。必要が生じたらCoordinatorへ差し戻す(勝手に移設しない)。
- 依頼文を生成するスクリプト・テンプレート自動化。
- Tier判定の型(`skills/delegation-tier/SKILL.md` が正本)、requirementの構成(`skills/requirements-analysis/SKILL.md` が正本)。

## 5. 受入条件(Given/When/Then)

- **AC1**: Given 過去の依頼文で実際に起きた逸脱(§1 O3・O4・O5)、When この型に沿って依頼文を書く、Then **少なくとも3クラス**(①実行identityと権限境界の未明示 ②方法の指定 ③原因を完成形で渡す)が型の構造として塞がれており、各クラスについて**どの章がどう塞ぐか**を1行で説明できる。**根拠として挙げる記録は現物で確認する**(引用の誤りが下流で発見された前例があるため)。
- **AC2**: Given 既存正本(`core.md` / `roles/*.md` / 既存Skill群)、When 新Skillを通読する、Then 規範本文の**複製が無く**、参照先が実在し、記述が現物と矛盾しない。
- **AC3**: Given `.claude/skills/subagent-briefing` symlink、When Claude Codeがプロジェクトスコープのskillを列挙する、Then `subagent-briefing` が候補に現れる。**確認はCoordinatorが行う**(harnessの登録タイミングは版依存であり、同一セッションで現れない場合は次セッションで確認して記録する)。
- **AC4**: Given 変更一式、When `scripts/git-pre-commit-check.sh` 相当の静的検査、Then IPv4リテラル等の混入なしで通過する。
- **AC5**: Given 案件フォルダ、When Auditorがコールドスタートで読む、Then requirement / plan / plan_review / implement / review / progress が揃い、経緯を再構成できる。

## 6. 制約と安全境界

- **doc-only案件である。** Ansible playbook / role / inventoryを変更しない。**実ホストへ触れない**(ad-hoc実行、`--check`実行を含め、本案件では一切不要)。
- 実行identityはansy上の作業ツリーに限る。書込先は `skills/`、`.claude/skills/`、`docs/ai/reviews/subagent_briefing/` の3つ**のみ**。それ以外のファイルを変更した状態で完了報告しない(§3の非ゴールに当たる変更が必要と判断したら、実施せずCoordinatorへ返す)。
- `git commit` / `git push` は行わない。**Yoshinobuのcommitは工程上の待ちとして計画へ入れる**(`docs/ai/roles/coordinator.md`「計画受領時のゲート」#5)。
- IPアドレス・VLAN ID・VM IDの実値、変化の速い値を書かない(`docs/ai/context-classification.md` §3)。時刻表記はJST。
- harnessの安全機構がブロックしたら、別の形で同じ結果へ到達せずCoordinatorへ上げる(`docs/ai/core.md`「安全機構がブロックしたとき」)。

## 8. Tier判定と、判定基準との食い違い(記録)

| 軸 | 判定 | 根拠 |
|---|---|---|
| 軸A(専門性・実機検証) | **Tier 1相当** | doc新設のみ。runtime挙動を変えず本番影響が無い。`skills/delegation-tier/SKILL.md` の補足「安全境界・Role間の責任分界の変更は、それ自体では軸Aを上げない」に該当 |
| 軸B(`+R`) | **該当** | 新Skillと既存正本の重複・矛盾は、書いた本人には見えない |

`skills/delegation-tier/SKILL.md`「計画レビュー」節は「Tier 1/2で査読を足したくなったらTier判定が誤っている信号」と定めており、**本案件はその規定に対する意図的な例外である。** 一般化してよいか(「工程の実地検証を目的にTierを上げる」を規定として書くか)は、**クローズ時にCoordinatorが判断する**。判断せずに前例だけ残さない。
