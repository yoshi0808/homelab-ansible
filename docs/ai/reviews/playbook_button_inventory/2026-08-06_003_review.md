## Code Review: playbook_button_inventory 差分6本

### Summary

R1〜R6の機構自体(検証play + `default()`によるhosts差し替え、role側allow-listの明示的assert、
カタログ追加)はAC1〜AC7を裏付ける独立検証(decoy fixture、filter plugin直接呼び出し、`comm`突合)
で確認でき、破綻は無い。一方で、`serial_getty_mask.yml`は`target_hosts`に対応するallow-list guardを
持たず、同じファイルのヘッダが宣言する「pve1/pve2はスコープ外」という制約をこの差分自身が技術的に
担保できていない。また`rsyslog_forward_to_monnie.yml`/`time_sync_ntp_reference.yml`のヘッダと
カタログのコメントは「新規VMを1台作ったらそのホストを指定して1回流す」用途を謳うが、今回追加した
role側guardは新規ホスト名(defaults未登録)を常に拒否するため、書かれている使い方は現状のまま試すと
必ず失敗する。いずれも差分内部の自己矛盾であり、外部記録の突き合わせを待たずに指摘できる。

Request Changes — Critical #1(`serial_getty_mask.yml`のホストスコープ矛盾)は、ヘッダが明言する
安全境界をこの差分自身が技術的に満たしていない自己矛盾であり、Coordinatorの再確認が必要。High #2
(rsyslog/time_syncの「新規VM」説明とAC7 guardの不一致)はドキュメントと実装の食い違いで、実害は

現実に合わせる、またはguardを追加する」判断で閉じられる性質のものと見る。
