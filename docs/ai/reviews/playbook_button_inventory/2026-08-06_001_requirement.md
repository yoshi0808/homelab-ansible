# requirement: ボタンが無いplaybookの棚卸し

2026-08-06 / Coordinator。`docs/ai/status.md` Next「ボタンが無いplaybookの棚卸し(残り13本)」の実施。

## 1. 背景

Semaphoreの「押せるボタン」の正本は `roles/semaphore_templates/defaults/main.yml` の
`semaphore_templates_catalog` である。ボタンが無いplaybookは、人が `ansible-playbook` を
組み立てて流すしかない。**Phase 4 で ansy が quory / authy / pve1 / pve2 へ到達できなく
なったため、それらを対象とするplaybookはボタンが無いと実行手段そのものが存在しない。**

`scripts/check-deploy-needed.py` の R1 は、**新規追加された** playbook にカタログ定義が
無いことを助言するが、既存分には発火せず、除外リストも持たない。したがって既存分は
この棚卸しでしか閉じられない。

## 3. 決めたこと(Yoshinobu、2026-08-06)

- **D1**: 10〜13の4本にボタンを与える。3本(11〜13)は現状ボタンが無いと実行手段が無い。
  `grafana_provisioning` は今はansyから届くが、Next「ansyがmonnieへも直接触らなくなる
  方向」に照らして先にボタン側へ寄せる。
- **D2**: `serial_getty_mask` は**対象ホストを引数で受ける**。運用の実体は
  「**cloud-init で新しいノードを作ると agetty のループで syslog に警告が大量に出る。
  VMを1台作ったら、そのホストを指定して1回だけ流す**」であり、全対象へ一括で流す
  ものではない(Yoshinobu、2026-08-06)。
- **D3**: 同じ性質を持つ `rsyslog_forward_to_monnie` と `time_sync_ntp_reference` にも
  同じ引数を入れる。`grafana_provisioning` は `hosts: monnie` 単独なので入れない。
- **D4**: 引数は**自由入力の必須項目**とする。enumにすると新しいVMを作るたびにカタログ側も
  直すことになり、この用途と噛み合わない。
- **D5**: 8本(2〜9)にはボタンを与えず、**その理由をカタログへ記録する。**
  次に誰かが数えたとき同じ問いを繰り返さないための置き場が要る。

### 独立レビュー(`..._003_review.md`)を受けた追加の決定(2026-08-06)

- **D6**: `serial_getty_mask` は**保護対象ホストを拒否する形**にする(Yoshinobu、2026-08-06)。
  塞ぐべきリスクは「保護対象へ届くこと」であり、これは既に列挙されている有限集合である。
  **allow-list は採らない** — 新しいVMを作るたびにinventoryとallow-listの2箇所を直してから
  でないとボタンが効かず、D2の「cloud-initで作ったら1回押す」と噛み合わないため。
  ホスト名は自由入力のまま(Yoshinobu「hostname手打ちで良いです」)。
- **D7**: `rsyslog_forward_to_monnie` と `time_sync_ntp_reference` は **guard が正しく、
  文書の側が誤っている。** 「新規VMへ向ける」という説明を撤回し、対象はリストにある
  ホストに限ること、新しいホストを足すにはrepoの変更が先に要ることを書く。
  この2本のボタンの用途は「**ansyから届かない既存ホストへ1台ずつ再適用する**」である。
  rsyslogのリストはホストごとのfilename・stop policy・snippetを持つ実質的なものであり、
  事前reconを要する制約そのものが正しい。

## 4. 要求

- **R1**: `playbooks/serial_getty_mask.yml` / `rsyslog_forward_to_monnie.yml` /
  `time_sync_ntp_reference.yml` の `hosts:` を、外から与えられる変数で選べる形にする。
  変数が与えられないときの対象は**現在の対象と完全に同じ**であること。
- **R2**: 与えられた対象がinventoryのどのホストにも解決しないとき、**そのことが分かる形で
  停止する。** 現状は警告のみで `no hosts matched` となり **rc=0 で緑になる**ことを実測済み
  (`ansible-playbook -i inventories/homelab/hosts.yml <pb> -e target_hosts=ansyy` → rc=0)。
  打ち間違えと「新しいVMをまだinventoryへ足していない」の両方がこの経路に落ちる。
- **R3**: `serial_getty_mask.yml` のヘッダへ、D2の運用の実体(いつ押すのか)を記録する。
  現在のヘッダは技術的な適用範囲しか書いていない。
- **R4**: カタログへ4本のエントリを追加する。classは4本ともSEMI-SAFE
  (押しても停止は起きないが状態は変わる。軸はカタログ冒頭の定義に従う)。
  R1の3本には対象ホストのsurvey項目を持たせる。
- **R5**: 2〜9の8本と、1のブートストラップについて、**ボタンを持たない理由**をカタログへ
  記録する。playbook側のヘッダに既に理由があるものは、それを指すだけでよい(重複して
  書かない)。
- **R6**: 既存のカタログエントリ(45件)の内容を変えない。

### AC7 の背景(2026-08-06、Coordinator が現物で観測)

R2 の guard は「inventoryに解決するか」しか見ないため、その先にもう一段のホストリストがある。

| role | 場所 | 既定 | リスト外のホストを与えたときの挙動 |
|---|---|---|---|
| `time_sync_ntp_reference` | `tasks/main.yml:7-9` の `when:` | `defaults/main.yml:4` の pve1/pve2/ansy/monnie/authy | **唯一のtaskがskipされ、緑で終わる** |
| `rsyslog_forward_to_monnie` | `tasks/main.yml:2-5` の `assert` | `defaults/main.yml:2` の ansy/quory/authy | 赤で止まるが、`fail_msg` はallow-listに触れない |
| `serial_getty_mask` | 該当なし(roleを持たずplay内にtasksを書く) | — | 任意のホストへ適用される |

**同じ値を2箇所へ持たせないこと**(`docs/ai/status.md` の規律4と同じ理由)。

到達する前に接続・become が起きる。判定はそこへ到達する前に済んでいる必要がある。

## 6. 制約

- **実ホストへ適用しない。** repoの変更だけではSemaphoreは変わらない。配備はYoshinobuが
  `semaphore_templates_setup` のボタンを押す。
- AC2 / AC3 の検証は**decoyまたは `--check`** で行う。R1の3本はいずれも `check-mode-native`
  であり、`--check` なしの通常実行は本番適用である(`docs/ai/policies/ansible_test_safety_policy.md`)。
- ansyから quory / authy / pve1 / pve2 へは到達手段が無い。AC1〜AC3で実際に接続が要る形の
  検証は成立しない — **対象ホストの解決結果**を見る形で確かめる。
