# quory月次ヘルス schedule登録

## 変更内容

- `roles/semaphore_templates/defaults/main.yml` の `semaphore_schedules_catalog` に、次の1件を追加した。
  - name / template: `SEMI-SAFE: Quory health monthly`
  - cron: `15 8 15 * *`
  - active: `true`
  - task_params.environment: `"{}"`
- 同ファイルの `quory_health_monthly` templateコメントを、schedule未確定の説明から、readback確認済みでscheduleを登録する説明へ更新した。
- 既存scheduleの値は変更していない。なお、依頼文の「既存20件」に対し、作業開始時のHEAD現物には既存23件（後続案件の3件を含む）が存在したため、23件すべてを比較対象として不変であることを確認した。

## 時刻選定の根拠

- Yoshinobu確定の実行時刻は毎月15日08:15 JST。既存の `SEMI-SAFE: Proxmox storage monthly`（毎月15日08:00 JST）の15分後に置いた。
- CoordinatorがNotion「バッチ処理工程管理表」を確認し、08時台の他の定期処理窓と重ならないことを確認済み。
- 実績所要時間はProxmox storage monthlyが31秒、quory health monthlyが13〜28秒であり、15分間隔で重ならない。
- このschedule自身が毎月15日08:15の枠を占有することをカタログコメントに明記した。
- `operation`は `roles/quory_health_monthly/defaults/main.yml` の既定値 `collect` を正本とするため、scheduleへ複製していない。

## 自己検証

- template名、既存のProxmox storage monthlyのcron、`task_params.environment: "{}"` の形を現物と照合した。
- YAMLをロードして対象scheduleのname/template/cron/active/task_paramsを確認し、HEADに存在した既存23件のscheduleのname/template/cron/task_paramsが変化していないことを確認した。依頼文の20件との差異は、Semaphore db backup daily、Semaphore update check monthly、Syslog weekly digestの3件が既にHEADへ含まれているためである。
- `ansible-playbook --syntax-check`相当のローカル構文検証と `git diff --check` を実施した。
- 実ホスト、Semaphoreへの適用、schedule readbackは実施していない。この依頼の範囲外であり、配備工程で行う。
