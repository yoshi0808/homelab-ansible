# quory月次ヘルスレポート テスト計画

## 範囲

- 要求001/計画002/Policy QHM-010〜050と、playbook・role・専用unittestの整合を確認する。
- unit（既存fixtureの再実行）と静的/dry-run（native `--check`）を分ける。実装が実host名`quory`と`groups['control_nodes'] == ['quory']`を要求するため、適法なdecoy inventoryによるfull-playbook結合はNot Runとする。
- 実ホスト名/IPを含むinventoryは作らない。実quory、Notion、Slack、Semaphore APIには接続しない。

## 観測項目

1. `quory`固定の対象検査と余分なcontrol_nodes拒否はコード静的確認に留め、実行経路のPASSにはしない。
2. root/EFI、memory/swap、NVMe列挙の成功・失敗・UNKNOWN、WARNING/CRITICALの健康判定とジョブrcの分離。
3. EFI等の部分失敗で成功部分を保存し、最終rc非0・全体OK抑止となること。
4. archiveの日時付きJSON/Markdown、report ID、前回成功観測との比較、履歴破損・未公開記録の保全、replayの再収集なしを確認する。
5. `--check` と `skip_notifications` の双方で保存・保持削除・token読取・Notion/Slack送信・host変更が抑止されること。公開応答不明/重複防止はfixtureで確認する。
6. 実quoryの値、Notion/Slack照合、Semaphore scheduleのactive/時刻はNot Runとして残す。

## 実行

```text
python3 -m unittest tests.test_quory_health_monthly -v
ansible-playbook --syntax-check playbooks/quory_health_monthly.yml
bash scripts/check-tester-gate.sh
```

外部通知は行わない。過去に作成した実host名入りinventoryと、`check-mode-native`境界に反する通常実行は無効な試行として再実行しない。
