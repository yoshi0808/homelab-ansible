## 前回指摘の確認

### 1. [解消] メジャー上昇判定

対象: `roles/codex_update_check/tasks/main.yml:135-145`

- `_latest_major | int > _current_major | int` に修正され、単なる不一致ではなく
  上昇時だけ更新対象となる。
- current=12 / latest=11 のようなケースは false となり、ダウングレードしない。
- 両メジャー部を `^[0-9]+$` で検証し、不正な取得値は `_collected: false`、最終的に
  `collection_failed` として扱うため、`int` の暗黙変換で誤更新しない。
- current=10 / latest=11 は更新、current=10 / latest=10 はマイナー・パッチ差分を
  含めスキップする構造になっている。

### 2. [解消] 更新失敗時の集約・通知到達

対象: `roles/codex_update_check/tasks/main.yml:59-74,150-166,171-266`

- Codex CLI と npm の両更新コマンドに `failed_when: false` が設定され、非ゼロ rc でも
  ホスト処理がその場で中断しない。
- 両フローとも直後の status 記録で非ゼロ rc を `update_failed` に変換する。
- `changed_when` も rc=0 の場合だけ true となり、失敗を changed と誤報告しない。
- その後、Codex CLI / npm の failed_hosts を合算し、Slack `alerts` / `error` 通知を
  試行してから最終 `ansible.builtin.fail` に到達する。
- 全対象ホストで更新コマンドが失敗しても、更新タスク自体ではホストが failed に
  ならないため、集約 block へ到達できる。

これにより、既存 Codex CLI フローも npm フローと同じ失敗処理構造に統一されている。
