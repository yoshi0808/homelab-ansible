このplaybookは `risk-accepted` のため `--check` に意味がない(常に本実行)。実行すると実際に
`npm install -g @openai/codex@latest` が走る可能性がある(2026-07-09時点、ansyの現インストールは
0.142.5、npmレジストリ最新は0.143.0で実際に差分あり)。

確認してほしい点:

1. quory上で `ansible-playbook playbooks/codex_update_check.yml` を実行(quory-only assertがあるため、
   ansy等から実行するとPlay 1で意図通り失敗するはず — それも合わせて確認)
2. ansy/quoryそれぞれで現在バージョン取得・レジストリ最新版取得が正しく行われること
3. 差分があるホストで実際に `npm install -g @openai/codex@latest` が実行され、`npm list -g` で新バージョンが
   確認できること
4. Slack通知が `info` チャンネルで「旧版→新版」を明記した内容で飛ぶこと
5. (可能なら)再度実行して、2回目は全ホスト最新のため更新が走らず、通知も行われないこと(冪等性の確認)

更新される可能性があります。実行中のプロセスは通常影響を受けませんが、次回起動時から新バージョンに
なります。
