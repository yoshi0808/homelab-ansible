# Codex Update Check Policy(要求仕様案 v0.1)

## 1. 目的

ansy・quoryにインストール済みのCodex CLI(`@openai/codex`, npmグローバルパッケージ)のバージョンを週次で確認し、新版があれば自動更新する。金曜17:30のパッチドライラン前に最新化しておく。

## 2. 対象と実行

| 項目 | 内容 |
| --- | --- |
| 対象ホスト | ansy, quory |
| 実行元 | quory(time_sync_checkと同じ接続パターンでansyへ) |
| 安全度 | SEMI-SAFE(冪等な更新系、core.md §16基準で自動実行可) |
| スケジュール | 毎週金曜17:00(quory systemd timer)。17:30パッチドライランより前 |

## 3. ライフサイクル

```text
Phase 1  各ホストで現在バージョン取得
         (npm list -g @openai/codex --depth=0 --json、shellは収集のみ)
Phase 2  npm view @openai/codex version でレジストリの最新版取得
Phase 3  Ansible側でバージョン比較(shellでは判定しない、core.md §7)
Phase 4  差分があるホストのみ sudo npm install -g @openai/codex@latest 実行
Phase 5  結果集約(host毎: 変更なし/更新実施/取得失敗) → Slack通知
```

## 4. 通知方針

| 状況 | チャンネル |
| --- | --- |
| 全ホスト最新 | 通知なし、または#info |
| 更新実施 | #info(旧版→新版を明記) |
| バージョン取得失敗・npm実行失敗 | #alerts |

## 5. 制約

```text
- IPリテラルを書かない(core.md §3、ホスト名で接続)
- npm install -g実行にはsudo権限が必要(ansy側の権限方式はtime_sync_check実装を参照して踏襲)
- registry.npmjs.org / npmjs.org は既存network許可リストに含まれる(疎通問題なし)
- 未確認コードをtimerで自動実行しない、というcore.md §17の原則は、本playbook自体が
  確定・commit済みのコードとしてtimer登録される前提で満たす(実行対象パッケージの
  中身=Codex CLI自体の信頼性はnpm公式レジストリに依存)
```
