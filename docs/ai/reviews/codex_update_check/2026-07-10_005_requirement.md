# npm 本体のメジャーバージョン更新対応（codex_update_check 拡張）— 要求仕様

- 日付: 2026-07-10
- 起案: claude（要件定義・ハブ役）/ 承認: Yoshinobu
- 対象: 既存 codex_update_check 機能の拡張

## 目的

Codex CLI は npm グローバルパッケージとして稼働している。その土台である npm 本体も
放置すると古くなるため、npm 本体に**メジャーバージョンアップ**が出た場合に限り、
既存の週次 codex_update_check の実行の中で自動更新する。

## 対象ホスト / 対象グループ

- ansy, quory（既存 codex_update_check と同一）
- 実行元は quory のみ（既存 assert を維持）

## 作成・更新対象ファイル

- `roles/codex_update_check/` 配下（tasks / defaults / 通知まわり等、必要な範囲）
- `playbooks/codex_update_check.yml`（ヘッダの tester-gate 理由文・最終仕様コメントの
  更新が必要な場合のみ）

## 実施項目

1. 各対象ホストで、現在インストールされている npm 本体のバージョンと、レジストリ上の
   最新バージョンを取得する
2. **メジャーバージョンが上がっている場合のみ** npm 本体をグローバル更新する
3. マイナー / パッチのみの差分は更新せず、Slack 通知もしない（静かにスキップ）
4. 更新を実施した場合は、既存の Slack 通知パターンに準じて info 通知する
   （codex 更新の通知と統合するか別建てにするかは実装判断に委ねる）
5. 冪等性: 更新直後の再実行では up_to_date としてスキップされること

## 確認項目

- 既存の @openai/codex 更新機能が退行しないこと
- メジャー判定: 例) 10.9.7→11.0.0 は更新対象、10.9.7→10.10.0 / 10.9.8 はスキップ
- npm 更新失敗時は既存パターンに準拠して fail し、rescue で Slack error 通知されること
- 更新なし時（up_to_date またはマイナー/パッチのみ）は rc=0 で完走し通知しないこと

## 制約

- **【2026-07-10 追記・オーナー提供情報】** Node.js / npm は NodeSource 経由で
  インストール済み（`curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -`
  → `sudo apt install -y nodejs`）。つまり npm 本体は NodeSource の nodejs deb
  パッケージにバンドルされており、**dpkg 管理下**（/usr/lib/node_modules/npm は
  dpkg 所有）である。これを前提に設計すること:
  - npm の self-update（npm install -g npm@latest 相当）は dpkg 管理ファイルを
    上書きし、パッケージ状態とファイルシステムがドリフトする
  - 後の apt upgrade（nodejs パッケージ更新）で npm がバンドル版に巻き戻る
    可能性がある。週次実行なので巻き戻り後に再度メジャー差分を検知すれば
    再更新される（自己修復）が、この挙動を設計上どう扱うかを implement に明記する
  - self-update 方式を採らない設計（例: 巻き戻りリスクを踏まえた別方式）を
    提案する場合は、その理由と代替案を implement に記載し、claude 経由で
    Yoshinobu の判断を仰ぐ
  - レジストリ上の npm 最新がすでにメジャー先行している場合、初回実行で
    即発動する点に注意（現在インストールは npm 10.9.7）。実レジストリの
    確認は tester 工程で行う
- npm prefix は `/usr`（2026-07-09 tester 確認: npm 10.9.7, /usr/lib/node_modules）。
  dpkg 所有の実機確認（dpkg -S 等）は **test_plan の確認項目に含めること**
  （実ホスト調査は tester が行う。implementer は実ホストに触れない）
- 秘密情報を扱わない
- 変更系 playbook。tester-gate: risk-accepted の分類を維持する場合、
  ヘッダの理由文に npm 本体更新を含む旨を反映する
- スケジュールは既存の週次実行（Semaphore UI 登録済みタスク）に相乗りし、
  新規のタスク登録・timer は増やさない
- IP アドレスをリポジトリに書かない

## shell と Ansible tasks の責務分離

- shell/command はバージョン収集と変数化まで
- メジャー判定・更新可否の制御・更新実行・通知制御は Ansible tasks 側で行う（core.md §7）
