### 指摘1 [must-fix] メジャー判定を「不一致」から「上昇」判定に修正

対象: `roles/codex_update_check/tasks/main.yml`（Phase 3n: npm メジャーバージョン判定）

- 修正前: `_current_major != _latest_major`（ダウングレードも更新対象になってしまう）
- 修正後: `(_latest_major | int) > (_current_major | int)`（上昇時のみ true）
- あわせて `_collected` の条件に `_current_major is match('^[0-9]+$')` /
  `_latest_major is match('^[0-9]+$')` を追加し、メジャー部が数値として検証できない
  出力は `_collected: false` → ステータス `collection_failed` 扱いにした
  （数値以外を `int` フィルタで暗黙的に `0` 扱いしてしまう挙動を避けるため、
  比較の前に正規表現で数値形式を検証してから `int` キャストする設計にした）

**検証（ローカル、実ホスト非依存のサンドボックス playbook で確認、実行後に削除）**:
同じ Jinja 式を `hosts: localhost` の使い捨て playbook で検証し、指摘の確認ケースを
含む6ケースすべてで期待通りの結果を確認した。

### 指摘2 [must-fix] npm 更新失敗時に集約・Slack error 通知へ到達しない問題を修正

対象: `roles/codex_update_check/tasks/main.yml`（Phase 4: Codex CLI 更新 / Phase 4n: npm 更新）

原因: 両方の `npm install -g ...` タスクに `failed_when` を指定していなかったため、
コマンドが非ゼロ終了するとそのホストはその場で failed になり、後続の
`Record per-host ... update status` に到達できず、全ホストが失敗した場合は
`run_once: true` の集約 block 自体も実行されない（実行担当ホストがそこまで
到達できないため）。

修正: 既存 Codex CLI 更新タスクと npm 更新タスクの両方に `failed_when: false` を追加し、
`changed_when` を `<result>.rc == 0` に変更（失敗した実行を `changed: true` と誤報告
しないため）。これにより、更新コマンドが失敗しても該当ホストの実行は止まらず、
`Record per-host ... update status` で `update_failed` として記録され、必ず
Phase 5 の集約・Slack `alerts`/`error` 通知・最終 `fail` に到達する。レビュー指摘の
「既存 Codex CLI 更新フローも同じ失敗処理構造に揃える」もあわせて反映した。
