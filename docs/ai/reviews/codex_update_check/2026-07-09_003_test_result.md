## 未検証・注意事項

- 初回更新時の Slack `info` 通知が実際に飛ぶことは未確認。今回の失敗は一時コピーの `inventories/vars/slack.yml` が `ann:ann 0600` で、`yoshi` 実行から読めなかったためと推定する。

  確認コマンド:

  ```bash
  ansible quory -m ansible.builtin.command -a "ls -l /tmp/codex_update_check_test_20260709/inventories/vars/slack.yml"
  ```

  結果:

  ```text
  -rw------- 1 ann ann 3271 Jun 27 20:06 /tmp/codex_update_check_test_20260709/inventories/vars/slack.yml
  ```

- quory の正式 checkout `/home/yoshi/homelab-ansible` には、テスト時点で今回の `playbooks/codex_update_check.yml` が存在しなかった。正式な quory checkout に反映後、初回更新が発生する条件で Slack 通知だけ再確認する余地がある。
- `common_slack/tasks/notify.yml` は Slack 失敗を rescue で握るため、通知失敗があっても playbook の最後の host failure にはならない。ただし今回の外側 ad-hoc command は `rc=2` になったため、Semaphore/systemd での扱いは別途確認した方がよい。

## 判定

機能本体（バージョン取得、最新版取得、差分更新、更新後確認、冪等性）は要求どおり動作した。

ただし、更新実施時の Slack 通知が実際に成功することは未確認であり、今回のテストでは通知ロードが失敗した。通知要件を合格にするには、正式 checkout 反映後または `yoshi` が読める権限のテスト環境で、更新発生時の Slack `info` 通知を再確認する必要がある。
