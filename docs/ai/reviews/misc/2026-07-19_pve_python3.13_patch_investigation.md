# Proxmox Python 3.13 patch investigation (2026-07-19)

## 結論

pve1 / pve2 は同一状態だった。

- 昨日 2026-07-18 に Python 3.13 関連4 package を **`3.13.5-2+deb13u2 → 3.13.5-2+deb13u3`** へ正常に更新済み。
- 現在 installed は `3.13.5-2+deb13u3`、candidate は **`3.13.5-2+deb13u4`**。
- したがって「昨日の patch が未適用」ではなく、**昨日の u3 適用後に u4 が新たに提示された正常な連続 revision update**。
- u4 は Debian `trixie-updates` / `stable-updates` から来ており、changelog entry に CVE はない。内容は **u3 が導入した `dict.clear()` の use-after-free regression 修正**。
- Debian metadata 上は `urgency=medium` の通常 stable update / regression fix で、security repository からの CVE 緊急更新とは分類されていない。

ただし use-after-free という memory-safety regression の修正なので、CVE 緊急対応ではなくても放置価値は低い。通常の承認済み patch 手順で早めに取り込むのが妥当である。本調査では適用していない。

対象:

## 4. Changelog and urgency assessment

両ホストの `apt-get changelog python3.13` は candidate `3.13.5-2+deb13u4` の Debian changelog を正常取得した。

### Candidate u4

```text
python3.13 (3.13.5-2+deb13u4) trixie; urgency=medium

* Fix use-after-free in dict.clear() with embedded values.
  Resolves a regression in 3.13.5-2+deb13u3. (Debian bug #1141977)
```

観測事項:

- u4 entry に CVE identifier はない。
- `urgency=medium`。
- source は `trixie-updates` / `stable-updates` で、security suite ではない。
- 修正対象は u3 による regression。

したがって、取得できた Debian package metadata の範囲では **u4 は CVE を理由とする緊急 security update ではなく、直前 revision の regression を直す通常 update** と判定する。

`use-after-free` は memory-safety bug であり技術的には重要だが、ここから未公開 CVE の有無までは断定できない。少なくとも Debian はこの u4 entry を CVE/security update として表示していない。

### Yesterday's installed u3

u3 changelog には SSL/object lifetime fixes に加え、次の CVE が明記されていた。

- `CVE-2026-1502`
- `CVE-2026-3276`
- `CVE-2026-7774`
- `CVE-2026-8328`
- `CVE-2026-9669`
- `CVE-2026-6019` patch update

つまり昨日適用した u3 自体は security fixes を含む revision だった。その u3 が別の use-after-free regression を導入し、今回 u4 がその follow-up fix として短期間で現れた、という時系列である。

## 5. Why it appeared immediately after weekly patching

version chain は次のとおり。

```text
before 2026-07-18: 3.13.5-2+deb13u2
2026-07-18 applied: 3.13.5-2+deb13u3
2026-07-19 candidate: 3.13.5-2+deb13u4
```

ベースの Debian revision `3.13.5-2` は同じで、stable update suffix が `u2 → u3 → u4` と進んでいる。「昨日 `-1`、今日 `-2`」という単純な Debian revision 差ではない。

急に見えた理由は、weekly patch の取りこぼしではなく、昨日入れた u3 の regression fix である u4 が、その後の repository metadata で新しい candidate になったため。

## 7. Recommended interpretation

分類は「weekly patch の失敗」でも「新しい CVE 緊急 patch」でもなく、**security fixes を含んだ昨日の u3 に対する、通常 channel の regression follow-up u4**。

本調査は適用判断や実行を行っていない。適用する場合は通常の Proxmox patch change 手順と事前確認を経ること。
