## 検査の対応付け

実装は `scripts/check-doc-consistency.py` のcheck1へ追加した。既存のindex読み取り方式、tester-gate照合、check2 / check3は維持した。サードパーティ依存・Ansible実行・Jinja評価・ネットワーク接続は追加していない。

- `hosts:` はplay単位で抽出し、`import_playbook` は同じindex入力集合から再帰的に読む。importのリテラルvarsを渡すので、weekly-fullからのtarget_node指定も反映される。
- 文字列hosts、変数単体、文字列default、および「2ノードの反対側を選ぶ」既存の条件式を扱う。条件式はtarget_node・比較値・分岐値とinventoryのproxmoxメンバーが対応することを検査する。未知の式を空集合へ落とさない。
- groupは `inventories/homelab/hosts.yml` のindexから直接のhost集合へ展開する。groupと実体の別名表をコードへ複製しない。現行のall/children/group/hosts構造以外は解析失敗とする。このinventoryを持たない既存の小型fixtureでは、展開を行わず文字列で比較する。
- 選定groupはplay中の `proxmox_exec_node` と `pen_target_group` から候補hostsへの対応を得る。`brv_restore_targets` は「動的restore対象」という既存の説明表記に対応させる。コード中のこの対応はhost一覧ではなくカタログの表示語彙であり、play内の当該group宣言を確認してから適用する。
- 対象セルのASCII/全角丸括弧内を補記として除去する。既存の `quory(delegate_to)` は前置したホスト名も補記扱い。対応しない括弧、空の対象、不明な表記は解析失敗とする。
- 既存B行などは、引数確認・報告だけのlocalhostを省略している。B行を変更しない契約との両立のため、actualにlocalhostと他の対象がある場合だけ、比較の両側からlocalhostを除く。localhost単独のplaybookは厳密比較する。

比較はこれらを正規化した集合の一致であり、playの順番や重複回数は検査しない。丸括弧内の補記の内容・委譲先そのもの・用途の自然文の意味は機械検査の対象外。したがってA09〜A13は修正したが、新検査による意味の保証は主張しない。
