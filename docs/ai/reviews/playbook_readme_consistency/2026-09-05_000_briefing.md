# 依頼: playbooks/README.md と playbook 現物の突合(3列)

日付: 2026-09-05
宛先: codex側 `implementer`
Role本文: `docs/ai/roles/implementer.md`(共通則は `docs/ai/core.md`「subagentが共通して守ること」)

## 依頼の性質

**実装ではない。現物の照合(事実収集)である。** repoの記述と現物が食い違っている箇所を見つけて一覧にする。直さない。

## 対象

`playbooks/README.md` のカタログ表の各行と、その行が指す playbook の現物。突合するのは次の3列だけである。

| 列 | 突合先 |
|---|---|
| **対象** | playbook の `hosts:`(`import_playbook` でつながる先を含む)、`delegate_to`、`target_node` 等の実際の適用先 |
| **用途** | playbook が実際に行う処理 |
| **主な role / 実装** | playbook が実際に呼ぶ role、`import_playbook`、`include_tasks` |

## 対象外(既に機械検査されている)

`scripts/check-doc-consistency.py` の check1 が pre-commit で毎回走っており、次の4点は既に検査されている。**重複して報告しない。**

1. 全 playbook に `# tester-gate:` ヘッダがあること
2. README の行が実在する playbook を指すこと
3. `tester-gate` 列がヘッダの値と一致すること
4. 全 playbook が README に載っていること

**`tester-gate` の分類が playbook の実際の挙動として妥当かどうか(Policy整合)も今回の対象外である。** 別案件とする。

## 受入条件

- **AC1**: `git ls-files 'playbooks/*.yml'` が返す全数(現在59本)を1本残らず突合したこと。突合できなかったものがあれば、その旨と理由を成果物へ書く。
- **AC2**: 成果物には**相違があった行だけ**を載せる。一致していた行を列挙しない。
- **AC3**: 相違の各件について、①README の記述 ②playbook の現物(`file:line`)③どちらが古いと判断できるか、判断できないならその旨 — の3つを書く。
- **AC4**: 「相違」と「READMEが要約しているだけで誤りではないもの」を分けて書く。用途列は要約なので、**言い落としと誤りは別扱いにする。**
- **AC5**: 成果物に書いた `file:line` の参照が実在すること。

## 到達してはいけない状態

- **成果物1本(下記)以外に、自分が変更したファイルが1つでもある状態で報告が返ること。**
- 実ホストへ触れた状態で報告が返ること(ansible の実行・接続を伴わない)。
- 実行identityを昇格した状態に到達すること。
