### 観測2: `ann` がバンドルツリーを読めるか(traverse + 実読み取り)

```
$ ssh -i ~/.ssh/id_ann ann@quory.internal '
whoami; id
namei -l /home/yoshi/homelab-ansible/reports/incidents
ls -la /home/yoshi/homelab-ansible/reports/incidents | head -30
find /home/yoshi/homelab-ansible/reports/incidents -maxdepth 1 -mindepth 1 -type d ! -name "_spool" ! -name "_runs"
'
```

出力(要旨):
- `whoami` → `ann`、`id` → `uid=1001(ann) gid=1001(ann) groups=1001(ann)`
- `namei -l` の経路 `/` → `home` → `yoshi`(`drwx--x--x yoshi yoshi`)→ `homelab-ansible`(`drwxrwxr-x`)→ `reports`(`drwxrwsr-x yoshi homelab-ansible`)→ `incidents`(`drwxrwxr-x yoshi homelab-ansible`)。**すべてtraverse可**(`x` ビットが全段に立っている。`yoshi` の自ホームは `drwx--x--x` で他人の直接listは不可だが execute は通るため経路の通過自体は妨げられない)。
- `ls -la` で `_heartbeat.json`(所有 `recovery-exec`)、`_runs/`、`_spool/`、`semaphore-*` 多数のバンドルディレクトリを確認。ACL(`+`)が付与されている。
- `find` によりバンドルディレクトリ(`_spool` / `_runs` を除く)を41件確認(観測3で計数)。

実ファイル読み取り(バンドル1件を無作為抽出 `semaphore-44`):

```
$ ssh -i ~/.ssh/id_ann ann@quory.internal '
BUNDLE=.../semaphore-44
getfacl "$BUNDLE/summary.json"
head -5 "$BUNDLE/summary.json"
cat "$BUNDLE/summary.json" >/dev/null 2>&1; echo "rc=$?"
ls -la "$BUNDLE"
LOGF=$(ls "$BUNDLE"/*.log | head -1)
head -c 200 "$LOGF" >/dev/null 2>&1; echo "logread rc=$?"
'
```

出力(要旨):
- `getfacl summary.json`: `owner: recovery-exec` / `group: recovery-exec` / `other::r--`(mask含め有効)。`ann` 個別のACLエントリは無く、**`other` の read権限で読めている。**
- `head -5 summary.json`: JSON構造(`bundle_id`, `source`, `semaphore` フィールド)を先頭5行で確認。中身は既知の構造(F1と一致)。
- `cat summary.json` の実終了コード: **`rc=0`**(読み取り成功)。
- `semaphore-44/` の内容: `semaphore-log.log`(17048 bytes)、`summary.json`(2710 bytes)。両方 `other::r--` 相当のパーミッション(`-rw-rw-r--+`)。
- `.log` ファイルの実読み取り: **`logread rc=0`**(読み取り成功)。

**結果**: `ann` は昇格せずにバンドルツリーへtraverseでき、`summary.json` と `.log` の両方を実際に読める(`rc=0` を実測)。読み取りは `other` パーミッションで成立しており、`ann` 固有のACL付与は不要だった。

### 観測3: 総容量とバンドル件数

**結果**: 実測41バンドル、2.0MB。ansy側の保持設計(§7 OQ-E)の材料として記録した(具体的な数値の解釈・提案はこの単位のスコープ外)。

## 2. 判定規則の適用

計画 §4 U0固定の規則:「**両端にrsyncがあれば `ansible.posix.synchronize`、片方でも無ければ `find` + `fetch` ループ**」

- 観測1でansy・quory双方に `rsync`(3.4.1)が実在することを確認した。
- **したがって規則を適用した結論は「両端にrsyncあり → `ansible.posix.synchronize` を採る」である。** `incident_sync_mechanism: rsync`(I-5の既定値)がそのまま成立する。

- 観測5点すべてに実測ベースの答えが出ている(上記1節)。
