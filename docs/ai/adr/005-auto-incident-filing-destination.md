## Context

Step 2は、quoryが捕捉した証拠バンドルをansyへ運び(転送)、ansyの月次無人セッションがそれを評価する。決めるべきは**何をどこへ置くか**であり、月次振り返りの中止条件・無人セッションの封じ込め・パッチ適用ゲートの3つと同時に成立させる必要がある。

現物確認(HEAD `1701a13`)で確定した制約。**初版から変わった項目には[変]、新規には[新]を付ける。**

1. **月次振り返りは `git status --porcelain` が非空なら何も書かずに中止する。** `fail` させず `ABORTED_DIRTY` としてSlackへwarningを出す(`roles/knowledge_review/tasks/main.yml:27-51`、`playbooks/knowledge_review.yml:36-37,52-55`)。規範文書側にも書かれている(`docs/ai/memory-classification.md:101`)。Policyでは IC-025。
2. **迂回変数 `knowledge_review_allow_dirty` はtimerから渡らない**(`templates/knowledge-review.service.j2` の `ExecStart`、`defaults/main.yml:22-24`)。
3. **振り返り自身もcommitしない。** promptで禁じたうえ `deny: ["Bash", ...]` により実行手段が無い(`templates/review-prompt.md.j2:79`、`templates/job-settings.json.j2:35-39`)。AIの `git commit` / `git push` 禁止は共通原則の正本(`docs/ai/core.md:25`)。
4. **月次セッションの読取allowlistは `Read(docs/**)` と `Read(skills/**)` のみ、書込は `Edit(docs/ai/memory/**)` / `Edit(docs/ai/context/**)` / `Edit(skills/**)`**(`templates/job-settings.json.j2:27-40`)。`reports/` は読めない。
5. **自動化が触れるのは `状態: 調査中` まで。`原因分類` タグを埋めるのは人**(IC-020、設計合意 D3)。月次のタグ集計は `解決済み` のみで、`調査中` は**滞留として件数と経過日数を報告する。滞留自体が検出対象**である(`templates/review-prompt.md.j2:27-31`、`docs/ai/memory-classification.md:80`、`skills/incident-recording/SKILL.md:57-58`)。
6. **[変] `.gitignore` の `reports/` 除外は拡張子依存だが、`*.tmp` も別行で無視される。** `reports/**/*.json` / `*.log` / `*.md`(`.gitignore:2-4`)に加え `*.tmp`(`.gitignore:23`)。`git check-ignore -v` で、Step 2が置く5クラスのパス(ミラーの `summary.json`・`*.log`・`*.tmp`、評価成果物の `*.md`、同期状態の `*.json`)が**すべて無視される**ことを確認した。初版は `*.tmp` の行を数えていなかった。
7. **`.gitignore` は安全境界でもPolicy本文でもなく、Coordinatorの承認範囲である。** `reports/` の追跡対象は `reports/radius-health/` の2件のみで、`reports/incidents/` 配下に追跡中のファイルは無い(`git ls-files reports/`)。ディレクトリ単位の除外へ変えても既存の追跡ファイルへ影響しない。
8. **無人 `claude -p` はrepo作業ツリーの外へ書けない。** 封じ込めが成立する構成(相対path allowlist + `acceptEdits` なし + `--setting-sources` 空)では、repo外への書込を絶対path・`//` 前置きとも許可できなかった(実測)。`--add-dir` は**読取を足すだけで書込の柵にはならない**。解も同じLessonが示している — 「repo外の記録を更新する必要があるなら、LLMではなく起動側(Ansible等)が確定的に行う」(`docs/ai/memory/lessons/claude-code-unattended-session-confinement.md:26-30`、読取側は `:13`、効かない構成の表は `:19-24`)。
9. **その「起動側が確定的に書く」形の先例が同じroleにある。** `roles/knowledge_review/tasks/main.yml:175-192` が `claude -p` の標準出力をAnsibleでファイル化している。
10. **バンドル内容は非信頼データである**(IC-016、ADR-003 `:88`・`:75`)。書き手に `recovery-exec`(Slack経由のCodexが到達しうるidentity)が含まれる。
11. **[新] IC-007により、事象ごとにLLMを起動しない。** 評価はまとめて行う。**したがって「第一報を叙述する主体」は存在しない。** 初版が識別の根拠として使った (a)(b) は、この主体の存在を前提にしていた(後述)。
12. **[新] 追加要求: 対話セッションからrepo内のパスで障害の中身を読めること**(requirement §2、2026-07-28 Yoshinobu)。初版にはこの要求が無かった。
13. **[新] 証拠と判断を別の場所に置く(IC-032)。ansy側の同期先はミラーであり、上書きされる前提で扱う(IC-031)。** 人およびAIの成果物をミラーへ書いてはならない。
14. **[新] 書込権は `reports/incidents/` 配下にのみ与え、`reports/` 直下へ与えてはならない(IC-030)。** `reports/` 直下にはパッチ適用ゲートの入力があるため、そこへ書ける主体は**パッチ適用の可否を書き換えられる**。**これはADR-005とは独立の制約であり、本改訂でも動かさない。**
15. **捕捉は平日ほぼ毎日発生し、実測で約半数が既知のpve1平日運用に由来する**(`..._031_production_status_check.md` 観測5)。
16. **中止条件に当たる汚れはStep 2と無関係に日常的に存在する**(requirement O7)。実際の汚れは `docs/ai/reviews/` 配下と `docs/ai/status.md` で、いずれも振り返りの書込allowlistの外にある。
17. **[新] quory側の保持は30日**(`roles/incident_capture/defaults/main.yml:59`、バンドルディレクトリのmtime基準)。転送が止まれば証拠はこの期限で失われる(IC-015)。

### 第2版の決定

**A-1 + H を採用する。** 具体的には次の5点をStep 2の設計制約として固定する。

- **(1′) 証拠のミラーと評価成果物は、ansyのrepo作業ツリー内の `reports/incidents/` 配下に置く。** ミラーは同期だけが書き、評価成果物は評価だけが書く。両者のパスを分け、**評価成果物をミラーの内側へ置かない**(IC-031・IC-032)。**`reports/` 直下には触れない**(IC-030。制約14)。
- **(2′) 書込主体は起動側のAnsibleである。`claude -p` は評価本文を標準出力へ返すだけとし、ファイル化・配置・命名はAnsibleが確定的に行う**(制約8・9)。**評価セッションの権限プロファイルに `Edit` エントリを1つも置かない。**
- **(3′) `docs/ai/memory/incidents/` への昇格は人または対話セッションが行う**(初版(3)の維持。IC-020)。
- **(4′) 「月次の新たな中止要因を作らない」を、拡張子1つに賭けず二重に担保する。** ①`.gitignore` を `reports/incidents/` のディレクトリ単位除外へ変える(制約7によりCoordinatorの承認範囲)②同期の最後に**スコープを絞った** `git status --porcelain -- reports/incidents/` を検査し、空でなければ同期を失敗させる。**スコープを絞ることは必須である** — 作業ツリー全体は人の作業で日常的に汚れており(制約16)、全体の清潔さを転送の受入条件にはできない。
- **(5′) 無人セッションの読取拡大は `Read(reports/incidents/**)` の1エントリのみとし、`--add-dir` を使わない。** allowlistのpathエントリは**相対表記に限る**(制約8の成立条件1)。**既存の月次セッションのプロファイルは1文字も変更しない** — 評価は専用プロファイルを持つ別セッションとして走る。

**月次振り返りの中止条件、`docs/ai/core.md:25`、IC-030、Step 1が決めたquory側のバンドル配置(`reports/incidents/`)は、この決定では一切変更しない。**

## Trade-off Analysis

**初版が A-1系 と A-2′ を識別するために使った3点を、そのまま第2版で再評価する。**

- **(a) 封じ込めの面の数** — 初版は「A-2′なら `claude -p` が `Edit` 許可を1つも持たない/Hは `Edit(reports/incidents/**)` を1つ開く」とした。**この差はIC-007とD-4で消えた。** 叙述者が居らず、ファイル化はAnsibleが行うため、A-1系でもLLMの `Edit` は**ゼロ**である。(a)はもはや両案を識別しない。
- **(b) 叙述の材料を叙述者が書き換えられないこと** — 初版の懸念は「Hで `Edit(reports/incidents/**)` を開くと、読む非信頼バンドルと生成物が同じ書込可能面に載る」ことだった。**(2′)により評価セッションは書込可能面を1つも持たない**ため、この形は発生しない。読取と書込の主体が分かれるという性質は、A-2′ではなく**(2′)そのものが持っていた**性質だったと分かる。
- **(c) `.gitignore` への依存** — A-1系に残る唯一の実質的なConだった。**(4′)①で依存を拡張子からディレクトリへ移し、②で実行時の検査を足す。**依存はゼロにならないが、「1行の維持に賭ける」から「1行が壊れたら同期が即座に失敗する」へ変わる。初版はこの(c)を「(a)(b)より弱い根拠であり単独では識別しない」と自己限定していた。**その自己限定は正しく、(a)(b)が消えた今、(c)だけでA-2′を選ぶことはできない。**

**決定を反転させたのは、根拠が消えたことに加えて、新しい要求(制約12)が加わったためである。** 対話セッションがrepo内のパスから障害の中身を読めることは、A-1系だけが素直に満たす。A-2′で満たすにはJ(読取範囲の拡大)が要り、それは無人セッションの読取を絞った理由(機密混入の経路。同Lesson `:13`)に触れるためYoshinobu判断側へ回る。**境界を動かさずに解ける道がある以上、動かす道を推奨に混ぜない**という初版の方針は、第2版でも同じ向きに働いてA-1系を選ばせる。

**代償を明記する。** 証拠を公開repoの作業ツリー内へ置くことは、A-2′には無かったリスクを1つ増やす — **`.gitignore` が壊れる、あるいは誰かが `git add -f` すると、生ログ(ホスト名・内部パスを含みうる)が公開repoの履歴へ入る。** gitleaksとIPv4 pre-commitチェックはcommit時にしか効かず、ホスト名や内部パスは素通りする(設計合意「実装前に潰す細部 #4」)。**これは(4′)の二重の担保と、昇格を人の行為に留める(3′)で受け止める。**Yoshinobuが制約12を要求として置いた時点で、この代償を引き受ける判断がなされている(requirement §4 D-2)。

**初版の結論「`docs/ai/memory/incidents/` へ自動で直接書かない」は変わらない。** 支える3本の論拠(①Gを成立させるには安全境界を動かすしかない ②非信頼データを人のレビュー無しで公開repoへ入れない ③ノイズ希釈は**未決の設計に依存する条件付きの根拠**)は、いずれもIC-007の影響を受けない。②はIC-016・IC-032として、①はIC-025として、Policy側にも独立に定着した。

**Bについては第2版でも明記する。Bは劣った案ではなく、別の問題の案である。** 月次の中止を実際に引き起こしている汚れは振り返りの書込範囲の外にあり(制約16)、Bはそこに効く。ただしそれはStep 2が作る汚れではない。

## Consequences

**確定したこと(Step 2の実装はこれを前提にできる)**

- ミラー・同期状態・評価成果物はいずれも `reports/incidents/` 配下のgitignore済みパスに置かれ、**転送も評価も月次の中止要因を作らない**((4′)が守られる限りにおいて。実装時と回帰検証で再確認する)。
- **評価セッションは書込許可を1つも持たない。** 評価本文は標準出力として返り、Ansibleがファイル化する。
- **既存の月次セッションの権限プロファイルは変わらない。** 承認済みの読取拡大 `Read(reports/incidents/**)` は、**新設する評価セッション専用プロファイルの1エントリ**として現れる。
- `--add-dir` を使わないため、査読R-1が指摘した絶対path表記の落とし穴は構造的に発生しない。
- `docs/ai/memory/incidents/` への書込は人の行為であり続ける。
- **Step 1側のRSK-13(拡張子依存)は(4′)①で同時に解消する。** 初版が「本決定には不要だが別途処理する価値がある」と記録した残件が、第2版では決定の一部になった。

**Step 2の実装計画へ渡す判断(本ADRは決めていない)**

- 転送の機構・周期の実値・ミラーの具体パス、評価成果物の命名と保持、滞留と転送停止の検知方法。すべて `..._007_step2_plan.md` が決める。
- **ansy側の保持・ローテーション。** 未決のまま実装すると**ローテーションが未昇格の記録を静かに消す経路**が開く(IC-021、Step 1が既に退けた失敗の形)。計画はv1で「削除しない」を選び、実値の設計を後続へ送っている。
- 既知条件(pve1平日運用)を機械的に弾くかどうか(IC-022)。Trade-off ③の条件に直結する。
- `skills/incident-recording/SKILL.md` への追記の要否。**相関ID欄が無いことが、滞留検知を粗い指標に留めている唯一の理由**である。
