# ADR-005: 自動起票した第一報の出力先と、月次無人振り返りの中止条件との両立

**Status:** Proposed

対象案件: `docs/ai/reviews/incident_auto_capture_step2/2026-07-28_001_oq5_requirement.md`(OQ5の決着)
前提決定: `docs/ai/reviews/incident_auto_capture/2026-07-27_001_design_agreement.md` のD3(第一報は `状態: 調査中` 止まり、`原因分類` タグは空)、D4(叙述はansy側の `claude -p`)
現物確認の一次記録: `docs/ai/reviews/incident_auto_capture_step2/2026-07-28_002_oq5_investigation.md`
計画査読(層2)とその反映: 同 `..._003_adr_review.md`(F-1〜F-3)。**初版の推奨A-2はそのままでは実行不能**であることが判明したため、本版で決定内容を差し替えた。

## Context

Step 2は証拠バンドルから障害の第一報を自動で起票する。設計合意はその書き先を公開repoの `docs/ai/memory/incidents/` と想定していた(`..._001_design_agreement.md:111`)。一方で同じ設計合意 `:110` が、その想定のままでは成立しない相互作用を自ら指摘し、解の方向を2つだけ挙げて requirement 段階へ送っていた — 「**起票先を分けるか、中止条件を『自分が書く範囲だけ見る』へ精緻化するか**」。これがOQ5である。

現物確認(HEAD `4419250`)で確定した制約:

1. **月次振り返りは `git status --porcelain` が非空なら何も書かずに中止する。** `fail` させず、`ABORTED_DIRTY` としてSlackへwarningを出す(`roles/knowledge_review/tasks/main.yml:27-42,208-216`、`playbooks/knowledge_review.yml:36-37,52-55`)。この条件はrole実装だけの取り決めではなく、規範文書 `docs/ai/memory-classification.md:101` にも書かれている。
2. **迂回変数 `knowledge_review_allow_dirty` はtimerから渡らない**(`templates/knowledge-review.service.j2:13`、`defaults/main.yml:22-24`)。
3. **振り返り自身もcommitしない。** promptで禁じたうえ `deny: ["Bash"]` により実行手段そのものが無い(`templates/review-prompt.md.j2:79`、`templates/job-settings.json.j2:35-39`)。AIの `git commit` / `git push` 禁止は共通原則の正本(`docs/ai/core.md:25`)。
4. **`docs/ai/memory/incidents/` は月次振り返り自身の書込allowlistの内側にある**(`templates/job-settings.json.j2:27-40`、`templates/review-prompt.md.j2:69`)。読取allowlistは `docs/**` と `skills/**` のみで、**`reports/` もrepo外も読めない。**
5. **自動化が触れるのは `状態: 調査中` まで。`原因分類` タグを埋めるのは人**(D3 = `..._001_design_agreement.md:47-49`、同 `:116`)。月次のタグ集計は `解決済み` のみを数え、`調査中` は**滞留として件数と経過日数を報告する。滞留自体が検出対象**である(`templates/review-prompt.md.j2:27-31`、`docs/ai/memory-classification.md:80`、`skills/incident-recording/SKILL.md:57-58`)。
6. **`.gitignore` の `reports/` 除外は拡張子3つ(`.json` / `.log` / `.md`)のみ。** `reports/incidents/foo.txt` は無視されない(`git check-ignore -v` で確認)。Step 1の調査はこれを「最も安価に壊れる受入条件」(RSK-13、`..._003_investigation.md:184-186`)とし、ADR-004 `:93` は実装を `.json` のみに縛って回避している。
7. **`.gitignore` は安全境界でもPolicy本文でもなく、Coordinatorの承認範囲である。** `reports/incidents/` 配下に**追跡中のファイルは無い**(`git ls-files reports/` の結果は `reports/radius-health/` の2件のみ)。ディレクトリ単位の除外へ変えても既存の追跡ファイルへ影響しない。
8. **無人 `claude -p` はrepo作業ツリーの外へ書けない。** 封じ込めが成立する構成(相対path allowlist + `acceptEdits` なし + `--setting-sources` 空)では、repo外への書込を**絶対path・`//` 前置きとも許可できなかった**(実測)。`--add-dir` は**読取を足すだけで書込の柵にはならない**。同Lessonはこの場合の解も示している — 「**repo外の記録を更新する必要があるなら、LLMではなく起動側(Ansible等)が確定的に行う**」(`docs/ai/memory/lessons/claude-code-unattended-session-confinement.md:26-30`、読取側は `:13`)。
9. **その「起動側が確定的に書く」形の先例が、同じroleの中にある。** `roles/knowledge_review/tasks/main.yml:175-192` は `claude -p` の**標準出力をAnsibleがファイル化**してrepo外のstate配下へ保存している。新しい機構ではない。
10. **バンドル内容は非信頼データである**(ADR-003 `:88`、同 `:75`)。Step 2はそれを読んで公開repoへ叙述する。
11. **捕捉は平日ほぼ毎日発生し、実測では約半数が既知のpve1平日運用に由来する**(`..._031_production_status_check.md` 観測5)。対して現状の `docs/ai/memory/incidents/` の蓄積は一桁件数である。
12. **中止条件に当たる汚れはStep 2と無関係に日常的に存在する。** 確認時点の実際の汚れは `docs/ai/reviews/` 配下と `docs/ai/status.md` であり、**どちらも振り返りの書込allowlistの外**にあった。
13. **設計合意は既に「通知を終点でなく入口にする」と定めている**(`..._001_design_agreement.md:101`)。同時に、良質な調査結果が**Slackの散文として蒸発する**ことを解くべき問題として挙げている(同 `:99`)。
14. **「静かな取りこぼしを作らない」はStep 1が既に採用した規律である**(`..._003_investigation.md:180`。どのバンドルにも取り込まれないspoolレコードを、消さずに `orphan` として必ずバンドル化する)。

## Decision

**A-2′を採用する。** あわせて次の4点をStep 2の設計制約として固定する。

- **(1) 第一報の出力先はansy上のgit作業ツリーの外とする。書込主体は起動側のAnsibleである。** `claude -p` は第一報の本文を**標準出力へ返すだけ**とし、ファイル化・配置・命名はAnsibleが確定的に行う(制約8・9)。**LLMがファイルを書く形を選ばない。**
- **(2) Step 2の `claude -p` には `Edit` 許可を一切与えない。** allowlistに書込エントリを1つも置かない。これにより「`docs/ai/memory/incidents/` へ書かせない」は、禁止を列挙することではなく**許可が存在しないこと**で達成される。読取は必要な範囲(バンドル)だけを `--add-dir` と `Read(...)` で与え、`Bash` はdenyする(`..._session-confinement.md`)。
- **(3) 第一報 → `docs/ai/memory/incidents/` の起票(昇格)は人または対話セッションが行う。** D3の「タグを埋めるのは人」「自動化が触れるのは `調査中` まで」と同じ線を、**ファイルの所在**にも引く。
- **(4) quory→ansyのバンドル転送経路にも同じクラス制約を課す。** 転送先も**git作業ツリーの外**とする(経路自体の設計は本件の非ゴールだが、この制約は先に固定する)。

**月次振り返りの中止条件、`roles/knowledge_review`、`docs/ai/core.md:25` は、この決定では一切変更しない。** `.gitignore` の変更も本決定には不要である。

## Trade-off Analysis

**まず、結論「`docs/ai/memory/incidents/` へ自動で直接書かない」を支える論拠を置き直す。** 初版はこれを「第一報は常に `調査中` だから、タグ集計の母数に**構造的に**入らない」と論証していたが、これは誤りである(査読F-3)。`skills/incident-recording/SKILL.md:14-15` の2段階は**同一ファイルの状態遷移**であり、canonical path上に第一報があれば、人が原因を確定させた時点でそのファイルがそのまま母数へ入る。入らないのは起票の瞬間だけである。滞留報告も副産物ではなく、**忘れられることを防ぐために設計された検知機構**である(制約5)。したがって「repoの中に置く利得はゼロ」ではない。**利得は実在する。**

それでも結論が変わらない理由は3つある。

1. **Gを成立させるには安全境界を動かすしかない。** 直接起票は制約1と衝突し、回避するにはB・C・Eのいずれかが要る。3案ともYoshinobuの領域であり、この案件では動かせない(requirement §4)。**境界を動かさずに解ける道がある以上、動かす道を推奨に混ぜない。**
2. **非信頼データを人のレビュー無しで公開repoへ入れない**(制約10)。人の昇格ステップは、設計合意 `:111` が求めた「生ログを本文へ転記させず参照だけ書かせる」規律が実際に働く唯一の検査点である。gitleaksとIPv4 pre-commitチェックはcommit時にしか効かず、ホスト名や内部パスは素通りする。
3. **ノイズ希釈の懸念**(制約11)。ただし**これは条件付きの根拠である** — Consequencesで未決として残す「既知条件(pve1平日運用)を機械的に弾くか」次第で大きく変わる。弾けばノイズは大幅に減る(`..._031_...md` 観測5が候補playbookまで特定済み)。**未決の設計に依存する前提を、確定的な根拠として使わない。**

**次に、A-1系(A-1 / H)とA-2′の識別を、制約6以外の言葉でやり直す。** 初版は「A-1でなくA-2を選んだ理由は制約6に尽きる」と書いたが、制約7のとおり `.gitignore` はCoordinatorの承認範囲で変更でき、Hはその唯一のConを消す(査読F-2)。したがって制約6は識別の根拠として使えない。使えるのは次の3点である。

- **(a) 封じ込めの面の数。** A-2′ではStep 2の `claude -p` が `Edit` 許可を1つも持たない。Hは `Edit(reports/incidents/**)` を1つ開く。**禁止を「手段」ではなく「結果」で書く**という既存の教訓(`docs/ai/memory/lessons/permission-boundaries-must-be-designed-not-prompted.md`)に、許可がゼロである構成のほうが素直に噛み合う。
- **(b) 叙述の材料を叙述者が書き換えられないこと。** Hで `reports/incidents/` 配下に書込を許すと、**Step 2が読む非信頼バンドルと、Step 2が生成する第一報が、同じ書込可能面に載りうる。** 材料を書き換えられる叙述者は、その材料の同一性を保証できない。避けるにはパスを分ける追加設計が要り、Step 2の未決定を増やす。A-2′は読取と書込の主体が分かれるため、この問題が発生しない。
- **(c) `.gitignore` への依存が残るかどうか。** Hは依存の強度を大きく下げるが、ゼロにはしない(1行の維持に賭ける)。A-2′は依存しない。**ただしこれは(a)(b)より弱い根拠であり、単独では識別しない。**

A-2′の代償は配管が1つ増えることだが、**新規性は無い。** 制約9のとおり、`roles/knowledge_review` が既に「LLMの標準出力をAnsibleがファイル化してrepo外へ保存する」形を実装している。むしろ「repo外へ書けない」は封じ込めLessonが**利点**と評した性質そのものであり(「書けないものは壊せない」)、それに沿う。

なお「月次振り返りから第一報が読めない」は**識別の根拠にならない。** 読取allowlistは `docs/**` と `skills/**` のみであり(制約4)、**Hでも `reports/` は読めない。** 読ませたいならJが要り、Jは読取範囲の拡大としてYoshinobu判断側になる。

Iを退けたのは制約13による。Slackは相関IDの入口として**どのみち必須**だが、それを**終点**にすると「良質な調査結果がSlackの散文として蒸発する」という、設計合意が解こうとした問題そのものを再生産する。Dを退けたのは機能ではなく責任の所在で、「誰がいつmergeするか」を決めない限りA-2′の欠点を解消せずに複雑さだけ足す。

Bについては誤解を避けるために明記する。**Bは劣った案ではなく、別の問題の案である。** 制約12のとおり、月次の中止を実際に引き起こしている汚れは振り返りの書込範囲の外にあり、Bはそこに効く。ただしそれはOQ5ではない(`..._002_oq5_investigation.md` §3-3)。

## Consequences

**確定したこと(Step 2のrequirementはこれを前提に書ける)**

- **第一報の出力に関しては**、自動起票がgit作業ツリーを汚さない。転送経路にも同クラス制約を課す(Decision (4))ため、Step 2が月次無人振り返りの新たな中止要因を作らない。**ただしこの保証はDecision (4)が守られる限りにおいてであり、転送経路の設計時に再確認が要る。**
- 月次振り返りの中止条件、`knowledge_review` role、`docs/ai/core.md:25` は変更しない。本件で `roles/` / `playbooks/` / `.gitignore` への差分は発生しない。
- **Step 2の `claude -p` は書込許可を持たない。** 第一報はLLMの標準出力として返り、Ansibleがファイル化する。この形はStep 2の実装契約であり、requirementに明記する。
- `docs/ai/memory/incidents/` への書込は人の行為であり続ける。
- 月次振り返りは自動起票された第一報を**読まない**(制約4)。これは現在の設定の帰結であって不変の構造ではなく、Jを採れば反転しうる。

**Step 2に残る判断(本ADRは決めていない)**

- **未昇格の第一報を検知する主体。** Decision (3)で昇格を人の行為に固定した一方、月次振り返りは第一報を読まない。**このままでは「拾われなかったこと」に気づく主体が誰も居ない。** 保持期間・ローテーションが未決のまま実装されると、**ローテーションが未昇格の第一報を静かに消す経路**が開く。これはStep 1が既に退けた失敗の形である(制約14)。したがってStep 2の必須要件は「人へ届ける経路」だけでは足りず、**「拾われなかったことを検知できること」**を含める。
- 出力先の実パス、保持期間・世代数、ローテーション。
- 第一報を人へ届ける経路の具体(Slackが第一候補。制約13の相関ID方針に乗せる)。
- 起票の粒度と重複排除、**既知条件(pve1平日運用)を機械的に弾くかどうか**(Trade-off 3の前提に直結する)。
- 昇格(第一報 → `docs/ai/memory/incidents/`)を誰がどの頻度で行うか。`skills/incident-recording/SKILL.md` へ**捕捉の前段(自動第一報)を追記する必要があるか**の判断を含む。現在のSKILLは2段階をcanonical path上で完結する形で書かれている。

**Yoshinobuの判断を要する事項(この決定には含めていない)**

- **B**(中止判定範囲の精緻化)— 制約12が示す**既存の**中止頻度への対策。`docs/ai/memory-classification.md:101` の改訂を伴う。
- **C**(自動commit)— `docs/ai/core.md:25` に抵触。
- **E**(中止条件の除去)— 安全弁そのものの改訂。
