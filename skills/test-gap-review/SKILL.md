# Test Gap Review

実装の正しさを代わりに証明するのではなく、欠陥が未観測のまま通過する穴を見つける。テスト数ではなく、受入判断を変えうる観測が揃っているかを確認する。

## 手順

1. 受入条件ごとに、実装が生む観測可能な結果と、その結果を確認する既存テストまたは検証記録を対応付ける。
2. 変更された条件分岐、状態遷移、外部境界について、次のうち差分に関係するケースだけを確認する。
   - 初回成功と、変更不要時の成功。
   - 該当なし・空入力と、取得失敗・判定不能。
   - 不正値、欠落値、型違い、境界値。
   - 複数項目の一部失敗、途中終了、失敗後の再実行。
   - check / dry-runとapplyで異なる経路。
   - 複数host、`run_once`、`delegate_to`、handlerなど実行単位が変わる経路。
   - Policyが禁止する経路を通らないことを確かめるnegative case。
3. テストが対象経路を本当に通り、期待する最終状態・出力・失敗をassertしているか確認する。mockやdecoyは、差し替えた接続先だけでなく対象コードがその値を実際に消費するところまで辿る。
4. 未検証のままなら現実的に逃す欠陥と、その影響を説明できるものだけをgapとして残す。
5. gapを塞ぐ最小のテストまたは観測点を推奨し、実行はTesterへ委ねる。

## 指摘しないもの

- 全task、全変数、全組合せを機械的に網羅するためだけのテスト。
- 実装詳細を固定し、同等なリファクタリングを妨げるassertion。
- 既存の静的検査で十分に検出でき、今回の差分に固有の逃げ道がない重複テスト。
- 発生しうる欠陥または受入判断への影響を説明できない「念のため」の追加。
- Testerのtest plan作成や検証実行の代行。

## 報告

各gapには、未検証の挙動、逃しうる欠陥、最小の推奨テストを含める。重大度と出力形式は`docs/ai/roles/reviewer.md`および`skills/code-review/SKILL.md`に従う。問題がない場合も、対応付けを確認した受入条件と未実施の実環境検証を明記する。

Testerが作るテスト計画の構造は`skills/test-strategy/SKILL.md`を正本とし、本Skillは計画を作り直さない。Ansibleの成立性そのものは`skills/ansible-correctness-review/SKILL.md`で扱う。
